# 事实分类配置

本目录的 `fact-categories.json` 是服务器分类字典，不是事实内容或审核规则。前端选择框、名称说明和图标色系、后端保存校验、话术挖掘模型的分类列表共同读取它。

## 生效方式

- 生产默认位置：`/opt/xiaolan/current/configs/fact-categories.json`。
- 可用环境变量 `FACT_CATEGORY_CONFIG_PATH` 指定其它文件；显式配置路径错误时不会偷偷回退。
- 服务每次请求读取文件，页面加载时通过 `GET /api/v1/live-agent-fact-categories` 读取最新配置；修改后刷新页面即可，不需要重编译或重启。
- 文件建议保存为 UTF-8，支持 UTF-8 BOM；建议完整校验后原子替换，不要让业务请求读到写了一半的 JSON。
- JSON 损坏会明确报错，页面提供重新加载，不用旧字典假装新配置已生效。

## 字段

- `schema_version`：当前为 `1`；`version`：运营维护的版本说明。
- `categories`：按下拉显示顺序排列，最多 200 条；相同 `group` 放入同一个选项组。
- `value`：保存和模型返回使用的稳定标识，正则 `[a-z][a-z0-9_]{0,47}`，不能重复。
- `label`：用户看到的名称，最多 40 字。
- `description`：表格名称下的分类说明，最多 200 字；不是模型生成的商品事实。
- `group`：选项分组名称，最多 40 字。
- `family`：图标和色系的大类，只能是 `product`、`link`、`trade`、`fulfillment`、`identity_location`、`other`；它不替换保存的 `value`。

新增条目只需填写这些字段。当前提供 7 组、42 类，涵盖商品信息、链接选购、价格活动、发货配送、售后服务、品牌资质、场景其它。

## 历史兼容与边界

必须保留原六个 `value`，且它们的 `family` 不能改变。已使用过的其它 `value` 也不要删除或改名；调整显示名称用 `label`，新增分类用新 `value`。删除历史标识会让旧事实无法通过后续保存校验，界面只保留原值并提示“历史分类”，不会自动改成其它事实。

增加分类不会迁移、重分类、确认或审核放行已有事实，不会更新已发布方案或正在运行场次。用户新增/修改事实仍按当前方案隔离保存，并继续经过原有风险处理。

发布包含配置文件和整个提示词母版目录，不能只改前端的静态选项。服务器部署包应检查分类 JSON 与母版清单哈希。
