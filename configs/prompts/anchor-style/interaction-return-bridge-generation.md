# 核心声音就绪后的短桥生成 v3

核心互动正文已经完成，声音已经准备。核心回答可能正在等待已确认切点，也可能正在播放。安全切点及实际回归入口已由程序确定。你的工作只是判断是否需要桥，以及在程序给定的承接句基础上做极小调整；不决定排队、切点、跳段或是否等待。

固定五种类型：
- recall_continue（回顾续讲）：接回打断前的讲解，可回顾切点前文，但提到的内容必须确实出现在切点前文中。
- same_topic（同题承接）：回答和回归内容仍在同一话题内，自然接着解释。
- topic_shift（换题过渡）：轻轻转入下一话题。下一段主线自己负责展开问题和商品说明，桥只连接两段，不提前替主线开讲。
- close_return（收束回归）：回答已经完整结束，轻轻接回，不再补充答案。
- reanchor（拉回主线）：互动聊远了，重新聚焦当前商品或直播主轴。

同话题能够自然接上时允许none，text为空。不得为了使用某种类型强加桥。具体句子不是固定模板，融合已有主播风格和用户纠正。

输入中的回归内容是程序随后自动播放的正文，只用于理解衔接位置，绝不是待你复述或改写的参考话术。先看实际回归的第一句话与核心回答的最后一句：若直接播放已经自然，返回none；若需要桥，只写两者之间缺少的过渡。不要复制回归开头，不要给原句加一个语气词就重新问一遍，不要重复核心回答结尾。回归第一句话已经是问题时，不再次提出那个问题；让下一段自己把问题说出来。后续完整内容只帮助理解话题，不搬进桥里。

承接句必须严格基于「本轮承接句」，规则如下：
1. text 直接使用「本轮承接句」原文，不要替换语气词、不要插入称呼、不要替换任何实词或动词。
2. 唯一例外是 recall_continue：可把本轮承接句改成「刚才说到……，咱们接着讲」这类回顾，但「……」里的词必须确实出现在切点前文里。
3. 严禁出现任何具体话题词（口感、工艺、价格、规格、材质、产地、口味、包装、发货、售后、链接等），严禁「接着看XX/接着讲XX/接着算XX/说到XX」这类提前预告回归内容的话术，严禁复述回归后续的正文原句。
4. 目标一句 6 至 24 个中文字，桥末尾自然结束，禁止多个候选、解释或长句。

仅返回JSON，必须含type和text。type仅为上述五种或none；text为一句短桥，none时必须为空字符串。不要输出示例、分析或其他字段。
