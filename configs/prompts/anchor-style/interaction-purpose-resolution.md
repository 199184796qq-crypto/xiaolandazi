# 意图分析 v2

## 任务
读观众原话，判断他问什么、为什么问。只做判断，不生成口播，不决定互动时机。

## 输出（严格 7 字段 JSON）
只输出一个 JSON 对象本身，不要用 ``` 包裹，不要输出任何 JSON 之外的文字或解释。

- question：是否真实提问（布尔）
- relevant：是否与业务相关（布尔）
- confidence：置信度 0~1
- purpose_id：已有目的编号，或空字符串
- purpose：目的中文描述，要体现"为什么问"
- scope：原话里明确出现的商品/数量/规格，没有就空
- task_angles：该目的可回答的任务，最多 3 项；每项只写「目的编号、角度、讲述任务」，不要写关联事实，事实由程序匹配

## 判断规则
1. 目的是"为什么问"，不是"问什么"：急着用 / 送礼 / 有顾虑 / 在比价 / 单纯了解。不确定就按"单纯了解"，不硬猜。
2. 不同目的不合并：快递公司、发货地、发货/到货时效、运费、生熟属性、售价、优惠、价值判断是不同目的，不能因同属物流或价格就合并。
3. scope 只写观众原话里明确出现的商品/数量/规格，不自行补入规格或反例数字。
4. 第一次或歧义问题可建立新目的；低置信不硬套。与业务无关的闲聊、打招呼、下单陈述不算商品问题。
5. 价格问题必答清楚价格，真实有效且条件满足的优惠才是可选推进；不机械逼单。
6. 地点类问题（在哪、哪里、地址、位置、门店、发货地）即使没说清对象，也要给出角度：优先归到位置/发货地/门店相关的目的；列表里没有就新建目的，不要返回空。
7. 只要是真实提问（question=true、relevant=true），purpose 和 task_angles 至少给出一项，不允许两个都空。
8. 输入里若带「领域卡」，先用它判断观众问的是哪个维度；purpose 和 task_angles 要围绕命中的维度，不要跳到价格、工艺等其他维度。
9. 输入里若带「本问题命中事实」，只把它当作该维度的语义提示，不得把事实里没写的条件、承诺或地区扩大；条件判断仍以事实原文为准。

## 红线
- 事实中的禁止表述和建议表述须完整尊重。
- 不得把写作建议、反例数字或假设优惠变成事实。

## 示例
{"question":true,"relevant":true,"confidence":0.96,"purpose_id":"P01","purpose":"了解当前商品售价","scope":"当前商品","task_angles":[{"目的编号":"P01","角度":"直接说明售价","讲述任务":"先回答价格和已确认计价单位","采用条件":[{"类型":"question"}]}]}
