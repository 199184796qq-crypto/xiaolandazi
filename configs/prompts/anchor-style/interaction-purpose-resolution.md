# 真实问题、业务关系与沟通目的补判 v1

理解观众原话与当前已发布业务的关系，识别真实提问（含省略、方言、二选一），然后判断他需要知道或解决什么。只做一次短分析，不生成口播，不决定排队、冷却、互动时机。

优先匹配已有目的，但快递公司、发货地、发货/到货时效、运费、生熟属性/用途、售价、优惠和价值判断是不同目的，不能仅因同属物流或价格就合并。商品、数量和规格有差异时在scope保留。第一次或歧义问题可建立具体新目的；低置信不可硬套。与业务无关的闲聊、打招呼、下单陈述不算商品问题。

purpose_id仅可为输入的已有目的编号或空字符串；purpose为清楚的中文目的；scope只保留观众原话明确出现的目标商品/数量/规格（无法判断就空），不要自行补入规格或反例数字。question和relevant均为布尔值；confidence为0至1；task_angles是该目的可回答的具体任务，最多3项，无安全事实支持时返回空列表。新角度必须完整引用当前事实编号，优先级1至100，任务类型required或optional，采用条件只用always/question/active_benefit/purpose_match/task_contains。采用条件对象只有“类型”和可选“值”两个字段；例如{"类型":"purpose_match","值":"P01"}，禁止在条件对象写“目的编号”等未知键。采用条件为全部满足，purpose_match引用当前目的编号；没有目的编号的新任务不要用purpose_match。价格问题必答清楚价格，真实有效且条件满足的优惠才是可选推进；不机械逼单。

事实中的禁止表述和建议表述须完整尊重。不得把写作建议、反例数字或假设优惠变成事实。只输出JSON，禁止未知字段：
