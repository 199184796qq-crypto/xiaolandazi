# 已确认卖点池增量更新与复核

事实包是唯一事实来源。输入 `phase` 为 update 或 review，包含完整的新事实包 `fact_package`、新增事实 `added_facts`、移除或修改前的事实 `removed_facts`、带稳定整数 id 的已确认卖点池 `existing_points` 和已有事实补充建议。

update 阶段只识别受事实变化影响的已有卖点，返回其必要修订或删除，以及新增事实确实支持的新卖点。未受影响的卖点和用户编辑不得重新生成或改写。先检查能否在已有主题内补充变化角度，不能因新事实就重复创建同一主题。修改后的卖点仍须含自身有明确事实边界的不同沟通任务，不用行业知识补答案；缺失不代表否定，标签不替代正文证据。

review 阶段还包含 `proposed_patch`。只复核这个增量补丁，不能增加新的更新 id；可删减不被新事实支持的角度或新增项，纠正价格、规格、活动范围和人群路由，不能修改补丁外的已确认卖点。全部新事实包用于核对，不要求再生成完整轮盘。某更新项没有可保留的事实时可将 point 置 null 删除该卖点。

禁止保留依赖已移除/修改事实的旧价格、优惠、时间或推断结论。共同事实影响多个卖点时，必须更新全部受影响项；不能只根据关键词机械判定。跨主题检查重复任务，但不得借此改写无关的用户编辑。

严格输出 JSON，仅以下三个顶层字段，所有数组均输出 [] 而不是 null；fact_gap_suggestions 允许 null，表示保留已有补充建议：

{"updates":[{"id":1,"point":{"卖点名":"原有主题","目标人群":"中性购买决策状态","痛点":"事实可回答的问题","角度":["包含明确事实的沟通任务"]}}],"additions":[],"fact_gap_suggestions":null}

updates 的 id 必须来自 existing_points 且不重复，point 可为 null（删除）或完整卖点对象。additions 为相同卖点对象数组。每个卖点只允许 卖点名、目标人群、痛点、角度 四个字段，角度为 1 至 12 个不同的非空字符串。目标人群和痛点不是适用或效果声明。补充建议若需更新，每项仅含 主题、适用范围、建议分类、待补事实、补充价值、填写提示，与完整轮盘协议一致。未确认内容只能放入补充建议。不能输出解释、代码围栏、原轮盘全文或其它字段。
