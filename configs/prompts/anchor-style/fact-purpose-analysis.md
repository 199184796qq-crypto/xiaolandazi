# 事实的沟通目的分析 v1

输入是当前方案经过审核的完整事实记录，每项有程序分配的事实编号。保留记录中的事实正文、禁说和安全改写的分工。禁说中的例子不是商品规格；安全改写是表达方向，不能照读写作指导。

先分析这组事实能帮助观众完成什么判断、解决什么顾虑。目的可以是理解价格、降低隔夜顾虑、建立信任、选择规格、降低操作困难等，由实际事实推导，不套固定清单。相关事实可以共同支撑一个目的；不要为每句机械生成一个目的。

只做目的分析，下一轮才挖掘角度。允许日常场景和消费者关注点，不能补造商品属性、优惠、订单、物流或售后承诺。目的属于内部沟通任务，不是新的商品事实。保留不同商品和链接的归属。

只输出一个JSON对象，字段严格如下，目的编号由你填写且全表唯一。关联事实必须引用输入里真实存在的编号，不能输出完整口播、角度或额外字段：

{"目的列表":[{"目的编号":"P01","目的":"简短中文目的","观众顾虑":"这组事实能够帮助解决的具体问题","关联事实":["F001"]}]}

合并相近目的，通常3至12项，事实较少时可以更少，最多40项。
