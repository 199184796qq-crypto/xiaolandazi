# 公共池与商品专属池的卖点×角度

输入是一份公共或商品专属内容池，包含适用商品、审核事实及事实编号。你只为这个池产生卖点×角度任务。公共池仅使用公共事实，普通公共任务用“这款/当前商品”等指代，不点名单个链接；专属池仅使用这个商品的事实和福利。每个任务必须引用实际使用的事实编号。

采用原始可讲事实，保留价格、数量、链接、条件和福利有效期；不把反例、错误规格、禁说、源材料中未经确认的数字当成商品事实。算账口径必须说明正确的主体，不能将一道菜的价格说成整桌饭价格。属性不足时不要补造库存、销量、口感或优惠。

事实足够时产生4至8个卖点主题，每个主题3至5个不同角度；资料较少时按真实材料生成，不凑虚假内容。角度要有不同讲法和关注点，避免逐句重复。普通任务只讲当前商品，多个商品都适用的资料不意味着同时推销多个商品。跨商品比较不在本次任务内。

给每个角度标一个 weight（1到5的整数），表示它在多轮讲解中的相对重要程度：核心种草点、有正式依据的高转化角度、主推商品的核心卖点给 3-5；一般信息、补充说明、低频适用场景给 1-2。不要因为角度多就给高权重，权重只反映"这个角度值不值得多讲"，与角度数量无关。缺省时按 1 处理。

如果提供 confirmed_legacy_content，这是用户已确认或手动编辑的原卖点与角度；将其中本池事实支持且适用于本池的内容迁入，保留讲解意图，不机械照搬其他商品内容。

如果提供旧任务，请保留未受来源变化影响的用户内容和原任务编号；仅修改受影响内容或补充有依据的任务。旧任务及 confirmed_legacy_content 是待迁移的方向，不能覆盖本池当前事实。旧句仍有一部分成立，不代表来源变更后整句仍完整：引用事实新增了适用对象、选项或条件分支时，重新理解当前事实，补齐本条需要的对应关系，不能为保留旧句而沿用旧摘要。商品编号、事实编号用于关联，标题可修改。

任务是讲述方向及必要信息的工作摘要，不是对引用资料的替代。说明多个选项的区别、选择依据或共同条件时，保留本次涉及的每个选项与其参数、期限、条件的对应关系；不能同时列出多个选项，却只留下其中一个的关键结果，让其余选项的区别消失。可以改写或精简，但用于区分选项的关键条件不能省掉。仅聚焦某一个选项的任务可以只讲该选项，须明确对象；不要求每条任务复述全部引用事实，也不把无关内容加进来。只有编号引用正确还不够，摘要必须完成所选方向需要的说明。

逐条独立完成：本条已经列出多个可选对象，并引用这些对象的同一维度差异资料时，把该维度的每个对象与对应取值一起写进本条 angle，不能仅说明一个对象，不能用其他任务已写了来替代。这样的任务不属于“只聚焦一个选项”。旧任务编号与方向可以保留，旧 angle 是待更新草稿，不是需要保护的定稿；必要条件有遗漏时重写本条 angle。内部对照本条涉及的对象与引用事实，再输出，不输出检查过程。source_ids 必须原样复制本池 facts 的 id 字符串，不缩写、不重编号、不改成数字。

仅输出JSON：
{"tasks":[{"id":"旧任务编号可保留，新任务可留空","selling_point":"卖点主题","angle":"本条角度","target_audience":"适用人群","pain_point":"具体关注点","weight":2,"source_ids":["事实编号"]}]}

不要输出完整主播文稿。所有事实引用必须来自本池。目标人群和关注点也不能引入资料外的新事实。

每条任务的 source_ids 至少有一个本池编号。旧任务在本池没有依据时不迁入，不保留空引用，也不引用全部编号来掩盖缺失；其他有依据的方向正常生成。
