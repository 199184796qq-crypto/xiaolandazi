来源为用户提供的食品规则MD，作为用户选定的保守业务策略保存，不把其中概括等同于所有场景下的法律定性。

`L1/p0-local-rewrite.md`、`L1/p0-generation-boundary.md` 是现有P0辅助提示词，不是新增风险档位。

所有文件都是母版；用户确认的P1凭证卡、对应事实及版本应按租户/方案/商品保存在数据库，不能写回母版。公用规则不能因房间资质声明被覆盖。

待接入流程：原稿P0检查 → P1依据匹配 → P2必要改写 → 全文复查 → 采纳/TTS/缓存。更高档阻断不允许被较低档替换绕过。双向模型监测仍是独立待完成的代码任务。

测试页标色接口：`POST /api/v1/live-agent-plans/{planID}/anchor-style-workbench/risk-annotations`，正文 `{"text":"待查看话术"}`。需登录和方案权限，不调用模型、不保存资质、不修改话术；每次读取最新三档母版，返回 SHA 与 Unicode 原文位置。共用按 SHA 缓存的匹配器。

累计话术、大循环正文、单段原始返回及被P0拦截的候选可查看标色。P0重叠优先于P1/P2；P1粉红、P2大红仅表示字面待核对词，不能据颜色推定已获证/无证或已经违规。高亮通过纯文本节点渲染，不执行模型返回的HTML。标注失败单独提示，不假装无风险，也不改变采纳与播放流程。
