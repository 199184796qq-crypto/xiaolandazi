# 系统提示词模板目录

用户指定：以后系统所有提示词模板统一放在本目录，以 Markdown 文件维护。`anchor-style` 是历史目录名，不限制只存放主播风格模板。

## 管理约定

### 母版与数据库方案

- 本目录所有文件都是项目级母版，不是某个直播间方案的运行副本。
- 房间对应方案的提示词、主播基准、卖点轮盘、评分权重与容差等稳定配置保存在数据库，按租户、方案和版本隔离，房间关联读取。
- 修改母版只影响后续初始化、分析生成或明确导入，不自动覆盖已有方案。页面对方案的修改和确认仅保存对应数据库版本，绝不能写回母版或覆盖其他方案。
- 卖点轮盘只在“初始化直播智能体”等明确生成动作中调用母版；模型提出的`事实补充建议`只负责引导用户补录，补录并重新初始化前不得进入正式卖点、角度或运行话术。
- `style-scoring-policy.md`也遵守上述规则：它是默认规则母版，接入后初始化为对应方案的数据库配置；实际运行不从共享文件动态替换所有房间的权重。当前仅建立母版，不代表已有方案权重已迁移或评分器已改用新规则。
- 大循环的本场临时状态与配置快照仍仅存Redis；稳定配置存数据库不意味着结束后或服务器重启后恢复旧场次。
- 公用P0规则不允许房间风格覆盖。每场启动读取最新MD并冻结Redis快照；规则版本和后台审核记录独立留档，不用于恢复本场进度。修改P0母版在下一场生效。
- 开场钩子在没有已确认方案版本时，每个新开场读取最新`opening-hook-library.md`。在测试页明确导入/编辑确认后，新增`live_opening_hook_assets`方案版本，后续新场采用该数据库版本快照；母版更新不覆盖它，可再次明确导入升级。同一开场重试保留已选择模板，采纳后才更新Redis避重记忆。

### 文件维护

- 默认每次请求从当前母版文件现读，页面旧预览和数据库历史提取模板不覆盖它；手动上传/编辑须显式选择本次手动模式。
- `ANCHOR_STYLE_PROMPT_DIR`可指定统一母版目录；服务器指向`/opt/xiaolan/current/configs/prompts/anchor-style`。单模板路径覆盖仍属明确运维配置，实际路径与SHA256随结果记录。
- 发布时整目录打包并生成、校验`MANIFEST.json`，不以固定名单遗漏新增模板。更新本地文件不会自动传到服务器，须部署更新后的文件；服务器下一请求再现读。

- 新增口播生成、调度、监督、回灌等提示词模板继续放在这里，不在业务代码中硬编码大段正文。
- 模板名称只标识用途，不绑定调用模型。
- 修改模板时检查后端加载路径与生产发布打包配置。
- 这是基础模板目录。用户确认的元提示词、基准表、卖点轮盘等运行资产仍保存在数据库中，关联对应直播间方案；模型原始返回独立保留。
- 本次只确立后续存放约定，不批量迁移或覆盖历史模板。
