# 主播风格插件开发规范

状态：v1（可实现）  
协议版本：`anchor-style-plugin/v1`  
实例版本：`anchor-style-plugin-instance/v1`

本文是主播风格插件的开发契约。开发者不需要知道当前使用 DeepSeek、Qwen 或其他生成模型，也不需要修改提示词主干。只要按本文提交插件清单、实例样例和测试，主播风格编译器就能识别该能力。

## 1. 插件解决什么问题

插件只负责“主播怎么说”，例如：

- 偶尔自然改口；
- 两三句话如何推进；
- 低频幽默；
- 固定称呼和自称；
- 偶尔口算岔了并马上纠正。

插件不负责：

- 商品、价格、规格、链接、产地、库存、物流、售后等事实；
- 遇到什么问题应该回答什么内容；
- 哪些问题必须打断、何时回归主线；
- L1/L2 审核规则；
- 模型选择、计费、声音合成和直播间调度。

这些边界必须保持。风格插件不能借“表达方式”之名修改事实或互动策略。

## 2. 总体架构

```text
用户自然语言 / 主播样本 / 人工反馈
                │
                ▼
       语义解释器（当前可用 Qwen）
                │ 只产生候选配置
                ▼
       Go 插件协议校验与注册表
                │
       ┌────────┴────────┐
       ▼                 ▼
  声明式插件          可信执行器插件
  固定受限规则        Go 内置、可做强保证
       └────────┬────────┘
                ▼
       风格编译产物 CompiledFragment
                │
       ┌────────┼────────┐
       ▼        ▼        ▼
     主线     低频刷新   实时互动回答
```

模型只负责解释和生成候选文本。插件是否合法、参数是否越界、是否可在当前场景运行、是否与其他插件冲突，由 Go 代码决定。

## 3. 两种插件模式

### 3.1 声明式插件 `declarative`

适合只需要受限表达规则的能力，例如自然改口、低频幽默、固定短句推进。

特点：

- 只需发布 `plugin.json`，当前服务在启动时统一加载；
- 不运行第三方代码；
- 输出固定场景指令、微动作和已校验参数；
- 可以由大模型执行，但必须经过现有事实约束和质检。

声明式插件不得声明 `runtime`。

### 3.2 可信执行器插件 `trusted_executor`

适合需要程序强保证的能力，例如“故意算错一个派生结果并立即纠正”。

特点：

- `plugin.json` 与服务版本一起发布，当前服务在启动时统一加载；
- 执行器必须由服务端 Go 代码显式注册；
- 插件目录不能携带并动态执行 `.dll`、`.so`、脚本或任意二进制；
- 未注册执行器时，插件加载失败，不能降级为普通提示词；
- 适合计算器、原子音频、原子字幕、不可打断等强约束。

v1 不采用 Go `plugin.so`。其跨平台和版本兼容性不足，也扩大了生产环境执行任意代码的风险。后续如确需第三方运行时代码，应另立 WASM 或隔离进程协议，不修改 v1 语义。

## 4. 标准目录

每个插件一个目录：

```text
plugins/anchor-style/<plugin-id>/
├── plugin.json
├── README.md                    # 可选，说明使用效果
└── testdata/
    ├── valid-instance.json      # 必须
    └── invalid-instance.json    # 建议
```

公共契约：

```text
shared/schemas/
├── anchor-style-plugin-manifest.schema.json
└── anchor-style-plugin-instance.schema.json

management-service/pkg/styleplugin/
├── contract.go
└── registry.go
```

可信执行器建议放置：

```text
management-service/internal/styleplugins/<executor-name>/
├── executor.go
└── executor_test.go
```

## 5. `plugin.json` 字段

完整 JSON Schema：`shared/schemas/anchor-style-plugin-manifest.schema.json`。

| 字段 | 必填 | 说明 |
|---|---:|---|
| `$schema` | 否 | 指向仓库内 manifest schema，便于编辑器校验 |
| `api_version` | 是 | v1 固定为 `anchor-style-plugin/v1` |
| `id` | 是 | 小写短横线命名；发布后不可改 |
| `version` | 是 | SemVer，例如 `1.2.0` |
| `name` | 是 | 前台中文名称 |
| `description` | 是 | 能力说明，不能写业务事实 |
| `mode` | 是 | `declarative` 或 `trusted_executor` |
| `category` | 是 | 风格分类 |
| `scenes` | 是 | 允许场景 |
| `parameters` | 否 | 用户可配置参数及边界 |
| `requires` | 否 | 运行依赖的系统能力 |
| `conflicts` | 否 | 不能同时启用的插件或能力 |
| `safety` | 是 | 安全能力声明 |
| `compiler` | 是 | 语义识别和编译输出声明 |
| `runtime` | 条件必填 | 可信执行器名称 |

### 5.1 分类 `category`

- `delivery`：说话表现，如改口、停顿、口误；
- `rhythm`：长短句、快慢、重复节奏；
- `lexical`：称呼、自称、口头词；
- `local_flow`：两三句话的局部推进；
- `humor`：幽默、打趣、自嘲；
- `interaction_delivery`：互动回答的表达方式，不包含回答内容策略；
- `storytelling`：叙述方式和场景化表达。

### 5.2 场景 `scenes`

- `mainline`：本场预生成主线；
- `interaction`：实时互动回答；
- `refresh`：低频更新的主线声音片段；
- `serious`：投诉、售后、事实澄清等严肃语境。

未声明的场景不得运行。若能力不适合严肃语境，应同时把 `serious` 放入 `safety.forbidden_scenes`。

### 5.3 参数 `parameters`

参数名使用小写下划线。支持：

- `integer`
- `number`
- `boolean`
- `string`
- `string_array`

每个参数必须有 `description`，可选 `required`、`default`、`minimum`、`maximum`、`min_items`、`max_items`、`enum`。实例出现未声明参数时直接拒绝，不能悄悄忽略。

频率必须量化。例如“时不时幽默”不直接交给生成模型执行，而应由解释器映射为类似：

```json
{
  "max_per_1000_chars": 2,
  "interaction_max_occurrences": 1
}
```

Go 校验边界，模型只理解表达意图。

### 5.4 安全声明 `safety`

```json
{
  "may_emit_intentional_false_derived_value": false,
  "may_change_source_fact": false,
  "atomic_output_required": false,
  "interruptible": true,
  "allowed_fact_kinds": ["none"],
  "forbidden_scenes": ["serious"]
}
```

硬规则：

1. `may_change_source_fact` 永远只能是 `false`。
2. 若 `may_emit_intentional_false_derived_value=true`：
   - 模式必须是 `trusted_executor`；
   - `atomic_output_required` 必须为 `true`；
   - `interruptible` 必须为 `false`；
   - `allowed_fact_kinds` 必须且只能授权可控范围，当前为 `derived_arithmetic`；
   - 错误值和正确值必须由 Go 计算，不允许模型自由填写。

“派生值”是由已知事实计算出的结果。例如单价 69.9 元、数量 2，派生总价为 139.8 元。插件可以在原子口播单元中先说一个邻近错误总价再马上改为 139.8 元，但不能把单价 69.9 元说错，也不能改规格、链接或库存。

### 5.5 编译声明 `compiler`

```json
{
  "recognized_intents": ["偶尔改口", "别说得太顺"],
  "output_capability": "self_correction",
  "instructions": {
    "mainline": "……",
    "interaction": "……"
  },
  "micro_actions": ["state_information", "self_correction", "supplement"]
}
```

- `recognized_intents`：帮助解释模型做语义匹配，只是样例语义，不是可执行提示词；
- `output_capability`：稳定的机器能力名；
- `instructions`：声明式插件各场景的受限指令；
- `micro_actions`：局部推进动作序列。

允许的微动作：

```text
audience_address, self_reference, state_information, direct_answer,
short_confirmation, rephrase, supplement, bridge, question,
scene_detail, reaction, conclusion, reason, example,
self_correction, close
```

不要把“留人→讲品→价值→链接→CTA”写入微动作；那是全局内容流程，不是主播语言风格。

## 6. 插件实例

用户在某个直播方案中启用插件时，保存的是实例：

```json
{
  "api_version": "anchor-style-plugin-instance/v1",
  "instance_id": "self-correction-demo",
  "plugin_id": "self-correction",
  "plugin_version": "1.0.0",
  "enabled": true,
  "strength": 45,
  "parameters": {
    "max_per_1000_chars": 2
  }
}
```

`strength` 表示整体表现程度，不替代参数频率。插件升级版本时，旧实例不会自动漂移到新版本，必须经过迁移或重新确认。

## 7. Go SDK

外部开发工具应引用：

```go
import "livecompanion/management/pkg/styleplugin"
```

加载与校验：

```go
manifest, err := styleplugin.DecodeManifest(file)
instance, err := styleplugin.DecodeInstance(instanceFile)
err = styleplugin.ValidateInstance(manifest, instance)
```

注册声明式插件：

```go
registry := styleplugin.NewRegistry()
err := registry.Register(manifest, nil)
```

注册可信执行器：

```go
err := registry.Register(manifest, numericrepair.Executor{})
```

生产启动时可以一次加载标准目录，并显式提供系统能力和执行器白名单：

```go
registry, loaded, err := styleplugin.LoadDirectory(
    "plugins/anchor-style",
    []string{
        "verified-calculator",
        "atomic-audio-segment",
        "atomic-subtitle-segment",
    },
    func(name string) (styleplugin.Executor, bool) {
        switch name {
        case numericrepair.ExecutorName:
            return numericrepair.Executor{}, true
        default:
            return nil, false
        }
    },
)
```

`LoadDirectory` 只读取 `<root>/<plugin>/plugin.json`，不会打开或执行插件目录中的其他文件。依赖缺失、未知执行器、重复版本或非法 manifest 都会让加载失败。互相冲突的插件可以同时出现在能力库中，但不能同时加入同一个主播方案。

编译：

```go
fragment, err := registry.Compile(ctx, instance, styleplugin.CompileContext{
    Scene: "mainline",
    TargetChars: 1000,
    Serious: false,
})
```

编译结果 `CompiledFragment` 是中间表示，不是最终口播。核心生成器把它与以下内容分层合并：

1. L1/L2 和平台合规；
2. 已核验事实；
3. 互动内容策略；
4. 主播基础风格；
5. 风格插件；
6. 今日状态；
7. 目标字数和场景。

高层不能覆盖低层：风格插件和今日状态都不能覆盖事实及 L1/L2。

### 7.1 按时间单元编译

长时间直播不能只在整篇稿件开头编译一次插件。固定片段和模拟测试已由时间扩写引擎切成连续口播单元，并把方案级插件能力分散挂到具体单元。实时模式的执行接口使用以下上下文；接入 Core 后应在每个单元开始前传入真实状态：

```go
styleplugin.CompileContext{
    Scene:              "mainline",
    Mode:               "fixed_simulation", // 或 live
    TargetChars:        180,
    ElapsedSeconds:     540,
    CycleIndex:         2,
    StepIndex:          11,
    RoomHeat:           "WARM",
    OnlineCount:        36,
    QuestionPressure:   0.2,
    AudienceTurnover5m: 0.18,
    RecentCapabilities: []string{"self_correction"},
    CapabilityUseCounts: map[string]int{
        "self_correction": 1,
    },
}
```

这些房间字段在真实直播中来自 Core，在测试和固定片段生成中来自虚拟时钟模拟。它们只决定插件本单元是否适合出现，绝不能被当成可播事实。插件不得把模拟在线人数、进房量或互动量写入口播。

当前固定片段和模拟测试已按方案级频率预算调度，同一单元不叠加多个偶发能力，并优先避开相邻单元。实时执行还必须持久记录最近出现时间和累计次数，避免重启或跨批次后口结、叠词、幽默、改口重新扎堆。可信执行器可以读取同一上下文，但仍不能自行决定互动打断。

### 7.2 能力归属

- `natural-hesitation`、`natural-reduplication`、`self-correction`：改变某个口播单元的文字表现；
- `thinking-tempo`：改变局部分句、停顿和信息密度；如果需要精确改变声音速度，还必须接入分段 TTS 速率执行链，不能只靠提示词声称已经变慢；
- `numeric-repair`：可信执行器生成不可打断的原子纠错单元；
- 同一个品讲多久、何时进入下一轮、哪些正式事实需要回环：属于时间扩写引擎，不属于风格插件；
- 主动互动只能形成候选，是否打断、何时打断和如何回归仍属于 Core。

## 8. 可信执行器接口

```go
type Executor interface {
    Compile(
        context.Context,
        styleplugin.Manifest,
        styleplugin.Instance,
        styleplugin.CompileContext,
    ) (styleplugin.CompiledFragment, error)
}
```

执行器要求：

- 确定性校验；
- 不直接访问数据库、模型密钥和网络；
- 不自行选择模型；
- 不写入事实库；
- 不决定是否打断互动；
- 所有失败显式返回，禁止静默放宽；
- 严肃场景禁用时必须失败关闭，而不是让模型“自行注意”。

`numeric-repair` 的参考执行器位于：

```text
management-service/internal/styleplugins/numericrepair/executor.go
```

它使用整数最小单位计算，校验正确结果后由 Go 构造邻近错误派生值，并返回一个同时具备原子音频、原子字幕和不可打断标记的单元。

## 9. 插件加载和生命周期

推荐启动流程：

1. 扫描 `plugins/anchor-style/*/plugin.json`；
2. 通过 JSON Schema 和 `DecodeManifest` 双重校验；
3. 检查 `requires` 是否被当前部署提供；
4. 检查 `conflicts`；
5. 声明式插件直接注册；
6. 可信执行器按 `runtime.executor` 从 Go 白名单查找；
7. 未知执行器、版本不匹配或安全声明不合法时拒绝注册；
8. 只有注册成功的版本可在前台出现；
9. 保存实例前再次执行 `ValidateInstance`；
10. 每次生成时按场景编译，不能直接拼接用户原话。

当前实现从 `ANCHOR_STYLE_PLUGIN_DIR` 指定目录启动加载。生产推荐值为 `/opt/xiaolan/current/plugins/anchor-style`；发布脚本会把仓库中的插件目录装入每个版本。替换文件后需要重启 `xiaolan-management`，当前没有文件监听式热重载。已在运行的实例绑定精确版本，更新 manifest 后必须创建新版本，不能覆盖相同 `id@version`。

当前 API：

```text
GET  /api/v1/live/style-plugins
POST /api/v1/live-agent-plans/{planID}/style-plugins/activate
```

声明式插件可以从“主播风格 → 主播能力插件”加入当前主播，保存后复用叠加风格的数据库、热生效和生成路径。可信执行器会显示在能力库中，但在相应原子执行链接通前，前台保持锁定，不能退化为普通提示词插件。

## 10. 人工反馈与动态编译

反馈学习不是让用户修改提示词。建议流程：

```text
真实主播样本 + 当前生成结果 + “哪里不像”的人工反馈
                         │
                         ▼
                 对比模型输出候选差异
                         │
                         ▼
           匹配已有插件 / 建议新插件能力
                         │
                         ▼
             Go 校验参数、证据和安全边界
                         │
                         ▼
              新实例或新版本进入离线测试
                         │
                         ▼
              质检优于旧版本后再激活
```

模型的候选输出不能直接成为运行时提示词。它只能：

- 选择已注册 `plugin_id@version`；
- 给出声明范围内的参数；
- 给出样本证据或人工反馈依据；
- 对无法表示的能力返回 `unsupported_capability`。

当候选无法被现有插件表达时，开发工具可以据此新建插件，但仍须完成本规范的测试和评审。

## 11. 版本规则

使用 SemVer：

- PATCH：文档、同义识别样例、不会改变编译结果的修复；
- MINOR：增加向后兼容参数、支持新场景；
- MAJOR：参数删除/改名、默认行为改变、安全语义改变、编译产物不兼容。

禁止修改已发布的相同 `id@version` 内容。若行为变化，必须升版本。

协议版本与插件版本分开。`api_version` 改变意味着 SDK 契约改变；`version` 只表示该插件自身版本。

## 12. 测试要求

每个插件至少提交：

1. 一个合法 manifest；
2. 一个合法 instance；
3. 参数最小值和最大值测试；
4. 未知参数拒绝测试；
5. 不支持场景拒绝测试；
6. 冲突/依赖测试；
7. 严肃场景行为测试；
8. 不改变事实的测试；
9. 输出不泄露元提示词、插件名和编译标签的质检；
10. 1000 字主线和短互动各一组回归样本。

可信执行器另需：

- 未注册执行器必须加载失败；
- 计算溢出必须失败；
- 正确值与计算器不一致必须失败；
- 原子输出标记必须存在；
- 禁止在错误与纠正之间打断；
- 音频和字幕必须使用同一原子文本；
- 生产日志记录插件 ID、版本、实例 ID 和触发结果，不记录模型密钥。

本仓库测试命令：

```powershell
cd E:\直播伴播\management-service
go test ./pkg/styleplugin ./internal/styleplugins/...
go test ./...
```

## 13. 开发一个新插件

以“偶尔低频幽默”为例：

1. 判断它只控制表达方式，不决定回答内容；
2. 创建 `plugins/anchor-style/micro-humor/plugin.json`；
3. 选择 `declarative`；
4. 声明 `mainline`、`interaction`、`refresh`，禁用 `serious`；
5. 把“时不时”转为有上下界的参数；
6. `instructions` 分别描述长主线与短互动如何执行；
7. 避免在指令里写具体商品、价格和用户问题；
8. 创建合法和非法实例；
9. 运行 SDK 测试；
10. 用至少两个不同主播样本、两个不同商品事实包做交叉测试；
11. 确认插件没有把某个主播的词硬编码为所有主播的默认习惯；
12. 提交评审并升版本发布。

## 14. 验收清单

插件合入前必须全部满足：

- [ ] `plugin.json` 通过公共 JSON Schema；
- [ ] `DecodeManifest` 无错误且没有未知字段；
- [ ] `id`、`version`、`output_capability` 稳定；
- [ ] 参数有类型、说明、默认值和合理边界；
- [ ] 未混入商品事实、互动内容策略、打断或回归策略；
