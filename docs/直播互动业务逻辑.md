# 直播互动业务逻辑

> 整理日期：2026-10-27。按当前代码与调度配置整理；线上是否生效以发布回执为准。

## 0. 一句话

互动不是“有弹幕就答”，而是：

**先判断这件事值不值得打断主线，再判断接谁、为什么接、怎么接；生成后过 P0 和事实；最后在安全切点插播并回归主线。**

## 1. 角色边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| 采集器 | 把抖音事件变成标准事件 | 不判断该不该答 |
| Core | 热度、排队、切点、播出、回归 | 不生成话术 |
| Management | 分类、调度、意图、生成、审核、TTS、记账 | 不决定切点 |
| 模型 | 生成文本 | 不决定播不播、不决定优先级 |
| 程序 | 优先级、预算、P0、缓存、切点、上限 | 不替模型编事实 |

## 2. 全链路

```text
事件采集
→ 归一化/去重/屏蔽
→ 开场观察
→ 事件分类
→ 聚合
→ 调度（优先级/热度/阶段/冷却/上限）
→ 决策（接不接、接谁、什么目的、什么角度）
→ 意图识别
→ 回答生成
→ P0/事实审核
→ TTS/缓存
→ Core 安全切点
→ 播出
→ 回归主线
→ 记账/学习
```

## 3. 七层职责

### 3.1 输入层

事件类型：

- `chat` 公屏弹幕
- `member` 进场
- `like` 点赞
- `follow` 关注
- `gift` 礼物
- `order` 下单
- `room` 房间人数/热度

处理：

1. 归一化成 `event_type + user_id + nickname + content + payload + occurred_at`。
2. 同一用户同一内容短时间只算一次。
3. 命中用户/内容屏蔽池的，在入口丢弃，不入库、不推 SSE、不进互动。
4. 按房间记用户维度：进房、最近发言、点赞、关注、下单。

在线人数口径：

- `total`：当前在线，0 是合法值。
- `total_user`：累计观看/场观，不能当在线。
- 源码已修“0 人回退累计值”的问题，已于 2026-10-27 20:04 以 Core-only 发布上线；上线后 room 26 验证 `total=5`、`total_user=5554`、`online_count=5`。
- 会话恢复：直播重开/恢复后 120 秒无人选择“续接上一场/作为新直播”，自动按“新直播”处理，清除上一场互动历史桶，恢复互动；原始事件与回放保留。

### 3.2 判断层

先判断“是不是问题”，再分 mission：

| mission | 含义 | 优先级 | 权重 | 冷却 | TTL | 聚合等待 | 批量 |
|---|---|---:|---:|---:|---:|---:|---:|
| `complaint` | 投诉/负面 | P0 | 100 | 30s | 600s | 0 | 1 |
| `product_question` | 商品提问 | P1 | 90 | 90s | 300s | 0 | 1 |
| `order` | 下单回应 | P1 | 85 | 45s | 60s | 0 | 1 |
| `warmup` | 暖场互动 | P2 | 40 | 90s | 25s | 90s | 1 |
| `welcome` | 欢迎新人 | P2 | 35 | 60s | 20s | 5s | 3 |
| `like_follow` | 点赞关注 | P2 | 25 | 45s | 30s | 10s | 3 |
| `smalltalk` | 普通闲聊 | P3 | 15 | 12s | 60s | 12s | 1 |

热度：`COLD / WARM / BUSY / HOT / OVERHEATED`。
阶段：`opening / explanation / selection / purchase / closing`。
开场观察：`120s`，期间只采集聚合，不入队、不生成、不插播。
每分钟回答上限：`less=2 / natural=4 / more=6`。
重试上限：`2`。

### 3.3 调度层

调度器只做四件事：

1. **排序**：P0 > P1 > P2 > P3；同优先级看权重、等待时长、热度、阶段。
2. **过滤**：冷却中、重复、超过每分钟上限、开场观察期，全部跳过。
3. **聚合**：同 mission 达到批量阈值或等满 `max_wait` 才出队。
4. **抢占**：P1 商品提问应优先于 P2 欢迎/暖场；P0 投诉应打断普通互动。

当前问题：欢迎/暖场调用量远高于回答，P1 问题会被 P2 挤后。

### 3.4 决策层

决定四件事：

1. **接不接**：优先级、冷却、上限、观察期、预算。
2. **接谁**：选主事件，其他事件并入同一批。
3. **为什么接**：从 mission 的 `goals` 里选目的，例如商品提问选“解决具体问题”，暖场选“了解需求/帮助新人进入话题”。
4. **从哪切入**：从 `angles` 里选角度，例如“直接答案/必要解释”“使用场景/规格选择”。

称呼计划：

- 单人问题：可点 1 个昵称，最多 1 次。
- 多人：合规昵称够 2 个才点 2–3 人，否则群称。
- `warmup`：强制 `GROUP`，只许群体称呼，不点名。
- 昵称不安全：降级“这位朋友/朋友们”。

### 3.5 意图层

两步：

1. **目的归并**：判断新问题是否与历史问题同一类。
   - 输出 `{"same":true,"match_index":N}` 或 `{"same":false}`。
   - 命中同类复用旧结论，省一次完整解意图。
2. **完整解意图**：给完整事实、事实编号、已有目的，输出问题类型、真实诉求、可用事实、回答边界、建议角度。

硬规则：

- 同一类必须“同一意图 + 同一实体”。
- 新问题出现新实体（空运/西藏/工厂/地址），强制 `same=false`。
- 拿不准一律 `false`，宁可多调一次，不可复用错答案。

问题聚类另有一条链路，把相似问题合并成可统一回答的类别。

### 3.6 生成与审核层

两种回答：

- **直接回答**：第一句必须给答案，不许“问得好/我这就/稍等”。
- **两步回答**：先接住观众（attitude），再给答案；适合需要缓和或解释的问题。

生成带四层约束：

- 【必说】当前任务/目的/角度
- 【可说】当前答案事实
- 【不提】没确认的未知项，正反都不说
- 【改写】P0 禁说 → 安全说法

审核：

- P0 硬拦：医疗功效、夸大功效、免检、站外引流、贬低同行。
- P0 语义复核：绝对词、背书数据、无依据限时。
- 命中后最多重写 3 次；仍不过就跳过，不拿违规稿凑。
- 事实边界：价格、库存、物流、功效、承诺必须有当前事实依据。

### 3.7 播出与回归层

1. 互动音频进 Core 队列。
2. Core 在当前主线找安全切点（优先 35 秒内、A 级）。
3. 计算 `lead_ms`，到点切入。
4. 播互动音频。
5. 播完回主线，`resume_ms` 回到切点或下一段。
6. 需要时补回归桥，避免硬切。
7. 主线恢复后，互动生命周期才标记 completed。

日志锚点：

```text
interaction cut selected
core audio interaction plan
core audio interaction start
core audio mainline resume
interaction lifecycle completed
```

失败处理：交付结果不明时保留 ID 和声音重试，不直接结束整场。

### 3.8 账务与学习层

每笔请求记账：

- 模型：完整输入、缓存输入、输出，按 Qwen3.7 Flash 阶梯计价。
- TTS：计费字符 × 0.8 元/万。
- 预算：主线 1.0、可选 1.2、总 1.3 元/小时。
- 必要业务（首声、真实互动、事实变更）可超用并记录；可选更新到线暂停。

缓存：

- 文本指纹 + 音色 + 语速 + 事实依赖一致才复用。
- 命中：0 模型、0 TTS。
- 当前互动成品复用是关闭的，所以互动基本每次新生成。

学习与记忆：

- 用户维度：进房、发言、点赞、关注、下单。
- 目的资产：跨场保存，按租户/方案隔离。
- 互动回放：问题 → 意图 → 回答，供复盘。
- 策略学习：人工纠正归因到规则层/行业层/用户层，错误事实不吸收。

## 4. 决策状态机

```text
收到事件
→ 在开场观察期？ 是 → 只聚合，不生成
→ 是问题/有效互动？ 否 → 归 smalltalk / like_follow / 丢弃
→ 分类 mission
→ 聚合够批或等满？
→ 冷却中？ 是 → 跳过
→ 超过每分钟上限？ 是 → 跳过
→ 预算不足？ 是 → 跳过可选，必要业务继续
→ 选主事件、目的、角度、称呼
→ 目的归并（same?）
→ 完整解意图
→ 生成回答
→ P0/事实审核
→ 通过？ 否 → 重写 ≤3 次 → 仍不过 → 跳过
→ TTS/缓存
→ Core 找安全切点
→ 播出
→ 回归主线
→ 记账
```

## 5. 常见跳过原因

| 原因 | 说明 |
|---|---|
| `observation` | 开场 120 秒观察期 |
| `resume_pending` | 会话身份未定；超过 120 秒自动按新直播恢复 |
| `cooldown` | 同 mission 冷却中 |
| `duplicate` | 同用户同内容重复 |
| `limit` | 超过每分钟回答上限 |
| `budget` | 可选用量不足 |
| `no_fact` | 事实不足，只能边界 |
| `p0_exhausted` | 重写 3 次仍违规 |
| `no_safe_cut` | 主线 35 秒内没有安全切点 |

## 7. 验收口径

- 每个问题有 `decision_id`，能追到 mission、目的、角度、回答。
- 回答第一句命中问题核心实体；不命中即视为答非所问。
- P0 零命中；事实不越界。
- 有切点、播出、回归、completed 日志。
- 费用可按请求复算；复用率、新生率、小时费用可分场统计。
- 跳过必须有原因，不能只记“没答”。
