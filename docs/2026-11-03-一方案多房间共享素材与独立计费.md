# 一方案多房间共享素材与独立计费

本地实现，尚未提交或发布。用户批准“方案共享素材，各房间独立运行”，并明确两个房间各运行一小时累计扣两小时。

方案维护一份原始话术、人设、事实、改写规则和允许使用的主播声色队列。同一客户、同一方案下，事实和完整规则一致的已接受改写文字可共享；音频还必须严格匹配正文、模型、声音、语速及合成指令。每个房间的开停播、上线声色、互动上下文、播放位置、主线队列和时间消费独立。

## 共享生成与付费保护

- 现有话术生成模式的分组原文已经位于 `<media>/<tenant>/plans/<plan>/.../paragraphs/`。本轮将生产目录选择收敛到一个受租户归属校验的入口，保留已有键与付费文件。
- 同一段落的锁从进程内 channel 改成支持取消的操作系统文件锁，阿里、火山、首段预热和共享改写复用同一套锁。多个进程同时请求相同音频只进入一次模拟付费；等待者可以沿原供料路径复用本房间缓存。
- 改写任务按客户、方案、片段加跨进程生成门，繁忙时跳过本次补充；取得锁后重读池子，保留供应商并发/速率和原改写串行规则。池的读改写也使用短文件锁，避免不同进程丢失版本或PCM回执。
- 未决付费任务仍由原来的供应商任务及 paragraph-job.json 检查点保护，未知结果不自动重买；已接受文字先保存，再准备音频。停止某个房间不删除共享资产，后续房间可以恢复既有付费结果。
- 改写文字的身份包含客户、方案、完整元提示词及事实。不同事实或规则分别存放，不覆盖另一份规则下的已接受文字。声音变化可复用同规则文字，声音参数变化不能冒用旧PCM。
- 旧池中仅记录事实散列的改写不能证明完整规则，保留其付费文件，不直接冒认当前规则。如果新一次校验接受了与旧付费音频完全一致的正文，可更新规则认可并复用现有音频，保留实际播放次数，不触发淘汰或重买。

## 房间独立运行

- 房间/场次的供料检查点与现有数据库声色运行态保持原隔离，不把共享方案当成运行会话。
- 新增 `<media>/script-room-playback/<tenant>/<room>/<plan>.json`，按片段和音频记录本房间的实际起播、完整播放、最近播放时间和有限幂等回执。
- 只使用实际PCM回执计数，排队成功不算播放；各房间从自己未使用/较早使用的版本中选择，其他房间的播放不推进本房间的历史。共享池总计数仍服务满池覆盖与30%有限批次换血。
- 满池容量继续依据方案内容和音色计算，不按使用房间数复制；原文保护、先新后退役、30%向下取整至少一份等原规则保持。退役移出分配池，付费源音频保留，因此其他房间已排队的音频仍可完成。
- 新共享资产的业务归属为方案，`room_id=0`，另记首次生成房间作为审计信息。旧/新主线段落音频均禁止通过单个媒体删除接口物理删除，返回409说明共享原因。普通上传不受此保护影响。
- 清理房间录音缓存只作用于房间目录，不进入方案目录；解绑和停止不清共享素材。保留现有引用安全原则，本轮不新增共享媒体的物理回收器，不删除旧文件或历史账本。

## 计费与保存保护

客户时长继续按每个房间的 Core working_seconds 与场次累计值事务结算；同时运行两个房间，各3600秒就是7200秒。方案、共享缓存命中和实际生成次数不参与合并或减免直播时长。

供应商真实费用只记实际触发购买的一笔请求，缓存复用不伪造另一笔供应商消费。这与客户直播时长扣费是两个账本。已上线的取消全部小时预算保持，不重新加入金额/字数门槛。

继续沿用保存规则：任一使用该方案的房间处于运行或暂停状态，禁止保存并列出房间；全部结束后允许保存。暂停/停止一个房间不解除另一个房间的保存保护。
