# 欢迎合成余量与在播期限保护

用户授权：修复第646场许牛府的两条欢迎异常，购买TTS前估算剩余时间，验证后上线。

已定位的两处问题：

1. 欢迎名单以原始进场事件的30秒窗口为期限，任务领取另有30秒执行期限。原流程只看后者，等时长额度放行后买TTS，可能声音完成时名单已经过期，welcome-ready返回409。
2. 领取接口先检查队首正文有效期，再检查是否已领取。已绑定播放的欢迎跨过待播期限后也会被移除，写成manual_cancel，丢失正常收尾。

修改：

- Core在欢迎任务中传递不可续期的welcome_names_expires_at。名单期限不随领取、重试或成品入队刷新。
- Management按最终文字长度估算合成耗时，冷启动至少5秒，近期最多32次合成的p95加25%只可提高估计，估值上限35秒，另留1秒入队余量。Core在TTS预检验证较早的名单/领取期限；真正发起TTS前再次验证，包含SSML降级和纠正后重合成。实际请求上下文也受名单期限减1秒约束，保留已发送请求原有回执收尾机制。
- 时间不足时不发起该次TTS，自动记FAILED及具体原因，释放欢迎占位，交由欢迎调度器后续重新收集最近观众；不会记成人工取消或为同一过期名单重复购买。
- 领取接口先由队列选出可领取任务，不对已领取/已绑定播放任务做待播过期清理。自动清理在锁内复核未领取且未绑定，记FAILED；已播放任务等待真实完成/失败回执。

限制：耗时估计不是供应商时延承诺，异常延迟或直播中止仍可能产生已发送的付费请求；最终成品身份/期限检查继续保留。服务端回执不证明现场扬声器。
