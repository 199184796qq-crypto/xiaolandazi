# 线上弹幕测试

入口：智能体方案 → 商品与事实 → 语境词后面的“弹幕测试”。默认18px，可输入观众弹幕及可选直播间介绍。当前方案已入库资料和已保存语境词由服务端读取，不使用浏览器传入的事实或自造归属。

## 处理流程

对齐 tools/import-preview 当前普通弹幕链路：一次意图审核 → 按诉求查询向量与召回 → 一次回答审核。纠错、语境理解、多诉求和条件提取在第一次请求内完成；不额外购买纠错、拆句或属性分类模型。两次审核使用运营配置的审核角色；查询向量沿服务端现有 Qwen 配置，不在浏览器配置密钥或展示向量模型名称。

意图模型只输出人类可读的对象名称、属性、诉求和待核对事项，程序负责绑定实际对象。原问题保留，不确定地点不盲改；“上海能寄吗，明天能到吗”拆为两项并继承同句已明确地区。“砍下点”和“切小点”根据命中的语境词及其适用条件理解，词义不是服务承诺。

数据库在只读、可重复读事务内取得同一版本的资料正文和原向量。当前方案全部兼容向量参加相似检索，不在读取时重建旧资料向量；无效/不同模型/维度不匹配的资料明确提示未参与。未归属、词义、原始资料和缺口记录不作为已确认事实。每个诉求分别限定其链接/门店及全局资料，门店到链接的已保存关联可以继承；对象未指定或不能唯一绑定时不借用其它商品专属事实。

条件和例外三值判断为适用/不适用/待核对，组合条件完整保留；未知地点、缺金额、未解析条件不能当作适用。否定命中例外的条目可在召回卡看见，但不提供给回答模型作为适用依据。回答只携带每项相关事实及完整条件、例外和原文，不携带内部ID、向量或调试轨迹。相关资料有数量和字符预算，整条保留或省略，不截断条件；每诉求最多8条、合计最多32条/24000字符。有限召回不等于穷尽事实或证明回答绝无遗漏。

## 页面

左侧显示意图、拆分诉求、未确定项、命中语境词和口语回答；右侧按诉求显示相似度、对象、属性、条件状态、正文、条件、例外及原文。页面没有JSON/调试面板。语义相似度不是业务正确率。

可每行输入一个查询，点击“召回”独立核对资料，不自动重生成左侧回答；输入/打字/点击历史或评价均不自动请求模型。历史最多40条，按租户、操作员和方案保存在本浏览器；“可以/有问题”只作本地记录，不自动训练、保存标准答案或改正式资料。切换方案/用户/离开页面后迟到结果不污染新页面。失败保留输入及上次成功结果，并标明旧结果；查询失败与无资料分别处理。

## 调用与边界

一次普通测试通常2次文本模型调用；原问题及最多8个诉求的查询文本去重、按现有批次调用向量服务。无资料时不购买查询向量；没有事实问题的招呼可自然回应。单独召回只查询向量，不调用回答模型。模型截断、解析失败或向量失败不自动重试购买；向量失败停止后续回答调用。输入/召回数影响实际用量，通常为数百至数千输入token估算，费用以供应商usage和现有日志为准。

这是人工测试入口，不替换正式直播互动链路，不触发TTS、播放队列、开停播，不修改客户资料、方案或语境词。测试可帮助核对，不能当作已实播或现场扬声器验证。开发只使用离线夹具和隔离MySQL，不发真实付费模型/向量/TTS请求。
