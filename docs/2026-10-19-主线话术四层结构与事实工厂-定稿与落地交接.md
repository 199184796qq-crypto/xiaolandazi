# 主线话术「四层结构 + 事实工厂」定稿与落地交接

> 日期：2026-10-19
> 状态：部分已落地（本地工作区，未 push、未部署），部分待办
> 依据：本地 git 工作区当前代码（非服务器二进制），实测数据来自生产库 + qwen3.7-flash 直连

---

## 一、结论先行

一次主线话术的 token 与合规问题，根子不在"模型"，在**三层**：

1. **system 稳定前缀太长**（母版 + 完整 P0 + 风格 + 标尺反复堆叠）→ 已通过「腔调卡合并」+「P0 拆进四层」解决。
2. **事实包组装不完整**（商品卡规格/价格没进事实）→ 模型只能脑补，编价格、算错账。
3. **违规词压制靠"审核兜底"而非"生成前置"** → 改为四层「不提 + 改写」前置拦截。

三者叠加后，一次主线话术 input 从 ~9350 token 降到 ~3740 token，且 30 条大样本实测真实违规词 0 漏。

## 二、当前主线话术一次请求的 token 账（实测）

| 形态 | input token | 说明 |
|---|---|---|
| 老方案（完整 P0 母版 + 风格母版 + 标尺 + foundation 七章） | ~9350 | 历史实测 id=25230 |
| 四层 + P0 拆进不提/改写（脚本验证） | ~2489 | 不带风格 |
| 四层 + P0 拆进不提/改写 + 风格腔调卡 | **~3740** | 叠加本次腔调卡合并后的目标态 |

费用（qwen3.7-flash 华北2：输入 0.2 元/百万 token、输出 0.8 元/百万 token）：
- 单次 ~3740 token，一场直播 1 小时约 60~90 段 → **约 0.05 元/小时**。
- 对比老方案约 0.15~0.45 元/小时，省约 70%，且未算老方案因违规词反复重写翻倍的部分。

## 三、已落地改动（本地工作区，本次完成）

### 1. 主播「腔调卡」合并（渲染层）

**背景**：`主播风格母版（StyleMD）` 与 `主播表达标尺（Baseline.Identity）` 讲的是同一批腔调（语气词/称呼/自指/节奏），之前并排塞进 stable 两份，重复且费 token。

**改动**（2 文件，编译 + speechbase/anchorstylescore 测试通过）：

- `management-service/internal/speechbase/render.go` 新增 `RenderAnchorVoiceCard(styleMD, baselineJSON string)`：
  ```go
  return map[string]any{
      "风格":   style,      // StyleMD 全文（腔调的"味"，不能丢）
      "量化基准": b.Quant,   // 程序统计的每百字频率（打分/频率控制的硬数据）
      "禁用表达": b.Forbidden, // 禁用书面客服语/称呼/过渡词（反向约束）
  }
  ```
- `management-service/internal/httpapi/text_generation.go`：
  - 新增 `cycleVoiceCard(state)` 委托函数。
  - `renderCycleTextMessages` 的 stable 由两个 key 换成单 key：
    ```go
    // 改前
    stable := map[string]any{"主播表达标尺": view, "主播风格母版": state.StyleMD, ...}
    // 改后
    stable := map[string]any{"主播腔调": voiceCard, ...}
    ```

**实测节省**（生产真实数据 id=10 StyleMD / id=13 BaselineJSON）：
- StyleMD 921 字符、Quant 1094、Forbidden 53、Identity(删) 1443。
- 改前 2817 字符 → 改后 2112 字符，**省 705 字符 ≈ 423 token/段**。

**边界**：`RenderAnchorExpressionView`（打分/审核/lecture/repair/preview 用的标尺）签名不变，那些路径仍吃完整标尺，打分逻辑零影响。只有主线话术 stable 前缀走新腔调卡。

## 四、真正待办（尚未落地，按优先级）

### 待办 ① 四层「不提/改写」承接 P0（删 stable 有效P0）

> 这是当前最大的剩余动作。现状：`text_generation.go:151` 的 stable 里仍有 `"有效P0": genP0`（完整 P0 母版编译的 9 字段 JSON，243 字符词表 + 1100 字符"怎么绕开"废话）。脚本已验证：把 P0 拆成「红线词清单进不提 + 通用改写规则进改写」，拦截力不变，省 ~930 token/段。

**目标态**：

- `stable` 删掉 `"有效P0"` 字段。
- 「不提」层 = 现有固定文案 `fourLayerNotMentionText` + 追加红线词清单（从 P0 母版抽取的 7 类裸词）。
- 「改写」层 = 无条件加一句通用规则（不再依赖事实卡带分隔符才出现）。

**红线词清单（7 类，进「不提」）**：
```
绝对词与极限词（最/最好/最低/最高/最便宜/最划算/绝对/绝不/绝无/绝佳/第一/唯一/首选/独家/100%/百分百/纯天然/国家级/顶级/极致/遥遥领先/保证）；医疗保健功效（治疗/治愈/抗癌/降三高/减肥/养胃等）；夸大功效（特效/神效/当天见效/永不反弹等）；站外引流（微信/加微信/转账/手机号/淘宝等）；贬低同行（别家垃圾/别家假的/不如我们）；免检承诺（质量免检/免抽检）；无依据逼单（最后一天/马上涨价/仅剩/秒杀/赶紧抢/抓紧/手慢无等）；无依据背书（销量/榜单/回购率/好评率/经营年限/门店数，事实里没写就不编数字）
```

**通用改写规则（一句，进「改写」）**：
```
凡是想把话说满的冲动（程度极限词：最/绝对/第一/顶级/100%/保证；功效承诺词：治疗/抗癌/降三高/特效/当天见效），一律降级改口：要么直接陈述事实本身（报真实的规格、价格、配料），要么用温和程度词「很/挺/相当/比较/确实」代替，不报具体数字、不承诺疗效、不制造紧迫。
```

**实测依据**：
- 「不提」列词 + 「改写」一句通用规则，30 条正常话术（不断换角度）真实违规词 0 漏。
- 只靠「改写」删掉「不提」的词表，「绝对/最大」会漏（2 处），故**两层缺一不可**：不提做主动规避、改写做被动降级。

**落点**：`text_generation.go` 的 `renderCycleTextMessages`（stable 组装 + variable 组装）；红线词清单从 `contentguard.Compile` 的 `Rules[].Terms` 抽取（需新增一个 `forbiddenWordList(md)` 函数）。

### 待办 ② 事实工厂补全：商品卡本体读进事实包

> 现状病根：`contentpools.Product` 结构体（`pools.go:14`）只有 `ID/Link/Name/Roles`，没读商品卡的 `spec`/`daily_price`/`quantity`/`audience`，导致事实包只有"商品名称"空壳，模型讲「6人餐价格/内容」时只能脑补（实测编出"大几百""几十块""人均不到31"）。

**数据已确认在库**：`live_agent_plan_product_links` 表（plan_id=5，id=8）有 `spec=含15道荤素菜...`、`daily_price=187`、`quantity=1`、`audience=6人以内`。

**三层修复链路**（从上游往下补）：

| 层 | 文件 | 要改 |
|---|---|---|
| 1 | `contentpools/pools.go` | `Product` 结构体补 `Spec/DailyPrice/Quantity/Audience` 字段 |
| 2 | 加载商品卡的代码 | 从 `live_agent_plan_product_links` 读 `spec/daily_price/quantity/audience` 进来 |
| 3 | `content_pool_runtime.go` | 把商品卡本体拼成「商品事实」塞进 `scope.Facts` |

**事实包最终形态**（一次话术的「可说」）：
1. 商品卡本体（名称 + 规格 + 价格 + 数量 + 人数）
2. 派生事实（人均/总样数/折扣，**代码算好**塞进可说）
3. 该商品专属事实卡（全带）
4. 公共事实尾巴（抽 0~2 个）

### 待办 ③ 事实包需含派生数（代码算，不让模型现场算）

> 重要指导原则（用户明确要求记录）：**能提前算的数，都别让模型现场算；模型只负责转述事实，不负责做算术。**

实测：不带派生数时，模型必自己算账且大概率错（"整整35样"实际36、"人均30出头"实际31.2）；带派生数后 100% 零错（"人均31块2出头""一共36样"）。

**派生数基准值**（代码算好塞进事实包）：
- 8 号链接：187÷6 = **31.17 元/人**；总样数 = 15+10+10+1(锅底油碟) = **36 样**
- 7 号链接：337÷10 = **33.7 元/人**；总样数 = 22+10+10+1 = **43 样**

**派生数类型**：人均（价格÷适合人数）、总样数（各规格项求和）、折扣幅度（原价-现价）。

---

### 待办 ④ 违规判定加「事实包授权词豁免」

> 用户明确原则：**事实包里有 → 放行**。判定标准是"来源"不是"词面"。

现状：`CheckP0Candidate`（`anchorcycle/p0.go:71`）是纯词面扫描，看到「限量」就报警，不看这个词是否来自事实包/商品卡授权。

实测：「限量」是商品名【限量回馈】6人餐自带，30 条压测里被误报 11 次。按"事实包里有→放行"原则应豁免。

**改法**：`CheckP0Candidate` 命中违规词后，先查该词是否在当段事实包/商品卡授权词表里出现，在就放行，不在才拦截。
