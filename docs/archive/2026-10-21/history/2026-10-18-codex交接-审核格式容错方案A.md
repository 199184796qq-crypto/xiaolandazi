# 审核格式容错（方案 A）—— 已提交，Codex 交接说明

commit：`070284e`（management-service 仓库）

## 一、问题背景

此前多份审核提示词各自规定「输出格式」，互相冲突：

- `audit-four-layer.md`（P0 审核）要求「只输出严格 JSON」
- `mainline-final-content-review.md`（最终文字审核）要求「第一行返回通过/有问题/不确定」
- `angle-direction-review.md`（角度方向审核）要求「第一行只返回…」

模型被 JSON 指令带偏，最终文字审核返回了 JSON 而非纯文本结论 → `ParseDirectionReview` 解析失败 → 该角度被 `P0SkippedKeys` 误标为本场跳过，后面只能反复选剩下的内容池（这正是「2 号链接价格算账与性价比的 5 个角度全被跳过」的根因之一）。

## 二、本次改动（方案 A）

### 1. 解析器容错 `internal/anchorcycle/direction_review.go`

`ParseDirectionReview` 新增三层兜底（原来只按「第一行 + 逗号/句号/冒号」切结论）：

1. **同义词归一**：`不通过` / `违规` / `不过`（含各种标点尾随）→ 统一映射为 `有问题`
2. **JSON 兼容**：若正文是 `{...}`，提取 `decision` 字段，`违规`/`不通过` → `有问题`
3. 需新增 `encoding/json` import（已加）

### 2. 审核调用重试 `internal/httpapi/final_mainline_content_review.go`

`auditFinalMainlineContent` 的「调用 + 解析」包成 2 次循环：

- 第 1 次解析失败 → 重置回执（ExchangeID/Raw/Input/Output/Latency 清零）重试一次
- 第 2 次仍失败 → 才 `fail`，但此时已是真正的技术失败，不是格式带偏

关键意图：**解析失败属于技术性失败，单独重试，不直接把该角度标记为本场跳过**。

### 3. 提示词去格式死规定（3 份）

统一原则：**程序自行识别结论，模型自由输出，只检查三件事**。

- `audit-four-layer.md`：删「只输出严格 JSON」整段 JSON 示例，改为「一句话给结论，格式不限」
- `mainline-final-content-review.md`：删「第一行必须」，退稿理由收敛为**三类明确错误**（① 事实讲错 ② 违反用户要求 ③ 触碰 P0），并明确「口语变化/换词换顺序/举日常场景/没讲全事实」**不退稿**
- `angle-direction-review.md`：删「第一行」，改为「先说结论，再看情况补原因，格式不限」

## 三、测试

`direction_review_test.go` 补容错用例：

```
通过。 / 通过 / 有问题。价格与事实不一致。 / 不通过。串了规格。 / 违规：命中极限词。
不确定：缺信息。 / {"decision":"通过"} / {"decision":"违规"} / {"decision":"不通过"} / {"decision":"不确定"}
```

均已映射到正确结论。

## 四、需要 Codex 注意/对齐的点

1. **这几个文件你可能也在改**（`direction_review.go` / `final_mainline_content_review.go` / 3 份提示词）。本次已提交到 `070284e`，请以当前 main 为准，避免覆盖。
2. **解析器仍偏窄**：目前同义词映射只覆盖了「不通过/违规/不过」三个词 + JSON decision。如果模型还会冒出其他口语结论（如「有风险」「要改」「过不了」），建议继续在 `ParseDirectionReview` 补归一映射，或换成更稳的结论提取方式。
3. **重试逻辑**只在 `auditFinalMainlineContent`（最终文字审核）加了；`direction_review.go` 的角度方向审核入口若也有同样的「解析失败即跳过」路径，需要你确认是否同样要加重试。
4. 建议跑一遍 `go test ./internal/anchorcycle/... ./internal/httpapi/...` 验证（`decisionexecutor` 的 worker_test.go:1414 是存量失败，与本次无关）。

## 五、判定口径（最终拍板，供对齐）

- 审核只查三件事：事实讲错 / 违反用户要求 / 触碰 P0
- 程序仍需识别「通过 / 不通过 / 不确定 + 原因」，由接口统一处理
- 返回无法识别时，**只重试本次审核**，不能因此屏蔽整个卖点或角度
- 正常口语变化、没讲完全部事实，**不是退稿理由**
