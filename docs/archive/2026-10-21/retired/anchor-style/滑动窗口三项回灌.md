# 滑动窗口三项回灌

自动生成流程：生成原文 → 保存原文 → 原有程序评分 → 三项窗口检测 → 有问题时调用所选快速模型一次 → 将合并回灌用于下一段。

## 程序判定

- 最近五次 API 完整返回为窗口，一次返回包含多行仍算一个调度段。窗口包含刚收到的本段，记忆跨同一会话的多次生成和刷新。
- 开头：识别主播风格肯定称呼段中的词；确认的简称归并。相邻重复立即触发；满五段时同一种起头占比超过50%触发。直接说事的开头按首个分句前8字符分组。
- 主播风格：按窗口总字数加权实测称呼、自指、语气词及问号、感叹号。窗口至少三段、200字符才做密度判断。词汇稳定区间为样本密度的80%到130%；样本在窗口内期望不足两次时不强制补缺口。标点只判断缺失，不以录音转写的稀疏标点为上限压制问句情绪。辅助语气词须在已确认风格的语气词段被明确列出，避免对模型识别的语法片段机械降频。最新段主力语气词至少三次且超过样本密度1.7倍时报告局部扎堆。最多报告三条风格问题，避免一次改动全部指标。
- 结尾：取最后一个完整句子的末80字符，忽略标点、数字、允许称呼及末尾语气词后比较。相邻重复或满五段占比超过50%触发。这是词面/格式重复检测，不是完整的语义重复判定；同义改写可能不会触发。

## 模型职责与来源

- 模型只根据程序问题、统计和原始窗口生成回灌文案，不重新打分、不评价商品事实。
- 候选称呼从当前已确认风格提示词的肯定称呼段提取，截去反推禁用和自指部分；不从事实包、禁用清单或其他主播样本取词。没有可识别候选时不提供默认称呼。
- 模型自由选择允许列表中的词，或不建议具体称呼；返回 `corrections` 和 `selected_addresses`。程序兼容中文类别名，过滤未触发类别；同类不同建议全部合并，相同建议去重。每条模型指令最多110字符，同类合并最多330字符。漏项、没有合格指令或同类合并超长时，用 `rolling-feedback-fallback.md` 中的对应类别模板补齐，不二次调用模型、不替模型选称呼。保留完整原始返回，并通过 `warnings`、`correction_sources` 记录合并、过滤及兜底。非法JSON或越界选词仍拒绝。
- MD 模板：`configs/prompts/anchor-style/rolling-feedback-generation.md`，可通过 `ANCHOR_STYLE_ROLLING_FEEDBACK_PROMPT_PATH` 替换。
- 回灌模型在“生成设置”下拉选择并保存，首次优先选已配置的 Flash/Turbo/Lite。这里只是快速系列优先策略，不代表已实测所有模型并证明最快。

## 执行保护和记录

- 无问题不调用模型，并清空旧回灌；到目标或暂停后不再生成无用回灌。
- 回灌失败则保留原文、评分和错误，暂停循环；继续时只补回灌，不重复生成话术。配置相同的已成功窗口结果可复用。
- 原始模型返回、真正请求、所选模型、耗时、问题和合并文案保存在本地测试记录中，可从高级设置或“导出完整测试”查看。
- 不替换原风格元提示词、不修改母版和历史话术。单步测试原有评分草稿仍保留；自动循环使用新三项回灌。
