# 故事自动整理与主动讲解库设计

状态：首版已上线（2026-10-11）。版本 `20261011-story-lectures-6255fd4`，发布源码 `6255fd412193fb35a0688fc4f6b2577c68b30daa`。以下保留原设计，实际交付范围以本节为准。

首版入口是“话术挖掘”下方的“任务讲解”，以及方案智能体的“任务讲解”模式。用户在这个明确的素材入口粘贴原文；普通聊天不会自动入库。现行规则审核和内容整理分两次请求，所有生成/规划携带有效P0，模型只返回内容，程序维护身份、范围和关联。违规原句与修改建议留在输入处；格式错误、未完成审核及事实冲突不冒充通过。全部通过后，事实与主题在同一事务归档，保留原文、事实版本、讲解目的、角度和相关问题词。

实时生成主线沿用当前生产供料、主播表达、文字审核、TTS和Core音频输出。在完整商品循环边界按“轮数且实际播放时间”选择一个主题的一个角度；单次预留60秒，实际声音超过60秒跳过。默认1—2主题为4—6轮/至少10分钟，3—7主题为3—5轮/至少8分钟，8+主题为2—4轮/至少6分钟；同主题默认30/25/20分钟间隔，讲解占比最多10%，每播放小时最多8段。生成、缓存和排队不计使用，完整PCM覆盖才计完成；部分播放只计实际时长和主题间隔。可停用、删除、调整频率、查看依据或预览文字；讲解失败释放预留并继续讲品。保留已有角度池的实际起播回执和三次补充机制。

讲解库随方案版本固定，仅所选任务送入讲解模型；原文不进入普通讲品上下文。故事事实独立于普通内容池修订，相关互动按具体问题词检索一个主题的事实；无关物流等问题不带故事。已有完整已保存方案且没有其它待保存改动时，素材归档后自动保存新方案；否则页面显示“保存智能体”及当前阻塞提示。正在运行场次保持原快照，新的内容下次开播使用。

首版不自动按相似标题合并不同提交，也不改写已确认事实来消除冲突；相同素材与范围幂等，删除后重新提交可恢复。原设计中的自动识别普通聊天意图、相近主题合并及录音/预生成主线主动讲解尚未实现。片段试听通过当前方案真实文字与声音模型生成，模拟“讲品→原料故事→口味选择”，没有启动直播或修改客户事实/方案。

本次发布已合并线上 `344c9f4` 的最新纠正修复，前端沿用线上隔离基线并仅叠加相关改动。Management/Core 全量 Go 测试通过；隔离 MySQL 测试覆盖原子归档、版本竞争和内容池触发器；真实模型回放验证违规拦截与有效素材拆分；前端验证回车发送、原文保留、预览、频率、删除和范围切换。47秒讲品过渡试听使用当前方案文字与声音模型生成，已获用户确认。

上线核对通过：三个服务健康，新讲解接口鉴权有效，两张新表与三个故事事实触发器存在，107份母版文件校验一致；公网页面及其实际加载的 JS/CSS 与发布文件完全一致。发布期间原事实、方案版本和直播场次数量保持不变，未自动导入示例或启动直播。真实场次中的长时间调度效果需在用户保存讲解素材后的下次开播观察。

## 1. 用户流程

用户在方案环境的智能体里直接粘贴故事、商品背景或制作介绍，点击发送。智能体识别这是要整理进方案的素材，开始“读取内容 → 拆分事实 → 规则核对 → 建立讲解主题”。普通提问、举例讨论、引用别人话术和明确只要求改稿的消息保持各自意图，不自动当作要入库的事实。

全部通过：自动保存用户原文、事实条目和讲解任务，默认加入可用讲解库，返回归档结果。用户无需选择事实分类、逐条采纳或跨页面操作。结果卡显示“归档事实数、新增或合并的主题数、可用角度数、播出安排、生效状态”，支持查看、修改和关闭自动讲解。

存在问题：保留分析草稿，突出问题原句、命中的当前有效规则、具体原因和可选修改建议。用户在原对话中修改并重新提交。建议改写不自动替换用户原话；整份提交通过前，不把其事实或讲解任务置为有效，不能出现事实已生效但任务被拦截的半次导入。

分类区别：明确规则违规需要修改；与当前方案事实冲突需要解决冲突；来源、商品范围或原话语义不明确需要补充说明。模型超时、解析错误和审核未完成属于处理异常，不能标成内容违规，也不能伪装审核通过。不将用户已确认的业务事实交给模型重新裁定真假；依据适用的规则核对其表达和条件。

## 2. 整理后保存什么

- 原始材料：完整原文、提交人、时间、版本、处理状态和原始模型请求/返回，供修改和追溯。
- 事实依据：原料、产地、养殖方式、工艺、品牌历史、口感等独立事实。保留原话中的时间、对象、条件、程度；地域背景不能自动推导为实际供应链事实，原料特征不能自动转成成品营养数据。拆分不得新增原文未表达的信息。
- 讲解主题：标题、讲解目的、适用商品范围、可用角度、相关事实版本、自动讲解开关。
- 回答策略：仅在原文明确包含“遇到某种问题怎样理解/怎样回答”等要求时建立；普通产品介绍形成事实和主动讲解，不为了分类齐全生成回答策略。

示例：一篇“南充土麻鸭与杨鸭子的本地特色”通常建立一个主题，下面有“产地背景、原料选择、口感体验、本地传承”等角度。每次选择一个角度讲清，不连续念完整原稿。另一篇“先卤后炸的制作工艺”可以成为另一独立主题。

同一个主题的新材料补充事实与角度；相同提交幂等处理，不重复入库。表达相近、同一主题的多个角度不算多个故事。主题是否相同可由模型对程序明确提供的两份内容执行语义判断；程序决定合并目标，不能让模型填写主题ID或猜测关联。

### 讲解任务库与业务提示词隔离

2026-10-10 用户明确：故事素材杂，应单独建立讲解任务库，需要讲解时才携带所选任务到模型，不污染直播核心业务提示词。

讲解任务库是当前智能体方案下独立保存、独立调度的资料资产。归入方案表示版本、权限和生效范围跟随方案，并不表示每次模型调用都把整个库展开。单场可以保存讲解库的有效版本快照，由程序按需读取；快照在服务端可用与内容被发送给模型是两个不同动作。

完整故事原文仅用于素材整理、修改和追溯，不追加到业务核心母版、主播风格、常驻对话历史或每轮公共上下文。拆出的有效事实保存在事实依据中，供相关任务使用；不把故事的整段叙述、广告句式及修辞当作通用业务规则。只有用户明确提出回答要求的内容，才进入对应回答策略的整理流程。

| 调用场景 | 本次携带的内容 | 故事资料范围 |
| --- | --- | --- |
| 素材整理与规则核对 | 用户本次提交的原文、明确适用范围、当前规则及必要的已有事实 | 可读取本次完整素材，处理完不成为后续调用的常驻上下文 |
| 普通商品主线 | 当前商品任务、目的、角度及相关业务事实 | 不携带无关讲解主题或完整故事 |
| 普通互动问答 | 当前问题、回答目的、相关事实和适用回答策略 | 问物流就取物流依据；问产地时可以取相关产地事实，不附带整篇故事 |
| 主动讲解或观众明确要求讲故事 | 已选中的一个主题、一个角度、讲解目的、必要事实、表达边界及目标时长 | 只携带本次任务需要的资料；确有必要时附少量相关原文片段 |

调度先选任务，再准备有限的任务资料并调用模型。模型不会先收到整个讲解库再决定本轮讲哪个，也不会收到其它主题、其它商品故事或历史素材对话。原文中的资料描述不提升为系统指令；讲解仍受现有业务规则与终审约束。

每次讲解按“目的 → 角度 → 本次内容”生成。任务完成后不把整段讲解自动追加到后续问答提示词；避重使用既有受限近期播放记录或摘要，不把故事库变成累积聊天历史。事实与讲解共用同一套方案资料及业务链路，供料范围按本次任务决定。

## 3. 主动讲解如何参与循环

增加一个“可选讲解时段”，放在完整商品小循环结束的安全衔接点。普通主线轮盘保持原职责，讲解主题库由这个可选时段统一选择。讲解库不直接展开成每轮必选的普通卖点队列。

一次机会最多选一个主题的一个角度，默认约30—60秒。程序先判断是否可以安排，再调用模型生成。模型只负责已选任务的正文；程序维护出现频率、主题选择、顺序、版本和实际播放计数。

进入条件：

1. 已满足间隔周期数和真实播放时间间隔，两项同时满足。
2. 当前商品适用该主题，事实版本有效，主题开启，审核完成。
3. 现有互动及商品调度允许进入这个安全时段；辅推、成交和正在处理的用户问题保持既有优先级。
4. 最近播放窗口与已准备的队列中没有同主题或高度相近的讲解。
5. 没有另一条主动讲解正在准备、待播、播放或等待回执。
6. 本场讲解占比仍有额度。

到期代表“可以安排”，不是强制立即播放。现场繁忙就顺延，不补播多条积欠讲解；找不到适用主题时继续普通主线。

主线 → 可选讲解一段 → 返回主线。讲解复用既有生成、主播风格、评分、P0终审、TTS、缓冲和播放链路。保留进入前的普通任务位置、商品焦点和环节状态，完成后恢复；讲解本身不额外增加商品完整循环计数。

讲解占比单独计量，不能冒充主推或辅推已完成的轮次，也不能通过混入普通主线字数绕过讲解预算。与既有辅推时段协调，每个衔接点避免叠加长讲解。

## 4. 默认频率

下表是建议的首版默认值，需要试听验收后调整。数量按“当前商品可用、已启用的独立主题”统计；角度数、推演版本数、重复材料和不适用主题不增加频率。

| 可用独立主题 | 距离上一段讲解的完整商品小循环 | 最短实际播放时间间隔 | 同主题最短间隔 |
| --- | --- | --- | --- |
| 0 | 不安排 | — | — |
| 1—2 | 4—6轮 | 10分钟 | 30分钟 |
| 3—7 | 3—5轮 | 8分钟 | 25分钟 |
| 8及以上 | 2—4轮 | 6分钟 | 20分钟 |

默认讲解音频累计占本场实际播放时长不超过10%，另设滚动一小时最多8段。开播先完成正常商品介绍，首段讲解也需满足间隔。一个主题拆出四个角度仍按一个主题应用冷却，防止轮换角度却连续讲同一故事。

在区间内确定下一次间隔后保存本场临时状态，不在每个轮询中反复随机。长期延期只保留一份待安排资格，不累计“欠讲次数”。可用主题数量变化重新计算后续安排，不能导致立即连讲。

讲解设置默认自动，提供“少讲／适中／多讲”和关闭入口；高级设置再展开具体间隔、时长与占比。用户提交材料时不需要填写这些参数。

## 5. 多个主题如何轮换

先过滤商品范围、有效事实、开启状态和冷却，再按本场实际播放次数少、距上次实际播放更久、新增且尚未讲过等因素排序。新主题只有适度优先，仍受总间隔和占比限制。

先选主题，再选该主题内近期未讲或讲得少的角度；继续使用已有角度推演资产及其使用规则。事实与目的相同的正文可结合当前上下文重新生成，不直接重放旧整段或旧音频。

相关观众提问可使用同一份事实和讲解资产。短问短答不占自动讲解时段；明确要求完整讲故事时沿用现有任务入口，并将实际使用过的主题角度纳入避重记录。无关问题不附带整段故事。

## 6. 回执、缓冲与中断

准备、生成成功、评分采纳、TTS完成和进入队列都不代表已讲。准备时只登记一份占位，防止预生成缓冲里排入多条故事；实际播放回执才更新使用次数、周期与时间冷却、累计音频占比。

回执按场次、版本、任务及播放标识幂等，重复上报只记一次。中断时已经播放的时长计入占比；未完成正文不冒充完整使用。近期记录保留已播主题，避免马上从头重讲。续播、回归仍由既有播放机制处理，讲解调度不新建播放状态机。

取消、生成失败或失效任务释放占位，允许以后重新安排，普通主线继续。新的计划、事实或规则使原任务失效时，重新核对其依赖后再进入可用库，不删除历史记录。

同一角度按既定实际使用阈值补充新推演，默认本场3次；生成和待播不计数，旧有效方向保留。单场进度在Redis，结束清理，服务器重启开始新场次；讲解资料及版本在数据库长期保存。

## 7. 自动保存与版本生效

全部核对通过后自动归档事实及讲解资产，作为同一份提交保存；不存在逐条确认步骤。出现问题先保留草稿，改完再整体核对。既有事实与本次冲突时不静默覆盖。

资产按租户、方案和版本隔离，讲解绑定明确事实版本与商品范围。用户修改原文建立新版本，旧版本及出处保留；重复提交不新增重复事实或主题。

直播消费仍使用已保存方案快照。方案没有其它待保存改动且本次完整版本准备成功时，可自动创建只包含本次故事变更的新保存版本，下一场使用。存在其它待保存改动时，不顺带发布那些修改；本次故事已归档、待统一保存，结果卡明确说明。版本准备失败时标为“已归档，待生效”，不能显示“已进入直播”。正在运行的场次沿用其开播快照。

用户可通过结果卡关闭或删除讲解任务；故事停止主动讲解与其事实删除分开操作，保留事实供问答使用。删除事实时核对依赖并撤下受影响讲解。运行中的场次按照既有版本及紧急规则处理机制执行。

## 8. 程序与模型边界

程序在调用前验证身份、当前方案、房间权限和资料范围。模型只返回拆分内容、目的、角度及规则判定内容；不返回内部ID、引用键、商品绑定、数据库键或生命周期状态。原文、事实、主题与子任务的引用由程序按本次明确请求范围建立。

模型母版统一放在 configs/prompts/anchor-style，按请求实时读取并记录实际版本。调度参数属于方案配置，写数据库并随方案快照读取；更新项目母版不能自动改所有用户的讲解频率。

保存前重新核对资料、规则与方案版本；请求期间已变化则重核对，迟到结果不覆盖新修改。原始模型返回保留；格式错误、审核未完成和违反规则分开显示。

## 9. 接入现有链路的实施顺序

1. 方案智能体素材意图识别、拆分、现有规则审核与修改回路；先验证只有用户确实要入库的材料进入该流程。
2. 原文、事实及讲解主题的事务保存、冲突处理和幂等；自动归档结果与现有方案版本生效机制衔接。
3. 已保存讲解库快照接入 createLiveAnchorRun，在 anchorcycle 中增加可选时段及独立预算，复用正式口播链路。
4. 预生成占位、实际播放回执、冷却与同主题避重，协调辅推和互动。
5. 结果卡与讲解库管理；补充正式播出与试听验收。

## 10. 验收重点

- 提交土麻鸭故事后自动形成可追溯事实及一个多角度主题；重复提交不重复写入。
- 一句触犯当前有效规则时，定位原句，整份内容不进入有效库；修改后重新核对并自动保存。
- 普通提问、举例讨论、格式失败及已有事实冲突不被错误自动入库或标成违规。
- 核对原始模型请求：普通主线与物流、价格等问答不携带无关故事；主动讲解只携带已选任务及相关依据，核心母版不写入用户故事全文。
- 方案保存及开播快照包含讲解库版本，不等于每次调用展开全库；完成一次讲解后，后续普通问答没有整篇故事的累积上下文。
- 只有一个主题时不会每轮讲；多个主题时轮换，主题拆角度不增加频率。
