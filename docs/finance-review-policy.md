# 财务分人审核开关与收款表排版

## 配置入口与范围

系统设定 → 财务审核规则 → 强制经办人与审核人不同 → 保存审核规则。

- 勾选（默认）：申请人或最后补件人不能审核自己的收款；原财务审批任务的发起人也不能自审。
- 取消勾选：有对应审核权限的人可兼任经办和审核，仍需核实并主动提交审核。
- 只有超级系统管理员能改设置。未给任何真实员工新增角色/权限，没有关闭当前运行环境的开关，也没有代为审核真实单据。
- 同一设置适用于客户收款审核及原充值、退款、奖励、AI时长审批。订单、金额、状态和幂等限制保持原逻辑；现金账户与缴存业务不在此变更范围。

## 后端实现

设置使用已有 mgmt_system_settings 表，键 finance_require_distinct_reviewer，种子默认 true，不覆盖已配置值。保存时严格接受 true/false。审批时读取并持有 FOR SHARE 行锁直到事务结束；配置读取失败或内容异常不执行审批，缺少设置行保持原强制分人行为。

Store.ReviewCustomerReceipt、ApproveStaffFinanceTask、RejectStaffFinanceTask 均调用同一策略函数，不接收浏览器提供的开关覆盖。HTTP 审核权限校验不移除。已明确授予财务角色的兼岗销售按财务权限办理，普通销售保持本人客户范围且无审核权。

收款事件增加 review_policy，记录当时模式及同一人审核情况；原审批任务在 payload_json 增加 review_policy_mode、review_same_operator，不改写原经办/审核信息和历史金额。系统设置修改沿用超级管理员权限、修改人时间与现有管理员审计。

## 前端实现

系统设定独立保存该项；全局文字保存不夹带此设置。财务页面从已认证 GET /api/v1/staff/finance/review-policy 读取规则，页面可见时15秒更新，窗口重新聚焦和配置保存后重新读取。读取失败时按钮禁用并支持重试；即使页面旧状态，服务端仍以事务内实时配置为准。

收款审核页表头/正文/按钮18px，辅助信息16px；审核按钮按内容宽度，不铺满整栏；禁用原因只显示短句，完整说明保留在悬停和无障碍标签。仍保留固定操作列、蓝色悬浮、卡片/表格和原服务端分页。此排版只限制收款页，不修改其他智能体的专用字号配置。

## 验证边界

已通过 Go 相关包测试、Vue 类型检查。真实 MySQL 回归使用随机前缀隔离测试表，所有查询均由测试连接器改写，结束已清理，不读取/修改真实客户资金。

TestFinanceReviewPolicyMySQL 覆盖默认强制、关闭后同一有权人员审核/驳回/补件、重新开启、异常设置拒绝、没有财务权限仍拒绝、重复审核不重复余额、原任务审批与模式留痕；同时重跑 TestCustomerFinanceSupportMySQL 及隔离SQL防护测试。

scripts/test-customer-business.cjs 使用独立 Chrome 且拦截全部 API，覆盖管理员配置保存、原审核入口、严格/非严格模式、无权限、打开弹窗后切换规则、读取规则失败，以及原销售/客户/运维和手机端操作。排版实测主要字号18px；测试夹具的行高79px或91px，审核按钮宽146px。此为模拟API的浏览器契约验证，不是对真实收款执行现场审核。
