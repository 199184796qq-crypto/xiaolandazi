## 目标

实现直播智能体中主线声音、实时交互声音、欢迎、答疑、插播声音均保持同一个主播声音身份。

用户听感目标：像同一个主播持续直播，而不是多个声音拼接。

---

## 一、声音身份 Voice Identity

声音身份不是单独音频，而是主播声音配置快照。

包含：

- 身份名称
- 身份版本
- 官方音色 ID / 克隆声音 ID
- 声音模型
- 语速
- 音调
- 情绪参数
- 风格参数
- 主播风格关联

示例：

跑山鸡主播声音 V1

- provider: aliyun_qwen
- model: qwen-audio-3.0-tts-plus
- voice/profile id
- 风格：热情、口语化、主播表达

---

## 二、声音生成绑定

所有声音生成必须引用智能体版本绑定的声音身份。

包括：

- 主线稿 A/B/C/D/E
- 欢迎声音
- 答疑声音
- 逼单声音
- 实时交互声音

禁止不同声音身份混用。

---

## 三、智能体版本快照

发布版本包含：

- 文稿版本
- 轮次版本
- 事实版本
- 商品版本
- 活动版本
- 主播风格版本
- 声音身份版本

版本不可覆盖修改，修改生成新版本。

---

## 四、整套试听

发布前支持连续试听：

- 开场
- 主线稿声音
- 欢迎
- 答疑
- 插播

用于确认声音一致性。

每套正式稿声音同时带精确文字时间轴。试听时播放器会根据真实播放进度高亮当前语义段，并显示每个段落的开始/结束时间和安全切换点。

---

## 五、发布校验

发布直播间前检查：

- 正式稿存在
- 正式稿声音存在
- 所有声音属于同一声音身份
- 实时交互声音绑定同身份
- 音频资源完整

不满足禁止发布。

## 八、人工验收流程

1. 在直播策略中生成并复核 A/B/C 等正式稿。
2. 为全部正式稿生成声音，确认“声音身份一致”。
3. 使用“整套试听”逐条确认主线声音。
4. 点击“保存为新版本”，确认产生新的 V 版本且旧版本仍保留。
5. 点击“发布到直播间”，确认发布不会自动启动 AI。
6. 回到对应直播间，在主播模式下点击开始。
7. 确认 Core 按发布版本正式声音轮播，而不是测试 WAV。
8. 发送弹幕问题，确认实时答疑使用与主线相同的声音身份。
9. 普通答疑时确认主线在当前语义段末尾切换，插播完成后从下一段继续。
10. 使用“抢答”在一句话中间触发，确认可以立即插播，但结束后不会重复被截断的半句话，而是从下一语义段继续。
11. 在直播运行页确认“当前稿 / 当前段 / 当前文字 / 下一安全切点”随播放推进。
12. 点击暂停/停止，确认声音停止但公屏采集等基础链路继续工作。

---

## 九、已有方案恢复编辑验收

1. 选择一个已经发布过智能体版本的直播方案并进入“生成智能体”。
2. 页面应显示“基于 Vx 恢复编辑”，并恢复文稿、生成内容时长、单轮时长、正式稿选择、声音身份、声音播放器与文字时间轴。
3. 如果存在比当前发布版本更新的待发布草稿，应优先恢复该草稿；旧于发布版本的历史草稿不得覆盖当前发布版本。
4. 不做修改时，已恢复的待发布草稿可以直接继续发布；恢复已发布版本时应作为编辑副本，不允许覆盖原版本。
5. 修改任一稿件、生成参数、正式稿选择或声音后，页面显示“有未保存修改”，发布前必须保存成新的版本。
6. 新版本保存后重新进入页面，应恢复全部 A/B/C/D/E 稿件；未选为正式稿的稿件也必须保留文字。
7. Core 运行时只读取 is_formal=true 的稿件，不播放工作区中尚未选为正式稿的草稿。

## 十、主播模式开始 / 暂停 / 继续 / 停止语义

- **开始**：创建新的运行会话，重新读取当前直播间已发布智能体版本，主线从第一套正式稿开头开始，同时开始计费。
- **暂停**：先冻结 Core 主线声音当前毫秒游标，并通过声音接收流广播 pause 控制事件让网页/设备立即停止实际播放；随后停止付费智能体与计费。不重新读取方案、不清空声音身份、不销毁主线 Program。
- **继续**：重新申请计费额度并启动付费智能体，然后直接从暂停时保存的同一声音毫秒位置继续播放；不得重新从稿件开头开始。
- **停止**：停止付费智能体并销毁当前主线 Program；下次点击开始必须重新读取当前已发布版本并从头开始。
- 暂停使用独立 Core 停止原因 manual_pause。该原因只清理付费决策/互动临时状态，不执行主线 Program 销毁。
- Core 停止付费智能体时继续保留主播模式、PlanID、PlanName，保证继续操作仍能识别原主播方案。

### 主线字幕与安全切点

- 主播实时口播左侧主线卡片直接读取已发布声音的文字时间轴，与 Core current_ms 对齐显示当前播放位置附近的字幕窗口，不展示整段长文。
- 字幕窗口按当前语义段的真实开始/结束毫秒估算段内文字位置；默认显示约前 18 字 + 当前 3 字 + 后 26 字，放大后仅扩大到约前 26 字 + 后 40 字，超出部分显示省略号。
- 当前语义段显示实时进度条。
- 当已有互动回答进入待插播状态且距离本次实际预定切点不超过 5 秒时，主线边框、切点提示与倒计时提前标黄。
- 主线与互动卡片都提供“放大 / 还原”；正在播放的声音卡片继续保留呼吸式外框反馈。
- 旧版本时间轴即使把所有分段标成 safe_cut，Core 运行时也只认可以句号、问号、感叹号、分号结束的完整语义句末；逗号和按最大字数截断的位置禁止作为互动切点。
- 新生成正式声音与自定义音稿最多保留 1024 个细分段；TTS 主线按真实生成 WAV 的 PCM 时长建时间轴，自定义音稿按 ASR 句级时间戳建时间轴，并统一归档 SRT / timeline / safe_points_v3 / manifest。
- 正式双轨调度沿用测试平台窗口：任务领取阶段优先在未来 30–55 秒内寻找接近 42 秒的 A→B→C 级安全切点；没有候选时退到 24–50 秒、目标 36 秒。回答生成完成后优先保留原预定点（仍剩 4–33 秒），否则重新寻找 5–30 秒、目标 12 秒，再退到 3–33 秒、目标 10 秒。
- Agent 获取切点前主线与切点后恢复句生成自然衔接；普通互动禁止立即截断半句话。

### 互动回答长度

- 最终可播互动回答仍以 **300 字为硬上限**，不是生成目标。
- Agent 根据问题复杂度、聚合问题数量、解释必要性和尽快回主线的节奏自行决定长度。
- 通常不少于 20 字；简单单问优先约 20–80 字，普通问题约 30–140 字，复杂/聚合问题可扩展到约 80–220 字。
- 禁止为了凑长度重复扩写；确有必要可以超过建议区间，但最终不得超过 300 字。

## 十一、自定义音稿

- “完整主线稿”旁提供“自定义音稿”入口。
- 浏览器支持直接上传 WAV / MP3 / M4A / AAC / FLAC / OGG / WEBM，单文件最大 50MB，并展示上传进度。
- 上传后通过 ASR 自动识别文字，按句级时间戳拆成最多 1024 个语义段；每段独立显示开始/结束时间与可校对文稿。
- 自动生成完整 SRT、timeline、safe_points_v3、manifest。人工修改任一段文字后，点击“保存校对并重建 SRT”重新生成调度资产，不重新上传音频。
- 自定义音频允许句子之间存在真实静音间隔，时间轴禁止重叠但不强制无缝连续。
- 浏览器会从完整主线自动生成约 12 秒、16kHz 单声道 WAV 克隆样本；后台优先用该短样本自动创建自定义音色，避免把 50MB 整段录音直接提交给音色克隆接口。
- 只有“原始主线音频 + 文稿 + SRT + safe_points_v3 + manifest + 自定义声音身份”全部就绪后，才允许“替换为正式主线”。
- 替换后版本只把 CUSTOM 标记为正式主线。发布后 Core 直接播放用户原始自定义音频；实时问答、桥接和回归使用该音稿自动克隆的同一 Voice Identity。
