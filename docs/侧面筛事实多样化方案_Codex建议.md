# 侧面筛事实多样化方案：Codex 评审与落地建议

日期：2026-10-15  
状态：设计建议，尚未实现；本文件不代表新方案已通过实测或已上线。  
评审对象：《侧面筛事实多样化方案.md》。原文保留，本文件单独记录建议。

## 1. 核心建议

**支持“用侧面筛选正文素材”，但应当在当前卖点×角度内筛选，不能让侧面改写本段任务。**

推荐链路：

```text
卖点×角度
  → 确定本任务允许的商品、事实与必要条件
  → 从相关且有事实支持的侧面中选择一个
  → 组织必要事实 + 侧面素材
  → 加入主播风格、有效纠正及完整 P0
  → 正文生成 → 润色与核对 → TTS → 播放
```

| 原方案内容 | 建议 |
|---|---|
| 侧面作为事实筛选器 | 保留，减少无关强信息对正文的干扰 |
| 卖点×角度作为调度 key | 保留，不预建 47×7 个任务槽位 |
| 角度与侧面冲突时，侧面优先 | 改为任务优先；只选择能完成当前角度的侧面 |
| 每个任务固定轮遍七个侧面 | 改为轮换本任务有依据的侧面；允许只有一两个 |
| 空侧面跳过 | 保留；全部侧面为空时，使用任务自身的必要事实 |
| 没有侧面标签就是通用事实 | 不采用；未分类不等于每次都可以加载 |
| 只改 HookFacts，其它链路完全不动 | 改为独立的正文素材视图，并核对润色、审核与复用身份 |
| 329 种讲法、零额外成本 | 改为组合上限示意；有效组合数量和成本需要实测 |

侧面可以重叠，一条事实也可以支持多个侧面。多样化的目标是改变展开方式与材料重心，不是强求事实集合完全不重叠，更不能用换题制造多样化。

## 2. 任务优先：防止“看起来丰富，实际上跑题”

例如当前角度是“麻辣味与五香味如何选择”，正文必须帮助观众选择口味。可以从口味偏好、适用场景等有依据的方向展开；不能因为轮到“品质来源”，整段就变成讲产地和养殖。

“侧面优先”实际上削弱了卖点×角度的意义。若确实需要一段专讲产地，应由调度选择对应的任务，而不是在口味选择任务下偷偷换题。

侧面只是完成本任务的方法。若已有通过核对的方向池，也应与本次方向相容，不能另起一套互相冲突的指令。

## 3. 事实分成三组，只有一组随侧面变化

### A. 必须保留的控制信息与商品边界

完整有效 P0、当前有效纠正、商品身份与成品/原料关系、明确的正负向限制，以及本次陈述成立所需的条件，不能被侧面过滤掉。

未知事项仍保持未知，不能因为删掉正向资料就自动变成否定事实。原料或部件的用途，也不能转成成品的功效和用法。

这里的“必须保留”不等于把所有价格、优惠和物流资料永久附在每段后面。控制边界和用于口播的正向素材应当分开。

### B. 完成本段任务所必需的事实

例如：

- 价格比较必须携带双方价格、对应规格及成立条件。差额等确定性计算由程序完成，并保留计算依据。
- 真空与非真空保存方式的比较，不能只留下“6天、3天”，丢掉对应包装、保存条件和开封要求。
- 口味选择应携带当前商品两种口味的已确认区别。没有确认的差异，不能让模型补写。

事实标题、正文和适用条件应作为一个有出处的资料单元处理，不能只截取数值。

### C. 本次侧面可选的展开素材

筛选关系建议为：

```text
当前方案已授权资料
  ∩ 当前任务的商品与事实范围
  ∩ 与当前任务/方向相关
  ∩ 当前侧面有依据的素材
```

先限定任务范围，再筛侧面。不能因为同属一个商品，就重新加载当前任务范围之外的全部事实或福利。

普通口感、手感、画面和主观感受仍按项目已确认规则允许合理表达；不把“资料未逐字写出”统一等同于违规。具体功能、功效、用法、数值与明确承诺继续按有效事实、P0及行业逻辑核对。

## 4. 保持四层提示词，不新增一套并行结构

| 层 | 本次输入 |
|---|---|
| 第一层：任务 | 卖点×角度、明确目的、本次选择的侧面及必要的方向内容 |
| 第二层：事实 | 必要事实、侧面素材、各自条件，以及只作约束的商品边界；明确区分用途 |
| 第三层：风格 | 已保存主播风格，只控制称呼、句式、节奏、情绪等表达方式 |
| 第四层：规则 | 完整有效 P0、有效表达纠正及输出要求 |

“四层”是输入组织方式，不表示 P0 优先级最低。任何生成、润色、核对及离线对照都保留完整有效 P0 的范围、条件与例外。

不把具体价格、优惠、库存、物流和商品范文塞进长期风格。提示词如需实际修改，仍统一在项目指定的 `configs/prompts/anchor-style/` 模板目录维护；本文件仅说明设计。

## 5. 侧面标签与空数据处理

建议先采用“程序预分类 + 人工可调整”。优先利用已有事实类别和已确认关系，不只凭几个关键词判断语义。模型辅助分类可以作为资料整理阶段的可选能力，不必为每一段正文增加一次分类调用。

建议的数据含义：

| 信息 | 含义 |
|---|---|
| 侧面标签 | 一条事实可以支持多个侧面，显示名与稳定代码分开 |
| 分类状态 | 区分未分类、已分类、有意不作侧面展开素材 |
| 对应事实版本 | 分类只对当前事实版本有效，资料变化后重新判断 |
| 分类来源 | 记录程序建议、人工调整或模型辅助及其版本 |

不建议把 `sides=[]` 解释为通用兜底。这个空数组无法区分“没有处理过”和“确认适用于所有任务”，会让旧价格事实重新出现在每个侧面。

商品边界也不应通过“通用侧面”间接携带，而应沿用独立的边界传递。

兼容旧资料时，先保留当前任务已授权且必要的事实；未分类的可选事实不自动加入所有侧面。一条资料未分类，不应让整个直播间停止供料。

如果使用分类模型，程序先绑定单条事实与当前版本，模型只返回分类内容及必要解释；内部事实 ID、商品 ID、关系和版本由程序维护，不让模型回填关联表。

原文举例中的“蛋白质足脂肪少”“嘉陵江、丘陵水田散养”等信息，不能因为出现在方案文档里就直接变成正式事实。需确认当前方案是否有对应依据；我此前读取的快照未确认这些内容。

### 可用侧面与轮换

先按任务、事实版本和标签版本形成可用侧面集合，再在这个集合中轮换。全部侧面都没有支持材料时，回到当前任务必要事实，不退回整个商品的全量事实，也不临时编造材料。

一次候选生成开始时，冻结选择的侧面与事实包。同一次重试、润色、修订沿用这个上下文，避免失败重试时悄悄换题。

代码核对发现，当前 `Used[key].Count` 在候选被采纳时增加，并非实际起播次数。第一阶段建议保持现有计数含义，不把“生成、采纳、实际播放”混为一谈。若以后改按观众实际听过的侧面轮换，需单独接入幂等播放回执。

现有“同角度实际使用三次后补充推演方向”的计数仍按其原有规则执行，不因新增侧面筛选而改变。

## 6. 代码改动范围：独立筛正文素材

本次代码核对基于已整合源码提交 `61a4478`，不是断言 E 盘旧工作目录已包含同样功能。

已经确认的调用关系：

| 位置 | 核对结果与建议 |
|---|---|
| `anchorcycle/angle_hook.go` 的 HookFacts | 已有 Task.FactScope 路径，不能把所有现状概括成“整商品全量事实” |
| `anchorcycle/angle_plan.go` | 方向池身份使用 HookFacts 摘要；若该公共函数随侧面变化，可能影响已有方向池命中 |
| `httpapi/text_generation.go` | 在正文输入组装处接入独立的侧面素材视图 |
| 方向审核与最终正文审核 | 也使用 HookFacts；不能因正文筛选而意外丢失核对依据 |
| 润色、局部修订 | 沿用已冻结的任务、素材授权与条件，不重新灌回所有正向事实 |
| `httpapi/speech_library.go` | 核对跨场正文复用的侧面与材料身份 |

建议新增职责明确的正文素材组装函数，例如 `BodyFactsForSide`，名称仅为示意。公共的任务事实范围继续稳定，侧面筛选只生成本次正文使用的视图。

审核可以读取足够的任务事实与边界来发现矛盾，但这不等于允许正文模型讲出参考资料中的所有正向内容。需要同时保存“核对参考范围”和“本次正文材料范围”。

因此可以争取不增加常规生成调用次数，但不能宣称润色、审核和复用完全无需适配。

## 7. 话术复用要能识别侧面，避免筛选后又取回旧正文

仅改变新生成时的事实包仍不够：若跨场复用仍只按卖点×角度取候选，就可能在选择“使用方式”后取回旧的“价格算账”正文。

建议：

- 调度 key 继续使用卖点×角度，不预建七倍槽位，也不自动把当前库容量扩大七倍。
- 每条候选由程序保存所选侧面、材料与必要条件的摘要、事实版本、标签/筛选规则版本；复用时验证当前侧面及授权仍匹配。
- 旧候选缺少足够出处时，不直接冒充已经满足新筛选规则；按可核实的既有记录判断，不能确认则走正常生成。
- 当前轮到哪个侧面，不应写入房间整体的稳定上下文指纹，否则每次轮换都可能使其它侧面候选失效。侧面匹配放在候选级处理，资料或规则变化再使受影响内容失效。
- 继续复用已核对的最终文字及与它准确对应的声音。声音或语速改变时，沿用既有文字/音频分开失效机制。

已有旧声音缓存路径包含 FissionSide；新持久主线话术库的身份与选择逻辑仍需单独核对，不能把两个机制视为同一套。

侧面筛选不要求修改当前平台缓存复用开关。模型供应商的输入缓存命中与项目正文/音频复用继续分别统计。

## 8. 如何验证这次改法有效

原文的三组实验提供了有价值的观察，但尚未拿到对应完整请求与原始输出，不能把“侧面优先后的话题差异”直接认定为“同任务内的多样化”。

我此前完成的 28 次 Qwen3.7 Flash 调用只证明四层输入能够生成候选正文，也发现了无依据包邮、比较价格、商品用法及超字数等问题；它们不是这套侧面筛选方案的直接 A/B 验收。

### 对照设置

固定同一模型版本、完整 P0、母版、风格、任务、事实快照、输出长度及其它参数，只改变正文事实选择方式：

- A 组：当前生成方式。
- B 组：任务必要事实 + 任务内相关侧面素材。

显式传 `enable_thinking: false`。温度 0.25 和 0.7 如都要测试，分别在各自同参数对照中比较，不能用跨温度结果归因。原文 41 条事实与我此前 30 条快照的差异，也需按读取时间和版本对齐，不据旧快照断言当前数据数量。

保存完整请求、原始返回、所选素材与条件、版本、耗时和 token；日志不保存密钥。

### 至少覆盖的情况

| 情况 | 验证重点 |
|---|---|
| 口味选择 | 各侧面仍完成选择任务，不能轮成纯价格或产地介绍 |
| 多规格与价格比较 | 商品对应正确，比较双方及条件完整，计算正确 |
| 保存、包装与开封 | 数值不脱离真空/非真空等适用条件 |
| 功能与使用方式未知 | 不补造功能、吃法或原料到成品的用途迁移 |
| 空侧面、全部未分类 | 按既定任务继续供料，不灌回全商品事实、不无限重试 |
| 跨商品、租户和方案 | 不串用其它授权范围的材料与福利 |
| 事实、标签、纠正或 P0 更新 | 旧判断和旧候选不能授权新内容 |
| 生成重试、润色及复用 | 侧面与材料上下文一致，最终正文没有重新跑题 |

至少另选一个非食品类目，验证公共规则没有写成鸭子特例。

统计任务完成、事实与条件正确、P0 语义核对、耗时/token 和表达变化。字面命中、待核对、格式异常与确认违规分开记录；不能把某个词的出现当成最终违规结论。

多样性按材料重心、展开顺序、场景和句式观察，不要求七段互不相关，也不新增“必须语义全新”的硬性否决。重复处理仍遵守项目已确认的逐字重复口径。

## 9. 建议的实施顺序

1. **先做离线对照**：用固定事实快照验证任务内筛选，保留原始输入输出；先证明不跑题且条件不丢。
2. **再做资料分类与版本**：实现标签、分类状态、旧数据兼容和必要的人工调整；新增界面文字遵守项目最小 16px。
3. **接通完整上下文**：正文、润色、核对和候选出处采用一致的材料定义，补齐复用匹配。
4. **再评估生产接入**：依据回归和实际发布状态决定范围，保持现有供料、调度和缓存配置；保留 WorkBuddy 页面与已上线功能。
