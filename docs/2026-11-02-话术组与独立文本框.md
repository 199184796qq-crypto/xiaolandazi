# 话术组与独立文本框

状态：本地实现与验证完成，用户随后授权“部署上线”，正在提交与打包；实际激活以文末发布回执为准。用户先取消段内去空白改动，再指定本结构，并要求当前编辑页面文字统一20px。

## 编辑与保存

- 标签为话术组，组名可修改；选中后显示该组自己的独立话术框。
- 每条400–4000字符，每组所有话术总计不超过4000字符，最多自然容纳10条；各组独立计算。汉字、标点、字母及Unicode码点各计1，空格和换行也计数，不再执行前轮的去空白整理。
- “添加话术”在现有每条均合法、且至少剩400字符额度时，才在最后一个框下新增空框。未完成的空框须先补足或删除，才能再添加。非法/不足额度不会新增；每框越界、少于400、只有空白，以及组内总数超限都在框上方红字说明；保存也由前后端校验阻止。
- 允许粘贴超限文本以便修改，显示实际字数和红字，不静默截断。删除独立话术可释放额度，最后一条保留；原标签新增、拖动、删除和固定标记保持。
- 新保存结构为 `recording_script.version=2`，每个 `tabs[]` 含组标识、组名、顺序、固定状态和 `entries:[{entry_id,text}]`；不额外拼接旧 `text`，也不使用`====`编码条目边界。新条目内的字面`====`只是原文。
- 从保存回执恢复独立条目，切换标签、方案后仍按保存的各框回显；保存过程中禁用相关编辑，失败保留输入。方案、租户、模式变化的旧回执继续由既有epoch保护丢弃。
- 当前话术优先编辑区域、标签、按钮、红字/字数说明和文本框统一20px，样式限定该区域。

## 播放与预生成

阿里和火山的新结构都把每条独立话术直接作为一个完整合成单元，支持单条4000字符，不再按分隔符再次切分。保存时只异步预生成全方案字符数最少的一条；相同长度按标签、框原顺序选择。新结构的运行单元仅把该条移到首位，其余顺序保持，以便开播复用同一身份的预热缓存；界面和落库顺序不变。之后继续既有整段供料、缓存与循环逻辑。

缓存继续按正文、声音、语速及现有指令身份隔离；没有清除历史已付费文件，没有新增文字模型输入或调用。保存后的正常首次TTS预生成沿用原计费路径，验证过程未真实购买声音。

## 旧数据与原始录音

历史版本不批量修改，旧播放/缓存读取保持旧语义。旧单框`====`文本进入新AI话术编辑器时拆成多框，显式保存后采用新结构；旧段不足400或一组总数超过4000时显示红字，须用户调整，不自动截断或重写。原始声音模式的长录音、上传资产、原正文和SRT/时间轴继续采用原绑定流程，不用新字数门槛破坏长录音。
