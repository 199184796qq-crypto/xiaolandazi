# 互动字幕残留排查与修复

用户截图中“谢谢老粉丝的点赞。”在主线商品讲解更新多句后仍留在顶部。截图有四行字幕，而当前实时口播模板只渲染上一句、当前句、下一句三个位置，属于异常显示。

## 查到的缺口

`web-console/src/views/RoomDetailView.vue` 的 `publicSpeechCaptionRows` 原先以 `feed-片段编号-tone` 作为 Vue 列表 key，后备主线字幕也只使用片段编号。同一快照包含重复编号时，两个不同位置的字幕会使用相同 key。实际组件计算逻辑和模板的浏览器复现报 `Duplicate keys found during update`，之后真实 DOM 出现四行，而计算结果仍只有三行；额外节点在后续更新中残留。

Core 的互动描述编号按每条互动重新从 `interrupt-001` 编号。编号是播放描述，不适合作为固定三行显示位置的独立身份。跨请求重新使用编号本身并不必然出错；本轮验证的异常触发条件是同一渲染列表中 key 重复。不能把“编号复用”一概当作每次互动都会触发的问题。

## 修复

按 `previous/current/next` 三个位置分配固定 key，Core feed 与后备主线分别加前缀。内容、红黄绿分类和字幕来源继续使用当前快照；三位置各自更新，重复描述编号不会制造孤立字幕节点。

仅修改字幕渲染标识。没有更改生成、审核、缓存、互动触发、音频排队或实际播放控制，也没有添加用定时器猜测播放结束的逻辑。互动结束后作为上一句短暂保留仍属于原本字幕历史；主线推进后应被新上一句替换。
