# 切换方案后的操作记录误报

切换方案页面先成功调用 `POST /rooms/{roomID}/runtime/plan`，再向
`POST /rooms/{roomID}/runtime/events` 发送 `LIVE_AGENT_PLAN_SELECTED`。
后台操作记录白名单遗漏该类型，返回400；前端公共请求层在调用方catch之前
已经弹出“请求未完成 / 不支持的直播操作记录”。因此切换成功仍弹失败，
并不是方案未保存，也不是声音或模型生成失败。

生产Nginx记录核实北京时间2026-10-16 16:15:09、16:15:18、16:24:01、
16:38:12均为方案选择200、紧随其后的操作记录400。

修复补齐当前房间页面实际使用的六种操作类型：创建并选择方案、选择方案、
收到场控回复、移动场控入口、屏蔽及取消屏蔽公屏用户。旧类型继续兼容，
不接受由客户端伪造的AI生命周期事件。操作记录仅写事件表，不修改方案、
AI状态、播放或模型池分配。鉴权和客户/房间范围沿用原接口。

不通过吞掉请求错误或关闭弹窗掩盖问题。未知操作返回400；数据库写入故障
现在返回500及“保存直播操作记录失败”，不再误标为不支持操作。

回归直接从房间页面提取所有实际操作类型，经真实Store方法及SQL驱动验证
持久化参数、租户/房间/操作者和方案详情；同时覆盖非法生命周期事件不落库、
数据库失败传播、HTTP错误分类及接口仍需登录。db/httpapi两个完整包共
897项通过（含子测试）、85项按环境条件跳过，无失败；不称跳过的数据库
集成实验已通过。没有调用真实模型/TTS或操作客户直播。

提示词、声音缓存/模型池设置及Core/网关。第302场运行期间不重启服务，
