# 直播策略与智能决策架构 V2

更新时间：2026-09-27

> 归档说明：本文件保留 2026-09-27 前一阶段设计。后续工作台模块、活动福利、互动策略和直播智能体生成以 `docs/live-agent-workbench-architecture-v3.md` 为准。

## 1. 核心结论

“直播方案”不再作为与其它功能并列的普通页签，而是整个直播策略工作台的业务容器。

运行时核心链路：

规则层
→ 行业层
→ 当前直播方案
→ 用户纠正 / 智能体记忆
→ 当前直播实时上下文
→ 智能决策
→ 文本生成
→ TTS
→ 音频分发

当前直播业务底座由“直播方案 + 用户纠正”共同构成。主播风格和声音属于表达与输出层，不能反向污染事实层。

## 2. 页面信息架构

页面顶部常驻：

- 当前直播间
- 当前直播方案
- 当前已发布版本
- 当前运行状态
- 切换方案
- 新建方案
- 复制方案
- 版本历史

方案内部功能按以下顺序组织：

1. 直播话术
2. 方案知识
3. 直播节奏
4. 学习记忆
5. 主播风格
6. 声音

旧“基础设置 / 策略调教 / 主播训练 / 固定话术 / 声音配置”先保持兼容，不删除数据，逐步迁移到新结构。

## 3. 直播话术

这是方案的第一入口。

支持：

- 直接粘贴直播话术
- 上传 TXT
- 上传 MD
- 永久保留原始话术
- 自动整理成更易读的版本
- 整理后允许人工继续修改
- 智能分析

同一份资料至少保存三层结果：

1. 原始话术：不可被自动整理覆盖
2. 可读话术：整理后的工作版本，可人工修改
3. 智能分析结果：事实与节奏结构

## 4. 方案知识

从话术中提取但不自动把所有内容当成“已确认事实”。

分类包括：

- 商品事实
- 商品 / 链接信息
- 交易事实
- 履约事实
- 地点 / 身份
- 其它事实
- 待确认事实

每条知识至少保存：

- 分类
- 名称 / key
- 值
- 状态（待确认 / 已确认 / 停用）
- 来源话术
- 来源片段
- 最后修改人与时间

原稿中出现过的内容不等于真实事实。模型首次提取时默认允许进入“待确认”，由用户确认后再成为正式事实。

## 5. 直播节奏

智能分析不只做摘要，而是把原稿还原成可复用的直播节奏节点。

典型节点例如：

开场留人
→ 产地
→ 原料
→ 工艺
→ 使用场景
→ 信任
→ 链接
→ 价格
→ 逼单
→ 答疑
→ 回主线

每个节点可以保存：

- 节点标题
- 目标
- 可引用事实
- 必讲点
- 禁止点
- 执行模式（100% 原话 / 按意思生成）
- 固定原话（如有）
- 建议持续时长
- 转场方式

主线文案生成时由“节奏节点 + 已确认事实”生成新口播，而不是重新凭空生成。

## 6. 学习记忆

直播过程中用户纠正继续沿用现有学习闭环。

重点记忆类型：

- fact：事实纠正
- semantic：回答策略 / 语义规则
- wording：用词纠正
- style：主播表达习惯

学习记忆必须保留来源、版本、采用时间和回滚能力。

## 7. 主播风格

从优秀录音、逐字稿和用户确认样本中学习“怎么说”，不学习样本中的商品事实。

学习内容包括：

- 句子长短
- 连接词
- 停顿
- 重复方式
- 叠词
- 情绪
- 转场
- CTA 习惯
- 产品故事展开深度

最终形成 Style Profile。

## 8. 声音

声音是最终输出层，支持：

- 官方音色
- 克隆音色
- 默认音色
- 试听
- 克隆状态

## 9. 第一阶段落地顺序

第一阶段优先：

1. 重构 LiveStrategyView 顶层信息架构
2. 让直播方案成为容器
3. 默认进入“直播话术”
4. 完成粘贴 / TXT / MD 导入
5. 保存原始话术和可读话术
6. 接入智能分析，生成结构化事实候选和节奏节点
7. 暂时保留旧功能和旧数据接口，避免破坏现有运行链路
