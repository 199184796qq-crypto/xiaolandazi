# 主播口播规范：跨模型调用边界

## 不是为一个主播手写提示词

分析模型根据用户当前样本返回 `anchor_style.delivery_spec`，协议版本 `anchor-delivery/v1`。其中包含8–16条具体执行规则、最多32条原词习惯（自称、观众称呼、语气词、连接词、口头禅），以及位置、适用和禁用场景。没有证据的词不得补充。商品事实、身份、承诺不得从风格迁移。

程序不信任模型给的计数、统计、哈希或成品规则文本：逐项核对原词是否存在于样本，重算次数和标点分句，再统一编译 `rulebook`。语气词覆盖检查仅针对本样本多次出现的句/段末语气词，不把词中同字误当语气词。直播样本中重复出现的观众称呼和主播方自指同样按原文证据兜底提取；一旦该类别已有稳定重复证据，真实的一次性变体也可以保留，但必须记录自身频次和位置。主播方自指跨商家、跨主播时必须替换当前主体，不能照搬身份。不合格时只补正规范一次，仍不合格则报错，不无限重试。

`anchor-delivery` 只承载“怎么说”的词表、密度、位置和场景边界。直播漏斗、内容环节、稀缺推进和风险逆转属于内容策略层；商品名、价格、数字、库存、产地和售后属于事实槽位层。内容策略可以复用结构，但只有正式事实存在时才能填充事实槽位，不能把样本数字或业务承诺当作主播风格继承。

前端只展示统计、默认折叠的“主播口播规范”和测试正文。确认保存的是已分析的同一个规范，源素材变更必须重新分析；不会再次调用分析模型偷偷改变规则。

## 生成链路

测试、整场主线、单稿重生成、局部刷新、实时互动读取同一协议。实时回答不再分析样本，也不要求每条短答塞满所有口头禅；事实、安全和严肃场景优先。

长稿检查充分取证的高频原词，保留主要自称而不泛化；观众称呼的真实变体可替换。测试同时检查已有数字和链接边界，自动补正最多一次；补正固定原来的模型和供应商。检查不过不返回成功正文。整场稿沿用现有审计与补正流程；短实时回答保持现有终审，不新增一轮风格评价以拖慢响应。

这些检查不是“像主播90%”的相似度证明，也不是完整事实、语义、合规或音色认证。文字样本不能推断真实音高、语速或克隆音色。不同模型能力仍影响结果。

## 模型切换由运营控制

- `ANCHOR_ANALYSIS_PROVIDER` / `ANCHOR_ANALYSIS_MODEL`：分析模型。
- `ANCHOR_GENERATION_PROVIDER` / `ANCHOR_GENERATION_MODEL`：测试、主线、局部刷新和实时回答模型。
- 留空沿用原来的 Qwen 配置，部署不切换现用模型。
- 可选择已注册的 `qwen` 或 `compatible`。后者需要服务端 `AGENT_COMPATIBLE_BASE_URL`（兼容API根地址，例如以/v1结尾）和 `AGENT_COMPATIBLE_API_KEY`，且必须显式指定模型，不发送Qwen专属 `enable_thinking` 参数。只支持兼容 chat/completions、字符串正文响应的接口；其它API需要实现并注册 `agentgateway.Provider`，不用改变规范协议。
- 已保存规范不会因切换分析模型自动重写。旧版没有规范的分析须重新分析；旧直播配置不被迁移或启动。

## 更换模型的上线门槛

本地测试覆盖：原词和统计不能伪造、无证据词被过滤、安静讲解不继承促销词、语气词遗漏被发现、自称不被缩写、短答不强制全词表、兼容接口模型路由、补正保持同一规范且最多一次、持续失败不放行。

这些是模拟接口/固定输入的工程回归，并非不同真实模型已经达到相同风格效果。上线新分析模型前，须在授权的多主播样本集上对照测试：克制讲解、热情促销、故事型、极短样本、不同自称/称呼、转写噪声、样本商品与当前商品不同、投诉和无事实场景。核对语气原词、自称、句式、转场、事实污染与延迟；不能只用一篇菜籽油稿通过就宣布兼容。密钥不得进入前端或日志。
