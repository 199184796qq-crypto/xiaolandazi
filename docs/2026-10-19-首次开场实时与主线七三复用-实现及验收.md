## 1. 本次结果和范围

已实现每场正式直播的第一次开场实时生成，并与近期同方案开场避重；首次开场声音也现场合成。后续普通主线的接新版开场、主体讲解、收口共同按70%复用、30%新生成安排。这里是**完整话术资产的复用比例**，不是模型厂商的输入token缓存命中率。

首次完整版开场单列，不占七三分母。互动、承接桥、插入讲解、辅助段、纠错重写和已有塑价续讲承诺沿用各自路径；本次没有把它们强行装进主线配额。客户关闭缓存复用的设置继续生效。

本次完成源码、测试、真实方案输入的离线回放和Linux编译；**尚未部署，没有新开直播，没有调用付费模型或TTS，没有修改客户方案或生产数据库。** 原监控保持停止。

## 2. 为什么原实现不能直接满足要求

1. 原主线长期库仅接主体段，开场全部实时；会话池还有“前60分钟全实时、其后约三分之二复用”的旧逻辑，两套口径没有统一。
2. 长期库按每个槽位库存选择30%/60%/70%概率；库存少时，即便希望全场70%，实际也达不到。不能再把七三配额乘一次旧概率。
3. “登记长期库的decision”包含新稿写库预留，不等于复用了旧稿。session316有72段采纳，22个decision，但只有6段明确旧稿复用。
4. 正文和收口、接新版开场不同；同一卖点角度的不同侧面也不同，不能只看商品和任务名就借旧稿。

## 3. 现在的具体规则

### 首次开场

- 用正式场的`phase=opening && opening_count=0`识别；不看“进程第一次启动”或“当天第一次直播”。
- 不查旧正文，不查旧音频；同一场同一已生成稿的幂等音频重试不重复合成。
- 在现有完整P0、事实、风格、角度、审核流程之上，增加`configs/prompts/anchor-style/first-live-opening.md`。历史片段仅供避重，不是新商品事实或授权；不改变稳定system前缀。
- 保存已采纳的首次开场正文资产；下一场读取同租户、同房间、同方案、同素材/规则上下文的最近5场，提示词最多携带3段、每段180字。
- 程序拦截归一化后完全一致的文字，以及长稿只改称呼、标点或少量字的近似复制。现代模型路径最多即时再生成1次；仍重复则明确阻塞，不拿旧稿兜底，也不转TTS。旧AgentStudio路径增加相同避重材料及最终拦截。
- 这不是“全历史语义完全不同”的承诺：历史窗口有限，新表没有反填此前全部直播；首个升级后的场次没有新表历史时，先现场生成并积累历史。素材或规则上下文变化也会隔离旧历史。历史写入失败会记录告警，需要处理，不能声称后续跨场避重记录完整。

### 七三混合

- 每次依据最近9个有效、已采纳的普通主线输出决定下一段，缓存充足时连续10段为7复用、3新生成。
- 冷库缺稿、失效、遇到本次纠错、时效材料或审核不符时，实时生成；**不为凑70%而串品、错角度、复读近期稿或跳过审核**。
- 失败回执明确确认未送出的段返还配额；不明确的回执继续预留，防止重复发送。生成重试、查询重试和未采纳退稿不另占配额。
- 冷启动未命中只影响有限窗口，不能积累成无限“补复用债”，以后长时间全讲旧稿。
- 长期库实际选择概率由本次配额统一设为0或100，仍保留管理端库容量、冷却、生命周期等设置。
- 缓存匹配继续绑定租户、方案、房间、源事实和完整规则、模型、风格、卖点角度、钩子、正文审核凭据；本次额外绑定环节、首次/接新版区别和冻结侧面。声音再绑定音色、语速、模型、时间轴和实际文件。
- 缓存凭据或近期避重校验不符时取消旧租约；新稿重新登记有效写库租约，避免沿用已取消的decision导致新稿不能入库。
- 新上下文指纹会隔离旧的环节/侧面不完整资产，未删除旧文件或客户资料。因此上线初期实际复用率可能低于70%，积累正确资产后才会接近目标。

### 保持原方案的调度边界

仍由既有滚动调度先选商品、卖点角度和适用侧面，然后决定这个任务取合规旧稿还是新生成；不让缓存库存反向决定讲哪个商品。商品1.2、同商品卖点1.3上限、公共主体20%、普通主线相邻同品不超过2段的逻辑没有被替换。

## 4. 方案到正式话术的链路核查

| 层次 | 当前结论 | 落地验收 |
| --- | --- | --- |
| 保存方案/加载版本 | 保存方案快照、启动加载固定版本；本次未改客户资料 | 新场核对version_id、run_id和源快照，不能仅看前端版本名 |
| 商品/卖点/角度调度 | 滚动差额调度已存在，本次七三不改变任务选择 | 只以有效已采纳body核公共和商品配额，开场/收口/互动另计 |
| 事实支撑侧面 | 已有按事实分类选可用侧面；仍不等于证明当前卖点×角度已完成 | 保留卖点×角度，只在有相关事实的侧面内选；不能因有停车事实就认定“介绍中式环境”有支撑 |
| 正文生成/审核 | P0和最终审核继续保留；历史已有语义漏检、条件主体错配与审核不一致 | 必须看最终正文是否完成本次角度，及条件到底约束什么对象 |
| 长期话术/音频库 | 本次接通首次例外及其后七三；缓存边界加强 | 统计`reuse_origin`、LibraryEntryID和实际命中；decision本身不算命中 |
| TTS/排队/播出 | 既有文字绑定、确认下发和失败返还保持 | 分开记录采纳、TTS完成、排队、Core开始、PCM完成；前四者不能充当完整播完 |

### 仍需单独处理的内容问题（本次没有宣称已根治）

session316本地归档中，10个公共主体段有3段没有完成被安排的公共角度。例如：

- `879528d415be07ae68303b9ca13c2c13`：任务是中式环境，正文主要回到2号价格/菜单，Core开始09:43:42。
- `9328c6a504e13759b3c09fe3e29bc01d`：任务是仅堂食、不外带，正文主要回到2号价格/菜单，Core开始10:08:32。
- `3295676c86afc555a348747fa5af6c13`：任务是不叠加优惠，正文主要回到2号菜单，Core开始10:29:47。
- `2b8ae526908e0b2274ae7e711e9f5001`：把餐券的每桌1张、不叠加、不包间条件套给“停车券”，已有审核仍通过，Core开始09:53:11。

这些例子说明公共body达到20%只证明调度标签数量正确，不能证明20%的公共话题都实际讲了。下一步应给**现有最终正文审核**增加可核查的任务完成项和事实主体关系：本次结论、正文证据句、对应事实ID、条件约束对象、缺失项；不能另加无边界多轮审核。明确不完成时只修本段，技术/格式失败不能屏蔽整个卖点角度。先用上述失败稿及已完成正例回归，跨行业验证，不能用商户关键词白名单假装语义验收。

另有两个统计/材料边界要继续保留：互动顺带点名商品会改变听到的全场分布，不能只用主线权重解释总提及比例；人均价必须明确人数分母，不能把按6人计算的人均金额套给3—4人的情境。
