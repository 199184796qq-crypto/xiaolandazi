# 后台直播计费与小时预算配置

状态：本地实现与回归，尚未提交部署。基线 `eda106b`，保留协作者的其它修改。

## 管理入口与计价单位

系统设置 → 直播业务 → 直播成本设置。平台管理员及具备系统设置权限的超级管理员可以读取、保存；普通客户及员工没有维护权限。页面支持保存后回显、重新进入读取以及并发修改冲突提示。

| 参数 | 默认值 | 核算方式 |
| --- | --- | --- |
| 声音合成 | 0.8 元／万计费字符 | 实际发送文本中，汉字计 2，标点及其余字符计 1；纯汉字约 1.6 元／万汉字 |
| 默认模型输入／缓存输入／输出 | 0.2／0.04／0.8 元／百万 Token | 未匹配特定模型规则时使用，可修改 |
| 主线可选更新目标 | 1 元／小时 | 按整轮时长预测、实际费用和待更新对象分布安排更新 |
| 全部可选工作软线 | 1.2 元／小时 | 共用本直播间的可选模型与声音请求账本 |
| 直播间总目标 | 1.3 元／小时 | 包含必要供料、互动和可选工作；可选调用需同时满足可选与总目标 |

内置的 Qwen3.7 Flash 规则保留完整输入的三档默认值：≤32,000 为 0.2／0.04／0.8，≤256,000 为 0.6／0.12／2.4，其余为 1.2／0.24／4.8 元／百万 Token。后台可以编辑档位，也可添加其它供应商及模型规则。缓存输入是输入的子集，选择档位时使用完整输入数量；计价时只分别计算非缓存输入、缓存输入和输出，不重复加输入。

金额用整数微元保存，页面最多六位小数，不采用浮点累计。TTS 每万价可以精确到一微元；每笔请求向上取整到一微元。明确填写的缓存输入零价允许生效，缺字段或坏配置不会被理解为免费。

预算必须满足 `0 ≤ 主线目标 ≤ 可选软线 ≤ 总目标`，总目标大于零。主线目标设零可暂停主线可选更新；可选软线设零可暂停全部可选工作。必要供料、首轮缺音、事实变化补音及必要互动仍按业务优先继续并记录超用，预算不是停播开关。

## 生效与历史边界

1. 保存后，新付费请求和每轮更新规划读取最新数据库配置，多进程无需重启。每笔请求开始前固定完整价格表及修订号，模型返回真实 Token 后在原表中选档；TTS 使用原单价。调用期间调价不会重新计价已发送请求。
2. 逐轮规划、执行前复核和请求级事务预留使用同一配置来源。一次规划只读一份完整配置，避免对每句话查询设置；实际付费调用前再按最新小时预算检查。
3. 如果在一轮中途上调单价，旧规划可能保留旧报价，但每次实际模型及 TTS 的新预留采用当前价格。模型成功后 TTS 因额度不足被拒绝时，模型费用照计、保留旧的有效声音并暂缓剩余可选更新。下一轮重新报价。
4. 成功生成即计费用，未采纳、未送播、未完整播完仍计费。`reserved/unknown` 待核对，不因修改价格自动退款。后台金额属于参考核算；供应商发票、结算账单可通过既有核对流程升级证据。
5. 已有费用记录不回算；改价不会改变业务请求键、文案缓存身份、事实或声音版本，不会清空缓存或重复购买结果不明的同一请求。
6. 配置读取失败时，可选更新暂缓，必要业务沿用最后有效配置；冷启动没有有效历史配置时使用已校验默认价留痕。无效或不完整配置拒绝保存，不能变成零价。

历史环境变量 `LIVE_COST_SUPPLIER_PRICE_CONTRACTS` 的精确供应商合约，仅在后台配置尚未保存（修订号为零）时兼容。第一次保存后，新后台参数为权威参考价，不再由旧环境价格覆盖；部署后首次维护应核对面板中的单价。既有供应商真实账单核对能力保持。

## 存储、接口与审计

- 使用现有 `mgmt_system_settings` 的 `live_cost_config` 单行配置，无新增业务表。启动种子只更新设置元信息，不覆盖运营人员的价格值。
- 专用接口：`GET /api/v1/system/live-cost-settings`、`PUT` 同路径，响应为 `{config: ...}`，禁止通用设置写入绕过校验。
- 保存使用事务、行锁和修订号比较，同一版本并发保存只有一个成功；过期返回中文冲突提示，页面必须重新读取后再保存。
- 审计记录管理员、旧配置、请求的新配置、保存结果和成功后的修订号。配置不包含密钥、访问凭据、话术正文或签名音频地址。
- 配置 JSON 最大 32,000 字节，最多 32 条模型规则、每条最多 16 档。请求价格快照最大 48,000 字节，保留现有费用表及耐久补记记录的大小边界。
