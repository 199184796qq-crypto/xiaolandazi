# 收款审核入口与不可审核原因（2026-09-24）

## 入口命名澄清（2026-09-24）

用户指出“收款审核”和“待审核”并列令人混淆。本次仅调整前端入口、标题与范围提示：`/staff/finance/receipts` 更名为“客户收款确认”，处理客户实际付款的核验及按用途入账；`/staff/finance/approvals` 更名为“资金与权益审批”，处理员工发起的充值、退款、奖励、AI 时长操作申请。“待审核”只保留为单据状态，不再作为笼统功能入口。

两类单据不是同一笔款的两道审批，不合并原数据，不要求已确认收款再建内部充值申请。保留所有原路由和审核权限、分人开关、幂等及入账逻辑。本次不执行真实审核、不改变客户资金。功能卡片同步显示清楚的英文标签和简短范围说明，主标题18px、说明16px；其他已去掉说明的卡片不受影响。财务总览原硬编码“职责分离已启用”改成“审核规则可配置”，避免与真实开关冲突；原待审计数明确仅统计内部操作申请，不冒充全部收款待办。

以下为历史记录，旧菜单名称以本节为准。

最新补充：用户已要求分人审核可配置。本人提交不可自审仅在“系统设定 → 财务审核规则 → 强制经办人与审核人不同”开启时成立；关闭时仍须具有相应审核权限。新版收款表主文字18px、紧凑按钮与短原因提示。以下保留之前的入口修复记录，实施细节以 `finance-review-policy.md` 为准。

客户收款单的实际审核页为 `/staff/finance/receipts`，在财务与结算的“收款审核”中处理。原 `/staff/finance/approvals` 保留充值、退款、奖励等原审批任务，不能把两个列表混为同一待办。

本轮补齐超级系统管理员左栏“财务管理 → 收款审核”的直接入口；财务导航增加同名入口；旧待审核页增加说明和“进入收款审核”链接。收款详情也可进入审核，宽表格操作列固定在右侧。

收款页面按角色解释审核入口。财务有查看权限但无审核权限、本人提交或最后补件的收款单，按钮保留为禁用并显示具体原因；销售/客户进度页只显示由财务审核的提示。未改变权限或经办、审核分离规则，也没有为任何账户添加权限。后端仍按 `finance.recharge.approve` 与原申请人/最后提交人校验。

已用隔离 Chrome 模拟 API 回归验证：普通财务正常审核交互、超级管理员侧栏和旧审批页跳转、详情审核入口、本人提交不可自审、无审核权限不可审核，以及表格/卡片与原客户、工单、手机端流程。模拟接口测试未调用真实入账接口。

本轮只修复前端可发现性和原因说明，不审核任何真实收款，不改资金、客户认定或现金点收/缴存业务。真实现金专用流程仍遵循 `customer-finance-qualification.md` 的已确认规则与实施边界。
