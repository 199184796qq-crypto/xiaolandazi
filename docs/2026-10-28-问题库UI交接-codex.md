## 2. 目标界面

「指的是（可选）」不再全量下拉，改成三段式：

```
[规格与切块 ✓] [口味与口感] [链接与购买]   更多    不指定
排除词：[价格、多少钱、贵不贵、便宜、优惠、划算]   （自动填好，可改）
```

规则：

1. 用户填完「问题」输入框、失去焦点后请求推荐；
2. 只展示前 3 个推荐目的，默认选中匹配度最高的一个；
3. 选中后自动把该目的的建议排除词填进「排除词」输入框（若用户已手填则不覆盖）；
4. 点「更多」展开全量下拉（原下拉保留，作为兜底）；
5. 点「不指定」清空含义与排除词；
6. 没有任何推荐时只显示「更多」和「不指定」。

## 3. 接口契约（已上线）

### 3.1 目的推荐

```
GET /api/v1/rooms/{roomId}/purposes?q={问题原文}

{
  "plan_id": 4,
  "query": "可以砍吗",
  "suggestions": [
    {
      "key": "spec",
      "name": "规格与切块",
      "keywords": ["砍","切块","剁块"],
      "score": 2,
      "suggested_excludes": ["价格","多少钱","贵不贵","便宜","优惠","划算"],
      "in_out": false
    }
  ]
}
```

- 不传 `q`：返回 `items`（全量目的），用于「更多」下拉；
- 传 `q`：返回 `suggestions`，最多 3 条，按 `score` 降序；
- `suggestions` 为空数组表示没有匹配。

前端封装已存在：`getPlanPurposes(roomId, query?)`（`src/api.ts`）。

### 3.2 问题库读写

```
GET    /api/v1/rooms/{roomId}/question-library          → { items: Entry[] }
POST   /api/v1/rooms/{roomId}/question-library          → 新建
PUT    /api/v1/rooms/{roomId}/question-library?id={id}  → 更新
DELETE /api/v1/rooms/{roomId}/question-library?id={id}  → 删除
```

`Entry` / 保存载荷字段：

```ts
{
  id: number
  question_type: string   // pool_in_out | fact | yes_no | number | list | process | compare | unknown | social
  question: string        // 一行可写多个关键词，顿号分隔
  answer: string          // 允许为空（待回答）
  sense_key?: string      // 选中的目的 key，如 spec
  sense_name?: string     // 目的名称，如 规格与切块
  exclude_words?: string[] // 排除词数组
  status: string
}
```

## 4. 实现要求

1. 只在 `QuestionLibraryPanel.vue` 内改，不动其他组件；
2. 每一行数据必须有默认值：`suggestions: []`、`showAll: false`、`excludeText: ''`，避免渲染时读 undefined；
3. 模板里不要用 TypeScript 断言（如 `$event.target as HTMLSelectElement`），改用 `(e: Event)` 处理函数或 `v-model`；
4. 推荐请求要防抖（≥300ms）并丢弃过期响应（用请求序号），切换房间或卸载时作废；
5. 推荐接口失败时静默降级为「更多」下拉，不弹全局错误；
6. 保留现有能力：表格增删改、类型下拉、右键让模型判型、待回答标红、16px 正文 / 20px 标题、方案级共享；
7. 不要改动 `RoomReadingRules`、`InteractionRulesWorkspace`、`AnswerStrategyPanel` 等相邻组件。
