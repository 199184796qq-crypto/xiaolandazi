# 小蓝直播搭子：本地到生产发布与交付流程

## 1. 生产入口统一规则

- `https://www.xiaolandaizi.cn`
  - 电脑浏览器：`web-desktop`（现有电脑管理端）。
  - 手机浏览器：`web-customer`（客户手机端），未登录时进入客户登录页。
- `https://sales.xiaolandaizi.cn`
  - 销售人员专用入口：`web-sales`。
  - 不在客户页面展示入口。
  - Nginx 返回 `X-Robots-Tag: noindex, nofollow, noarchive`。
- 三个前端共用同一套 Management API 与 Core Audio，前端请求继续使用 `/api/` 和 `/core-audio/`。
- 客户手机端只接受 `customer` 角色；销售手机端只接受 `sales_staff` 角色，地址隔离不是权限边界。

## 2. 目录职责

- Git 仓库：`E:\直播伴播`
  - 只保存源码、脚本、配置模板、文档、任务资料。
- 本地产物：默认 `E:\直播伴播-local`
  - `releases/`：生产 release 目录与 tar.gz。
  - `backups/`：本地部署备份。
  - `archive/`：历史大文件、旧发布包、一次性产物。
- 生产服务器：`/opt/xiaolan`
  - `releases/<release-id>/`：不可变发布版本。
  - `current`：指向当前版本的符号链接。
  - `deployments/`：部署记录。
  - `/etc/xiaolan/*.env`：生产环境变量和密钥，不进入 release、不进入 Git。

## 3. Release 内容

`scripts/build-production-release.ps1` 生成：

- `bin/core-service`：Linux amd64 Core。
- `bin/management-service`：Linux amd64 Management。
- `collector-worker/`：worker 与 `playwright-core` 运行依赖。
- `web/`：兼容旧 Nginx 的电脑端目录。
- `web-desktop/`：电脑端。
- `web-customer/`：客户手机端。
- `web-sales/`：销售手机端。
- `VERSION` / `VERSION.json`：版本、Git SHA、构建时间、dirty 状态。

三个 Web 都有内部部署标记，生产冒烟测试会检查实际拿到的是不是正确端，而不只是检查 HTTP 200。

## 4. 本地质量门槛

正式发布默认执行：

1. Core：`go test ./...`
2. Management：`go test ./...`
3. 客户手机端：`pnpm --dir customer-mobile check`
4. 销售手机端：`pnpm --dir sales-mobile check`
5. 构建电脑端、客户手机端、销售手机端。
6. 交叉编译 Linux Core / Management。
7. 组装 Collector 运行依赖。
8. 打包 tar.gz 到 `E:\直播伴播-local\releases`。

正常生产发布要求 Git 工作区干净。仅测试发布可显式使用 `-AllowDirty`。

## 5. 一键发布

生产 SSH 参数可放在本机环境变量：

```powershell
$env:XIAOLAN_PROD_HOST = '47.114.55.117'
$env:XIAOLAN_PROD_USER = 'ecs-user'
$env:XIAOLAN_SSH_KEY = "$env:USERPROFILE\.ssh\xiaolan-ecs-deploy"
```

正式发布：

```powershell
.\scripts\publish-production.ps1
```

流程为：

1. 本地测试与构建。
2. 生成 release tar.gz。
3. SSH 鉴权预检。
4. SCP 上传 release 与部署脚本。
5. 服务端解压到新 `releases/<id>`。
6. 校验二进制、Collector、三个 Web 与部署标记。
7. 原子切换 `/opt/xiaolan/current`。
8. 重启 `xiaolan-core`、`xiaolan-management`。
9. 检查 8081/8080 `/healthz`。
10. 失败时自动切回上一版本。
11. 从公网检查电脑端、客户手机端、API、Core 代理、销售端。

在销售域名尚未启用期间，只允许临时测试使用：

```powershell
.\scripts\publish-production.ps1 -SkipSalesSmoke
```

正式交付不能跳过销售端冒烟测试。

## 6. Web 路由首次安装

模板：`deploy/nginx/xiaolan-sites.conf.template`

首次启用三端路由前必须满足：

1. `www.xiaolandaizi.cn` HTTPS 证书在服务器可用。
2. `sales.xiaolandaizi.cn` 已解析到生产 ECS。
3. 销售子域 HTTPS 证书在服务器可用（或使用覆盖该域名的通配符证书）。
4. 已通过 `nginx -T` 确认当前生产站点配置文件路径，避免和旧 server block 冲突。

安装命令：

```powershell
.\scripts\install-production-routing.ps1 `
  -MainCert /实际/主域名证书.pem `
  -MainKey /实际/主域名证书.key `
  -SalesCert /实际/销售域名证书.pem `
  -SalesKey /实际/销售域名证书.key `
  -TargetConfig /etc/nginx/conf.d/xiaolan-sites.conf
```

安装脚本会备份旧配置、运行 `nginx -t`，校验失败会恢复旧配置，不直接带病 reload。

### 销售子域一键启用

主域名的电脑/客户手机分流可以先独立上线。销售端只需要先在 DNS 增加：

```text
记录类型: A
主机记录: sales
记录值: 47.114.55.117
```

DNS 生效后运行：

```powershell
.\scripts\enable-sales-production.ps1
```

脚本会验证 `sales.xiaolandaizi.cn` 确实解析到生产 ECS，然后通过服务器现有 Certbot 账号申请 Let’s Encrypt 证书，安装销售端 HTTPS Nginx 配置，最后执行完整生产冒烟测试。证书续期后会自动 reload Nginx。

## 7. 上线测试

```powershell
.\scripts\test-production.ps1
```

必须同时满足：

- 电脑 UA 访问 `www` 得到 `desktop`。
- 手机 UA 访问 `www` 得到 `customer-mobile`。
- `/api/v1/system/public-config` 正常。
- `/core-audio/healthz` 正常。
- `sales.xiaolandaizi.cn` 得到 `sales-mobile`。
- 销售子域 API 正常。

除此之外，业务交付前仍需要实际账号完成：客户登录、销售登录、直播间读取、Agent 工作、TTS/音频播放等业务冒烟。

## 8. 生产状态与日志

查看当前版本、systemd 状态和健康检查：

```powershell
.\scripts\production-status.ps1
```

看 Core 日志：

```powershell
.\scripts\production-logs.ps1 -Service core -Lines 300
```

持续看 Core 日志：

```powershell
.\scripts\production-logs.ps1 -Service core -Follow
```

Management 同理使用 `-Service management`。

## 9. 一键回滚

回滚到上一发布版本：

```powershell
.\scripts\rollback-production.ps1
```

回滚到指定版本：

```powershell
.\scripts\rollback-production.ps1 -ReleaseId <release-id>
```

回滚后会重新启动 Core / Management 并执行健康检查。

## 10. 交付完成标准

一次生产交付只有同时满足以下条件才算完成：

- Git 版本可追溯，release 有明确 ID 与 SHA。
- Release 构建与质量门槛通过。
- Core / Management systemd 为 active。
- 8080 / 8081 健康检查通过。
- 电脑访问主域名得到电脑端。
- 手机访问主域名得到客户手机端。
- 销售专用域名得到销售手机端且不在客户侧公开入口。
- API 与 Core 音频代理通过。
- 关键业务账号完成实际登录与直播业务冒烟。
- 出现异常时可在数十秒内通过固定脚本切回上一 release。
