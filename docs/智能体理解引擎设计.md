# 智能体理解引擎设计

> 状态：已实施。2026-09-28 已完成理解引擎抽层、程序/大模型/AUTO 分流、分层配置、成本降级、权限隔离和主要回归测试。

## 1. 目标

把“用户自然语言理解”从业务执行链中独立抽成一层：**智能体理解引擎（Agent Understanding Engine）**。

这一层只负责把用户输入理解成统一结构化意图，不直接写数据库、不发布、不停用、不绕过权限。

统一链路：

`用户输入 -> 智能体理解引擎 -> Unified Intent -> Interaction State Machine -> 权限 Gate -> 确认 -> Command Executor -> 数据库/Core/审计`

下游业务不得依赖“前面是程序理解还是大模型理解”。

## 2. 两种正式理解模式

### 2.1 程序理解

适用于免费、低利润、欠费、测试或需要严格控制模型成本的客户。

特点：

- 不调用大模型，不产生大模型理解费用。
- 使用当前模块、直播间、方案、正式商品、活动福利、事实依据、话术参考、Pending Action、固定语法、实体匹配、状态机完成理解。
- 能确定就输出统一 Intent；不能确定就返回 `clarify`，不猜。

### 2.2 大模型理解

适用于有利润、高等级会员、内部高级场景或复杂自然语言场景。

特点：

- 使用大模型处理复杂上下文、指代、错别字、纠正、跨句语义。
- 只能输出与程序理解完全一致的 Unified Intent 协议。
- 大模型只有“理解权”，没有“执行权”。

## 3. 预留 AUTO 模式

底层预留第三种 `AUTO` 模式，但初期前台不一定开放。

逻辑：

`先程序理解 -> 置信度高则直接继续 -> 有歧义/复杂上下文时再调用大模型`

目标是在保持自然语言体验的同时降低模型调用成本。

## 4. 统一接口

建议抽象：

- `IntentInterpreter`
- `ProgramIntentInterpreter`
- `LLMIntentInterpreter`

统一返回至少包含：

- `kind`
- `intent`
- `target`
- `changes`
- `missing`
- `confidence`
- `reply`

Web、后台、客户手机端、销售端均只消费这一统一协议。

## 5. 后台配置

建议位置：`系统设定 -> 智能体配置 -> 智能体理解配置`。

配置层级：

`系统默认 -> 会员等级 -> 客户单独覆盖`

典型策略：

- 免费用户：程序理解
- 基础会员：程序理解
- 标准/高级会员：大模型理解
- 特殊客户：单独指定
- 内部测试账号：单独指定

大模型模式可配置：

- 模型供应商
- 模型名称
- 最大上下文
- 最大 Token
- 超时时间
- 月度理解预算
- 达到预算后的降级策略

## 6. 成本与客户状态联动

支持按客户经营状态自动选择理解方式：

- 正常付费且满足配置：大模型理解
- 会员过期：会员级别覆盖失效，重新继承系统默认
- 欠费/非合作：程序理解
- 恢复付费：按配置恢复大模型理解

预算达到上限后可配置：

- 自动切换程序理解
- 停止高级理解，仅保留程序理解

## 7. 权限原则

理解模式绝不能改变权限边界。

无论是程序理解还是大模型理解，最终都必须经过：

`Unified Intent -> 权限 Gate -> 确认 -> Command Executor 再鉴权`

大模型不能拥有额外权限，也不能直接调用写库接口绕过 Command Executor。

## 8. 实施约束

- 不再针对每句自然语言继续向业务页面堆大量 if/正则。
- 程序理解规则只能存在于理解引擎内部。
- 大模型 Prompt 只能负责语义理解和结构化输出。
- 商品、活动、事实、话术参考、方案等下游状态机必须共享同一 Interaction State Machine。
- 所有端统一复用该理解层，为后续手机端接入做准备。

## 9. 实施状态

已完成并进入代码：

1. `internal/agentunderstanding` 已抽象统一 `IntentInterpreter`、`UnifiedIntent`、PROGRAM / MODEL / AUTO 调度协议；
2. 直播策略已接入后端统一理解入口，商品链接、活动福利、事实依据、话术参考、方案绑定/切换共享同一结构化意图协议；
3. 后台智能体和终端智能体已接入同一理解策略，原有权限 Gate、确认卡和正式执行器保持在理解层之后；
4. 直播间学习/聊天/测试/采用意图分类已受同一理解策略控制，程序模式不会调用分类大模型；
5. 后台“智能体理解配置”已支持系统默认、会员等级、指定客户三级覆盖；
6. 已支持 PROGRAM、MODEL、AUTO 三种模式，并可配置供应商、模型、上下文、Token、超时、最低置信度和月度理解预算；
7. 会员无有效订阅时不再应用会员级别覆盖，而是重新继承系统默认；非合作客户、理解预算耗尽会自动降级 PROGRAM；恢复有效状态后按继承策略恢复；
8. Qwen 调用已记录输入/输出/总 Token，用于月度理解预算核算；
9. PROGRAM 不能可靠理解时只返回 `clarify`，图片在 PROGRAM 下不会猜测；MODEL 失败安全回退 PROGRAM；
10. 后端仍在解释前/执行前进行权限校验，大模型只拥有“理解权”，没有数据库写权限；
11. PROGRAM 已支持基于正式商品、活动、事实依据和当前方案的只读问答；例如“发什么快递”只读取正式事实，有值就回答，无值明确说明未确认且不猜；
12. PROGRAM 的事实维护支持自然口语定位，例如“快递改成圆通”会先匹配当前正式“快递方式”事实，再输出统一的 `fact.update`，仍需后续确认与执行器写入；
13. 已建立理解模式、商品/活动/事实/方案、只读事实问答、自然口语纠正、取消、歧义、后台导航/员工查询等回归测试，并纳入管理服务测试；
14. Web 只消费后端统一协议；后续手机端可直接复用同一 API 和权限/确认/执行链，不需要复制理解规则。

### 9.1 运行链路

`用户输入 -> Agent Understanding Engine -> Unified Intent -> 现有交互状态机 -> 权限 Gate -> 确认 -> Command Executor -> 数据库/Core/审计`

### 9.2 成本边界

PROGRAM 保证“理解层”不调用大模型。明确需要大模型生成内容的独立能力（例如完整直播稿生成）仍按其自身业务配置计费，不属于理解引擎成本。
