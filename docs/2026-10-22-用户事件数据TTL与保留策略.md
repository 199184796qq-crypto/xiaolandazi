# 用户事件数据 TTL 与保留策略（2026-10-22）

> 本文记录 2026-10-22 的生产数据清理、当前 TTL 机制，以及后续“消除事件”的重设计方向。
> 本次没有改业务二进制，没有重启 Management/Core；只做数据库清理和系统级定时任务。

## 1. 背景

排查发现 `live_room_event_archive` 累计 229 万行，其中：

```text
member       1,958,323
room           246,875
chat            39,640
like            35,013
follow          11,603
order_signal     2,407
session_*          132
```

实际弹幕只有约 4 万条，绝大多数是进房/房间事件。

结论：

- 这张表不是聊天记录表，是全量直播事件流水
- 包含 `user_id`、`nickname`、`content`、`payload_json`
- 原代码没有时间清理，历史记录在删除房间时也保留
- 需要 TTL，且后续要从“全量事件流水”改成“最小必要事件”

## 3. 当前自动 TTL

系统级 timer：

```text
xiaolan-purge-ttl48.timer
```

执行频率：

```text
每 10 分钟
```

cutoff：

```text
47 小时 50 分钟
```

目的：

```text
10 分钟执行间隔 + 47:50 cutoff
→ 任何数据最多约 48 小时
```

脚本：

```text
/opt/xiaolan/scripts/purge_ttl48.sh
```

日志：

```text
/var/log/xiaolan-purge-ttl48.log
```

覆盖表：

```text
live_room_event_archive
live_runtime_events
live_interaction_replays
live_generated_speech_history
live_session_speech_assets
live_model_exchanges
live_p0_audit_events
```

删除方式：

- 按时间字段批量删
- `live_room_event_archive` 每批 20,000
- `live_model_exchanges` 每批 1,000
- `live_p0_audit_events` 每批 500
- `flock` 防止两个清理任务重叠

新增索引：

```text
live_model_exchanges.created_at, id
live_p0_audit_events.created_at, id
live_room_event_archive.occurred_at, id
```

## 5. 仍然没有 TTL 的内容

### 用户/模型内容

- `live_model_exchanges`：已纳入 48 小时 TTL
- `live_p0_audit_events`：已纳入 48 小时 TTL

### 业务资产（不建议按用户事件 TTL）

- `live_plan_analysis_assets`
- `live_plan_content_observations`
- `live_plan_content_sets/jobs/tasks`
- `live_agent_plan_facts`
- `live_agent_plan_product_links`
- `live_agent_plan_benefits`

这些是方案资产，应按方案生命周期保留。

### 采纳后的记忆

`agent_memory_items` / `agent_memory_versions` 等可能长期保留“已采纳策略”，这是业务设计，不是原始事件流水。

## 6. 后续重设计：消除事件

### 6.1 目标

不要把所有事件都落成永久流水。

### 6.2 新链路

```text
采集
→ 瞬时事件流（Redis Stream / 内存队列）
→ 消费：互动 / 统计 / 聚类
→ 只落必要事件
→ 其余只保留聚合计数
```

### 6.3 事件分级

| 事件 | 处理 |
|---|---|
| chat / order / follow | 落库，48 小时内可追溯 |
| member / room / like | 不落原始行，只聚合计数 |
| session_start/end | 只留会话摘要 |
| model_exchange / p0_audit | 48 小时，必要时只留摘要/哈希 |
| 语音音频 | 对象存储短期生命周期，数据库不长期保留 |

### 6.4 用户标识

- `user_id` / `nickname` 只在 48 小时内保留
- 超过后只保留哈希或聚合维度
- 不做跨场长期用户画像，除非单独授权

### 6.5 验收

```text
48 小时后：
- 无原始 member/room 行
- 无原始 chat 行
- 无未脱敏 user_id/nickname
- 聚合计数仍可用于复盘
```
