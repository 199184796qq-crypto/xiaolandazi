# 互动话术「半省规划」改造：让规划消费意图分析的角度

日期：2026-10-20

## 背景

互动话术三步链：意图分析（interaction_purpose_resolution，~3018 token）→ 规划（interaction_agent_plan，~7866 token，0 缓存）→ 回答（interaction_agent_answer，~8726 token）。

查证生产数据发现：意图分析已经算出「目的 + task_angles（角度 + 关联事实 fact_ids）」，但规划步骤又把「判目的 + 列角度」**重新做了一遍**（同 room 29 问题「是否含鸳鸯锅」id 25940 意图 vs 25941 规划铁证），纯浪费。规划的 basis 就是把事实包原文照抄，摘事实这步程序按 fact_id 抽即可。

## 改造目标（半省，非全删）

让规划消费意图分析已算出的 `task_angles`，规划从「全盲重判目的+列角度」退化成「在意图给的角度里选一个 + 补 basis/avoid/requirements」。**保留规划兜底**：当意图分析的 task_angles 为空时（关联事实为空、purpose_id 识别失败等），规划回退到原来的自行判断路径。

## 数据流（摸清结论）

1. core 服务 `paidpipeline/purpose_resolution.go` 调 management 的 `POST /internal/v1/interaction-purpose/resolve`，拿到 `knowledge`（含 task_angles）。
2. core 把 `purpose_id` + `purpose_knowledge` 填进 decision 的 item，通过 `claimResponse.Item` 传给 management。
3. management 的 `decisionItem.PurposeID` / `PurposeKnowledge` 字段接收（json 标签 `purpose_id` / `purpose_knowledge`）。
4. **此前**：decisionexecutor 里 `PurposeID` 只在 `interaction_facts.go:181` 被读做选材过滤；`PurposeKnowledge` 完全没人读。
5. **本次改动**：`planInteractionAnswer` 解析 `PurposeKnowledge` 的 `task_angles` → 存入 `decisionItem.IntentAngles` → `answerPrompt` BusinessPlanning 分支把它作为 `intent_angles` 传给模型。

## 改动清单

1. `management-service/internal/decisionexecutor/worker.go`
   - `decisionItem` 新增字段 `IntentAngles []contentstrategy.Row`（`json:"-"`，不序列化）。
   - `answerPrompt` BusinessPlanning 分支的 data 里新增 `"intent_angles": item.IntentAngles`。

2. `management-service/internal/decisionexecutor/interaction_agent.go`
   - 新增 `intentTaskAngles(knowledge json.RawMessage) []contentstrategy.Row`：解析 `task_angles`。
   - `planInteractionAnswer` 开头 `item.IntentAngles = intentTaskAngles(item.PurposeKnowledge)`。

3. `configs/prompts/anchor-style/interaction-agent-plan.md`
   - 母版重写为「第一步优先消费 intent_angles（不重新判断目的），intent_angles 空时才回退自行判断」。

## 验证

- `go build ./internal/decisionexecutor/` 通过。
- 临时单测验证 `intentTaskAngles` 能正确解析生产真实 task_angles 样例（中文键 `目的编号/角度/讲述任务/关联事实/优先级/任务类型/采用条件` → `contentstrategy.Row`），2 角度 + fact_ids F010/F011 解析正确；空/非法输入返回 nil/空。

## 待办 / 未部署

- 母版 `interaction-agent-plan.md` 改动需重建 MANIFEST 哈希后，走生产就地增量发布（参考部署真相：生产母版≠git 母版，生产是真相，就地改+就地重建哈希）。
- 代码改动需重新编译 management-service 并部署（走 Codex 增量链或手动发布）。
- 部署后需验证：意图分析有 task_angles 时，规划 input token 是否下降（预期从 7866 降到几千，因为不再重复判目的+列角度，且 basis 可复用意图的关联事实）。

## 风险点（查证已定位）

1. 意图分析的 `task_angles.关联事实` 经常是空 `[]`（事实包里无对应信息时）。空时规划回退自行判断，安全。
2. 意图分析的 `purpose_id` 命中率不高（8 条样本里 3 条有 P02/P04，其余空）。空 purpose_id 时 task_angles 可能仍非空（25940 就是），此时规划仍能消费角度。
3. 意图输出字段是中文键，与 `contentstrategy.Row` 完全同源，能直接 `json.Unmarshal` 打通（已验证）。
