# 资料对象归属与多链接关系

用户已确认：只用全局、独立链接、门店/商家三类对象；服务作为可关联多链接的属性。待归属是人工处理区。

## 对象与适用范围

| 类型 | 身份 | 适用方式 |
|---|---|---|
| 全局 | 当前方案 | 当前及以后加入该方案的全部链接共同适用 |
| 独立链接 | 方案内真实商品卡/卡券卡 ID | 每张卡独立，即使商品名或卡券类型相同 |
| 门店/商家 | 当前方案内具体名称 | 显式关联多个真实链接，门店属性随关系适用 |

王家店可关联1、2号卡，李家店可关联3、4号卡。切块、上门服务等保留为属性，可多选任意具体链接或门店，不创建第四类服务对象。一个链接可同时享有本链接、全局和对应门店的属性；同一属性在列表只显示一次。门店未关联链接时只归该门店，不能扩散到全部。

## 操作与界面

移除示例、清空草稿按钮以及模型/费用和原文覆盖大块提示；保留逐条条件、风险、原文与错误信息。树按全部、全局、商品/卡券链接、门店/商家、待归属展示，勾选框18×18，不受父页全局输入框宽高影响。

每条属性直接展开下拉多选，提供搜索、已选数量和确认；取消或操作失败保留原记录。全局与指定对象互斥。库中改变归属走原完整更新接口，更新同一条记录和向量，不复制成多条。草稿中改变归属只保存本机草稿。明确的共同声明保留一份正文与多个对象，限定包装/规格等不同属性另行拆分。

“门店关联”在当前内容区展开，可添加具体商家、勾选多个卡片并保存；采用版本号防覆盖。仍被资料引用的门店不能直接删除，须先重新分配其属性。门店关联修改不调用模型，也不修改原向量正文。

## 分析、数据库与向量

原审核模型的既有分析请求增加紧凑的当前方案对象目录（真实卡ID/编号/商品名、已保存门店关系）和三类归属契约，不新增模型步骤。模型返回 object_targets 数组。找不到唯一卡片、指代不明、归属不确定的内容进入待归属，不能当全局；未绑定实际卡片的商品、规格、卡券类旧对象也进入待归属。泛称“本直播间、线下门店”不制造具体门店。

单条属性的多个目标与条件等保存在既有 details_json，保留原文、例外与标准值。只有用户明确确认入库或修改库中资料才按原流程调用服务端真实Qwen向量模型，一条属性对应一份向量文档。关联编辑只改变适用关系，不重复购买向量；确认/库中重新归属的向量费用仍按实际调用计费。

新增 live_agent_plan_material_objects（tenant_id、plan_id、revision、stores_json、updated_at），以租户/方案为联合主键；没有自动初始门店或客户数据回填。GET/PUT material-objects 与原导入采用同一租户/方案鉴权。写入与资料确认/完整更新使用同一方案行锁，引用检查和版本比较在事务内完成。

旧记录仅在读取响应中做兼容呈现，不批量改写旧正文、归属、向量或直播正式事实。编号只作显示和旧输入兼容，必须唯一解析到本方案实际卡ID，不把1号链接当数据库ID=1。
