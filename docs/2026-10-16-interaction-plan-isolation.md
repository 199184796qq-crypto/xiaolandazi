# 互动规则与当前方案隔离

用户切到“巴国布衣本地生活”后仍看到杨鸭子的回答策略。生产只读核对确认：杨鸭子为方案4，巴国布衣为方案5；房间26有方案4的已绑定策略及无方案归属的旧记忆，没有方案5的策略。未删除或迁移任何业务数据。

## 原因与处理

- LiveStrategyView原回答策略查询只传roomId，后台agent-memories返回该直播间全部有效记忆；前端只筛选类型，没有筛选当前方案，也没有在方案切换时重新加载。原修改预览未传plan_id，会回退到房间绑定方案。
- 列表显式传plan_id，服务端验证当前租户及有效方案，使用与生成一致的严格归属过滤。旧客户端未传方案时只读取房间绑定方案；无绑定返回空列表。未绑定的旧记忆保留，不能自动归到任意方案。
- 新增usePlanAnswerStrategies，在租户、房间、方案、账号切换时同步清空；请求序号处理同方案来回切换及迟到结果，失败明确显示并允许重试。前端同时验证返回记录的归属和活动状态。
- 修改会话显式绑定当前方案；修改、采用、删除异步回执按编辑轮次及完整范围校验，切换后不能显示旧预览或继续下一步请求。删除、版本查询/回滚及纠正来源在后台校验所属方案，不能借其他方案的ID修改其策略；回滚不能将策略版本的归属改到另一个方案。
- 模拟挖掘、直播互动和处理历史原有plan_id列表范围及切换丢弃逻辑保留，纠正模型输入改用严格方案过滤，防止旧无归属记忆影响新纠正。
- 实际直播回答、衔接语、场控和模拟挖掘本来就使用GenerationMemories按租户+房间+方案过滤；保持该边界，并拒绝记忆键和结构归属相矛盾的记录。此次不修改模型、P0或提示词、不启动模型/TTS/直播。
- 回答策略组件新增状态与修改文字最小16px，四种屏宽验证无水平溢出。WorkBuddy业务模式/行业代码及配置不改，原开发目录只读。
