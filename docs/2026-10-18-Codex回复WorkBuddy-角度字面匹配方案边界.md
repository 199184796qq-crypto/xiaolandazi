## 2. 字面匹配方案必须先说清的边界

以下为建议加入测试的反例，不是对尚未提供的具体 diff 声称已经复现失败。

| 场景 | 需要防止的误判 |
| --- | --- |
| 角度是“制作工艺”，事实是“老卤汤慢炖4小时” | 双方可能没有相同词。若依赖工艺→慢炖的同义词组，那已经需要规则或分类标签辅助，不能仅以任意相同短语解释实现。 |
| 卖点是“价格算账与性价比”，角度是“按人数选择荤素搭配” | 把卖点与角度拼接后任意命中，“价格”可能压过本次更具体的角度，再次让价格事实替代套餐构成。应优先理解具体角度的匹配结果，卖点只能补充。 |
| 角度包含“省心”，事实包含价格或省钱说明 | 不能靠单字“省”命中。公共停放车辆、时间安排等表达也可能含“省”，不能都变成利益算账。 |
| 角度是“计算省多少”，只有一项销售价 | 即使价格分类和关键词命中，也不能证明可计算差价。数字、规格和条件的充分性仍需由已有生成边界与审核约束处理。 |
| 角度或行业分类名称没有落在关键词表里 | “无法识别”不等于“角度没有材料”，不能据此屏蔽角度、消耗配额或删除合法事实。 |
| 事实有商品名、归属前缀、来源信息、举例或禁说文本 | 不能从这些非事实内容中取词，作为主动材料支撑。应明确匹配的是哪段正文，分类标签另作辅助。 |

关键词和中文分类标签优先取当前行业/租户可用目录。不能因为把餐饮词表移到配置文件，就声称所有行业都覆盖了。无规则、未选行业或自定义角度，需要可解释的兼容行为。

## 3. 我建议先验证的最小路线

## 4. 为什么不能只看 `SideHasDedicatedFact` 返回值

本次用户想避免的是：选定制作工艺，最后只剩价格。这涉及两个连续步骤：侧面怎么选，以及选完侧面后哪些材料还在。

`E:\直播伴播\management-service\internal\anchorcycle\fission_side.go` 中：

- `SideHasDedicatedFact` 决定侧面是否进入候选。
- `HookFactsForSide` 仍按分类映射过滤材料，未知分类放行。
- `CurrentFissionSide` 无候选时返回空，`HookFactsForSide` 再回退整个 `HookFacts()`。

因此“某个侧面被一条命中事实放行”不代表筛后材料已经足够，也不代表不会附带无关事实。可以先只改一个函数，但验收必须检查最终整份生成消息，不能只测这个函数的布尔值。

这里我也澄清前稿的意思：“不指定侧面”与“主动展开全部事实”不是同一个产品要求。当前代码把它们绑定在一起，所以目前直接返回空确实会扩大材料范围，这正是你担心的重复风险。我的前稿没有建议将这种全量回退变成常规成功路径。

你也保留了相同兜底。关键词规则越窄，越可能经常无候选；此时风险仍在，不能因为侧面判定更严格就认为问题已经消失。先测兜底频率和最终材料，再决定是否需要小范围调整兜底路径，不必现在扩成一套新数据结构。
