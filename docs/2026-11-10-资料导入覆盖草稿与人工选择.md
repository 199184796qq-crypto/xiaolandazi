# 资料导入：新草稿覆盖、手动选择与清除

“分析”后依次显示“清除草稿”“清除库中数据”。清除草稿只清浏览器中当前账号/方案的草稿，粘贴原文保留。清除库中数据先刷新并显示当前方案实际条数，明确确认后清除该方案资料库的有效记录及同记录中的向量；草稿、商品卡、门店关系、正式事实及直播快照保持。

每次分析成功，以本次有效结果整体替换旧草稿，去掉旧的追加/覆盖选择。网络或分析失败、无有效结果时保留原草稿；跨方案迟到结果丢弃。已有浏览器草稿仍可恢复，但下一次分析成功即替换。

确认入库前刷新库并保存比较快照。本次未与库中匹配的属性显示为直接追加；匹配到的属性分组展示“本次草稿”和“库中已有”，同时显示归属、条件、例外，必须逐组选择“替换为本次草稿”或“保留库中的”，不预选。替换明确显示将移除的旧记录数量及最终采用的新归属；保留不修改旧记录、对应本次草稿不入库。新属性与选中的替换项一起确认。未选择的草稿、待归属和未核对的条件仍保留。草稿内部重复继续先由“重复属性”对比处理，不自动合并矛盾值。

匹配与现有重复属性逻辑对齐：分类/属性相同、条件/例外相同，适用范围重叠或正文标准值相同时为候选。独立卡不同价格和不同条件规则独立。一个旧多对象记录对应多个新对象时，作为同一组选择，防止一边保留、一边删除同一旧记录。服务端重新计算匹配，不信任客户端 replaces_id 或无选择的自动替换。

GET material-claims 新增 library_revision，按原始有效记录稳定散列。POST commit-import 使用全库快照和门店关系版本，付费向量前检查，方案锁和资料行锁内再次检查；新记录及显式替换原子提交。仅保留库中内容时不请求向量；新记录/替换记录沿现有 Qwen 接口生成，没有新增分析模型步骤。向量失败或并发更改导致整批不采用，原草稿和库记录保留。POST clear 同样需要全库快照；确认后出现新资料或被修改时拒绝，避免清除未见到的数据。清除不会对原有正式事实或其它方案执行删除。

验证使用本机 Vue + 模拟接口及实际隔离 MySQL，覆盖原界面归属/编辑/重复处理、无默认选择、追加/保留/替换、取消/失败、并发快照、范围隔离与失败回滚。没有调用真实付费模型、写入生产商户资料或以模拟用例冒认生产登录实操。
