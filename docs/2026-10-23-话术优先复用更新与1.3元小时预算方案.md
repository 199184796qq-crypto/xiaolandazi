# 话术优先：文章复用、局部更新与1.3元/小时预算方案

日期：2026-10-23。保存版本：v1.0。状态：已保存的当前评审稿，供用户与 DeepSeek 评审；未实施或部署。

保存依据：本聊天确认以话术优先为主、首场允许原文原句参与、模型与TTS合计预算上限1.3元/直播小时。后续实施以本稿为评审依据；保存不代表业务已落地或成本已通过实测验收。

## 1. 按本轮最新要求收敛范围

- 主要解决**话术优先模式**，不把实时主线轮盘或互动业务一并重构。
- 允许1—20篇文章，每篇正文最多3000字，总正文最多60000字。
- **首场允许原文原句参与播放**，不要求文章先润色四轮才有可复用库存。
- 用户把原先约1元目标调整为**每个直播小时模型与TTS合计不超过1.3元**。
- 互动仍占同一直播间的总费用，因此即使本次主要改话术优先，也不能把互动TTS从成本表里漏掉。
- 本稿只做方案和纯算术验证，不修改客户文章、事实、方案、提示词、队列或业务源码，不开播、不调用真实模型/TTS。

推荐方案是：**原文作为基础版本，文章按语义组管理；先选已有成品，只有内容确实需要变化且预算允许时，才局部润色并制作新声音。** 复用比例是预算和库存产生的结果，不用两个概率相乘控制。

## 2. 先把费用边界算明白

### 2.1 单价与计算口径

TTS使用用户给定的价格：

`1.6元 / 10000汉字 = 0.00016元 / 字`。

供应商实际若对英文、数字、标点或规范化文本有其它计费规则，最终以其计费字符和账单为准。本稿的字数是预算近似，实施时应校准，不能用音频时长代替计费字符。

Qwen3.7 Flash官方北京地域、单次输入不超过32K tokens的目录价：输入0.2元/百万tokens，输出0.8元/百万tokens；输入缓存命中0.04元/百万tokens。超过32K会进入更贵档位。来源：[阿里云官方模型价格](https://help.aliyun.com/zh/model-studio/qwen3-7-flash)。日期为2026-10-23，不将免费额度、活动折扣或供应商输入缓存命中当作预算必备条件。

统一费用公式：

```text
本小时成本 = 全部新TTS计费字数 × 0.00016
           + 全部文字模型实际token成本
           + 本次约定纳入的其它可变费用

新TTS包括：原句首次制声、润色新声、互动、开场、承接桥、重试、已制备但未播声音。
```

基础设施固定费、OSS和公网流量没有本轮单价与账单，本稿不承诺它们也包含在1.3元里。若要求含这些费用，先从1.3元扣除实测分摊，再计算可用模型/TTS预算，不能当作免费。

### 2.2 推荐共享预算

| 用途 | 日常目标额度/小时 | 控制方式 |
| --- | ---: | --- |
| 全部新TTS | 1.10元 | 主线、互动、首开、承接共用，约6875个新计费字 |
| 全部文字模型 | 0.10元 | 只是初始目标，使用实际token结算；不能当成已证明的固定费用 |
| 机动余量 | 0.10元 | 必要重试、事实变化、价格或计费误差等；动用前仍检查总账 |
| 合计硬边界 | **1.30元** | 同房间跨场次、跨进程统一约束，重开不重置过去一小时花费 |

主线和互动不分成互不相干的死预算。互动少时，主线可多制作；互动多时，减少可选润色与新声，保留必要回答和安全更新。不是1.10元主线之外再另算互动。

例如互动及桥本小时已花0.55元，正常TTS额度剩0.55元，对应约3437个主线新字；不是仍让主线生成6875字。

### 2.3 用本场首小时校准量级

只读475场，北京时间08:54:04.467—09:54:04.467：

- 在1.10元共享TTS目标内，按这组互动量粗算，主线还可新制备约3469字。

证据位于 `E:/直播伴播-local/reuse-budget-design-20261023/session475-first-hour-text-tokens.json` 和 `session475-first-hour-calibration.json`。不能把本文预算估计写成客户实付账单。

## 3. 文章规模不能直接决定每小时费用

| 正文规模 | 全部制一版声音的TTS费 | 是否适合首次直接全量制作 |
| --- | ---: | --- |
| 1篇3000字 | 0.48元 | 可在预算内分段按需制作，仍要给互动留额度 |
| 5篇各3000字 | 2.40元 | 不适合都塞进首小时1.3元 |
| 20篇各3000字 | 9.60元 | 应渐进建库或另列初始化费用 |
| 20篇各3000字、每篇4版 | 38.40元 | 不采用这种强制预生成方案 |

这是纯TTS费，未算模型与必要重试。60000字按220字/分钟约需4.55小时播放；即使完全使用原句，若全部没有已有声音，这段首次全覆盖的TTS平均仍是2.112元/口播小时，超过1.3元总目标。

**原句能省润色，不能使首次制声免费。** 高达90%的音频复用也不表示观众每小时听到90%的重复内容：以前已制作、今天第一次播放的声音同样属于缓存复用。

## 4. 文章、语义组、文字版本、音频版本分开管理

```text
方案
  └─ 文章（稳定article_id，标题、顺序、钉住位置、原文版本）
       └─ 语义组（稳定group_id，原文范围、上下文、事实依赖）
            ├─ 文字版本：原文A / 润色B / 润色C
            └─ 各文字版本的音频成品：音色、语速、情感、PCM、字幕及合法边界
```

### 文章与分组

- 3000字是编辑和保存上限，不是一次模型调用或一次TTS的大小。
- 默认尊重用户文章顺序、钉住位置与篇内段落关系，不随机打散句子，不把结论放到条件前面。
- 一个润色语义组建议约100—220字，随语义伸缩；价格与限制、问答、因果和代词承接不能为了凑字数拆开。
- TTS可将一个组编译成数个较短的完整句片。使用真实PCM建立时间轴，不按字数估计切点；组中未说完的价格条件限制互动插入位置。
- ID和绑定由程序维护，模型只负责当前组的内容。不能让模型维护文章索引或把别篇样例当成本篇事实。

### 版本数

- 原文A是正式的一种来源类型，不是“润色失败”的别名。
- 默认先有A；确实会反复用到的热点组逐步补B，再按实际重复需要补C。
- 初始上限建议每组3个有效文字/声音版本；极短、高频文章可按预算扩展到4个。它们是容量上限，不是每组必须凑齐的制作目标。
- 长文章库存足够时保留1版也可以；不按“命中6次就淘汰”强迫付费，优先淘汰失效、长期不用或低质量版本。
- 文字可比声音多留一些；声音只为近期确实会选用的版本生成。按租户/房间/方案隔离，可跨本方案后续场次复用有效成品。

## 5. 首场与冷启动的明确行为

### 已有原始声音

只有当前声音模式允许、且当前标签确实关联了可用原音和字幕，才直接使用。选择AI声音时不能为了省钱偷偷换成上传人的原声。音色不一致的录音也不能无提示混入主线。

### 只有文章文字

首场允许原句A进入现行适用的校验，不先强制润色。原句通过后直接按需TTS，完整成品入库；这会减少润色调用和误改事实，但首次TTS仍计费。

文章有需处理的规则/事实问题时，走局部修正或暂停该组，不能以“用户原文”为由绕过现行P0与事实边界。无问题的其它组继续供料。

先制作未来约45—90秒的有效供料，不在开播前把20篇或四套版本全部做完。**话术优先首篇即使标题是“开场”，也允许原句A参与，本设计不自动追加一段实时轮盘开场。** 用户另行明确要求的独立实时首开作为单独片段生成并计费，不扩展成整篇文章必须改写；实时主线模式原有首开规则不在本次修改范围。

### 两种可选的冷启动约束

| 选择 | 行为和代价 |
| --- | --- |
| 从首小时起严格控制1.3元 | 小窗口建声库，原句先入库；同小时允许重用已制作的部分，尚无声音的文章逐步覆盖。不能同时保证首小时60分钟全是未听过的新内容 |
| 另列一次性初始化费用 | 可以先为准备使用的文章制作基础声音，日常小时再受1.3元控制；9.6元全库初始化必须明确列出，不能隐藏或仅用摊销数字代替当天现金支出 |

默认按第一种设计，不擅自发生初始化付费。实际若已有长期有效库，就不需要再付全量初始化费。新音色、全量事实更新等会造成新的部分冷启动，不能假装永久只付一次。

## 6. 一次决定“复用还是更新”

调度发生在“当前文章语义组的这次播放机会”，只作一次决定：

```text
1. 核对文章、事实、规则及音色依赖
2. 读取有效成品，检查最近选用/实际开始记录
3. 有合适版本且不需更新 → 直接选成品，不调用润色或TTS
4. 缺声音/事实改变/重复过近/需要新表达 → 检查优先级与总预算
5a. 文字仍有效，只缺声音/只换语速音色 → 直接用批准文字制作声音，不调用润色
5b. 事实或文字需要变化/本次决定新表达 → 四层任务只改本组 → 验收 → TTS → 完整成品
6. 这次已决定更新且成功 → 锁定新成品用于本次供料
7. 失败或预算不足 → 可用的旧成品/其它有效组，记录延期原因
```

不允许两个旧行为：

- 先选30%更新，再对这30%抽70%缓存，最终把新生压到约9%。
- 刚付费生成新声音，再从四个历史版本随机选一个，使新声音当次只有约1/4机会被用到。

同一组、同一文字/事实/音色成品的并发任务用幂等键合并。新声生成只服务近期45—90秒供料，避免提前制作几篇后用户停播造成大量未播支出。

## 7. 如何减少重复感

推荐把“70%复用、30%更新”降为**暖库主线的参考目标**；在1.3元预算内按以下条件调节，而非强制每轮达标：

| 当前可用成品能覆盖的不同内容时长 | 初始更新倾向 | 原因 |
| --- | --- | --- |
| 超过60分钟 | 5%—15% | 有很多今天尚未讲过的库存，不必为换词付费 |
| 20—60分钟 | 15%—25% | 逐步更新下一次将重现的重点组 |
| 少于20分钟 | 25%—30% | 短文重现快，优先更新观众容易记住的部分；预算不足会降低 |

以上是建议初值，不是实际效果验证或每小时承诺。比例按本次主线预计口播字量/时长规划，费用仍按新计费字符控制，不能用片段个数代替。

具体做法：

1. 下一次轮到同一篇时，优先选择最近没用过的**有效已有版本**，不急着生成。
2. 需要更新时，轮换选择完整语义组，避免总改第一段、其它段永久不变；有前后关系的组一起维护衔接。
3. 同一事实可以换说法、节奏和合理衔接，不能新增商品事实、承诺或虚构实时观众行为。
4. 在库存允许时，偏好同一声音至少间隔约15—20分钟；短文库存不足可放宽并记录，不能死等或无限请求模型。
5. 不删“虽然重复但仍有效”的声音强迫重制，也不把文章重排当成全库内容变化。
6. 一篇100—300字的材料没有足够信息支撑长期不重复。同义改写只增加表达版本，不能凭空增加事实内容；应给运营“可用内容不足”的提示，而不是编故事。

例如一篇3000字反复讲，初始A不必全部替换成B。可在下一轮对少量连贯段落补B，后续换另一批组，逐步形成A/B/C组合；文章逻辑仍保持原样，不拼接互相矛盾的版本。

## 8. 预算账本与优先级

### 总账

- 按房间记录模型与TTS的**已花费＋已预留＋结果待核对**，并有账号总账；并发实例不能各自认为额度还有1.3元。
- 默认按累计有效直播时间轴的滚动60分钟约束1.3元，暂停/停播时该时间轴不前进，待机不积攒额度；同时记录真实请求时间以便对账。跨场延续同一房间账本，重开不能再领一份启动额度。
- 首个未满60分钟的窗口也最多预支首小时1.3元，可有有限启动突发。开播5分钟花0.3元只是首小时花费，不能据此宣称这个5分钟短场折算后也小于1.3元/小时。面板分别展示总花费、完整有效小时均价及未满小时花费；若商业要求逐分钟同比例封顶，应改为更严格的线性发放，冷启动首出声与库存建立会更受限制。
- 每次请求前预留保守上界：TTS按即将实际发送的计费文本，模型按输入和输出上限/实际计费档位。请求结束再结算差额。
- 超时或回执不明不直接退钱；仅确认未发送或未计费才返还，避免重复调用导致超支。
- 以约1.20元为正常目标、1.30元为总上界；当下一笔会超过预算时，先取消可选润色/备用声音，不取消必需的事实和规则检查。

### 费用紧张时的顺序

1. 先停止制作不在近期播放窗口的备用版本。
2. 减少主线纯表达更新，使用有效已有声音。
3. 合并合理的欢迎/感谢，避免对每个普通事件分别长篇生成；这需要沿用互动本身的业务准入，不能在本次顺手改掉回答流程。
4. 事实变化、重要问题及必要安全处理优先占用剩余额度。回答尽量短而有信息，不用无依据承诺凑“真人感”。
5. 若互动本身或强制更新已超1.3元可承载量，明确提示预算不足、需增额或限制相关内容；不能同时承诺无限互动、即时更新、完全不重复和固定低价。

## 9. 事实与声音变化如何失效

缓存依赖至少包括：

```text
文字依赖 = 稳定语义组 + 当前原文内容 + 相关事实/条件 + 生效规则 + 风格/润色合同
音频依赖 = 最终批准正文 + 实际音色/模型 + 语速 + 情感/指令 + 合成/时间轴规则
```

- 改价格、日期、适用范围等：立即禁止受影响旧版本再次选用，重新确认对应文字与声音；相关依赖不明确时扩大失效范围。
- 失效覆盖在途生成和Core中已排队未开始的供料。每次生成结束、入库、提交及开始前复核事实/文章代际；旧代际结果不再发布，已排队的受影响内容条件撤回或替换。已开始组在合法边界处理，不能追溯撤回已经说出的内容，也不能切断价格条件留下错误半句。现有Core若缺少按代际撤回能力，须补齐协议后才能宣称实现端到端失效，不能只改缓存键。
- 改一篇中的一段：更新该段和有必要的上下文依赖，不让20篇全失效。
- 改语速/音色：文字仍有效，受影响声音按需重制，不重写文章；新旧声音不能无提示混用。
- 重排/钉住文章：仅更新播放序列，保持正文和声音缓存。
- 新事实没钱立刻制声：跳过失效组，先用其它仍有效内容；不能为省钱继续播过期价格。无有效内容时提示运营处理。

缓存保留音轨ID、PCM/字幕和审批依赖，取用时重新签URL；不把临时签名URL当成永久缓存身份。预算检查不替代P0报告、事实验证或Core边界校验。

## 10. 成本推演：为什么1.3元可行但不应锁死更新比例

下表为纯算术场景，假设互动文本均新TTS，模型0.10元/小时；总口播量包含互动占用，主线目标更新其余正文的30%。不含固定服务器/带宽费用，也不是已上线实测；表中没有额外重试或生成未播浪费。独立首开若没包含在主线新字里，也要另扣总预算余量。

| 全部口播字量/小时 | 互动及桥新字 | 主线口播字量 | 主线30%新字 | 全部TTS费 | 加0.10元模型后 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 13200 | 600 | 12600 | 3780 | 0.7008 | 0.8008 |
| 13200 | 1800 | 11400 | 3420 | 0.8352 | 0.9352 |
| 13200 | 3406 | 9794 | 2938.2 | 1.0151 | 1.1151 |
| 15600 | 3406 | 12194 | 3658.2 | 1.1303 | 1.2303 |
| 13200 | 6000 | 7200 | 2160 | 1.3056 | 1.4056，需降更新或限制费用 |

第四行虽然总额仍低于1.3，但超过1.10元常规TTS目标，可少量用机动或把主线更新降到约28.4%；第五行不能机械坚持30%。实际请求必须按整组字数预留，不能合成小数个字。

首场完全冷库、只用原句也需要逐步建立成品。以220字/分钟、整小时13200字为例，1.10元最多付6875新字，剩余部分需要已有声音；没有已上传/预制库存时，只能逐步复用本小时已制备部分，或另付初始化费用。不能把“原句参与”误算成零TTS成本。

## 11. 适配现系统的实施顺序与验收

### 第一批：堵住重复花费

- 内容调度只改话术优先的活跃producer入口；复用/更新决策移到预润色之前，不重构实时轮盘或互动回答业务。
- 加原文基础版状态，区别“原文可用”“有效润色”“请求失败回退”。
- 正确核对P0报告Passed和最终批准正文，不能把检查函数返回nil当成审核通过；数字/单位/价格条件及语义完整性独立核对。具体旧缺陷见[润色输入与缓存供料修正建议](E:/直播伴播/docs/2026-10-22-给DeepSeek-润色输入与缓存供料修正建议.md)，预算不足不能成为放宽准入的理由。
- 选更新成功后直接选新成品，不再随机选回旧历史。
- 在共享模型/TTS调用边界接入统一请求预留/结算、稳定幂等键及预算拦截，覆盖互动、首开、桥和取消不明回执。只限制producer却让互动独立付费不能保证房间1.3元总额；本地缓存读取、免费本地检查也不能误记成付费调用。

### 第二批：增量多版本与失效

- 按文章/语义组持久保存A/B/C成品及多片音轨，跨场恢复；删除强制四轮铺库与按次数硬淘汰。
- 事实、风格与音色依赖分层；兼容现有有效缓存，不批量把未知旧稿改成“已审核/已润色”。
- 保留文章顺序和钉住规则，先做热点组版本轮换，不把句子乱序当成防重复。

### 第三批：自适应更新与运营反馈

- 根据有效库存时长、最近重复、互动实际花费和剩余预算选择更新组。
- 低库存、预算不足和事实失效在运营页用中文说明；不要把内部代码或费用估算伪装成供应商账单。

最小验收清单：

1. 1、5、20篇；每篇100、3000字；空库/暖库/跨场恢复均覆盖。
2. 首场原句能直接成为基础版本；没有原声时确实计入TTS，AI声音模式不偷偷换原声。
3. 选择复用时模型调用和TTS调用都为0；选择更新时新版本当次被锁定使用。
4. 模拟低/高互动、180/220/260字速、重试、取消和回执不明，已花＋预留始终满足预算合同。
5. 事实变化及时禁用旧音频，单段修改/重排/语速变化失效范围正确。
6. 价格条件和引号/换行等分组案例正确；一组多音轨缓存可跨场恢复，不假造切点。
7. 第一窗口不等待整篇/全库完成；组失败不静默漏掉必要条件，也不无限付费重试。
8. 至少做1、4、24小时的离线费用推演及受控上线核对。纯算术通过不表示真实TTS账单、听感或平台效果已验证。

最终统计应同时显示：已花费用、已预留、预算余量、新生成字数/声音数、实际选中更新次数、按声音时长和字量的复用率、短时间重复次数、过期成品拒用、生成未播成本。不能继续用“供料数减新制备数”的下限替代新架构应有的精确来源记录。

设计结论：**话术优先以原句建基础库、逐段补版本、按预算只生成本次需要的声音。1.3元约束的是实际付费请求，70/30只是可调整的内容新鲜度参考。**
