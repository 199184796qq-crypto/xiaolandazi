## 2. Browser Collector 最终结构

浏览器采集层采用：

~~~text
Go Core Service
      ↓ stdin JSON command
Node / Playwright Worker
      ↓
单 Chrome
      ↓
单 BrowserContext
      ↓
多个直播间 Page
      ↓ CDP Network.webSocketFrameReceived
Douyin binary frame
      ↓ stdout JSON + base64
Go Core Service
      ↓
PushFrame / gzip / Response / Message[]
      ↓
RoomEvent
~~~

说明：

- Node Worker 只负责浏览器和 CDP。
- protobuf、Room、事件、数据库、SSE、Agent 等业务仍在 Go Core。
- Worker 不是新的管理服务，也没有用户界面。
- 多房间复用一个 Chrome，不会每个房间启动一个 Chrome 进程。

## 3. 为什么不用 chromedp 作为主实现

本机实测：

- chromedp 能打开直播页面
- 能看到 /webcast/im/fetch
- 但在 headless 场景下 WSS 建立行为不稳定
- Network.getResponseBody 也出现阻塞

同机使用参考项目一致的 Playwright headless 方式：

- 成功建立 webcast WSS
- 20 秒内持续收到二进制帧

因此 V1 Browser Collector 使用 Playwright Worker，Go 只消费帧。

这不改变三层服务架构。

## 5. Worker 配置

Core 可使用以下配置：

~~~text
COLLECTOR_NODE_PATH=
COLLECTOR_WORKER_PATH=
COLLECTOR_BROWSER_PATH=
COLLECTOR_BROWSER_HEADLESS=true
~~~

留空时：

- Node 从 PATH 自动发现
- worker.mjs 从项目相对路径自动发现
- Chrome / Chromium / Edge 从系统常见路径自动发现
