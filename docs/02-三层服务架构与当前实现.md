# 三层服务架构与当前实现

更新时间：2026-09-21

## 1. Core Service

Core Service 是整个直播伴播产品真正执行业务的后台进程，没有用户界面。

默认本地地址：

~~~text
127.0.0.1:8081
~~~

当前职责：

- 房间持久化
- 房间事件持久化
- 实时 RoomEvent Hub
- Collector 抽象
- 内部 SSE
- 内部房间 API

未来继续放在 Core 的能力：

- 抖音 / 快手 / 视频号 Collector
- Room State
- Event Priority
- Sales Agent
- LLM
- TTS
- Speech Task
- Device Gateway

Core 的 /internal/* API 仅供 Management Service 调用。

## 2. Management Service

Management Service 是客户端和 Core 之间的管理层。

默认本地地址：

~~~text
127.0.0.1:8080
~~~

当前职责：

- Tenant
- 用户角色
- 平台管理员 scope
- 客户 scope
- 对外房间 API
- 对外公屏 API
- Core API 转发
- Core SSE 转发

当前开发环境提供临时“平台视角 / 客户视角”切换，仅用于开发联调。正式版本替换为真实登录 Session。

## 3. Web Console

Web Console 是唯一的网页控制台。

平台管理员与客户不维护两套重复页面。

### 平台管理员

可以看到：

- 全部客户
- 全部房间
- 客户筛选
- 全局状态

### 客户

相同页面组件，但 Management Service 强制限制为：

~~~text
tenant_id = 当前登录客户
~~~

客户不能通过修改 URL 或请求参数查看其他客户数据。

## 4. 数据边界

V1 本地开发阶段两个后台服务使用同一 MySQL 实例，但表归属明确分开：

Core：

~~~text
core_rooms
core_room_events
~~~

Management：

~~~text
mgmt_tenants
mgmt_users
~~~

服务间不建立跨服务外键。

## 5. 当前请求链

### 添加直播间

~~~text
Web Console
  ↓ POST /api/v1/rooms
Management Service
  ↓ 鉴权 / tenant scope
Core Service
  ↓
core_rooms
~~~

### 查看公屏

~~~text
Collector / 开发模拟事件
  ↓
Core RoomEvent
  ├─→ MySQL 历史
  └─→ Event Hub
          ↓ SSE
Management Service
          ↓ SSE
Web Console
~~~

## 6. 下一开发目标

M0 的下一个实际目标：

> 输入一个真实抖音直播间房间号，Core Collector 建立连接，Web Console 看到真实公屏。

真实采集代码不得放进 Management Service 或 Web Console。
