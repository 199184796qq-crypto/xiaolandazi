# 事实驱动话术生产系统 · 总方案

> 状态：方案定稿（2026-10-15，多轮实测验证 + 代码核对）
> 定位：替代现有「内容池文案 + 角度钩子工作卡」中间层链路，彻底剥离，改为「事实驱动 + 侧面筛选」的单链路
> 关联：《话术生成链路架构.md》《话术库复用机制设计方案.md》《侧面筛事实多样化方案.md》

---

## 0. 一句话总结

客户只填 3 样（商品信息 + 活动福利 + 事实依据），系统全自动完成「卖点×角度挖掘 → 事实侧面归类 → 按侧面筛事实生成话术」，砍掉所有中间层，话术真实可靠、结构多样、成本更低。

---

## 1. 核心架构：事实驱动单链路

### 旧链路（要剥离）

```
事实包 → ①卖点挖掘 → ②内容池文案(angle字段) → ③角度钩子工作卡(实时) → ④正文 → ⑤润色 → TTS
              └── ②③两个中间层是冗余，且②③都被④绕过/清空
```

### 新链路（事实驱动）

```
【准备阶段 · 静态，开播前】
客户填 商品信息 + 活动福利 + 事实依据
   ↓
① 卖点×角度挖掘（一次模型调用，角度锚定 source_ids）
   ↓ 覆盖校验：每条事实是否被角度覆盖 → 漏挖回灌补全清单
   ↓
② 事实打侧面标签（分类→侧面映射表，自动，零模型成本）

【直播阶段 · 运行时，每段】
③ 调度选本段：卖点×角度（47 选 1，防重复+加权）
   ↓
④ 侧面轮换：该角度第 N 次 → 第 N%7 侧面
   ↓
⑤ 按侧面筛事实：只取该侧面的专属事实
   ↓
⑥ 正文生成：卖点×角度 + 侧面事实 + 主播风格 + P0 → 话术
   ↓
⑦ 润色（条件触发：检测到数字短语复读才润色）
   ↓
⑧ TTS → 播放
```

**关键变化**：砍掉 ②内容池文案、③角度钩子工作卡两个中间层；侧面从「软约束」升级为「事实筛选器」。

## 2. 卖点挖掘可靠性（真实可靠 + 丰富）

现状已有：高危词表 21 词拦截 + 契约校验 + 事实补充建议。但只有「负向拦截」，缺「事实绑定」和「覆盖校验」。

### 2.1 角度锚定事实（治编造）

- 卖点挖掘时，每个角度必须标注 `source_ids`（依据的事实 ID）。
- 程序校验：`source_ids` 必须都在事实包内，不在 → 删除该角度。
- 这是「每个角度都有事实锚点」，比 21 个高危词强一个量级。

### 2.2 事实覆盖校验（治遗漏）

- 反向校验：事实包每条事实，是否被至少一个角度引用。
- 未被引用的事实 → 漏挖维度 → 回灌「补全清单」提示模型补角度。
- 保证 41 条事实 → 角度全覆盖，一个维度不漏。

### 2.3 语义去重（治重复）

- 挖出的角度做语义相似度去重，相似度高的合并。

### 2.4 品类卖点模板（治彻底漏）

- 已有 `fact-gap-checklist.md`「必查事实清单」：通用卖点层 10 项 + 品类必查层（食品/服装/电器）。
- 挖卖点时拿模板对照，模板里维度事实包没有 → 提示客户补（走「商品资料补充」界面）。

### 2.5 闭环（覆盖校验 + 事实补充建议）

```
① 客户填事实 → ② 模型挖卖点(锚定source_ids + 输出补缺建议)
   → ③ 覆盖校验(漏挖) + ④ 补缺建议(缺事实)
   → ⑤ 合并成"缺口提示"回灌补全清单 → ⑥ 客户补 → 回到②
```

## 3. 事实侧面标签（分类→侧面映射，零成本）

事实已有分类体系（`LiveFactCategory`），侧面标签通过**映射表自动推导**，无需模型、无需人工逐条标。

### 3.1 七个侧面（产品无关，固定）

使用场景 / 过程细节 / 利益算账 / 对比参照 / 人群痛点 / 品质来源 / 使用方式。

### 3.2 分类 → 侧面映射表

| 事实分类 | 映射到的侧面 |
|---|---|
| 商品信息（工艺/原料/产地）| 过程细节、品质来源 |
| 价格 / 规格 | 利益算账、对比参照 |
| 物流发货 | 对比参照、使用方式 |
| 售后保障 | 人群痛点 |
| 使用方式（开袋/复热/保存）| 使用方式、使用场景 |
| 门店 / 品牌历史 | 品质来源 |

### 3.3 数据模型

事实表 `live_agent_plan_facts` 加 `sides` 字段（数组，可跨多侧面，0 条表示通用兜底）。

## 4. 话术生成（侧面筛事实 + 砍中间层）

### 4.1 核心改造：HookFacts 双维筛选

- 现状：按【商品】筛事实（1 号链接喂 1 号链接全部事实）。
- 改造：按【商品 + 侧面】筛事实（只取当前侧面的专属事实）。

### 4.2 砍掉的中间层

| 旧中间层 | 现状 | 处理 |
|---|---|---|
| 内容池文案（angle 字段）| 被角度钩子清空/绕过，实际没进正文 | **剥离** |
| 角度钩子工作卡（angle hook plan）| 实时生成"沟通任务"，软约束 | **剥离**（侧面筛事实替代其"细化"作用）|

剥离后正文生成的输入变成：
```
卖点×角度（定位）+ 侧面专属事实（素材）+ 主播风格 + P0 → 正文
```

### 4.3 实测依据（2026-10-15）

| 方案 | 同角度 20 次结果 |
|---|---|
| 关键词筛事实 | 100% 滑向价格 |
| 全量事实 | 单条丰富但条间同质 |
| **侧面筛事实** | 7 话题 × 3 轮，结构彻底拉开 ✅ |

## 5. 润色降级（复读才触发）

- 现状：每次正文后必跑同义改写（`mainline_text_rewrite`，占 session 281 文本 token 的 6%）。
- 改造：默认不润色；检测到「同一数字短语（如"微波炉叮1分钟"）在近 N 段内反复出现」才触发润色换动词。
- 原因：数字短语采样随机无效（数字锁死 + 模型爱照抄），必须靠润色主动换动词、锁数字。
- 保留复读检测 `IsDuplicateSpeech` 作为硬兜底。

---

## 6. 缓存优化（可说事实挪 system 末尾）

- 现状：system 结构里「可说事实」在中间，它一变，后面的 P0/纠正/改写/标尺前缀全断。
- 改造：把「可说事实」挪到 system **末尾**（或 user），让母版+P0+标尺（~10000 token，占 92%）稳定命中前缀缓存。
- 效果：侧面筛事实不破坏缓存命中，反而提升命中率。

---

## 7. 话术库复用配合（Codex 已做）

- 话术库（47 slot × 3 条，填充度自适应复用 0/30/60/70%）已实现。
- 侧面筛事实后，slot 存的是**不同结构**的话术，复用出去才真不重复。
- 关系：侧面筛事实给话术库供"不重复弹药"，话术库负责"零成本复用"。

## 8. UI 改造

### 8.1 事实依据界面（侧面标签 + 覆盖回显）

- 每条事实显示「侧面」标签（按映射表自动打好，客户无感）。
- 覆盖校验结果回显：事实没被任何角度引用时，卡片标 ⚠️「此事实暂无对应话术角度」。
- 可选高级操作：点开微调侧面（默认不动）。

### 8.2 商品资料补充界面（补全闭环）

- 已有「必查清单」机制（通用卖点层 10 项 + 品类层），承载"查缺事实→提问→客户补"。
- 改造：覆盖校验结果也回灌到这里（挖完卖点后，漏挖维度变一条补全清单项）。

### 8.3 保存方案一键化

- 现状：初始化智能体 / 更新受影响内容 / 保存方案 三步，串行强依赖。
- 改造：一个「保存方案」按钮，后端自动编排（轮盘过期→初始化；内容池过期→更新；最后保存），带分阶段进度提示。

## 9. 剥离清单（跟旧链路彻底切割）

| 旧模块 | 剥离方式 |
|---|---|
| 内容池文案生成（content pool 的 angle 口播文案）| 不再生成，只保留「卖点×角度 + 权重 + source_ids」 |
| 角度钩子工作卡（angle hook plan 实时规划）| 删除，侧面筛事实替代 |
| 同义改写「每次必跑」| 降级为「复读才触发」|
| 事实按商品整包喂 | 升级为「商品 + 侧面」双维筛 |

**保留不动**：卖点挖掘、P0 审核、复读检测、话术库复用、加权调度、TTS、开场不缓存、互动不缓存。

## 10. 改造路线（分阶段）

| 阶段 | 内容 | 依赖 |
|---|---|---|
| P1 | 事实打侧面标签（映射表 + sides 字段）| 无，可先行 |

## 11. 待决策点（均有推荐项）

1. 事实打标签：分类→侧面映射表自动（推荐）vs 人工 vs 模型。
2. 空侧面兜底：跳过该侧面（推荐）vs 降级全量。
3. 角度 vs 侧面优先级：侧面优先（推荐）。
4. 润色触发阈值：同一数字短语近 8 段内重复才触发（推荐）。

## 12. 验收标准

- [ ] 同卖点×角度连续 7 段（轮 7 侧面）信息结构互不相同。
- [ ] 卖点挖掘每个角度有 source_ids，覆盖校验能发现漏挖并回灌。
- [ ] 事实表有 sides 字段，保存时自动打好。
- [ ] 正文生成不再依赖内容池文案/角度钩子。
- [ ] 润色只在复读时触发，缓存命中率不降。
- [ ] 客户操作流程不变（仍只填 3 样 + 开播）。
