# 系统配置中心重构与权限设计

更新时间：2026-10-03  
状态：已按本文结构进入实现与部署

## 1. 目标

把散落在各业务工作台中的系统级配置、规则配置和基础主数据统一归入“系统设置”。配置入口采用固定三级结构：

```text
系统设置
  -> 二级配置域
       -> 按内部业务分类分组的配置页面
```

系统设置不是把所有业务操作堆到一个页面，而是统一回答三个问题：

1. 哪些内容可以配置。
2. 配置属于哪个业务域。
3. 当前岗位可以查看还是可以修改。

## 2. 二级配置域

| 二级配置域 | 内部分组 | 主要内容 |
| --- | --- | --- |
| 基础与品牌 | 品牌与公共展示 | 系统名称、智能体名称、页脚、备案和公共文字 |
| AI 与智能体 | 理解与模型、智能体行为 | 理解路由、模型指令、直播分析、直播策略中心 |
| 直播业务 | 行业与规则、会员与容量 | 行业目录、系统/行业规则、显示规格、会员房间上限、客户额度 |
| 商品、计费与财务 | 商品与价格、营销与计费、财务与结算 | 会员、时长卡、设备商品、活动、虚拟豆、奖励、审核、返佣和代理等级 |
| 设备与仓储 | 仓库基础资料、设备商品主数据 | 仓库、物流商、产品单位、设备商品主档 |
| 权限、流程与审计 | 组织与权限、审批与审计 | 部门、员工、角色、权限、审批策略、操作审计 |

## 3. 权限显示原则

页面权限分三层执行：

1. 系统设置入口权限：没有任何配置查看能力的账号不显示“系统设置”。
2. 配置域和配置项权限：进入后只返回当前岗位可见的分类和配置项。
3. 接口操作权限：即使手工输入 URL 或调用接口，后端仍重新校验查看和管理权限。

禁止只依赖前端隐藏按钮实现权限控制。

## 4. 默认岗位口径

| 岗位 | 可见范围 | 默认修改范围 |
| --- | --- | --- |
| 平台管理员 | 全部配置 | 全部配置 |
| 系统超级管理员 | 除平台专属项外的全部授权配置 | 模型指令及明确授权项 |
| 管理部 | 组织、权限及跨部门只读配置 | 按单独管理权限决定 |
| 营销运维负责人 | AI、直播、商品、营销与计费 | 直播系统策略、理解路由及本部门管理项 |
| 营销运维专员 | 直播、商品、营销相关配置 | 会员、时长卡、活动、虚拟豆等已有授权项 |
| 财务部 | 财务、结算、审批、审计相关配置 | 按财务岗位的管理或审核权限决定 |
| 仓储售后负责人 | 仓库、字典、设备商品资料 | 仓库和基础字典 |
| 仓储售后员工 | 仓库、字典、设备商品资料 | 默认只读系统配置，库存业务权限保持不变 |
| 销售主管 | 组织与审计范围 | 按原有组织权限决定 |
| 普通销售 | 不显示系统设置 | 无 |
| 代理与终端客户 | 不显示内部系统设置 | 只维护各自业务页面内的个人或租户配置 |

## 5. 高风险配置

以下配置不能因为员工可以看到系统设置就自动获得修改权：

- 全局品牌、系统名称、页脚和备案。
- 模型总指令和系统级提示词。
- 智能体理解路由和预算。
- Agent 停止、设备离线停计费等安全规则。
- 财务审核隔离规则。
- 订单锁库等平台交易规则。
- 角色权限定义。

其中安全停止与停计费规则属于平台红线，不开放为普通业务配置。

## 6. 不进入系统设置的内容

以下内容虽然也可编辑，但属于业务对象或个人偏好，不归入系统级配置：

- 某个客户或直播间的主播、话术、商品、活动和用户层策略。
- 某台设备与直播间的绑定关系。
- 采购入库、出库、物流、售后、订单和结算批次等业务单据。
- 用户头像、联系方式、密码和个人显示偏好。
- 服务器密钥、数据库密码、对象存储密钥、模型密钥和 WSS 凭证。
- 必须强制执行的安全规则和财务不可变流水规则。

环境密钥继续由服务器安全配置管理，不进入网页和数据库普通设置表。

## 7. 路由与兼容

- `/system/settings`：系统设置首页，按权限显示二级配置域。
- `/system/settings/{category}`：二级配置页，按内部分类展示可见配置项。
- 具体配置使用 `/system/settings/{category}/{item}` 路径。
- 原业务工作台入口暂时保留，避免已有收藏、历史链接和工作流程失效。
- 从系统设置进入配置详情时，面包屑始终返回对应二级配置域。

## 8. 验收标准

1. 系统设置首页不再直接堆放全部表单。
2. 二级配置域固定为六类，配置页面内部继续分组。
3. 平台管理员可以看到全部六类。
4. 不同部门登录后看到的配置域和配置项不同。
5. 只有查看权限的员工不能看到保存、新增、发布等操作。
6. 手工输入无权限配置 URL 会被拒绝或返回岗位默认页面。
7. 后端接口独立校验权限，不能依赖前端。
8. 原配置数据、版本历史和业务接口保持兼容。
9. 系统名称统一使用“系统设置”，不再同时出现“系统设定”。
10. 桌面端和窄屏均能完成分类浏览和配置操作。
