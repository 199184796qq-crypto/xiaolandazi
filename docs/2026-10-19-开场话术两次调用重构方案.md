# 开场话术「两次调用」重构方案

日期：2026-10-19
状态：待落地（方案已定稿，代码/母版待改）

## 一、目标

把服务器现有的「开场一次调用生成」替换为「两次调用」，让开场话术：
1. **选材精准**：模型先选「卖点×角度 + 开场方式」，再专心写话术，不再把候选池和事实全塞一段导致报菜名。
2. **欢迎永不丢**：欢迎暖场固定前置，不依赖模型自觉。
3. **钩子可控**：8 类开场方式，模型显式选，程序可解析。

## 二、铁律：统一话术基座（四层）

不管哪次跟模型交互，一律走「话术基座 = 两个四层」：

- **内容四层**：必说（本次任务/选材要求）/ 可说（事实包）/ 不提（未知项 + 红线词）/ 改写（禁说→安全替换）
- **表达四层**：主播腔调（风格 + 量化基准 + 禁用表达）/ 量化基准 / 禁用表达 / 近期避重

## 三、两次调用结构

### 第一次：选材（也套四层）

**输入**（给模型）：
- 必说：从「卖点×角度候选池」挑一个最能勾住观众的卖点×角度作为开场主线；再从 8 类开场方式里选一个最合适的。只输出一个 JSON 对象。
- 可说：候选池（`state.Queue` 全部 Task，每个带 SellingPoint / Angle / TargetAudience / PainPoint）
- 不提：未知项正反不说
- 改写：只做选择，不写正文，不解释，不编候选池之外的内容

**输出**（模型返回，程序解析）：
```json
{"卖点":"...","角度":"...","开场方式":"..."}
```
开场方式枚举（8 选 1）：欢迎型 / 利益钩子型 / 悬念型 / 痛点型 / 身份背书型 / 互动型 / 自嘲亲和型 / 直接开讲型

### 第二次：写开场（四层 + 精准事实 + 开场四步写法）

**输入**（给模型）：
- 必说：开场四步写法 = ①欢迎暖场（固定前置）→ ②选定开场方式对应的钩子 → ③讲选定的卖点×角度 → ④轻轻招呼看链接
- 可说：只给「选中的卖点×角度」对应的精准事实（不是全量）
- 不提 + 不提红线词：未知项 + 红线词表（含边缘逼单词）
- 改写：8 类安全替换 + 事实卡改说
- 主播腔调：风格 + 量化基准 + 禁用表达
- 选定卖点 / 选定角度 / 开场方式：第一次的选材结果
- 字数上限

**输出**：一段完整开场正文（无 JSON、无编号、无解释）

## 四、8 类开场方式写法（母版内定义）

| 开场方式 | 钩子写法（欢迎前置之后） |
|---|---|
| 欢迎型 | 欢迎后自然带出商品 |
| 利益钩子型 | 欢迎后直接抛福利/价格反差（省多少、团购价vs原价） |
| 悬念型 | 欢迎后卖关子制造好奇，再揭晓 |
| 痛点型 | 欢迎后戳中观众买同类东西的顾虑/踩坑点，再说怎么避坑 |
| 身份背书型 | 欢迎后亮身份建立信任（地址/口碑） |
| 互动型 | 欢迎后让观众回应（打个1、扣个想要） |
| 自嘲亲和型 | 欢迎后自嘲放低姿态（今天人不多、不整虚的） |
| 直接开讲型 | 欢迎后不废话，直接说讲什么、重点讲哪几点 |

**欢迎暖场固定前置**：每段开场第一句先欢迎、招呼留人（欢迎新进来的哥哥姐姐们、别划走、点点关注、今天人不多都是自己人），营造自己人氛围，然后才上钩子。

## 五、落地改动清单

### 改动 1：重写 `cycle-opening.md` 母版
- 现：四步钩子（钩子→背书→卖点×角度→招呼），程序从 `opening-hook-library.md` 选钩子塞 `{{opening_hook}}`
- 改为：欢迎前置 + 8 选 1 钩子写法 + 四步，钩子由「第一次选材」的 JSON 结果决定，不再靠 `opening-hook-library.md` 的 `{{opening_hook}}`

### 改动 2：`renderCycleTextMessages` 开场分支插入第一次选材调用
- 位置：`text_generation.go` 的 `state.Phase == "opening"` 分支
- 逻辑：先调 `completeOpeningSelection`（第一次），拿到 JSON → 解析出卖点/角度/开场方式 → 再走现有 `renderCycleTextMessages` 拼第二次的 packet

### 改动 3：补红线词（边缘逼单词）
往 P0 JSON「不提」的「无依据限时逼单」类补：
手慢就没了、抓紧、赶紧冲、别等、不等人、真不是天天有、今天才有、就这个价、错过这波、再不下手

### 改动 4：测试 + 部署
- 改 `first_live_opening_test.go` 等断言（开场母版结构变了）
- 编译、部署到服务器

## 六、数据源映射

- 候选池 = `state.Queue`（`[]Task`，每个带 SellingPoint / Angle / TargetAudience / PainPoint）
- 事实包 = `state.HookFactsForSide()` / `generationMaterialViews`
- 模型调用 = `ResolveSpeechModel(TextProfileID)` + `CompleteSpeechEndpoint`（qwen3.7-flash 直连）

## 七、已验证的测试结论（本次对话实测）

1. 一次调用（候选池+事实全塞）→ 报菜名、没欢迎、事实覆盖太多 → 否
2. 两次调用（选材 + 写话术）→ 选材精准、事实聚焦 → 采用
3. 欢迎前置固定 → 每个开场第一句都是欢迎，7 种方式都稳定 → 采用
4. 红线词补边缘逼单词 → 逼单话术消失 → 采用
5. 「可说」里加逼单依据 → 模型反而借活动当挡箭牌乱催单 → 结论：有活动依据只能「如实转述截止时间」，不能衍生催单话术
