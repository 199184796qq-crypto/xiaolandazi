# 主动互动分流与语义计数

2026-10-31，用户确认“可以”。本轮处理格式、意图分类、优先级和计数，不审改客户保存方案的回答内容。源码及本地验证完成，尚未发布。

## 当前流程

1. 主线或插播的字幕句段有首帧PCM进入服务端主输出时，观察该句段文字；准备、下载、缓存、未来字幕不激活口令。这个信号不证明盒子已经完整出声。
2. 从明确的“扣1”“打666”“把收到打在公屏上”等指令提取口令；支持多个选项、全角数字、常用短词、引号短语，单独的商品编号、价格、“想要”和否定指令不激活。
3. 弹幕先按稳定UID归属正在进行的澄清对话，再检查当前口令。相符的参与回复只累计不同UID；同一用户多次扣字不增人数、不延长统计。
4. 未关联口令的纯数字先保留上下文及短期参与证据，不擅自判定刷屏、不创建语义任务，也不编造口令统计播报。澄清对话中的数字仍交给该人的模型上下文理解。
5. 其余候选继续使用最近60秒、最多10个不同用户、每人本人前5条消息的统一批次；相同真实问题不会因不同人重复提问就被程序过滤。
6. 模型类型新增“主动互动”，与“刷屏”分开；两者正文可以留空。主动互动进入聚合，刷屏忽略；有效提问、下单意向、催单、投诉、闲聊更新近180秒语义人数，按UID去重、按原事件时间计时。
7. 格式、作用域及分类结果经过原有校验后，程序最终按通道、类别、有限紧急建议、时效、配额和正在播放保护选人。只有选中的语义项进入称呼和TTS。

## 统计收口

- 已知口令按不同UID计人数，单轮最多保留2048个身份；没有稳定UID的回复可以分流，但不宣称已确定是不同人。
- 口令所在句段播放的剩余时长用于防止首帧后提前结束；随后没有新增参与用户持续10秒才收口。重复扣字不续期；源句段剩余时长只接受本地时间轴的合理范围，观众报文不能指定它。
- 0人不播；1至2人保留为后续话术的补充现场；3人及以上生成1项主动互动任务，不逐人口播。
- 新的不同口令会收口旧组再开始新组。同一口令在同一活跃轮内再次被观察，不清空已有参与者。
- 未关联已播口令、但模型明确识别为主动互动的相同短内容，按不同UID聚合，达到3人且静默10秒生成1项任务；任务明确标注未关联口令，不声称主播刚刚发起该口令。未确认纯数字不会借此生成播报。
- 口令匹配采用归一化相等及受控的重复数字形式，例如666/6666。包含真实问题的“1号多少钱”“想要麻辣的，多少钱”继续进模型，不做宽泛子串吞并。

## 计数和配额

只有模型已确认的有效语义消息才更新近180秒不同UID人数。待分类、纯数字、主动互动、刷屏、进房和点赞均不直接增加人数；同一个人后续参与扣字，不会抹掉他之前的真实提问，也不会刷新那个提问的时间。

| 近180秒有效语义人数 | 原语义播出次数配额 |
|---|---|
| 0至4 | 不另设次数上限 |
| 5至10 | 滚动60秒最多2次 |
| 11至20 | 滚动180秒最多2次 |
| 21及以上 | 滚动300秒最多2次 |

分类与播出分离：语义次数或播出冷却已用完时，仍可在原有批次和并发边界内分类新候选，避免真实语义人数统计停更；这些额外分类仍可能产生文字模型费用。不会给所有已生成结果继续调用称呼/TTS。保留每房间单批在途、每批最多10人、全局既有模型槽位、候选60秒及执行入队50秒期限，不增加新的逐人模型阶段。实际起播计费/预留释放与原音频时长预算保持。

## 模型协议

每人仍返回独立编号KV，新增可选类型“主动互动”。程序共享输入增加一次`engagement_token`，来源是已进入服务端PCM输出的口令现场，不含用户身份。各人的上下文保持隔离。

模型分类规则补充：明确准备购买、拍哪个链接等属于下单意向，即使同时问价；问已下订单进度属于催单；质量或服务纠纷属于投诉；不能仅提高优先程度却仍把明确购买归成普通提问。程序继续把分类作为类别排序依据，紧急建议只有明确原因才生效。此规则已接入模板与模拟测试，尚未重新用真实供应商验证分类准确率。

主动互动的优先程度固定回普通，不能通过自报紧急抢占；该类型不生成个人正文。正在澄清的dialogue任务如果被误标主动互动，明确返回错误并走原有限重试，而不是悄悄吞掉数字回复。页面文字测试也显示空回复，不进入称呼处理。
