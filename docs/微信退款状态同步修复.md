# 微信退款状态与钱包显示同步修复

## 线上证据（2026-10-03，北京时间）

退款单 ID 2，退回 10.00 元：18:15:46 创建接口返回 202；随后的财务 dashboard 读取返回 500；18:15:52 微信退款通知返回 204。退款实际成功，余额 16.00 元、冻结 0.00 元。前端通用错误引用误把读取失败显示成“操作未完成”。五接口 Promise.all 丢弃其他成功结果，旧退款列表没有处理中订单，原来的 60 秒刷新条件也不成立。

原 dashboard 500 没有具体 SQL 日志，不能确定其底层数据库错误。新增仅包含 MySQL 错误编号与取消标志的诊断日志，不记录 SQL、密钥或付款人信息。

## 修复

- 手机与电脑共用 display-only 同步逻辑；财务读取最多重试 3 次，各接口独立更新。
- 可用现金、冻结及退款记录从持有钱包锁的同一事务读取；该快照覆盖旧现金显示，未知本金/冻结显示“核验中”，不冒充 0。
- 创建成功即保留受理结果，读取失败只显示同步提示；不触发“操作未完成”。成功必须来自服务端核验，不能把受理当成到账。
- 处理中或读取失败时，前台每 5 秒 GET 同步；返回页面立即刷新。背景轮询绝不创建或提交退款。
- 已受理按钮切换为查询进度/完成，金额锁定；丢失创建响应保留原幂等键，不自动创建另一笔。
- 防止较早读取响应覆盖新状态；离开页面取消定时器和监听器。
- 余额卡片的可退本金与冻结文字移至余额下方；手机退款列表不再同时显示记录与“暂无退款记录”。
- 后端仅对坏连接、MySQL 1205/1213 的只读 dashboard 有限重试；金额冻结、退款分配与结算逻辑未修改。
