# 声音模型偏好保存表名修复

## 原因

用户截图报：Error 1146 (42S02)，Table 'livecompanion.rooms' doesn't exist。

保存入口为 PATCH /api/v1/rooms/{roomID}/voice-profiles/{profileID}/model-preference。
`SaveVoiceModelPreference` 中的房间归属检查查询了 `rooms`，实际表名为 `core_rooms`。之前的假数据库测试也识别 `FROM rooms`，重复了实现里的错误假设，因而单元测试通过并不能证明生产表名正确。

## 修复

- 房间归属查询改为 `core_rooms`，仍严格校验 room_id 与 tenant_id。
- 模拟数据库明确拒绝错误表名，不再把不存在的表模拟成功。
- 新增真实 MySQL 集成测试，声音档案表采用项目生产 DDL；测试只读写随机前缀隔离表。
- 测试通过：正常模型偏好保存；声音 ID、模型克隆身份、样本、头像、默认声音标记不变；其他房间和租户不变；禁用 / 不存在 / 越权声音与无效模型被拒，偏好不被失败事务改写。
- API 失败时不再将数据库内部异常原文展示给用户，完整诊断留服务日志。
- 不新建虚假的 rooms 表，不迁移用户声音，不额外调用克隆或 TTS。
