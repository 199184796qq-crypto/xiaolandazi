# 问题2 修复：公共资料反复混进商品段（已改，待提交）

## 现象

地址、有效期、用券限制等公共资料被当成「每段都要讲」，反复混进商品段。

## 根因

「公共 vs 商品」在**任务/调度层**已区分（`common_share.go:43-45` 有 20% 公共段配额），但**事实注入层没有区分**：

- `ProductFacts`（`product_focus.go:345` 原 `allowed := fact.Shared`）——公共事实对任何商品段无条件放行。
- `HookFacts`（`angle_hook.go:158-168`）遍历 `ProductFocus.Facts`，公共事实同样全量加入。

两条路径最终都喂给 `renderCycleTextMessages → HookFactsForSide`，导致公共资料逐段重复出现在商品段。

## 分类方案（用户拍板：方案 C「程序按 category 分类」+ 混合「程序粗筛+模型把关」）

复用事实分类已有字段 `Family`（`LiveFactCategory.Family`，受限枚举：product/link/trade/fulfillment/identity_location/other），**不新增字段、不硬编码 category 名**。映射：

| Family | 归类 | 商品段处理 |
|---|---|---|
| `trade`（价格/优惠/赠品/库存/付款） | A 类·交易条件 | 保留，结论依赖时按需引用（模型把关） |
| `fulfillment`（发货/配送/运费/自提/售后/退换/保修） | A 类·履约条件 | 保留，同上 |
| `identity_location`（品牌/资质/产地/门店/历史） | B 类·品牌背书 | **挡掉，只进公共段** |
| `product` / `link` | 商品本体 | 正常进商品段 |
| `other` | 兜底 | 保留 |

分类表是「全局基础 + 租户自定义 + 行业包」三层叠加、分行业动态的（`planFactCategoryCatalog`），A/B 区分随行业自动变化，零硬编码。

## 改动（4 文件 + 1 测试，未提交）

### 1. `internal/anchorcycle/state.go` — 新增字段
```go
FactFamilyMap map[string]string `json:"fact_family_map,omitempty"`  // category → family
```

### 2. `internal/anchorcycle/fission_side.go` — 新增 family 判定
```go
const (factFamilyBranding = "identity_location"; factFamilyTransactional = "trade"; factFamilyTransactional2 = "fulfillment")
func (s *State) factFamilyOf(text string) string   // category 反查 family，查不到返回空
func (s *State) isBrandingFact(text string) bool   // B 类
func (s *State) isTransactionalFact(text string) bool  // A 类
```

### 3. `internal/anchorcycle/product_focus.go` — ProductFacts 收口过滤
在原有「allowed」判断后，对 `fact.Shared && t.ProductMode != "common"` 的公共事实，若 `isBrandingFact` 则 `continue`（挡掉）。A 类保留。

**关键**：`HookFacts`（`angle_hook.go:158-168`）对每条事实单独调 `ProductFacts` 判断，所以这一处改动自动覆盖 `HookFacts → HookFactsForSide → generationMaterialViews` 全链路（已用测试验证）。

### 4. `internal/httpapi/industry_pack_loader.go` + `anchor_generation_live.go` — 注入 family map
- 新增 `packFactFamilyMap(categories []model.LiveFactCategory) map[string]string`（value→family）。
- `anchor_generation_live.go:157-161` 直播启动时 `state.FactFamilyMap = packFactFamilyMap(pack.FactCategories)`。

### 5. 测试 `internal/anchorcycle/product_focus_family_test.go`
- `TestProductFactsFiltersBrandingCommonFacts`：商品段挡 B 类、保留 A 类+商品专属；公共段全带。
- `TestProductFactsNoFamilyMapKeepsAll`：无 family map 时向后兼容（不挡）。

## 生效时机（重要，回答用户问题）

- 「初始化直播智能体」「保存方案」阶段：family 只是随事实**存进数据**，不参与筛选。
- **真正生效在「直播时」**：开播加载行业分类目录，把 category→family 装进 State，之后每段商品话术按 family 区分 A/B。
- 因此**要重新开播一场**才能看到效果；初始化/保存方案无需重做。

## 待 Codex 注意

1. **A 类「按需引用」目前只做了「程序保留 + 模型把关」的粗筛**，未做「本段任务显式引用才保留」的精确过滤（判断「哪句话结论依赖哪条条件」是语义判断，程序难精确做）。若后续要精确化，可在 `ProductFacts` 里加「A 类是否在 `TaskFactScope` 显式引用」的判断。
2. **无 `FactFamilyMap`（旧状态/未选行业）时向后兼容**：`factFamilyOf` 返回空，`isBrandingFact` 恒 false，不挡任何公共事实——旧场次行为不变。
3. `isTransactionalFact` 目前定义了但未在过滤逻辑中单独使用（A 类直接走「保留」默认分支）。留作后续「按需引用精确化」的钩子。
