# 主线话术与声音成品复用机制

核对日期：2026-10-21。现行实现依据为[首次开场实时与主线七三复用](2026-10-19-首次开场实时与主线七三复用-实现及验收.md)及[主线成品复用闭环修复](2026-10-21-主线成品复用闭环修复.md)。本文替代早期“Redis单JSON永久库、槽容量决定30/60/70概率”的设想；不再叠加该随机概率。

## 适用段落与七三目标

| 段落 | 行为 |
| --- | --- |
| 每场首次完整开场 | 实时新文字、新TTS，保留开场避重，不计七三 |
| 后续普通opening / body / closing | 条件满足时参与主线成品复用 |
| 互动、辅助段、修复/明确续讲承诺等特殊任务 | 不借普通成品替代当前任务；互动复用仍有独立开关 |

程序读取最近9个有效已采纳普通主线输出，连同下一段形成最多10段窗口，朝70%复用、30%新稿控制。重试、退稿不另消费配额；确定送播失败或已返还排除，回执不明保留。只看最近窗口，冷启动不积累无限“复用欠账”。

比例是合格采纳段的目标，不是每10次模型请求、每个小循环、音频时长或供应商cached_input_tokens的比例。冷库、冷却和材料变更会降低实际命中，不能为补比例绕过事实/质量边界。

## 持久化、隔离与失效

长期文字条目、租约与采纳凭据在MySQL，完整音频包在OSS；Redis保存本场运行态。停止直播释放本场租约，不删除仍有效的跨场成品，也不将旧场播放游标带到新场。

槽位包含本次任务、环节、开场变体和侧面；不同侧面可以同时保有库存。缓存先匹配程序已选任务，不能反过来换商品、卖点或角度。租户、方案及运行作用域由库契约校验，不跨租户或跨方案取稿。

- 有完整TaskFactScope时，按任务事实/商品边界失效；另一商品改事实不应清空无关槽位。缺来源关联的历史方案保守按全量事实失效。
- 事实或正文改变，相关文字及其声音同时失效；公共规则、风格、模型、生成参数或实际生成P0等变化按文字指纹隔离。
- 音色、TTS模型或语速改变只改变声音指纹，合格文字可保留，重新合成相应声音。
- 默认每槽容量3、重复冷却180秒。选择受冷却及租约保护；FIFO淘汰须尊重活动引用。对象回收走现有安全回收流程，不能在选稿时直接删正在使用的OSS对象。

## 从选择到实际播放

1. 检查主线开关、环节及任务准入，生成文字和声音上下文指纹。
2. 按滚动窗口决定本次尝试复用还是新稿；库未命中、冷却、指纹/凭据/近期正文检查失败则正常新生成。
3. 命中文字仍要满足当前质量及事实契约。`generation_accepted`明确是免模型审核模式下的程序采纳；`review_passed`要求真实审核回执，二者不能伪造或混用。
4. 声音指纹及完整音频包也命中，才跳过TTS；只有文字命中时仍需生成对应声音。音频必须含当前正文、字幕/时间线及安全切点等完整信息。
5. 新稿被真实采纳、音频完整准备后才发布成品。可选缓存写入失败记录原因，不打断已经准备好的本段声音。
6. 分别核查排队、Core开始和PCM进度/完成；文字采纳、租约音频非空或played_at都不能证明完整播放。

`text_hit`可能随后因校验取消，不能只凭选择日志统计命中。应关联候选的 `reuse_origin/library_entry_id`、实际租约复用、音频 `CacheHit`、Core回执与本场归档，按来源去重。

## 代码与验收

- `management-service/internal/anchorcycle/mainline_reuse.go`：首次开场排除、滚动配额和特殊任务准入。
- `management-service/internal/httpapi/speech_library.go`：任务指纹、选择、采纳凭据、文字/声音关联与发布。
- `management-service/internal/speechlibrary/`：库与凭据契约；SQL实现由管理服务数据库层承接。

验收覆盖跨场读取、冷库回退、不同侧面共存、相关事实修改、无关商品保留、语速仅换声音、并发租约、淘汰与活动引用、首开新文字新TTS。离线模拟达70%不等于真实暖库已达70%；实播按“入库→实际采纳复用→音频命中→Core开始/完成”分别核验。
