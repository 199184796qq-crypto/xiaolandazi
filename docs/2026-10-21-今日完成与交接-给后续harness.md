## 4. 今天踩过的坑（可复用教训）

1. **生产母版 ≠ git 母版**。生产 `configs/prompts/anchor-style/` 有 169+ 文件（含现场手改和 `.bak`），MANIFEST 190+ 条而 git 只有 161 条。**严禁用 git 覆盖生产**，只能就地改 + 重建该文件哈希。
2. **Codex 与你并发发布**。发布前必须**重抓基线**（`capture_baseline.py`），并用 `git diff <生产commit> HEAD` 核对「我的二进制是否含他全部代码」。
3. **中文断言串进不了 `strings` 输出**（只输出 ASCII 可打印序列），首次因此断言崩并回滚。改用读 `/proc/<pid>/exe` 的 `vcs.revision`。
4. **纯前端 / 纯后端发布的脚本分支**：`assert sha(...) == metadata['files']['bin/management-service']` 在无 bin 时 KeyError；`vcs.revision` 校验在纯前端发布必然失败。三处都要包在 `if 'bin/management-service' in metadata['files']:` 里。
5. **硬链接复制（`copytree(copy_function=os.link)`）+ `write_bytes` 会破坏原文件**，必须 `os.replace` 原子替换。
6. **「数字有没有出现过」拦不住差额错误**。`10` 在「10人餐」「10道凉菜」里都出现过；必须识别「多/少/相差 + N」语境并核对运算。
7. **用户报「保存不了」时先要截图文案 + 查服务端有无对应请求**。今天我先归因成「服务重启」，实际是事实审核没通过；另一次确实是重启夹在中间（无请求）。
8. **改筛选口径前先搜同名测试**。设计意图常写在测试名里（`...KeepsConditions...`）。
9. **`deploy_*.py` 的 `meta_name` 必须和 `package_*.py` 一起改**，只改一个会 `KeyError: filename 'XXX.json' not found`（今天踩了三次）。
10. **新母版已在基线里且内容变了 → 必须加进 deploy 的 `mutable` 白名单**，否则 asset collision 断言崩。

### P1-1 对比角度结构化（治「可比性」）

- **问题**：角度是 `[]string`（`anchor_style_workbench.go:127`），程序不知道这条角度在比「哪一项」。`Task.Comparison/Links` 是另一个判定模型事后猜的。
- **方案**：角度对象化 `{"文本","维度","对比链接":[...]}`，字符串形式兜底兼容老轮盘。程序四道校验：
  1. 维度名在两边事实里都有值，只有一边有 → 剔除
  2. 两边数值原样来自各自链接（复用 `unknownDigits`）
  3. 维度在可比白名单内（价格/分量道数/适用人数/服务项/规格）；口味、氛围、好评率等主观项不进
  4. 品类不同（套餐 vs 代金券/单品）→ 直接不出对比角度
- **验收**：新初始化后，轮盘里不存在「一边有数、一边没数还要比」的角度；单测覆盖 4 条。

### P1-2 轮盘生成后加程序扫描剔除（用户已同意但要求「先记着」）

- **内容**：角度生成完，用「不提」裸词表 + 跨链接比较正则（`对比|比较|两档|两款|两个套餐|均|同样|一致|哪个更划算|按人数选`）扫一遍，命中即剔除并记录，复用已有 `programRemovedBoundaryItems`（`anchor_generation_initialize.go`）。
- **起因**：wheel 74 的「对比两档套餐的绝对节省金额」同时踩极限词「绝对」和跨链接比较，证明把词表贴进 system 压不住。
- **验收**：故意造一条含「绝对」的事实 → 初始化后轮盘里该角度消失，且日志有剔除记录。

### P1-3 互动话术缺「直播间规范」

- 互动（欢迎/答疑/下单引导）走独立链路，用的是 `interaction-*` 母版，既没有「主播腔调」也没有「直播间规范」。而互动里称呼最常出现（「欢迎欢迎，咱们家今天…」）。
- **改法**：在互动提示词组装处注入同一条 `roomSelfReferenceRule`（约 2–3 处）。
- **验收**：互动话术里不出现「这家店 / 该店」。

### P1-4 方案级对比开关（现在只有母版全局）

- 现状：`comparison_mode` 在母版 JSON 里（全局），不同直播间不能不同策略。用户要的三档：按事实 / 一律不比 / 只比指定品对。
- **改法**：方案配置字段 + 保存时覆盖 `focus.Policy` + 前端三档控件；`pairs` 档要支持「只比指定品对」的配对列表。
- **验收**：两个方案设不同档，各自快照 policy 不同，行为不同。

### P2-1 三个以上链接的对比语义

- 母版第 11 条写「角度必须写清**哪两个**链接在比」，勾 5 个链接时语义不够用。
- 建议：改成「最多两个；3 个以上必须拆成两两对比，每次只讲一对」。纯母版改动，成本低。

### P2-2 归属上限 8 的报错文案

- 勾第 9 个链接时后端只回「事实归属无效」，不说明超上限（前端已加灰化 + 提示，但后端文案未改）。

### P2-3 初始化三次调用没命中前缀缓存

- 三次（总轮盘 + 每个链接一次）system 完全相同（约 8741 字符 ≈ 5350 token），实测 `cached_input_tokens` 全为 NULL。
- 若命中，第 2、3 次可省 8000–9000 token（是「删 464 字符省 850 token」的十倍）。先确认是没打开缓存还是 provider 未上报。

### P2-4 轮盘 system 剩余冗余

- 「输出协议 + 归属要求」重复段今天已合并（省 464 字符）。
- 「内部工作流程」1228 字符经逐条阅读，**约 90% 是判据不是流程**（粒度/命名/人群与痛点不许虚构/禁用限定词清单），删了会明显退化 → **不建议动**。真正纯流程话术只有约 120 字符（省 1.4%），不划算。

4. 编译 Linux 二进制：`GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o <release dir>/management-service ./cmd/management`，并核对 `go version -m ... | grep vcs.revision`
5. **重抓基线**：`python capture_baseline.py`（Codex 可能刚发过）
6. 打包：`python package_xxx.py`，记下输出的 `sha256`
7. 上传并部署：`scp <tar.gz> production-baseline.json deploy_xxx.py xiaolan-prod:/tmp/`，再 `ssh xiaolan-prod "sudo -n python3 -u /tmp/deploy_xxx.py <tar> <baseline> <sha256>"`

- 部署脚本有 `assert_idle`：**直播进行中会拒发**（会重启服务）。停播后再发。
- 发布失败会自动回滚，但 PID 变化 → **必须重抓基线再重试**；服务器可能残留半个 release 目录，重试前 `rm -rf`。
- 纯母版发布：不重编译二进制；改 `mutable` 白名单放行该母版。
- 纯前端/纯后端发布：`files` 里不要放空的 bin 键，`vcs.revision` 校验要包在条件里。
