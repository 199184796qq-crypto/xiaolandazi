# 话术优先：成品复用与请求费用闭环

状态：实现完成，固定源码 Management/Core 全量、费用专项、静态检查与 Linux 编译通过；尚未发布。不得据本文件推断服务器已经运行本次代码。

## 业务目标

用户指定 Codex 接手规划修复。在保留 DeepSeek 当前原句准入、事实隔离、纯文本方案和增量生成修复的基础上，补齐复用与费用闭环。以话术优先模式为主，不改为另一套实时主线生成业务。

- 第一次冷库可使用经审核的原文原句，缺声音时合成基础版本；暖库重进直接使用已有合法成品。
- 普通更新以 1.3 元/小时为目标，业务优先，允许必要超用。可选更新约在 1.2 元处收缩，为互动等留余量。它不是供应商扣费的硬上限。
- 必要首声、真实观众互动、事实变更后的重新交付不得因达到预算而停止直播；必须记录超用原因。
- 原有实时模式首次开场必须新生成的规则保持；不能把话术优先可用原句套用到实时模式首次开场。
- 不通过改事实、跳审核、换音色或停止正常互动来制造高复用率、低费用数字。

## 修复后的工作流

1. 先确定当前租户、房间、方案、已解析音色、语速、表达指令规则、事实与审核母版身份，再读取对应成品清单。正文、音轨和时间轴一起复用，只重新签发播放地址。
2. 每轮先确定更新目标；复用句不调用润色、不调用 TTS。坏缓存先找同范围其它合法版本，再考虑新生成。
3. 首轮基础声音成功就入库，包括未改写原句。后续每句最多保留四个合法版本。
4. 更新成功时当轮直接使用刚生成的版本，不能付费后再随机选回旧版本。改写未变化、失败或预算拒绝则保留已有合法声音，不再为相同正文合成一次。
5. 新生成和缓存恢复都核对实际文字审核回执。接口返回 nil、请求 completed 都不等于审核通过。
6. TTS 付费边界仅是供应商请求；下载、归档、重新签名、合块和播放复用不记作再次 TTS。成功音频不能因费用回执保存失败而被丢掉重新生成。
7. 原有就绪队列、追加身份、未知回执处理、Core 交互返回和人工控制围栏继续生效。媒体成功开始不等于完整 PCM 播完，也不证明实机外接声音。

## 跨轮更新分配

原来每个标签向上取整，哪怕一条句子也每轮至少更新一条，导致名义 25% 实际 100%。改为按源句字符量累计更新余额，余额绑定稳定标签 ID，正文变化重置对应余额。

- 一句标签、25% 目标：四轮累计够一次完整更新，不提前向上取整。
- 长短句按字符量分配，优先最久未更新的完整句；不足以更新老长句时先积累，避免一直消费在短句上。
- 只有新成品成功取得才扣减余额；预算拒绝、无变化或生成失败不冒算更新成功。
- 余额最多保留该标签一整轮，恢复后不无限补债。
- 更新余额和成功更新顺序随成品清单保存；新进程恢复，标签重排仍按稳定 ID 识别。
- 首轮不新增可选更新；文本时长对应的 25%/20%/10% 是更新意愿，最终仍受请求前预算预留约束，不代表每轮必须花满。

## 请求费用账本

新增独立请求表，不再用 `media_assets.duration_ms` 之和控制更新。历史时长快照不是供应商账单；缓存音频重新归档也不能算再次付费。

每次真实模型或 TTS 请求先原子预留，再允许发送；同一房间的模型与 TTS 共用滚动一小时预算，跨并发请求加锁，不能各看一份旧余额同时超发。每个逻辑请求有稳定身份，租户与房间隔离。

| 请求结果 | 费用处理 |
| --- | --- |
| 确认本地未发送 | 幂等释放预留 |
| 请求成功，有发送文本或 Token 但无合约单价 | 按参考价更新估算，不能称实付 |
| 供应商计量与明确匹配的合约价 | 记为供应商用量费用，保留请求编号 |
| 回执未知、超时、发送后断开 | 保留预留，不按时间自动退款，不换身份立即重付 |
| 供应商实际账单导入 | 按请求编号核对，覆盖较弱估算；重复导入不重复计费 |

预算数据库暂不可用时，可选更新暂停；必要业务留本地持久记录后继续。记录目录在持久媒体根目录的 `live-cost-spool`，不放进 release。重放只补账，不重放供应商请求；记录不包含话术正文、凭据或签名音频 URL。

默认参考价沿用本次讨论：TTS 1.6 元/万字符；模型输入 0.2 元/百万 Token、输出 0.8 元/百万 Token、命中前缀输入 0.04 元/百万 Token。模型名称或供应商计费单位不同，不能据此冒称实际单价；以显式匹配配置或实际账单为准。供应商返回的字符、Token、时长分别保留，禁止互相当作同一计量单位。

## 真实用量与账单核对

TTS 网关保留供应商返回的请求编号和实际用量字段，区分“缺失”与“显式 0”。腾讯当前 WebSocket 回执没有账单用量字段时，只保留请求编号与发送文本估算，不从 PCM 长度反推实付。

提供独立 `cmd/reconcile-live-cost` 命令。默认只本地检查导入文件；显式应用时才连接请求账本，校验租户、房间、供应商、请求编号、币种与金额。CSV/JSON 不能代替供应商原始账单来源证明。没有拿到真实账单前，本项只能验收接入和核对机制，不能写“实际实付已核对”。
