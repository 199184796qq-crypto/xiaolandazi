# 互动回归等待超时修复

## 已确认故障

生产第239场（房间15，北京时间2026-10-11 21:47:43至22:05:33）中，互动决策
`d-15-1791726888100-000088` 已开始播放回答，随后进入 `returning`。
21:55:45的Core日志记录等待30秒后仍未回归；旧实现直接结束观察。
后来实际主线PCM已恢复，互动状态仍停留在 `returning`，后续领取被
`speech_busy` 拒绝。该场统计为2条完成、19条超时失败；不能把完成数当作实际已说出的回答数。
结束原因为 `manual_stop`，不是监控程序停止。生产Core源码版本为
`6255fd412193fb35a0688fc4f6b2577c68b30daa`。

## 修复边界

30秒只提示回归慢，继续观察同一互动。当实际音频进入主线、来源为主线且
已输出主线PCM时，原子比较任务及决策身份，将该互动状态置为完成。
不因时间到了就释放占用，避免旧音频未结束时叠播。停止、替换任务及终态会结束旧观察。
原子完成保留回答、回归桥、任务出处和音频记录，旧回调不能覆盖新任务。
已取消或过期的队列条目不补造完成统计；日志记录队列完成是否实际成功。

本次仅修改Core的运行状态与观察生命周期，不修改模型、提示词、P0、
互动频率、管理服务、前端或设备网关。

## 验证

- 回放30秒告警后延迟恢复：告警后仍占用；仅切换主线但未输出PCM仍占用；
  PCM恢复后释放，下一条决策可以领取。
- 观察期间停止或替换任务：退出旧观察，不复活停止场次、不覆盖新任务。
- 队列条目已取消：恢复后释放音频占用，保留取消统计，不伪造完成。
- 同时执行旧完成和新任务替换100次：新任务状态及身份始终保留。
- Core全套 `go test ./...` 通过（发布前再次核对最终源码）。本机未安装C编译器，
  未执行Go race detector；并发回放结果不代替race detector。
