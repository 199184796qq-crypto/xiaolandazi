# 互动保留完整事实包

## 问题与修改

互动业务规划阶段原本读到了当前方案的完整正式事实，但回答生成分支用“必要商品上下文＋模型业务计划”覆盖了它。新版商品卖点快照不再写旧 `content_pools` 引用，精简读取器返回空字符串，导致正文失去两张商品卡和公共条件，事实检查也取不到这些材料。

本次回答生成保留已读取的完整事实快照。业务计划作为回答范围指导追加，不能替换事实；同一请求不重复读取或重复拼接正式快照。模拟业务核心通过 `current_facts` 使用同一完整材料。旧池仍兼容，旧必要商品卡只作为补充。互动事实检查优先读取正式版本的 `derived_safety` 审核事实，包含商品及公共条件；引用损坏、指纹缺失、资产不可读或方案不符时报错，不回退其他方案。

互动回答母版仅澄清这一事实权威关系。另修正互动日志接口漏掉 `cachedInputTokens` 参数的问题，恢复规划/正文请求与返回记录，并用编译期接口断言防止再次静默跳过。缓存命中数只用于日志，不改变任何缓存开关。

没有修改 Core、商品/卖点权重、主线四层正文、条件润色、TTS、已保存方案、事实归属或客户资料，也没有自动初始化、保存或开播。WorkBuddy 原开发目录未写入。

## 验证与局限

- 新增跨餐饮、成品/原料、家电/部件、课程服务的直播及模拟材料回归，验证业务规划存在时完整商品和公共事实仍在；覆盖正式引用损坏、跨方案拒绝、事实检查实际请求及成功/失败请求日志。
- 修改前源码通过 Go overlay 对照：新回归会复现丢事实及日志缺失；修复后全部通过。decisionexecutor 中原有失败与修改前一致；完整包不能描述为全部通过。详细 JSONL 和逐项对照位于工作区 `work/interaction-full-facts-proof`。
- 只读加载生产巴国布衣方案5/V5/id118，验证完整商品卡、337/187价格、堂食及每桌1券条件进入正文和模拟请求，真实数据库满足日志接口。没有操作客户方案或直播。
- 真实 Qwen3.7 Flash 关闭思考的五组规划＋回答共10次调用均返回可解析内容，完整有效P0均随请求携带；用券、成品/原料、家电/部件、预约条件四组人工核对符合资料。真空问题仍出现“没有宰杀和抽真空这些环节”的无依据否定，来自规划对堂食事实的过度推断。这个回放不是五组质量全通过，事实传递修复不能保证所有模型推断正确。
- 目的解析失败后 Core 将相关性回退为提问判断、事实缺口检查目前仅提示、历史决策跨场重复等问题没有在本次修改，仍需分别处理；不宣称串内容全部根治。

## 发布

发布前以服务器实际 current 的所有文件及运行进程指纹为基线，持共享锁和两次全房间空闲检查；只替换 Management 和上述一份互动回答母版。整个母版目录、行业目录、前端、手机端、Nginx、设置/模型池及客户方案资产逐项保护。实际发布结果以证明目录的 deployment-report 和 production-verification 为准。
