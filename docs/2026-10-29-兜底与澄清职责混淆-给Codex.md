# 兜底与澄清职责混淆问题说明（给 Codex）

更新：2026-10-29 16:50（北京时间）

## 一、问题一句话

当前回答链路把“系统答不了”的兜底，错误地接到了“问用户是不是这个意思”的澄清上，导致问题已经很明确时仍然反问。

## 二、真实案例

### 案例 1：今天发货？发什么快递

意图正确：

```json
{
  "purpose": "询问今天是否发货以及发什么快递",
  "task_angles": [
    {"角度": "今天的发货安排", "关联事实": ["F048", "F047", "F016"]},
    {"角度": "快递选择", "关联事实": ["F018", "F047", "F048"]}
  ]
}
```

模型实际答对过：

```text
小王老乡，咱们一般是下单后第二天上午发货，快递统一发京东物流，今天发不了。
```

但程序后处理又追加边界，或直接改反问：

```text
小王老乡，您是想问“今天发货？发什么快递”，对吗？
```

### 案例 2：这是卖什么的

3 次里出现过：

```text
正常介绍商品
您是想问“这是卖什么的”，对吗？
这个问题我这边不清楚哈，安排中控回答
```

同一意图、同一事实，回答不稳定。

### 案例 3：3号还上吗

出现过：

```text
3号链接已经上架了，可以拍。
您是想问“3号还上吗”，对吗？
空回复
```

## 三、当前兜底触发链

### 1. 回答事实为空

```text
singleAnswerFacts(item) == ""
→ generateNoFactBoundary
→ 先尝试澄清
→ 再中控
```

### 2. factbound 判定未覆盖

```go
bound := factbound.Evaluate(question, answerText, true)
```

只要有 uncovered，就可能：

```text
boundaryOrClarify
```

### 3. 答案后追加边界

`management-service/internal/decisionexecutor/interaction_single.go`

```go
if bound.NeedsBoundary() {
    text = softenTerms(text, uncoveredTexts)
    line := w.boundaryLine(...)
    text = text + "。" + line
}
```

模型已经回答“今天发不了”，程序仍因为“今天”没有独立事实而追加“今天没确认”。

### 4. 负向表达再次触发澄清

```text
answerNegativePattern 命中
且没有 answerPositivePattern
→ 澄清
```

模型说“今天不敢拍胸脯”，本意是否定，却又被当成需要澄清。

### 5. 审计/仲裁后为空

```text
factguard.Audit
arbitrateAnswerClaims
→ text 为空
→ 兜底
```

## 四、根因

### 根因 1：把“没覆盖”当成“没回答”

```text
今天没有独立事实
≠
今天这个问题没回答
```

事实是：

```text
下单后第二天上午发货
```

可以推出：

```text
今天发不了，明天上午发
```

这是 DERIVED，不是 UNKNOWN。

### 根因 2：兜底函数内部调用澄清

```text
generateNoFactBoundary
→ fallbackClarification
→ 复述原问题“您是想问……对吗”
```

兜底的前提是：

```text
系统没有事实
```

不是：

```text
用户没说清
```

系统没事实，不能反问用户“你是不是想问这个”。

### 根因 3：触发器分散

```text
回答前
factbound
审计后
仲裁后
边界追加
负向表达
```

每一层都可能触发，互相叠加。

### 根因 4：缺少统一的答案状态

没有判断：

```text
这个点到底是
已支持 / 可推出 / 已否定 / 未知 / 与事实矛盾
```

只判断字符串有没有出现。

## 五、正确职责划分

### 澄清

只在：

```text
用户表达有歧义
或缺用户才能补的槽位
```

例子：

```text
新建发货吗 → 新建区还是新疆？
没有抽真空啊 → 您是哪里的订单？
```

### 兜底

只在：

```text
问题清楚，但系统没有业务事实
或模型技术失败
```

输出：

```text
这个我这边没确认，安排中控回复你。
```

不能输出：

```text
您是想问“今天发货吗”，对吗？
```

## 六、建议的答案状态机

对问题需要的每个点计算：

```text
SUPPORTED     事实直接支持
DERIVED       可由事实/常识安全推出
NEGATED       回答明确否定
UNKNOWN       没有依据，也没有回答
CONTRADICTED  回答与事实相反
```

### 今天发货

```text
事实：第二天上午发货
问题点：今天
状态：DERIVED / NEGATED
处理：直接答“今天发不了，明天上午发”
```

### 没有抽真空啊

```text
问题点：包装方式
缺槽位：本地/外地
状态：NEEDS_SLOT
处理：问“您是哪里的订单？”
```

### 新建发货吗

```text
候选：新建区 / 新疆
状态：AMBIGUOUS
处理：候选澄清
```

### 今天能到吗（没有时效事实）

```text
状态：UNKNOWN
处理：边界/中控
不反问
```

## 七、建议的最终判定

```text
答案为空
→ 边界

模型断言了事实没有的内容
→ 修复一次
→ 仍矛盾 → 边界

关键点 UNKNOWN，且答案没有否定/替代
→ 边界

关键点 DERIVED / NEGATED / SUPPORTED
→ 通过，不追加边界
```

## 八、必须删除/改造的点

```text
1. generateNoFactBoundary 不再调用澄清
2. boundaryOrClarify 删除或只做边界
3. bound.NeedsBoundary 不再因为词没出现就追加
4. answerNegativePattern 不再单独触发澄清
5. 回答前不根据 uncovered 判死刑
6. 澄清只保留在意图歧义/缺槽位
```
