# 运维直播间、客户授权与内容模式

## 本次落地范围

- 内部人员直播间列表固定为可检索表格；客户原有布局不变。
- 具备直播间配置权限的内部人员可永久删除直播间，不以合作状态为前提。不提供恢复接口。
- 删除先写入持久清理任务，再停止所有 Core 实例的采集、音频、播放与缓存。失败时保持待清理并重试；所有实例及关联清理成功后才标记完成。
- 保留删除身份、操作审计、历史账务/用量等记录；解除设备、方案、授权关系，取消运行和配额占用。不删除其他直播间共用的方案、声音库或客户资产。
- 运维查看或修改客户智能体必须有当前人员、当前租户、当前直播间的有效授权。管理员身份不是客户授权。共享方案修改须覆盖全部关联直播间授权。
- 授权工作台复用客户方案界面，限定单直播间；运营自己的策略入口仍保留系统/行业分层策略。

## 模式与配置权限

| 模式 | 客户默认可选 | 说明 |
| --- | --- | --- |
| `ai_pregenerated` | 是 | AI话术、确认、提前生成成品声音，直播时实时互动 |
| `user_audio` | 是 | 原始录音作为主线，直播时AI实时互动；不需要先生成AI文稿 |
| `ai_dynamic` | 否 | 仅后台单独授权后显示；选择此模式并开播后，按后台参数自动局部换稿、换声音 |

客户接口只允许提交模式枚举，不接受更新周期或授权字段。高级授权撤销后有效模式回退到预生成，并停止后续自动生成；已生成的合法静态成品仍可使用，不因历史模式标记被锁死。旧版已发布录音、尚未保存模式偏好的直播间，根据已登记正式音频的来源识别为录音模式；显式模式选择优先。原始录音保持原声，切换AI互动音色不会重生成或改写录音主线。

权益状态与所选模式分开存储，并保留授权来源字段。会员权益尚未对接，不自动授予任何会员高级模式。

主线TTL、FAQ TTL、提前生成、替换比例、问答版本数、重复间隔，仅系统管理员或获得用户授权的运营可配置。默认主线和FAQ均为7200秒、主线每批约25%，提前600秒准备。仅开通权益不会切换模式或开播。

## 实际更新链路（2026-10-04）

1. management 启动持久任务调度器，扫描当前运行、已授权且选择动态模式的直播间。静态预生成与原始录音模式不参与主线更新。
2. 从开播或上次实际更新（取较晚者）计算两小时。提前生成阶段只建立 `prepared` 版本，不改发布关系；未到期不得向 Core 提交。
3. 从每条正式声音的语义时间轴选取约25%的连续片段，循环轮换位置。只改写这些文字、只合成这些声音，其余PCM保持原样。25%不会因只有一条声音而变成全量重生成。分段不足、格式不兼容或事实检查失败时保留原成品。
4. 使用已发布、用户确认的主播风格快照（称呼、口头禅等）和当前正式事实/规则。新分析但尚未发布的风格草稿不会直接进入直播。保留部分也需通过当前事实检查；旧价格等失效时要求人工确认重发。
5. 每条正式稿完成后保存检查点；全部完成后才准备新版本。进程重启可恢复已完成稿件，不重新合成这些成品。未完成的单条模型调用仍可能因网络失败重试，不能保证外部付费API严格一次。生成阶段最多5次尝试，耗尽后需处理原因并重新发布或调整后台策略，不无限重试扣费。
6. 到期后 Core 在整条当前音轨和已排队下一条旧音轨播完后应用新列表，不重启直播、设备或计费。确认已应用后才写正式发布关系，下一次周期从实际生效时间起算。因此不是两小时时刻硬切音频。
7. 生成、应用、撤销分离执行；短租约、版本和节目ID比较保护并发。停播、删房、撤权、切模式、手动换方案、事实/规则变化使旧任务失效。管理每次续期重新校验，Core待生效请求30秒内不续期即在边界丢弃。授权核验与播放边界间仍有短暂竞态，已播内容不会倒退。
8. 授权运营面板显示最近更新状态与错误原因；后台任务、成品和应用/取消事件均留痕。不物理删除可能仍被Core使用的声音资产。

FAQ缓存已接入真实问答执行器：按租户、直播间、场次及完整事实/风格/规则上下文隔离，默认最多3个回答版本，最短重复间隔20分钟。只缓存无点名的适用问题；到期后按需生成，不为空闲问题预先付费生成。命中不延长原文2小时寿命；音色变化或签名地址过期只重新合成需要的声音；命中仍需终审。进程重启/leader切换会丢弃内存缓存并重新生成，不使用过期内容。

局部更新还会在付费生成前核对原音频归档的 `voice_id`、`tts_model`、`voice_rate` 与已发布声音身份。切换实时音色或语速不会改变已有PCM，因此不一致时必须重新生成并发布整套正式声音，不能将新音色/语速的25%混入旧声音。历史音频若没有可靠的原始语速记录，仍可正常播放和校对字幕，但首次启用局部更新前需重新生成并发布一次；系统不会猜测为1.0。新生成和更新后的归档、manifest均保存实际语速，字幕校对只保留已知原始语速。

`minimum_buffer_seconds` 的设置字段保留为后续非循环音频储备管理参数，本次循环成品替换不依赖它；播放始终保留旧列表作为失败保底。

## API 与数据

- `GET/PUT /api/v1/system/live-content-policy`：系统默认配置。
- `GET/PUT /api/v1/liveops/rooms/{roomID}/content-policy`：用户授权下的运营配置和高级模式开通。
- `GET/PUT /api/v1/live/rooms/{roomID}/content-mode`：当前可用模式和客户选择。
- `DELETE /api/v1/rooms/{roomID}`：完成返回204，已排队但未完全清理返回202及 `deletion_pending`；202不代表资源已经全部释放。
- 新表：`live_content_policies`、`live_room_content_access`、`mgmt_room_deletions`、`live_content_refresh_jobs`、`live_content_refresh_events`，由服务启动迁移创建。
- 更新策略使用版本比较，并校验读取时的 `expected_mode`，避免旧运营页面覆盖客户刚切换的模式；操作与审计同事务，房间级保存与删除互斥，避免删后重新生成配置。
- 内部协助请求使用 `X-Live-Support-Room-ID` 明确房间范围；媒体播放使用受限同源URL的 `support_room_id`。这些值只是范围，不是授权，服务端仍核验当前有效授权。

## 发布前验收

1. 测试账号无授权：表格不出现“直播策略”，手工打开地址或直接请求配置返回拒绝。
2. 用户授予房间A权限：只能查看A；不能修改未授权B或借共享方案影响B。用户撤销后刷新/下一次请求拒绝，前端自动清除工作台。
3. 新客户仅两种模式；通过接口提交高级模式、更新参数、授权标记不能越权。开通、选择、撤销高级模式分别核对前后端一致。
4. 旧版原始录音可恢复；新录音无需AI文稿可保存发布；录音模式不显示AI重生成声音。
5. 删除专用测试直播间：验证采集/声音停止、设备解绑、用量不继续增长、账务和操作记录保留。一个Core不可用时返回待清理，恢复后自动完成；重复删除可安全重试。
6. 新增回归验证两阶段发布、约25%替换保留其余PCM、到期前不应用、Core重试不重跑已完成生成、撤权/换方案拒绝旧结果、FAQ绝对TTL与签名过期。真实设备零间隙及真实模型音色效果仍需单独验收。

本轮生产授权操作仅针对房间15/租户14“菜籽油”：开通高级模式，保留 `user_audio`，未开播；全局默认7200/7200/25。没有删除客户直播间，也未为该房间发起付费生成。
