# 话术改写上次上下文

状态：本地实现和验证，未提交、未部署。基线 b45cc7713af38a69d8a145545fc94cd128cf4b57。

用户要求：每次保留模型返回的上下文，下次生成时提供上次上下文，请模型尽量避开已采用的表达安排。

## 返回与播放

支持模型按文本 KV 返回三个字段，不要求 JSON：

```text
话术骨架：本次讲述安排
一句话上下文：本次切入角度、重点和组织方式的一句话记录
改写内容：可直接念出的正文
```

允许字段之间有空行、CRLF、中文或英文冒号，字段值里的冒号保留。只有 `改写内容` 进入原有 P0 检查、局部修正、共享正文及声音合成链路。骨架和上下文不会被念出。后台独立改写 API 另返回 `context`；已有 `skeleton` / `script` / `model` / `usage` 不变。

兼容旧的“话术骨架／话术内容”以及纯正文响应。三个新 KV 缺项、重复或混用两个正文字段时拒绝，不将整份元数据兜底当正文。旧格式没有上下文时保留空值，不把更旧的简介冒充本次记录，也不额外调用模型补简介。

## 下一次请求

每次接受有效正文后，在现有媒体根目录下保存一份最新记录：

```text
MEDIA_ROOT/script-rewrite-contexts/<tenant>/<plan>/<original-sha256>-<facts-sha256>.json
```

记录包含范围、骨架、上下文、对应的接受正文及时间。使用现有原子 JSON 写入方法和 0600 文件权限。后台在共享正文保存后、开始 TTS 之前保存记录，所以随后合成失败不丢失上下文。手动改写入口同样保存、读取该记录。读取失败或索引范围不匹配时保留文件，本次不购买新改写。

范围按租户、方案、去除首尾空白的原始样本文本和冻结事实区分，不按主播声音区分。原始样本或事实改变时使用新的范围；同一方案里完全相同的原文和事实共用记录。仅切换音色、模型或修改规划，不清空已经采用的表达记录。

下次实际请求注入上次骨架和一句话上下文，不传上一条完整正文，也不无限累加历史。优先填入方案已有的 `{{近期写作记录}}`；旧提示词没有这个占位符时，在请求末尾补同一份记录。保存的客户提示词、规则原文及 `【样本话术】` 占位符不被改写。

记录说明使用集中模板 `configs/prompts/anchor-style/rewrite-previous-context.md`，可通过 `SCRIPT_REWRITE_PREVIOUS_CONTEXT_PATH` 指定。模板要求在事实、人设和红线内，尽量调整切入角度、重点组合、顺序、句式或结尾；允许事实含义相同，不靠改变事实制造差异。没有新加产品专用规则、词语黑白名单或 P0 例外。所有运行时占位符单次替换，样本和元数据中恰好出现占位符的字面文本不会互相替换。

同一范围在单个 Management 进程内按“读记录→调用模型→保存记录”串行；不同范围互不等待。排队可取消，空闲锁回收，TTS 不持有该锁。没有改全局生成并发、播放池容量、费用闸门、换声、淘汰比例或已有声音复用规则。复用旧声音不触发记录更新，也不增加模型调用。
