# 直播间内设备选择与绑定

状态：2026-10-11 已发布 `20261011-room-device-bindings-dbab61b`，源码 `dbab61b9d7fd72d8c93745a2158d8b2af627f97b`。服务、设备接口鉴权、公网实际加载的 JS/CSS/API 文件及107份母版校验通过；Core和设备网关保留原进程与二进制。本次发布没有替用户执行设备绑定。

直播间控制页的小蓝盒子卡片顶部显示设备绑定模块。尚未绑定时显示一行设备选择、绑定按钮及角色选择；房间内已有设备时，每台设备显示独立一行，底部保留新增设备行。设备名单按当前房间租户筛选，绑定结果和主设备状态分别通过原设备列表与房间运行接口刷新。

第一台设备自动为主设备；新增设备默认监听，也可明确选择主设备。已绑定监听设备选择主设备后立即保存；原主设备在同一数据库事务中降为监听。现有主设备的监听选项禁用，用户通过提升另一台设备完成主设备切换。重复点击绑定不会并发提交；失败恢复原角色，旧轮询不能覆盖刚完成的绑定，切换房间或离开页面后忽略旧请求结果。

复用原 `POST /api/v1/live/devices/{id}/bind`，增加可选 `replace_primary`。只有显式选择主设备的房间内操作发送该标记；原设备管理页面及旧调用保留“加入已有主设备房间默认监听”的行为。身份、设备归属、可用房间、正在运行的直播任务、租户锁与自动角色迁移均沿用原绑定事务。AI直播运行期间先停止任务再调整绑定，监听权限没有扩大。

验证：DB角色兼容及显式替换测试、HTTP/模型包测试通过；新模块浏览器测试覆盖租户过滤、首次绑定、多行、已有与新增主设备替换、失败恢复、旧轮询、运行保护和房间切换。隔离发布前端构建通过，实际房间页面在1680、1100和390宽度下控件无溢出，原设备管理页面浏览器回归通过。浏览器验证全部使用本地测试数据，没有修改客户设备绑定。
