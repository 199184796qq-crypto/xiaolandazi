# 直播间内设备选择与绑定

状态：2026-10-11 已发布 `20261011-room-device-bindings-dbab61b`，源码 `dbab61b9d7fd72d8c93745a2158d8b2af627f97b`。服务、设备接口鉴权、公网实际加载的 JS/CSS/API 文件及107份母版校验通过；Core和设备网关保留原进程与二进制。本次发布没有替用户执行设备绑定。

直播间控制页的小蓝盒子卡片顶部显示设备绑定模块。没有名下设备时隐藏模块；只有一台设备时自动选中该设备。两台及以上仍默认只有一行，优先显示当前房间主设备，其它已绑定设备可从下拉框选择或点击左侧“＋”增加一行显示。每行右侧“－”减少选择行，至少保留一行，减少选择行不执行解绑。刷新、绑定和解绑都不会自动追加空白行。设备名单按当前房间租户筛选，同一设备不能在多行重复选择。

所选设备未绑定到本房间时显示“绑定”，已绑定时显示“解绑”，复用原解除绑定接口。解绑主设备后由后台自动提升可用监听设备并刷新角色及主设备状态。第一台设备自动为主设备；新增设备默认监听，也可明确选择主设备。已绑定监听设备选择主设备后立即保存；原主设备在同一数据库事务中降为监听。现有主设备的监听选项禁用，用户通过提升另一台设备完成主设备切换。重复点击不会并发提交；失败恢复原角色，旧轮询不能覆盖刚完成的绑定，切换房间或离开页面后忽略旧请求结果。

复用原 `POST /api/v1/live/devices/{id}/bind`，增加可选 `replace_primary`。只有显式选择主设备的房间内操作发送该标记；原设备管理页面及旧调用保留“加入已有主设备房间默认监听”的行为。身份、设备归属、可用房间、正在运行的直播任务、租户锁与自动角色迁移均沿用原绑定事务。AI直播运行期间先停止任务再调整绑定，监听权限没有扩大。

验证：初版DB角色兼容及显式替换测试、HTTP/模型包测试通过；新版浏览器测试覆盖零/一/两/多台设备的默认显示、手动增减行、重复设备过滤、绑定解绑切换、主设备替换及解绑后的提升、失败恢复、旧轮询、运行保护和房间切换。隔离发布前端构建通过，实际房间页面在1680、1100和390宽度下控件无溢出。浏览器验证全部使用本地测试数据，没有修改客户设备绑定。本次界面修正复用现有后台接口。
