# 批量界面清理与财务邀请查询（2026-09-24）

## 对照用户标注的改动

1. 后台智能体删除名称下方的工作域说明和整块常驻能力标签；保留对话/我的待办及实际能力。终端已有的无待办、英文副标题、18px 正文和居中圆角发送保持。
2. 客户收款确认不再常驻显示分人/不分人模式说明。超级系统管理员的配置入口移至标题操作区；读取配置失败时仍显示错误和重试，不隐藏真实办理障碍。
3. 资金与权益审批删除标注的重复说明，保留业务标题、充值/退款/奖励/时长简述与客户收款入口。财务操作删除审计与钱包流水的常驻提示；实际审核策略、财务流水和审计写入均未改动。
4. 我的待办改为轻量分组切换与浅色筛选栏：正文18px，辅助16px，红底白字待办角标，选中蓝底白字、悬浮蓝光；下拉与18px复选框同排居中，窄窗口自动换行。空状态采用小图标和明确的当前已接入业务范围提示。移除底部长篇办理说明。
5. 收款表金额、状态、时间所在单元格顶部对齐，状态标签下的实际审核备注保留并左对齐。历史卡片按标题/正文/底部经办人时间排版。
6. 仅在历史呈现中精简 review_policy 事件的“不强制分人，按审核权限办理”前缀，保留同一人办理的实际事实；数据库原始审计事件不修改。

## 财务“邀请与推荐”

入口：财务管理/财务部 → 邀请与推荐；财务与结算首页也可进入。
路由：`/staff/finance/invitations`。

使用现有 `finance.dashboard.view` 财务查看权限；不因主部门是仓储、销售等就阻挡已经获授权的兼岗人员。外部客户、代理和没有财务查看权限的人员不能访问财务查询。没有分配新的写入权限，也没有更改岗位授权记录。

财务页复用既有邀请关系与客户资料，提供服务器分页、搜索、认定状态筛选和表格/卡片切换。展示邀请人、被邀请客户、来源、邀请码、注册时间、首次财务确认收款和对应时间。查询不会生成个人邀请码。

每条记录可进入客户收款、资金记录，或查看关联订单产生的已有奖励/提成、实际受益人、规则版本、退款冲回和结算批次。关联订单收益不一概认定属于邀请人，页面明确显示受益人。没有产生收益记录时如实显示空记录，不估算应发奖励。

奖励审批与收益结算链接仍进入原业务模块。新功能仅增加读取接口：
- `GET /api/v1/staff/finance/invitations`
- `GET /api/v1/staff/finance/invitations/{invitationID}/earnings`

不复制邀请来源、不冒用管理员身份、不修改邀请码、营销规则或客户归属，也不自动发放资金。当前读取权限沿用现有财务账户的全系统业务可见范围；不是新建任意租户参数的越权接口。

## 查询与验证边界

列表以参数化查询检索且最多100条/页，确认信息只对当前页做一次批量查询，不逐行查库。收益明细按邀请记录确定关联客户，再通过订单读取，每次分页。接口检查登录与财务查看权限并使用 no-store。

隔离 MySQL 测试在随机前缀表中验证14条分页、财务兼岗权限、首次确认、邀请人/邀请码检索、恶意搜索字符串、原个人推荐范围及奖励/退款/冲回/结算依据；不使用真实客户或财务业务表。

浏览器测试使用独立 Chrome 目录和模拟 API/推送，检查18px、筛选对齐、选中悬浮、窄屏布局、历史卡片对齐、删字不删记录、财务邀请入口、分页、卡片和证据弹窗，以及终端简化不回退。浏览器测试不是实际员工凭据和真实付款的验收。

本轮不提交 Git，不推远端。生产构建、本地服务更新和最终健康检查分别记录，以实际命令结果为准。
