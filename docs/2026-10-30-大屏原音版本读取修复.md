# 大屏原音方案开播前读取失败

2026-10-30，用户点击大屏“开始”后显示“无法启动直播搭子／读取直播间已发布智能体版本失败”。

## 根因与修复

大屏先请求 `GET /api/v1/rooms/{roomID}/live-agent-plan/published-version`，成功后才启动播音。该接口调用 `GetPublishedLiveAgentPlanVersionForRoom`。原 SQL 联结当前方案选择后，对包含整段录音、时间轴和生成上下文的完整 JSON 行按 ID 排序，再取一行。MySQL filesort 会携带大字段，`LIMIT 1` 仍可能报 1038 排序内存不足。

上一轮修复的是方案工作区列表查询，未覆盖这个独立的大屏读取入口；之前的 Core 原音播放测试也不能替代这个入口验证。

本次改为同一条 SQL 内仅聚合符合条件版本的最大 ID，再读取这一行，不排序录音 JSON。保留当前房间的方案选择、租户隔离、有效状态集合（draft/published/superseded）、方案共享、历史 room_id 来源和语速覆盖；prepared/abandoned 不参与。单条查询避免拆成两次读取后遇到并发切方案时拼错范围。

两个旧版方案指针辅助路径也去除完整 JSON 排序，显式比较 ID 选择每种内容模式的最新版本，不依赖数据库返回顺序。不增加索引、迁移或全局排序内存参数。
