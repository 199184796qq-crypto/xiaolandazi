# 小蓝直播搭子：向量语义记忆与检索层落地方案

> 项目：小蓝直播搭子  
> 日期：2026-10-01  
> 状态：实施基线  
> 目标：先建立统一向量能力，再逐步改造问题聚类、长期纠正记忆、参考回答检索、直播素材检索和近期口播语义去重。

---

## 1. 核心结论

小蓝直播搭子不需要把现有业务改造成“纯 RAG 系统”，而应该增加一层独立的 **语义记忆与检索层（Semantic Retrieval Layer）**。

四类能力必须严格分工：

- **MySQL：存确定的真相**。价格、库存、快递、发货时间、活动有效期、正式事实、方案版本、权限、订单等仍以结构化数据为准。
- **Redis：存实时状态**。直播间在线状态、事件桶、短期问题桶、任务队列、角标、短期缓存等继续走 Redis。
- **向量索引：存“可能相关的记忆”**。负责相似问题、历史纠正、已采纳回答、话术素材、近期口播的语义检索。
- **大模型：负责理解和表达**。模型使用检索到的少量高相关上下文生成自然口播，但没有执行权，也不能把向量命中结果直接当正式事实。

> 向量检索只能回答“什么可能相关”，不能回答“什么一定是真的”。

---

## 2. 第一阶段改造范围

第一阶段只改造五类高收益场景，不碰资金、权限、扣费、库存和确定性状态机。

### 2.1 公屏问题语义聚类

解决：

- “多少钱”
- “什么价”
- “今天卖好多钱”
- “这个怎么卖”

文字不同但实际是同一个问题的问题桶聚合。

链路：

```text
公屏事件
  ↓
文本预处理
  ↓
Embedding
  ↓
当前直播间活跃问题桶相似度匹配
  ↓
命中已有桶 / 新建问题桶
  ↓
累计人数、次数、热度、最近时间
  ↓
互动策略决定是否生成回答任务
```

约束：

- 向量只参与“归哪个桶”，不决定任务优先级；
- 人工抢答仍然必须进入最高业务优先级；
- 当前场次问题桶优先使用短期缓存，不强制长期保存所有弹幕向量。

### 2.2 用户纠正与长期记忆

适合向量化：

- 语义纠正；
- 用词纠正；
- 风格纠正；
- 回答偏好；
- 用户对主播表达的自然语言调教。

例如：

- “娃娃”在这个直播间指小孩；
- 不要一直喊“宝宝们”；
- 油的用途不要说“喝”，说“炒菜 / 做饭 / 食用”；
- 这种问题回答短一点。

查询链路：

```text
当前问题 / SpeechMission
  ↓
Embedding
  ↓
按 tenant/customer/room/plan/version/status 过滤
  ↓
相似度检索
  ↓
Top 3~8
  ↓
加入用户层上下文
```

事实类纠正一旦正式采纳，必须写入正式事实模型；向量副本只用于召回，不作为最终事实源。

### 2.3 已采纳参考回答检索

目标：优先复用用户已经认可过的回答方式。

```text
观众问题
  ↓
问题向量
  ↓
搜索当前方案已采纳问答
  ↓
取最相似的参考回答
  ↓
正式事实校验
  ↓
大模型按当前直播语境重组
  ↓
终审
  ↓
TTS
```

要求：

- 只召回“已采纳 / active”的参考回答；
- 历史回答中出现的价格、规格、活动等信息不能直接升级为当前事实；
- 新版本覆盖旧版本后，旧向量必须停用或降权。

### 2.4 直播素材 / 逐字稿 RAG

适合：

- 自己过去的直播稿；
- 优秀逐字稿；
- 已确认生成稿；
- 用户上传长文本；
- 录音转写后的内容。

处理：

```text
原始素材
  ↓
按语义段落切块
  ↓
Embedding
  ↓
保存 chunk + metadata + vector
  ↓
当前讲解主题发起检索
  ↓
Top K 相关段落
  ↓
加入话术参考上下文
```

这里的素材主要提供组织方式、讲解路径、转场和表达案例，不能自动成为正式事实。

### 2.5 近期口播语义去重

目标：解决“文字不一样，但主播刚刚其实已经说过”的重复问题。

例如：

- “我们这个油炒菜特别香”
- “拿来炒菜香味是很足的”

字符串不同，语义高度重复。

链路：

```text
生成候选正文
  ↓
切句 / 切语义段
  ↓
Embedding
  ↓
对比本直播间最近 3~10 分钟已播内容
  ↓
高相似命中
  ↓
删除 / 换角度重写 / 降低重复内容
  ↓
事实与合规终审
  ↓
TTS
```

近期口播向量属于短期记忆，可设置 TTL，不需要永久保留。

## 3. 不使用向量模型的业务

以下业务继续使用确定性程序逻辑：

- 价格；
- 库存；
- 快递；
- 发货时间；
- 售后条件；
- 活动是否过期；
- 时长卡扣费；
- 钱包余额；
- 返佣；
- 订单；
- 权限；
- 登录；
- 抢答任务优先级；
- 直播开始 / 暂停 / 停止；
- Core 生命周期；
- 设备状态；
- 审计日志；
- TTS voice_id；
- 平台硬性规则。

这些内容不能因为“向量相似”而被修改。

## 4. 统一语义层接口

业务代码不能直接绑定某一家向量供应商。

建议新增：

```text
SemanticStore
├─ EmbedTexts()
├─ UpsertDocuments()
├─ DeleteDocuments()
├─ SearchSimilarQuestions()
├─ SearchCorrections()
├─ SearchReferenceAnswers()
├─ SearchMaterials()
└─ SearchRecentSpeech()
```

底层再拆：

```text
EmbeddingProvider
├─ QwenEmbeddingProvider
└─ FutureProvider

VectorRepository
├─ MySQL/Vector 扩展或独立向量库
└─ FutureVectorRepository
```

这样后续可以替换模型和存储，不影响上层 Agent。

## 5. Embedding Provider 设计

统一输入：

```go
type EmbedRequest struct {
    Texts []string
    Purpose string
}
```

统一输出：

```go
type EmbedResult struct {
    Vectors [][]float32
    Model string
    Dimensions int
}
```

配置建议：

```env
SEMANTIC_ENABLED=true
EMBEDDING_PROVIDER=qwen
EMBEDDING_MODEL=<当前选定模型>
EMBEDDING_DIMENSIONS=1024
EMBEDDING_API_KEY=<复用现有安全密钥注入方式>
EMBEDDING_BASE_URL=<供应商接口地址>
SEMANTIC_TIMEOUT_MS=2500
SEMANTIC_BATCH_SIZE=32
```

要求：

1. API Key 只能在服务端；
2. 前端不得拿到 Embedding Key；
3. Provider 必须支持超时、批量、重试和熔断；
4. Embedding 失败不能阻塞直播主链；
5. 可降级回关键词 / 规则 / 原有逻辑；
6. 记录调用量、耗时、失败率，但日志不得写完整密钥。

## 6. 向量文档统一数据结构

建议统一 metadata：

```text
id
tenant_id
customer_id
room_id
plan_id
content_type
source_id
source_version
status
text
text_hash
embedding_model
embedding_dimensions
created_at
updated_at
expires_at
```

content_type 第一阶段固定：

- `question_cluster`
- `correction`
- `reference_answer`
- `material_chunk`
- `recent_speech`

隔离规则：

1. 所有检索必须先按 tenant_id 做硬过滤；
2. 有客户归属时继续过滤 customer_id；
3. 直播方案内容优先过滤 plan_id；
4. 直播间短期内容必须过滤 room_id；
5. 禁止跨租户相似度搜索；
6. 禁止把 A 客户召回内容注入 B 客户 Prompt；
7. 所有 source_version / status 必须参与有效性判断。

## 7. 相似度与 Top K 实测校准参数

2026-10-01 已使用真实 `qwen3.7-text-embedding-flash`、1024 维接口对中文直播短句、纠正记忆、参考回答、长素材和口播改写进行第一轮实测。该模型的余弦分数整体明显低于最初按经验预估的 0.7~0.9 区间，因此阈值已按真实返回值下调。

当前代码参数：

```text
问题桶：
候选阈值 = 0.40
说明：这里只做高召回预筛，后面仍由大模型确认是否真正合并。

纠正记忆：
TopK = 8
最低阈值 = 0.42
至少保留排名最高的 3 条候选；正式 fact 不参与向量淘汰。

参考回答：
TopK = 5
最低阈值 = 0.43

话术素材：
TopK = 6
最低阈值 = 0.32
说明：短问题对长素材块的相似度天然更低。

近期口播去重：
最近窗口 = 10 分钟
弱重复阈值 = 0.60
强重复阈值 = 0.78

Core 回归点语义去重：
触发阈值 = 0.66
候选回归点阈值 = 0.58
```

第一轮真实样本中：

- “这个多少钱” ↔ “什么价”：约 0.666；
- “我们这个油炒菜特别香” ↔ “拿来炒菜香味是很足的”：约 0.705；
- “我们家默认发顺丰” ↔ “下单之后默认走顺丰快递”：约 0.787；
- “这个多少钱” ↔ 一段包含当前价格的较长素材：约 0.449；
- “发什么快递” ↔ 对应物流参考回答：约 0.528；
- 明显不相关样本大多约 0.19~0.43。

因此不能把 0.8 以上作为通用“相似”门槛。后续仍需用真实直播日志持续做误召回 / 漏召回统计，并按 scene 单独调参，不能把上述阈值视为永久规则。

## 8. 与 SpeechMission 的整合

SpeechMission 黑板增加一个只读字段：

```text
semantic_context
├─ relevant_corrections
├─ reference_answers
├─ material_chunks
└─ recent_similar_speech
```

最终上下文建议：

```text
SpeechMission
+ 当前直播方案
+ 正式事实依据
+ 当前有效活动
+ 规则层
+ 行业层
+ 用户层
+ 主播风格
+ 语义检索上下文
+ 近期说话历史
```

约束：

- 正式事实优先级高于所有向量召回内容；
- 用户最新明确纠正高于历史纠正；
- 过期活动不能因历史向量命中而重新进入 Prompt；
- 语义层只提供少量上下文，避免 Prompt 无限增长。

## 9. 写入时机

### 9.1 correction

用户采纳纠正后异步写入或更新向量。

### 9.2 reference_answer

参考回答“采用”后写入向量；取消采用、删除、版本替换时同步停用。

### 9.3 material_chunk

素材上传、转写、分析完成后切块并批量向量化。

### 9.4 recent_speech

真正进入播出链的正文，在确定播放后写入短期向量缓存；未播出的草稿不能算“已说过”。

### 9.5 question_cluster

当前直播间问题桶只维护代表向量；新弹幕先与代表向量比对，再决定聚合或建桶。

## 10. 一致性与更新策略

采用最终一致性：

```text
业务数据写入成功
  ↓
提交 semantic indexing job
  ↓
异步生成 embedding
  ↓
upsert vector
```

如果向量写入失败：

- 不回滚正式业务数据；
- 任务进入重试；
- 达到重试上限写入失败队列；
- 业务继续使用原有逻辑；
- 后台可查看语义索引状态。

需要保存 text_hash，文本没有变化时不要重复生成向量。

## 11. 成本控制

向量模型成本不是第一约束，仍需做好调用优化：

1. 相同文本按 text_hash 去重；
2. 批量生成 embedding；
3. 历史素材使用 Batch 模式时优先批处理；
4. 只给需要语义能力的数据建索引；
5. 公屏短文本优先缓存；
6. 已经命中当前问题桶的重复文本不重复建长期向量；
7. 近期口播设置 TTL；
8. 每个租户统计 embedding token / 次数 / 失败率。

成本统计至少记录：

```text
tenant_id
scene
model
input_tokens
request_count
success_count
failed_count
latency_ms
date
```

## 12. 降级策略

任何语义服务故障都不能让直播停下来。

### 问题聚类降级

```text
向量不可用
→ 关键词 / 归一化文本 / 原有问题桶逻辑
```

### 纠正记忆降级

```text
向量不可用
→ 只加载结构化正式纠正 + 最近明确上下文
```

### 参考回答降级

```text
向量不可用
→ 不召回历史答案，继续正常生成
```

### 近期去重降级

```text
向量不可用
→ 保留现有字符串重复检查
```

不得因为 Embedding 接口超时阻断 TTS。

## 13. 安全边界

1. 租户隔离必须在向量搜索过滤层强制执行；
2. 不把系统提示、密钥、密码、Token 建入向量库；
3. 不把完整用户隐私信息当普通记忆长期保存；
4. 删除客户数据时必须联动删除向量；
5. 删除方案、删除素材、撤销采纳时必须使对应向量失效；
6. Prompt 中只能注入业务需要的文本片段；
7. 向量召回内容仍然必须经过终端输出保护和事实校验。

## 14. 第一阶段代码落地顺序

### P0：基础设施

- 新增 semantic 包；
- 抽象 EmbeddingProvider；
- 接入 Qwen Embedding Provider；
- 增加配置；
- 增加批量 embedding；
- 增加超时和降级；
- 增加单元测试。

### P1：近期口播语义去重

原因：对当前“主线 / 打断 / 回归重复”问题收益最直接，业务风险低。

- 播出后写入 recent_speech；
- 生成正文后检索最近语义；
- 高相似时触发现有快速重写；
- 向量不可用时继续走现有字符串重复检查。

### P2：纠正记忆召回

- 已采纳学习记录写入向量；
- 生成前按当前问题召回 Top K；
- 严格区分“纠正记忆”和“正式事实”。

### P3：已采纳参考回答

- 采用时建索引；
- 观众问题到来时召回；
- 结果作为参考，不直接复制；
- 继续执行事实终审。

### P4：问题桶语义聚类

- 为问题桶维护代表向量；
- 替换纯字符串相似逻辑；
- 与现有互动策略和强制任务规则兼容。

### P5：直播素材 RAG

- 素材切块；
- 批量索引；
- 方案生成和直播场景按主题召回。

## 15. 第一阶段验收标准

基础能力：

- [ ] Embedding Provider 可独立切换；
- [ ] 配置关闭后系统完全退回原逻辑；
- [ ] Provider 失败不会阻断直播；
- [ ] 支持批量 embedding；
- [ ] 支持 text_hash 去重；
- [ ] 租户隔离测试通过。

近期口播：

- [ ] 同义句重复能被识别；
- [ ] 正常承接语句不会大量误杀；
- [ ] 向量服务失败时字符串去重仍工作；
- [ ] 只索引真正播出的内容。

长期记忆：

- [ ] 已采纳纠正可被相似问题召回；
- [ ] 未采纳内容不会进入正式记忆；
- [ ] 已停用 / 旧版本不会进入 Prompt；
- [ ] 正式事实始终覆盖历史向量召回的冲突信息。

参考回答：

- [ ] 同义问题可找到历史已采纳回答；
- [ ] 历史回答中的过期价格 / 活动不会覆盖当前正式数据。

## 17. 当前实施决定

第一版执行以下决定：

1. 不建设独立“向量知识库产品页面”，先作为底层公共能力；
2. 上层统一通过 SemanticStore 使用，不直接调用模型；
3. 第一版默认使用 Qwen 系 Embedding Provider，但 Provider 可替换；
4. 优先接近期口播语义去重，再接纠正记忆和参考回答；
5. 正式事实继续使用现有 MySQL 数据结构；
6. 向量不可用时所有直播核心链路必须可继续；
7. 任何向量召回内容进入 TTS 前仍然经过事实、合规、用户纠正和重复检查。

## 19. 生命周期清理规则（2026-10-01 已落地）

向量是业务派生数据，生命周期必须跟随原始业务对象，不能留下“幽灵记忆”。当前统一规则：

- 删除直播间：删除 `tenant_id + room_id` 范围内全部语义文档；不删除同方案的 plan 级向量，因为同一个方案可能仍被其他直播间使用。
- 归档直播方案：删除 `tenant_id + plan_id` 范围内全部方案级语义文档。
- 停用已采纳话术参考：同步删除该 `reference_answer` 的语义文档。
- 删除客户登录账号但 tenant 仍有其他用户：保留 tenant 全部语义数据。

- `recent_speech` 等带 `expires_at` 的短期向量：查询时忽略过期数据，并由集群 leader 每 15 分钟物理清理过期行。
- 历史订单、支付、退款、扣费、运行账本和审计记录不属于语义派生数据，不随房间向量清理。

### 20.1 运维命令

环境中须设置 `SEMANTIC_ENABLED=true` 与 `DASHSCOPE_API_KEY`；默认关闭，不能只配置密钥就认为已启用。管理服务启动时调用 `MigrateLiveRuntime`，应先在目标 MySQL 的备份/预发库验证唯一键迁移，再开启生产语义开关。

在 `management-service` 目录运行以下命令。维护工具默认只读；`--apply` 才写入索引并将该精确范围内不再存在的旧版本标记为 `superseded`，`--force` 会重新请求全部向量，可能产生额外费用：

```powershell
go run ./cmd/semantic-maintenance --tenant 1 --plan 2 --type material_chunk
go run ./cmd/semantic-maintenance --tenant 1 --plan 2 --type material_chunk --apply
go run ./cmd/semantic-maintenance --tenant 1 --plan 2 --type reference_answer --apply
go run ./cmd/semantic-maintenance --tenant 1 --room 3 --type correction --apply
go run ./cmd/semantic-maintenance --tenant 1 --plan 2 --type material_chunk --apply --force
```

回放输入是每行一个 JSON 对象，字段为 `scene`、`query`、`candidate`、`same`（人工标注是否应判为同义）；工具只输出汇总混淆矩阵，不回显原句：

```powershell
go run ./cmd/semantic-replay --input .\internal\semantic\testdata\replay_examples.jsonl --scene recent_speech --threshold 0.60
go run ./cmd/semantic-replay --input <已脱敏的真实标注文件.jsonl> --scene question_cluster --threshold 0.40
```

`/metrics` 中可用 `livecompanion_management_semantic_embedding_latency_seconds_bucket` 计算 P95；`livecompanion_management_semantic_retrieval_hits_total / livecompanion_management_semantic_retrievals_total` 是各场景召回命中率。所有计数为进程内计数，重启后归零。回放样例仅供工具自检，不能据此调生产阈值。
