# 当前主线话术生成链路

核对日期：2026-10-21；以仓库实现及明确的发布回执为依据。旧2026-10-14架构已归入[历史原文](archive/2026-10-21/retired/话术生成链路架构.md)，其“厚system、每段固定四次调用、1000字回灌”不再是当前执行规范。本次文档整理没有部署；服务器运行版本需另核对。

## 从方案准备到本场任务

1. 资料分析生成候选，用户确认形成商品、活动及正式事实等资产；初始化与保存不是开始播放。
2. 开播读取本方案正式版本、有效事实、任务/角度、可选主播风格及声音，冻结本场快照。事实正文、分类、禁说、安全改写和来源关联一并进入事实工厂。
3. 调度器逐段选商品/公共任务、卖点、角度及侧面。公共20%与商品80%、商品最大偏好比1.2、卖点1.3均按有效采纳主体段核查；开场/收口另计，不能按所有模型请求计比例。

任务与事实必须对应。只提供本次有事实支撑的内容，公共条件不因存在于资料中就成为每段必读尾巴。详见[事实工厂与四层结构交接](2026-10-19-主线话术四层结构与事实工厂-定稿与落地交接.md)和[滚动调度](2026-10-19-滚动权重与防连续讲解修复.md)；交接中的实测token、当时未发布状态只代表其记录时点。

## 生成请求与首次开场

当前渲染器围绕单条user JSON组织内容四层：**必说、本段可说事实、不提/红线、改写指导**，风格以可选腔调卡提供。不能把事实限制、禁说或改说散在无效字段后认定模型已经受约束，也不能将禁说例子的数字当可用规格。

每场首次完整开场先选材再写正文，程序轮换卖点/开场方式，模型选候选角度；历史只用于程序去重，不把完整旧开场喂给模型抄写。首开必须新文字和新TTS。正常两次调用不含可能的重复重生成、复核或失败重试，详见[首次开场](首次开场话术生成逻辑方案.md)。

后续普通opening/body/closing先检查[成品库](话术库复用机制设计方案.md)。命中当前合格文字可省正文调用；完整声音包同时匹配才省TTS。空库、冷却、事实变化或凭据失效会正常转新稿，不能为达比例放宽事实边界。

## 候选、检查与采纳

正文返回后保留模型原文，按当前配置执行解析/本地检查、可选风格评分和显示标点处理。程序采纳后才推进主线配额和游标，重试/退稿不另占名额。

- `SkipReview=true`：不执行被跳过的模型复核，以实际程序采纳签发 `generation_accepted`，不能伪造模型通过。
- `SkipReview=false`：执行该分支要求的复核并保存真实回执，成品入库验证 `review_passed`及其对应正文、事实范围和母版身份。

免模型复核不代表生成P0为空，也不代表输出绝不会违反事实。有效P0来自实际加载内容并参加缓存指纹。仓库已删除评分纠偏回灌和主动任务讲解链路（`feae7fd`、`2552f2d`）；旧生产/回滚版本的母版不在此次文档整理中清除。

## 声音与真实播放

采纳文字→完整TTS/合格音频命中→排队送Core→Core开始→PCM进度/完成，各阶段独立记录。声音按音色、模型和语速隔离；事实变化使相关文字及声音更新，单改语速可保留文字重做声音。租约有音频、API completed、played_at或Core开始均不等于完整PCM已播完，更不证明听到了外接设备。
