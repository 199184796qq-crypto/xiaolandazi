# 文字模型账号池

后台入口：系统设置 → AI 与智能体 → 模型池配置。每条记录包含账号名称、加密保存的 API Key、接口、文字模型和管理员手动填写的直播间名额 X。可读取供应商模型列表，也可填写模型编号。账号名称必须对应实际供应商账号；同账号同模型不能以多个 Key 重复增加容量，同一 Key 同模型也不能重复登记。供应商无法通过任意 Key 自动证明其账号归属，因此不同 Key 的账号名称需要管理员正确填写。

## 分配与调用

- Management 启动加载持久化池表，分配管理集中在数据库，Core 无供应商密钥副本，无需修改或重启 Core。
- AI 启动的同一事务创建运行场次并领取名额。池满则整个启动事务回滚并明确提示，不占时长、不超分、不回退到共享账号。
- 同一 AI 场次固定账号、模型、密钥和连接快照。口播、审核、规划、互动与回归桥使用该分配；暂停、采集停止、Management 重启不按时间回收。实际 AI 停止、启动失败回滚、配额耗尽、永久删除房间等终态释放。
- 名额编辑、领取和释放共用 InnoDB 行锁；读取使用当前锁定版本，不能使用等待前的旧事务快照超额分配。按已用/总名额优先选择有剩余容量的账号。
- 运行场次编号隔离迟到的生成和停止操作，旧场不能使用新场 Key 或释放新场名额。正在使用的账号不能删除或改绑账号/模型/地址；暂停新分配、轮换 Key 不改变已占用的快照。
- 非直播的后台分析、资料整理和测试继续使用现有全局模型角色；TTS、声音识别和独立向量服务不属于本次文字模型池。任务提示词和 P0 业务链路保持原样。

## 配置与迁移

建表为增加式迁移，密钥沿用 MODEL_CONFIG_ENCRYPTION_KEY 进行 AES-GCM 加密，公开接口只返回是否配置。调用日志记录池记录、分配编号和账号名称，不记录密钥。

不猜测供应商额度，也不自动配置 X。管理员可点击“导入当前口播账号”，服务端安全复制现有 Key，先以未启用、名额零保存；填写 X 并保存启用后可分配。池没有可用名额时新 AI 不能启动，已有声音、事实和方案不变。首次发布需要确认没有运行或暂停 AI，避免把未绑定的旧场混入新机制。

## 集成边界

独立分支开发，以 WorkBuddy 主线和 GitHub 最新主线共同整合；不改原开发目录，不覆盖他的新功能。生产包继承发布前实际 current，只有 Management 二进制和两个桌面入口更新，添加新哈希资源；Core、网关、提示词、手机页面、Nginx 和原静态资源须逐项验证保留。保留最新直播下载及 24 小时记录、资料补充双栏、声音模型后台配置和用户声音缓存入口。

验证记录保存在本聊天 work/model-pool-upgrade-proof；新池的实际数据库并发和生命周期实验只用随机隔离 schema 与虚拟 Key，不向真实模型或直播队列发测试内容。既有模型/互动测试失败须与未修改基线逐项比较，不能宣称全套通过。
