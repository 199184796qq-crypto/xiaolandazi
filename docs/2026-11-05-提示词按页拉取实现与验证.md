## 后端仍需 DS 修正或确认

以下结论针对本机交接源码，只读留证；未连接生产确认当前二进制与这些文件完全一致。

1. **新占位符填充值不完整。** `management-service/internal/httpapi/plan_prompt_draft.go` 的 `planPromptWriterValues` 没有 `本页要求`；`现有提示词` 固定取 `sections["persona_md"]`。`renderPlanPromptTemplates` 只返回 persona/facts/redlines/speech/interaction 短键，因此该值通常为空，也没有各页现有正文。建议按 page 组装取值，明确现有正文来源，发送前验证占位是否残留。
2. **“白名单外保存拒绝”尚未接线。** `UnknownWriterPlaceholders` 仅定义和单元测试调用，母版保存及 `Templates.Validate` 没有使用它。现有维护页 @ 兼容目录仍是旧 24 项，与 Writer 的新 11 项不同。建议母版保存、真实替换与前端菜单由同一份按页目录驱动，明确事实页和运行时规划占位符的兼容策略；不能只删旧菜单项或覆盖运营已保存母版。
3. **请求解码失败会落入全页生成。** `plan_prompt_template.go` 忽略 `json.Decoder.Decode` 错误。非法 JSON 或 `page` 类型错误可能留下空 page，按旧兼容行为触发五页生成；未知非空 page 则静默跳过全部。建议严格校验格式和六个允许值，错误在付费调用前返回 400；明确 `{}` 兼容接口与新单页入口的边界。
4. **回退内容仍经旧渲染器。** 新母版含 `{{方案名称}}` 等 Writer 占位时，回退用的 `renderPlanPrompt` 不填这些新值，并会丢弃含未填占位的整行。模型失败后返回的可能是删行后的生成器指令，不能视为正常成品。建议按相同占位取值生成可靠回退；若没有可用正文，返回明确失败保留客户端原稿，或明确让运营检查回退内容后保存。此项涉及回退产品语义，需与交接文档“回退母版”要求一并确认。

另外，五页串行且单页超时 45 秒，最坏约 225 秒；源码注释“整次两分钟内”不成立。新 UI 单页请求可避免这个整批等待，但旧 `{}` 调用仍需单独关注。
