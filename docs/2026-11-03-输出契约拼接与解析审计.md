# 输出契约拼接与解析审计

用户委托检查 DeepSeek 4.1 Flash 完成的格式接管，随后授权修正后直接上线。Codex 接续当前文件，先保存基线与独立失败回放，再修正请求和消费链路。

## 已复现的问题与修正

- 保存组合使用新的系统保留标题，互动运行时只去除旧标题；真实批量请求同时含“话术”和“回答”两套协议。统一剥离完整格式章节，每次请求只拼接对应的程序协议。批量仍保留隔离编号、结束、分类与优先级，避免改变原调度职责。
- 互动仍只认“回答”，多条“意图”被判重复，改写的两个正文别名又可能同时存在。当前新正文统一为“话术”，保留旧“回答”及改写“改写内容”的读取兼容；同一结果不能同时提供两个正文。互动一至三条意图分别保留置信度和建议，最高置信度意图供既有逻辑使用。
- 正文后的说明能进入改写 TTS；批量没有结束行时也可能被当作完整结果。正文与非口播信息严格隔离，重复、未知尾部字段或截断结果拒绝，坏的互动结果只影响对应的人，继续保留其它有效结果与主线。
- 只在保存时加协议，旧方案或删除格式后仍可能没有格式要求；后台开场补充又放在协议之后。实际改写请求重新接管协议，保存样本占位符并在执行时注入样本；补充开场、时间、上次上下文后再固定协议。协议单独作为 system 消息发送，业务内容与样本在 user 消息。新请求必须返回骨架、上下文和完整末行正文后才保存，历史结果读取仍兼容旧双字段和纯正文。
- 章节匹配范围过宽，内联“【输出格式】”或后面的 Markdown 业务标题可能被吞。标题按完整行识别，保留后续业务章节；编辑器读取只剥离系统契约，不反向修改旧客户原文。
- 互动请求原本省略完整有效 P0，只有返回后校验。依据 AGENTS 中用户明确要求恢复生成时携带；生成后有效 P0 校验继续执行。没有增加请求次数，但相比省略 P0 的版本，每次互动模型输入会增加相应 token，仍经过原费用闸门。

格式约束不能保证模型永远服从，程序负责在异常结果进入声音、上下文和缓存之前拒绝。格式错误不记为内容违规，也不停止主线。未改变各片段循环、声音队列、费用预留或事实业务。

## 实际入口

- 保存：`planprompt` 编译分区与话术规划，原文和组合沿用单次 SQL 保存、方案与租户隔离及直播保存保护。
- 互动：单人也进入 `interactionplan.GenerateBatch`，实际请求使用唯一批量协议，结果按人隔离解析后仅正文进入语音。
- 改写：手动预览和后台池生成均使用同一请求构建、三字段解析；骨架与简介保存给下一次使用，只有正文进入共享文本和声音。
- `speech_prompt_md` 当前检查到的是保存与回显路径；没有发现独立读取该列执行生成的运行消费者。不能把保存出来的两字段格式当成已经验证过的额外语音生成入口。
