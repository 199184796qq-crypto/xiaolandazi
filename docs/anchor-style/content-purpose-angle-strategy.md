# 事实 → 目的 → 角度内容策略

本策略只增强生成内容，不拥有事件筛选、优先级、队列、切口、打断、回归、缓冲或播放状态。主播风格仍是表达包装；已采纳问答、自然语言纠正、长度和原话模式继续执行。

## 准备与保存

从方案经过审核的 `SafeFacts` 提取完整记录，保留事实正文、安全改写、禁说和多行内容，程序分配事实编号。第一次普通 API 调用分析沟通目的；第二次把实际目的回答带入上下文，挖掘讲述角度。两次均关闭思考。模型产生目的和角度，程序不编造内容，只验证结构、字段长度、目的及事实引用。

分别使用母版 `fact-purpose-analysis.md` 和 `fact-purpose-angle-analysis.md`。原始请求、回答由现有模型交换日志保存；错误结构明确返回错误，不覆盖已有策略。成功结果作为 `live_plan_analysis_assets` 中 `fact_purpose_angles_v1` 类型的独立不可变版本保存，按租户、方案和正式事实指纹隔离，不覆盖用户确认的卖点轮盘或发布版本。

正常初始化仍以原有四项为准，额外内容策略失败会在 notice 和 content_strategy 分项说明，原流程继续。已存在的策略（含明确关闭版本）不会因初始化或母版更新被自动重写。

## 接入位置

- 正式主线和试听新场次：读取匹配正式事实的策略，复制入原场次快照。当前商品范围先过滤事实引用，只将范围内的任务送入现有生成提示词。仍按原轮盘选任务；模型从兼容的目的和角度展开，不重新调度主线。
- 互动：读取本场正式事实包，选择开播前已保存的匹配策略。已有普通模型 API 在一次正文生成中完成相关性、观众目的、事实与角度选择；不增加逐条问题的目的/角度 API 调用。缺失或无效资产记录诊断后继续原流程，100%原话不注入改写策略。
- 字数、纠正、P0和商品核对按现有流程执行。表达复核使用 `fact-purpose-angle-review.md` 区分主观评价、感官类比与客观交易承诺，不能把自然表达压回事实原句。
- 主线声音缓存增加策略及生成母版指纹，避免旧策略口播命中；关闭或没有策略时保留原缓存身份。

生成母版 `fact-purpose-angle-generation.md` 每次请求读取。完整记录是核对依据，不要求全部朗读；每段完成一个角度。金额、单位、工艺、优惠和明确履约承诺不变，允许普通生活场景、情绪与主观价值判断。无关问题不强行推销；缺少西瓜报价不能推出不卖西瓜。禁说反例中的数字不能作为商品规格。

## 管理接口

沿用现有方案权限：

- `GET /api/v1/live-agent-plans/{planID}/content-strategy`：查看最新保存版本，没有时返回关闭状态。
- `POST /api/v1/live-agent-plans/{planID}/content-strategy`，`{"enabled":true}`：按当前正式事实准备/启用策略；`regenerate:true` 明确重新分析。
- 同一 POST，`{"enabled":false}`：保存关闭版本，下一场次生效。旧版本保留。

正常初始化也会为缺少策略的方案准备。正式场次把策略保存在原Redis运行快照；互动查询限制资产创建时间不晚于本场 StartedAt，后续新分析/关闭不会改动进行中的场次。服务器重启不恢复旧场次。

## 验证范围

回归覆盖未知结构/错误引用、完整表达限制、多行记录、事实变更、跨商品隔离、原话模式、策略缺失回退和旧声音缓存隔离。普通 API 实测包含两阶段建表、价格主线、新鲜制作主线、价格提问及无关报价问题；不创建直播或生成/播放音频。真实主播模型与完整登录态直播闭环仍需实播验收。
