# 多商品主辅推运行机制

## 运行责任

线上调度由程序、提示词和已配置模型完成，不依赖开发代理在场。商品编号、名称、事实、租户、直播间和方案均来自当前方案数据，不在规则中绑定示例商品或直播间。

程序先决定合法出场范围，再由模型生成、语义复核。复核失败时保留原始返回并带原因重写当前段；超过既有重试上限暂停，未通过稿不计入采纳记忆，不进入声音队列。高风格评分、历史声音缓存或P0确认不扩大商品范围。

## 配置和生命周期

- 沿用商品卡 `room_roles`，多商品方案要求且仅有一个 `main`。其余现有定位保留，作为辅推候选，不自动修改用户标签。
- 保存新实时方案版本时，由服务端读取当前安全事实和轮盘，通过模型分析每行事实、每个角度的链接归属；严格校验完整ID集合、链接和必需字段。未知归属保留为未知，不当成共享事实。
- 策略默认从 `configs/prompts/anchor-style/cycle-product-focus.md` 初始化，和归属分析一同保存到该方案数据库版本。默认主推至少75%的累计采纳字数、完整主推轮次后才允许辅推、单次辅推最多160字符。
- 母版变化不自动重写已保存版本。已有无商品调度快照的版本保持原路径；明确保存、发布新版本后，下一场开始采用新机制。
- 当前主推、辅推轮转、采纳字数和完成轮次仅属于本场Redis状态。新场清零，不把上场临时进度从数据库恢复。

## 一轮与辅推分支

主推沿用原有开场、中间段数和收口状态机。一轮完成前，包括收口本身，都只允许主推链接及确有依据的共享事实。

完整主推轮次后，程序从可用辅推角度中选择一个链接，最多短插一段，紧接着回到主推开场。不创建独立辅推开场/收口，不做逐段A/B平铺，不把多个辅推挤进一段。每次辅推必须作为主推的真实补充选项，语义复核检查独立催单、假分工、第三商品和价格规格串用。

所有辅推共用篇幅额度，按实际采纳的最终口播字符数累计，不按候选稿、循环次数或预估声音时长计算。预算不足、任务避重或没有安全可用辅推角度时继续主推，不强制耗尽额度。辅推段不允许留下继续讲辅推价格的钩子；主推已有价格承接义务优先兑现。

用户参考文档同时写了“辅推1～2段”和“辅推后紧接一段必须为主推”，当前采取一段短插的更严格实现，不自动扩展为两段。

## 隔离和校验

- 生成每段均注入本段链接、模式、授权事实、字数上限和前次混讲原因；历史上下文不授予额外权限。
- 未知或错误链接号先由程序拒绝；不报链接号的规格混讲由模型语义复核。
- 采纳和转声音时再次校验正文及商品范围指纹。缓存按租户、方案、直播间、风格、事实、声音、商品范围和策略隔离。
- 正式Core音频协议和盒子通信协议未改动。

## 本地验证

覆盖完整主推轮次、三个商品辅推轮转、任意链接编号、主推不在第一张商品卡、拒绝稿和Redis恢复不消耗额度、累计主推份额、无可用辅推、价格承接、语义拒绝、最高评分拒绝稿不复活、声音缓存与租户/方案/房间隔离。

单元测试使用明确的模拟语义结果，不替代生产模型实测。上线需发布管理服务和完整母版目录；服务重启前须确认不影响正在直播的场次，不自动替商户修改商品定位或发布方案。
