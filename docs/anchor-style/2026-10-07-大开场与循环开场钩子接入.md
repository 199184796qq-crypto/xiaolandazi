# 大开场与循环开场钩子接入

范围仅两个开场。中间2～6段计划、卖点轮盘、收口、1000字回灌、TTS和core声轨协议保持原流程；没有增加辅助模型请求。

## 母版与方案

统一目录：`configs/prompts/anchor-style/`。

- `opening-hook-library.md`：18个通用骨架、首场/循环允许类型及优先类型、最近避重次数（默认3）、数字与主播禁用词检查开关、槽位来源。
- `cycle-opening-full.md`：钩子先行→完整身份→本轮卖点→轻呼告。
- `cycle-opening-reentry.md`：轻钩子接新→一句身份→本轮卖点，不重复完整版身份。

无方案版本：每个新开场读取最新母版（缺失或结构错误明确报错）。同一开场重试保留已选钩子快照，不重新抽取。不是每次重试把整套基础风格再次发送给Agent。

测试页面折叠项“大开场 / 循环开场钩子库与选择规则”支持加载MD、编辑、确认保存，以及明确导入最新母版。
确认后追加数据库`live_opening_hook_assets`版本，按租户/方案查询，绝不写回母版或覆盖其它方案。已有版本的新场采用数据库快照；正在运行的场次不变。更新项目母版后，如方案已有确认版本，须显式重新导入，不能自动覆盖。

## 程序职责

1. 根据母版允许类型和优先类型筛选，跳过没有槽位资料的模板，避开最近已采纳ID。
2. `槽位来源`声明取值：当前卖点字段（卖点/角度/人群/痛点）、指定分类及键的正式事实条目、有效福利指定字段；可用一个捕获组的正则提取子值。程序只支持这些明确协议，未知来源报错。
3. 硬槽由程序填入半成品；软槽和值作为JSON调度资料交给原Agent做腔调润色，钩子类型由程序选定。
4. 只对开场执行配置化硬槽数字存在性检查和主播基准禁用词检查。中文/阿拉伯数字等值不触发重写。不新增“你们/您”全局禁词。
5. 未采纳稿不消费ID、不进1000字窗口；采纳后记录ID与本次模板/来源SHA，最近队列只在Redis，结束清理、重启新场。
6. 没有满足条件的模板明确停止本次请求，不虚构缺失槽位，也不自动放宽避重。

数字检查只验证装载钩子中的数量是否仍出现，不是完整语义事实审查，也不能证明模型正确复述所有福利条件。钩子第一句和润色质量依赖环节提示词及人工口播测试，不宣称程序能硬判所有修辞。

## 调试与测试

现有“候选稿、逐段评分、采纳结果和1000字回灌JSON”保留完整请求与原始返回。
`pending_opening_hook`显示当前模板与填槽资料；采纳段`opening_hook`显示实际使用模板、类型、来源SHA。`recent_opening_hook_ids`显示采纳后的避重队列。

先关闭TTS、运行2轮：首轮检查第一句钩子和完整身份；第二轮检查轻钩子、身份不重复及快速进卖点。模型调用由用户在测试页启动，自动化测试仅用模拟输出，不花模型费用。

已覆盖：母版热加载、方案快照不被母版覆盖、配置优先级/任意槽名、缺项跳过、20次采纳避重、重试和Redis序列化不重抽、失败候选不进入记忆、中文数字等值、主播禁用表、重试上限只选择合格候选、中间/收口不插入开场资料、数据库跨租户/方案隔离及追加版本。
