# 大循环：Redis本场状态与采纳后1000字控制

## 已落实的调度

- 默认滚动模式：首场完整版开场1段→中间N段→本轮收口1段→接新版开场→中间N段→收口。测试页默认N=3、测试2轮；轮数设0可在页面持续推进，直到暂停、结束或错误保护。关闭滚动模式可保留原固定队列单轮对照。
- 原始卖点池在本场冻结，但每次采纳后动态选下一个组合。优先符合间隔的未讲组合；都讲过后，优先累计次数少、距离上次更远的组合。同卖点间隔和同组合间隔分别设置，均按已采纳段计算（收口计一段）。重试不会消费或重选任务。无法满足间隔时进入spacing_blocked，保留已采纳稿、停止新的模型请求，不偷偷降低间隔。
- 新增opening_count、cycle_number、body_count、task_index：opening_count只在开场采纳后增加；收口采纳进入新轮时不增加开场次数。完整/接新版本由次数派生，采纳段另存opening_version供复盘。首场完整介绍身份、引出钩子、轻呼告；循环开场简短接新、一句身份和当前钩子，两种开场都不重逼单。动态进房热度触发开场暂不实现。
- 收口后沿用同一session、风格/事实建档、近期及远期记忆、1000字窗口；不每轮重复建档。使用过的组合保留次数、最后位置、最近讲法180字摘录，复用提示要求换切入和首尾表达，不承诺只靠调度就保证模型语义完全不重复。
- 每个任务首次生成加最多N次重试（默认3）。新场次测试页默认单段原始评分达到40即采纳，低于阈值才重写；阈值仍可调整。全部低分时取首次及所有重试里的最高分版本。同分优先较早版本。已有场次保持其冻结配置，重新开始才采用新设置。
- 默认启用“补齐明确句末标点”：只修明确催问句、在高亢风格下明确行动呼告的句末标点及缺失的段尾标点；不增加词语、不改数字、不把每句语气词改成感叹号，不强拆无标点长句。无法确定语义的句子保留原样。补标点不调用模型、不超每段字符上限。
- 候选`raw_text`保留模型原始返回（含前后空白）；`text`为去掉前后空白的模型原稿；`output_text`仅为补标点后的显示/下载文本；`punctuation_edits`记录修改位置。`score_scope=model_raw_text`表示评分仍对原稿，1000字窗口同样统计被采纳的模型原稿，不用程序补的符号抬高模型情绪得分。关闭补标点或旧记录没有output_text时显示text。
- 候选原文、真实发送提示词、评分、耗时、事件ID全部保留。只有采纳版追加到正文并更新指针、已讲记录与摘要。
- 原有字数循环保留为独立对照模式，不覆盖它的历史记录。

## 记忆与1000字宏观控制

- 远期记忆是本场已采纳的卖点×角度记录，保存次数、最后出现位置及讲法摘录；移出风格窗口不清掉记录，旧组合只有满足冷却条件才可再使用。
- 近期记忆保存最近3段采纳稿的一句话摘要：任务、开头、尾句。程序截取，不增加摘要模型调用。
- 风格窗口只在采纳后更新，严格取最近1000个Unicode字符（含标点、不含空白）；保留段落换行用于句长统计。
- 不对候选稿计算宏观窗口，不因宏观偏差撤回或重写采纳稿。窗口不足1000字时只观察密度；完整段的开头/结尾重复检测仍可提示。
- 超出样本80%–130%密度区间时生成轻量建议，指导后续，不追讨过去缺口、不在下一段猛补。低期望次数不强补；稀疏转写标点不作为压低情绪的上限。
- 完整段开头/结尾用最近5段检测，密度用1000字，两个窗口不混算。尾句检测仍是词面归一化，不承诺完整的语义重复识别。
- 同类同指标建议间隔至少两次采纳，窗口每次都重新统计；没有问题或间隔未到时清空旧建议，避免重复累加。辅助模型失败记录告警，无回灌继续推进。

## 临时运行态

- 大循环使用独立Redis连接池，不共用工作收件箱的500毫秒快速失败连接池。`ANCHOR_CYCLE_REDIS_TIMEOUT_MS`设置连接、读、写及等待连接池超时，默认5000毫秒；正常返回仍立即完成，并非每次固定等待5秒。请求自身的截止时间仍有效。
- Redis写入不做自动命令重试；超时后先读取当前revision核对，不能因此重新请求模型。生成结束后的状态落盘截止时间至少10秒，允许SSH隧道连接协商及读写。网络真正断开时仍暂停核对，不把扩大超时视为断线恢复。

- 仅保存Redis，没有MySQL运行表或浏览器运行状态副本。稳定风格、评分基准、事实来源、轮盘资产仍从现有数据库读取，并冻结本场资产版本。
- Redis键按运行端、进程启动标识、租户、房间、方案隔离，24小时过期，每次更新续期。服务器重启更换启动标识，旧场次不能续跑，旧键自行过期。不执行FLUSHDB。
- 页面刷新只读取本场Redis状态，不自动发请求。页面关闭后不发下一轮；服务器会收好已在进行中的这一次候选，完成评分和必要的采纳/回灌，刷新后先核对进度。在途请求不会因页面断开而丢失，但未知的上游错误仍暂停，不盲目重发。
- 每次推进需要客户端提交当前revision，Redis租约阻止同时生成，CAS防止重复和晚到结果覆写。生成结果不确定时暂停，不能自动重发。
- 测试页“结束本场并清理”取消本场请求、删除本场状态；正在生成时向阿里发送用户interrupt事件。绑定房间的运行态也在该房间停止AI伴播时清理。
- 独立测试room_id=0不绑定真实房间，须用测试页结束按钮清理。只影响本场，不删除风格或轮盘、不修改阿里母版。
- 本轮完成并不自动清理：先供用户查看和导出；结束本场或真实房间停止时清理。刷新或重启后不存在的状态不会从浏览器恢复。

## 入口与模板

测试页：`/operations/live/style-workbench`，默认“大循环：采纳后1000字控制”。仍只显示一个采纳正文框，中间状态默认隐藏；展开“显示设置与单步调试”可看完整JSON与导出。

正文框上方直接显示实际轮次、完整版/接新版、开场→中间讲解→收口、当前卖点×角度、每轮已采纳任务数与全场覆盖数、当前候选版本及生效阈值。拒绝稿不增加进度；收口采纳进入新轮后本轮进度归零，全场覆盖记录不清空。结束后显示最后一轮完成，不虚增下一轮。当前等待秒数包含生成、评分及必要回灌；上一采纳段另列选中稿模型耗时和全部候选累计耗时。完整评分/提示词仍留在调试JSON，不增加正文框。

Redis接口：GET/POST `anchor-style-workbench/cycle`，POST `cycle/{runID}/advance`，DELETE `cycle/{runID}`。房间用`room_id`查询参数；沿用账号、租户、方案及房间授权检查。

## 验证

1. 设置测试组合数3、每轮中间3段、测试2轮，验证首场完整开场→中间→收口→接新版开场。40分即采纳；低于阈值首次加最多3次重试，总共最多4版；正文只包含采纳稿。
2. 设置组合数8或更多，让采纳字数超过1000，检查`macro_report.stats.chars=1000`和辅助模型输入中的`accepted_style_window`；拒绝稿不能出现在窗口。
3. 中途暂停和刷新，核对同一run_id、指针及候选次数；继续不能重复消费组合。
4. 结束本场后核对GET返回run=null；晚到请求不能创建旧状态。重启后也返回null，新建独立会话重新开场。
5. 关闭或故障回灌模板，已采纳稿仍保留，记录model_error并继续，不重复生成本段。
6. 全池讲过后继续运行，检查used_combinations次数递增且跨轮保留，已复用组合的真实提示词带上次讲法摘录。间隔过大时须明确停止，而不是短期复读。

持续滚动仍受故障与存储保护约束：单个Redis调试状态有16MiB上限，超过会停止并提示导出；不保证无上限记录或服务器重启后续播。页面关闭后服务器只收完当前请求，不会在无人操作时继续后台无限生成。

自动验证：Go全量测试；前端调度测试；真实Redis验证租约、CAS、TTL、结束删除、不同启动标识隔离及晚到结果拒绝。滚动单测验证80次采纳、20轮开场、跨轮避重及1000字窗口保持。真实模型整场质量仍需人工测试，不把单测当作风格达标证明。

阿里显式中断协议参考：[发送Event](https://docs.agent.bailian.aliyun.com/zh/api/managed-agents/session/send-event)，使用`input=[{"role":"user","type":"interrupt"}]`，不发送新口播任务。
