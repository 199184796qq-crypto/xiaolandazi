# OSS声音复用缓存

## 生命周期

- 默认5小时（18000秒），在“系统设定 → 直播业务 → OSS声音缓存”由具备`system.settings.liveops.manage`权限的运维人员统一设置，配置保存在数据库系统设置。普通用户和测试页不能设置，也不能以API请求覆盖。
- 运维保存后，之后新生成的缓存使用新时长（现有运行队列的新声音也会读取）；已经存在的缓存保持原到期时间，命中不续期。不写共享母版，不改变数据库中的风格、评分基准、卖点轮盘。
- 从TTS合成完成、准备上传时计算绝对到期时间。命中不续期。
- WAV、SRT、PCM时间轴、句末安全切点、manifest分别上传OSS私有对象，存放于独立`anchor-voice-cache/v1/`前缀。没有OSS配置则拒绝开启声音，不降级到本地。
- Redis保存完整包引用及到期时间，采用独立稳定缓存命名空间。不属于大循环恢复状态：结束场次/重启不恢复本场，缓存仍可在期限内复用。
- 缓存到期立即拒绝复用；清理任务每分钟扫描到期清单，删除该缓存条目的五个明确OSS对象。服务停机时物理删除延后，恢复启动先补清理。并非OSS原生秒级自动删除。
- 上传前先登记清理记录。部分上传失败不会作为命中包发布，已上传文件仍可清理；清理失败保留记录重试。清理清单不能随缓存TTL一起消失。
- 仅新缓存对象受5小时清理，已有媒体库资产、正式录音及已发布声音不会被删除。新短期包不作为永久媒体资产登记。

## 复用规则

缓存按租户、方案、房间、卖点与角度、环节、风格/基准/轮盘版本与内容、事实包、母版Agent及TTS音色/模型/语速隔离。声音波形身份不受浏览器播放缓存上限影响。

1. 中间讲解装载任务后先查对应缓存。缓存话术重新按当前标尺评分、检查字数；最近至少5段（或更长的已设间隔）不复读同一稿。
2. 若有回灌待执行、待兑现塑价钩子、候选正在重试，仍生成新稿，不以缓存绕过纠正/承接。开场和收口也按本轮上下文生成。
3. 命中时同时采纳缓存原话术和对应声音，正文不显示新稿却播放旧稿；照常进入采纳记忆、评分和1000字窗口。记录`cache_id`及`cached_text_rechecked`，不伪造模型请求或模型耗时。
4. 声音worker仍对精确的送入TTS文字校验（含补齐末尾标点）。不同文案不能套用旧音频。命中不调用TTS，重新签名URL但不超过原到期时间。
5. 未命中才合成、上传完整包并发布缓存引用。靠近到期、无法覆盖整段播放的条目不再装载。

缓存是可淘汰的声音资产，不是直播会话记忆。最终正式主线仍需生成端适配完整资产和播放消耗；本次测试不会进入真实房间或发送core命令。

## 测试

- OSS SDK本地模拟服务验证私有五文件上传、完整包校验、精确文字命中、上传失败不发布、过期五文件删除；不调用收费模型。
- 真实Redis独立测试命名空间验证重启后缓存可查、命中不延长TTL、过期拒绝、清理记录保留、范围校验。
- 真实云OSS访问与真实音频试听仍需本地测试新场确认，不将模拟测试称为云端端到端验证。
