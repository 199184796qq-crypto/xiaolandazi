# 统一互动智能体

直播间观众互动和方案里的话术测试共用 management `decisionexecutor` 的业务回答生成、事实约束、已采纳回答策略和终审。没有另建模拟回答模型或第二份互动策略。两处使用同一组热加载母版：先由 `interaction-agent-plan.md` 完成目的、角度和相关依据的规划，再由 `interaction-agent-answer.md` 按选定范围生成简短正文。它们是同一互动智能体的两个内容步骤；不另建模拟策略或说明智能体。规划沿用系统智能体模型角色，正文沿用实际互动口播模型角色，两入口一致。

## 已核查的直播链路

core接收观众事件，按既有事件分类、目的识别和问题桶筛选，建立场次互动任务。management按场次正式方案及事实指纹取业务资产，并读取本场实际播放历史；已识别目的时，程序先筛选对应角度的事实依赖、采用条件和优先级。业务回答完成后仍走原有正文规则校验、TTS、切口与播放队列，core收到实际播放回执后记录历史。

直播仍应用已配置的称呼、主播风格、打断和回归等表现约束。它们不能扩展问题目的、改动事实或把答案变成长篇卖点介绍。运营人员的固定原话任务继续使用原有原话协议。

原模拟入口遗漏互动任务类型，跳过业务策略阶段，同时加载主播风格。本次修正：模拟明确建立 `reply_question` 业务任务，只运行 interaction 阶段；不加载风格记忆、风格叠加、素材表达案例和参考话术，也不调用打断、回归、称呼、开场、拟人化阶段，不生成声音或写直播播放状态。

## 事实与记录范围

正式直播读取已发布正式事实和开播前的对应策略版本，保留场次快照。方案编辑测试读取明确选中的当前方案完整事实，包括商品卡和有效福利；匹配当前事实指纹的已有角度资产可复用，资料变化后不复用不匹配的旧资产。测试不会修改房间绑定、准备新资产或发布方案。

本次规划仅返回 purpose、angle、aspects、avoid、basis、requirements 等内容，正文步骤返回 reply 和已有建议内容。程序持有租户、房间、方案、目的引用和已有任务依赖，不让模型回填ID。实际播放记录保存本次规划供后续选择相关角度；历史只带问题、目的和角度，不重新注入历史事实包。模拟的最近8条记录来自本组件，切换方案、房间或账号即清空，只影响角度重复判断，不能变成事实或覆盖用户纠正。

问题下显示本次目的、具体角度、回答方面和不要展开的内容。采纳时只保存用户确认的正文，不把说明当事实。纠正重测重新执行共用业务核心；没有完整说明时保留有效答案并明确标出说明未完成，不伪造规划。

## 长度、变化与既有缓存

简单提问通常1至2句；没有最低字数要求。只补充会改变答案的条件，不顺带复制采纳段落中的工艺、复热、吃法或促销。规划每次只返回一个针对当前问题的目的与角度，结合近期已用角度选其他相关内容侧重点，并一并给出其回答方面和相关依据，不能只改标题。解析保留旧候选协议的局部兼容，格式异常明确提示，不把未完成候选冒充有效规划。变化来自同一目的下其他相关角度，事实和必答规则保持一致；只有一个明确必要事实时允许重复正确结论。

保留系统的固定问答复用开关、版本池、过期、冷却和声音复用规则。缓存指纹包含规划母版与完整供料指纹、正文母版、选定任务和实际历史，缓存正文与对应规划一同保存。模拟始终调用业务核心，不使用直播固定问答缓存。角度推演池的实际使用计数、播放回执和3次补充机制沿用现有规则，本次没有新建另一个推演池，也不将模拟或生成次数算作实播。

## 本次范围与验证

本次接入共用业务回答和可见规划，并修正模拟的表现边界。旧core目的识别接口及目的角度资产生成接口的历史ID协议未在本次批量迁移。

回归检查包括两入口同一回答协议、模拟排除风格/打断/回归且无播放副作用、已采用策略与纠正继续生效、正文与规划/建议分离、规划和正文原始请求、返回分开记录并由程序关联当前租户、方案和房间；说明格式异常不阻断有效正文、近期记录上限、缓存规划对应性、方案隔离及对话框移动缩放、回车发送和采纳留在当前页。

业务规划收到按完整句子分开的已确认内容及当前事实，不混用正文生成协议。正文的interaction_agent_answer阶段与现有互动口播使用同一模型角色，单独执行业务母版，不自动叠加通用文字生成的称呼母版。模拟请求显式标记business_core_only，排除问好、称呼、促单和不必要的商品链接；正式直播仍叠加原有表现约束。
