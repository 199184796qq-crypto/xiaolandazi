# 初始化、保存与试听分析复用

- 无模型互相对话：日志中初始化和保存分析使用同一个已配置模型；耗时来自串行阶段、重复分析和校正。
- 空卖点池或完全没有可用角度：必须首次完整生成、事实核对、必要补全和终审，不能复用空结果。
- 非空已确认池且事实内容指纹一致：直接复用当前池（包括用户修改），不重复模型生成，不因为点击初始化而创建新池版本。
- 事实有变化：从旧池的精确事实快照计算新增/移除内容，由模型识别受影响卖点，仅返回增量补丁；第二次调用只审核补丁，程序保留补丁外的用户内容。旧池缺少可核对的事实快照时明确提示并完整核对一次。
- 商品归属分析为稳定方案资产：按租户/方案/输入指纹存 MySQL，输入包含完整商品、角色、事实、角度、当前规则与模型路由。保存、试听相同输入复用原始已验证返回，再做严格程序校验；数据/规则/路由改变则重新分析。仅稳定分析结果持久化，不存任何运行游标或计数。
- 初始化和保存通过原有 SSE 传输真实阶段。取消前台定时推进至92%的假进度；旧 JSON 客户端仍可使用原接口。
- 不跳过必要安全检查，不改变现有正在运行方案、音色或直播协议。
