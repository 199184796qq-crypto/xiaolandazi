# 大循环塑价、可变段数、TTS与缓存测试

## 已实现的范围

- 新测试默认中间讲解2～6段。程序每轮计划一次，重写、刷新不重新抽取段数；相邻轮避免相同目标。该选择是程序范围调度，不声称来自热度判断。必要塑价承接可以延长本轮，但不超过6段；到上限由下一收口段先兑现。
- 塑价默认本段完成。显式价格预告保存在Redis，下一段优先兑现。六段内最多一次新钩子，兑现段不能再延期，最后测试收口不能承诺未调度的下一段。
- 兑现判定仅检查明确价格数字与算账表达结构，不声称能判断所有语义或价格真实性。没有兑现的候选不推进；到重试上限暂停，保留全部稿件，不拿高风格分的未兑现稿顶替。
- 主播禁用词按本方案确认的基准单独统计，`你们`、`您`分别计数。禁止对所有主播写死同一黑名单。单段反馈优先指出明确禁用词；1000字尚未满时也能反馈明确禁用表达。
- 问句计数增加无问号的句末正反问，同句与问号去重。陈述句“嘛”、内部“不得不”“没得”不算问句。感叹号仍只统计真实标点；短段按基准期望不足2个时观察，不强凑标点。纯问号次数与综合问句次数分开保存，重新校对基准后显示两项。

## 声音链路及隔离

测试页面TTS默认关闭。打开并选系统官方音色或已有ready克隆音色后，只将已采纳稿转为声音；未采纳候选不转。音色、模型、语速在本场冻结，不默默换音色。

沿用固定声音的分段TTS、WAV拼接及资产归档链路，生成同格式的：

1. WAV音频；
2. SRT字幕；
3. timeline.json，时间基于各段实际PCM长度，不用字数估时间；
4. safe-points.json，完整语义句末切点及左右文本；
5. manifest.json，formal-voice-bundle-v3契约。

这是分段精确时间轴，不是ASR逐字强制对齐。语义切点复用固定声音实现，不额外声称做了新的模型语义分析。资产媒体落库/存储，运行内仅保存引用与完成状态；本场临时状态仍只在Redis。

测试包标记`usage=test_preview`、`published=false`、`is_formal=false`；不创建发布版本，不绑定房间，不向core发送播放命令。新的短期声音包存入OSS专用复用缓存，默认5小时，不登记成永久媒体资产；已登记的旧预览媒体不删除。具体见[OSS声音复用缓存](2026-10-07-OSS声音复用缓存.md)。以后移植正式主线时复用音频包契约，不把测试预览误当已发布主线。

文字生成器、声音生产队列和浏览器播放器分别推进。每采纳一段即追加文本框，并交给独立顺序TTS队列；下一段文字不等待该声音完成。TTS完成只返回本场ID、采纳稿ID和声音结果，不整包覆盖文字进度。

声音任务使用本场专属Redis hash，与文字生成锁、revision、轮盘指针隔离。重复请求不重复合成；结果丢失但状态为generating时，只读查询状态，不盲目重复计费。失败只暂停声音队列，不立即停止文字；用户明确点击“继续／重试声音队列”才重试失败段。后续声音不越过前面失败或未完成的段。结束本场清理对应声音任务，晚到结果不能重新创建本场。

## 缓存背压

测试窗口使用浏览器顺序播放器，而非房间播放器。默认未播放缓存上限120秒，可设20～600秒。

缓存占用=待合成文字预计时长＋已完成声音的实际未播放时长。首次按每秒4个口播字符和所选语速估算，已有音频后按最近最多10段的实际语速校准。估算只用于生产背压，SRT与时间轴仍使用实际PCM时间。音频完成后以实际时长替换估算，不重复计算；已播完段不占缓存。

达到上限不再发下一次话术请求，等播放消耗后继续。一次在途段可能使缓存略超上限，随后等待；不要求先合成完上一段，待合成/失败文字同样占缓存，所以TTS慢或失败也不会无限堆文字。

浏览器阻止自动播放或音频播放失败时提示手动播放/核对，文字最多继续到总缓存上限。播放器按采纳顺序消费完整音频包。文字完成后声音队列可继续补齐和播放；页面关闭不发新请求。刷新仅恢复本场生成记录，不自动重播历史声音、不假装恢复core播放位置。结束本场停止浏览器试听并清理Redis，不删除已归档媒体。

测试调度由页面驱动，背压统计和顺序声音worker已提取为可复用模块。正式移植还需生成端持续调度及core播放消耗适配；本次未接入真实房间，也未实现服务器脱离页面的自动生产。

- 主次权重70/20/10仍只有`style-scoring-policy.md`母版，尚未导入方案数据库或接入实际加权评分器；不能把本次问句/禁用词修复称为权重迁移完成。
- 没有自动发布生产服务器、没有启动真实直播间。真实音色及浏览器试听由用户下一场测试确认。
