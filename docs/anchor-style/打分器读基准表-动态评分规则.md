# 打分器如何读基准表 —— 动态评分规则规格

> 目标：让程序打分器不再写死「啊要多、问号要够」这类通用规则，
> 而是**拿「基准提取器」输出的基准表当标尺，动态决定每一项怎么扣分**。
> 这样换任何主播（哟为主/啊为主、问号多/问号少），打分器都能正确评判，不误判。

---

## 一、核心原则

**打分器的评分规则 = 通用框架（固定） + 基准表参数（换主播变）。**

- 「通用框架」：8 个维度、扣分逻辑——**写死，系统开发时定**
- 「基准表参数」：主力语气词、配比目标、称呼频次、情绪特征、问句频率——**来自基准提取器，换主播就换**

打分器启动时，先读基准表，把参数「注入」到通用框架里，生成「这个主播专属的评分器」。之后每段话术都用这个专属评分器打分。

---

## 二、通用框架里，哪些「死规则」要改成「读参数」

以下用早期固定数值说明为何要读取当前基准；具体适用范围、叠加/封顶规则以[评分功能落地说明](评分功能落地说明.md)和现有scorer为准：

| 原写死规则 | 问题 | 改成读基准表 |
|---|---|---|
| 啊:嘛 ≥ 5:1 | 假设「啊」永远是主力，换主播失效 | 读「语气词配比目标」，判断「主力词占比是否达标」 |
| 啊 ≥ 3.5/百字 | 同上 | 读「每百字_主力语气词」，判断「主力词密度」 |
| 哥哥姐姐们 ≥ 2.5/百字 | 假设称呼永远是哥哥姐姐们 | 读「每百字_主力称呼」，判断「主力称呼密度」 |
| 我们家 ≥ 1.5/百字 | 假设自指永远是「我们家」 | 读「每百字_自指词」，判断「自指词密度」 |
| 问号 ≥ 1.5/百字 | 假设主播靠问句互动 | 读「问句使用频率」，动态调权重 |
| 感叹号 ≥ 1.5/百字 | 同上 | 读「每百字_感叹号」+「情绪特征」 |

## 三、动态评分规则（打分器照着实现）

### 维度 1：语气词配比（满分 15）

**读基准表**：`语气词配比目标`（如「哟:啊 ≈ 1.1:1」）、`主力语气词`（如「哟」）。

```
主力词 = 基准表.主力语气词
实际主力词频次 = 统计(文本).主力词次数
其他语气词频次 = 统计(文本).其他语气词次数

扣分规则：
- 主力词次数 < 其他任一语气词次数  → 扣 8（主力词被反超，最伤）
- 主力词 = 0 → 扣 12（主力词绝迹）
- 主力词占比达标（≈ 基准表的配比目标）→ 不扣
- 主力词绝对量 < 基准表「每百字_主力语气词」× 0.5 → 扣 4（密度塌）
```

**关键**：不再写死「啊要多」，而是「**基准表里的主力词必须最多**」。

### 维度 2：主力称呼密度（满分 15）

**读基准表**：`每百字_主力称呼`、`主力称呼`、`各称呼频次`。

```
目标值 = 基准表.每百字_主力称呼（如 2.2）
实际值 = 统计(文本).主力称呼次数 ÷ 文本字数 × 100

扣分规则（按缺口扣）：
- 实际 ≥ 目标 × 0.8 → 不扣
- 目标×0.5 ≤ 实际 < 目标×0.8 → 扣 5
- 目标×0.3 ≤ 实际 < 目标×0.5 → 扣 9
- 实际 < 目标×0.3 → 扣 12
```

**关键**：称呼词是「从基准表读出来的」，不是写死的「哥哥姐姐们」。

### 维度 3：自指词密度（满分 15）

**读基准表**：`每百字_自指词`、`自指词`（如「我们家」）。

```
目标值 = 基准表.每百字_自指词（如 0.9）
实际值 = 统计(文本).自指词次数 ÷ 文本字数 × 100

扣分规则：
- 实际 ≥ 目标 → 不扣
- 实际 = 0 → 扣 12（自指归零）
- 0 < 实际 < 目标 → 按缺口扣（目标×0.5 以下扣 8，其余扣 4）
```

**关键**：统计时只数基准表里的「自指词」（如「我们家」），**「我」「我们」不算**——这是基准提取器已经定死的规则，打分器直接继承。

### 维度 4：句式节奏（满分 15）

**读基准表**：`平均分句长度`、`确认句库`、`长句短句搭配`。

```
扣分规则：
- 文本里一个「确认句库」里的确认句都没有 → 扣 10
- 确认句只有 1 种、反复用（如通篇只「都拍到了不」）→ 扣 5
- 平均分句长度偏离基准表「平均分句长度」±50% 以外 → 扣 3
```

### 维度 5：情绪（问号+感叹号）（满分 15）—— 权重动态调

**读基准表**：`问句使用频率`、`每百字_问号`、`每百字_感叹号`、`情绪特征`。

```
这是最关键的一维，权重必须跟着基准表走：

Case A：基准表「问句使用频率 = 高」
  → 问号权重 8 分、感叹号权重 7 分（主播靠问句互动）
  → 问号 < 基准表.每百字_问号 → 扣相应

Case B：基准表「问句使用频率 = 中/低」（如本例「中」）
  → 问号权重降到 3 分、感叹号权重升到 12 分
  → 因为这种主播不靠问句，靠「哟/感叹号/催单短语」驱动情绪

扣分规则：
- 感叹号 < 基准表.每百字_感叹号 → 按缺口扣（权重 12 分里扣）
- 问号 < 基准表.每百字_问号 → 按缺口扣（权重 3 分里扣）
```

**关键**：本例主播「问句频率=中、每百字问号仅 0.33」，那「问号少」就不能扣太多分——否则误判。**情绪这一维的总分不变（15 分），但问号和感叹号各自的权重，按基准表的「问句频率」重新分配。**

### 维度 6：数字比价（满分 10）

**读基准表**：`算账句式`、`价格表述方式`、`比价锚点举例`。

```
扣分规则：
- 文本无任何价格数字 → 扣 7
- 有价格但无「省/便宜/划算」等优惠动作 → 扣 3
- 有「省X」但数字卡壳/逻辑乱 → 扣 3
- 符合基准表「算账句式」（如「平时X→今天Y→省Z」）→ 不扣
```

### 维度 7：重复回环（满分 10）

**读基准表**：`高频回环短语`、`回环强度`。

```
目标回环短语 = 基准表.高频回环短语（如「新粉跟着老粉丝走…」）
扣分规则：
- 文本里没出现任何「目标回环短语」→ 扣 5（该主播的标志性回环丢了）
- 出现了但只 1 次 → 扣 2（回环强度不够）
- 回环强度=高 的主播，回环短语应出现 ≥2 次，不够扣 3
```

### 维度 8：环节位置（满分 5）

**读基准表**：不依赖基准表，通用判断。

```
扣分规则：
- 无任何逼单/稀缺/呼告 → 扣 2
- 逼单堆在开头（位置错）→ 扣 2
```

## 四、打分器的「启动流程」

```
1. 读基准表（JSON）
2. 提取参数：主力语气词、配比目标、主力称呼、自指词、每百字基准、问句频率、回环短语
3. 生成「专属评分器」：把参数注入 8 个维度的扣分规则
4. 之后每段话术 → 用专属评分器打分
5. 换主播 → 重新跑 1~3，生成新评分器
```

## 五、评分输出边界（2026-10-21）

评分输出各维得分、实际值、基准与扣分原因。`feae7fd`已下架评分侧纠偏草稿；不再产生回灌模板或自动向下一段补偿密度。此处保留八维评分设计，不能将评分误作事实核验或实机声音情绪判断。

---

## 六、评分实现与验收约定

1. **读基准表**：`load_baseline(json)` → 解析出参数对象
2. **生成评分器**：`build_scorer(baseline)` → 返回「注入了参数的 8 维扣分函数」
3. **打分**：`score(text, scorer)` → 返回 8 维得分 + 总分
4. **解释结果**：保留实际统计、基准快照、扣分原因、样本/正文SHA及规则版本；不生成纠偏草稿。

**验收标准**：
- 换两个不同主播（哟为主 vs 啊为主），同一套代码跑，各自打分不误判
- 对「问句频率=低」的主播，问号少不会被扣大分
- 同一段话术跑 10 次，结果逐字节一致
