- 商品归属 JSON 保持严格字段和类型校验。初次校验失败后，使用 `cycle-product-scope-repair.md` 回灌错误给已配置模型，最多校正两次；逐次保留原始请求和返回。不靠程序删字段、数字强转或猜归属来放行。
- 归属分析日志现在携带当前 room_id。事实和角度错误反馈包含输入 ID 和所需链接，方便模型精准校正。

- 保存后事实变化导致主辅推范围与安全包不一致时，拒绝发布并提示重新保存，不覆盖旧发布版本。
- 实时模式的发布入口不再要求固定文稿或预先生成的声音。

## 异步失败

失败原因按租户、直播间和场次存入本进程命名空间的 Redis，含场次编号、错误码、用户可读原因和时间。即便失败发生在创建大循环状态之前，也可返回给前台。

失败后关闭本场计量记录，按 Core 实际工作秒数结算，不留下「暂停」假状态。失败详情不用于恢复运行；重启后不恢复旧进度。晚到错误不得应用到不同场次。

运行状态返回 `failure` 和 `agent_stop_reason`。前台收到本场失败立即结束第一声等待动画，显示弹窗并保留页面提示；同一场不随五秒轮询重复弹窗。手动停止和普通暂停不算失败。提供给用户的错误不包含模型密钥或签名资源地址。

## 统一弹窗

公共请求入口覆盖 HTTP、网络、响应解析、流式错误；录音/音稿上传也接入。直播间与方案页面的业务校验错误接入全局反馈。未处理的组件或 Promise 异常提供通用错误弹窗，完整诊断仍留在日志。

不同错误排队展示，不覆盖前一个未确认错误；连续相同 GET 失败只提示一次，恢复后再次失败会重新提示；用户重新提交的写操作失败仍提示。主动取消请求不报错。保存失败明确「未生成或发布新版本」，发布失败明确「仍使用原版本」。
