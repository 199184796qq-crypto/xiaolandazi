## 金额与归属

金额全部用整数微元核算，1 元 = 1,000,000 微元。按 tenant + room 的滚动一小时合计，不按自然整点或 session 清零。停止、重开、更换方案或声音仍继承同房间已有费用。

| 语音池 | 总额目标 | 主线 TTS | 互动模型与 TTS | 主线改写模型 | 差额预留 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 标准 | 1.30 | 0.80 | 0.35 | 0.05 | 0.10 |
| 高仿真 | 3.00 | 2.10 | 0.60 | 0.10 | 0.20 |

新请求只能使用对应分类额度，不能挪用另一分类或差额预留。总额同时检查。主线原文、改写正文、换主播后补声音的 TTS 都算主线；正文生成、修复、补写等主线模型工作算改写；互动问题归类、回答和声音合用互动额度。必要供料也必须通过费用检查。

额度档位取直播间实际已发布方案的 TTS 池，不取当前正在调用的文字模型供应商。旧账也计入同房间合计；变更池档位不会抹掉此前费用。方案授权与当前上线音色仍由前轮运行态协议校验。

## 发送前预留与回执

1. 所有直播付费发送入口先核对租户、房间、场次、方案、运行域及 running 状态。
2. 在已有 `live_cost_room_locks` 的房间行锁下读取费用，检查分类和总额，再写入预留；不同进程和场次使用同一数据库锁。
3. 成功按供应商有效用量及发送前的价格快照结算；已付费结果的缓存、归档或日志失败不会触发重复购买。
4. 明确未发送的请求释放预留，可以使用相同操作标识重新申请。预算拒绝不永久占用操作标识；未来窗口有余额后允许再次申请。
5. 已发送但回执未知的请求持续保留预留，超过一小时也不当作免费。迟到结算从回执更新时间继续覆盖一小时，避免已付费请求刚补记就消失。重复相同回执不延长窗口；后续有效账单修正可能保守延长计入时间。
6. 账本、配置或预留失败时，严格直播入口不再走原来的“必要供料继续付费”降级。旧非直播调用的兼容行为保留。

数据库沿用现有请求账本和行锁；本轮仅向 request_json 添加费用分类和语音池元数据，不新增表或列。新元数据不改变供应商工作身份，旧未知请求不能因升级或价格变化再次发送。前轮音色批次新增状态表仍是未来整合发布时的独立迁移要求。

## 费用不足时的播放

主线使用既有缓存接续和退避重试：未生成的新片、换声准备及改写暂停购买，已有有效声音继续播放。没有缓存时不能承诺有声；不得为持续出声绕过费用限制。预算拒绝属于明确未发送，不留下永久的整段购买标记。

互动额度耗尽时停止新付费互动，主线继续；已完成的结果保留。后台“可选软线”为零时，改写和换声准备仍暂停。原 14,000 汉字计划级限制保留为次级保护，不能用它代替金额账本。

## 价格及可保证的边界

- 高仿真 seed-icl-2.0 默认按 3 元 / 万 Unicode 字符预留，标点纳入；不使用阿里汉字双字符换算。显式匹配的供应商价格配置可以覆盖参考价。[火山计费说明](https://docs.volcengine.com/docs/doubao-voice/billing-instructions?lang=zh)
- Qwen Audio 3.1 TTS Flash 北京地域参考输入 1.5 元 / 百万 Token、输出 12 元 / 百万 Token；已有明确 Token 合约价优先。发送前以每字符 4 个输入 Token + 512、每字符 8 个输出 Token + 512 保守预留，收到有效用量后校正。缺少用量时保持该预估费用，不能降成廉价字符报价。[阿里模型说明](https://help.aliyun.com/zh/model-studio/qwen-audio-3-1-tts-flash)
- 文字模型按 UTF-8 输入字节及消息余量、实际请求 max_tokens 保守预留。直播中无法核对输出上限、图片计价或不透明旧 Agent 请求结构的工作不发送；不修改提示词、不额外添加模型输入，也不擅自添加供应商未支持的参数。
- Qwen HTTP TTS 官方参数没有可用的输出 Token / 音频时长硬上限，因此以上是系统对估价和已知费用的发送闸门，不能保证任何单笔供应商账单都不超估。差额先落账，后续请求据余额停止；部署前应核对实际账号地域和价目。[HTTP 参数说明](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api)
- 保存方案预生成等无直播场次的离线操作仍沿用原账本与费用路径，不计成某一直播间的本场付费生成；它们可能另行产生费用。缓存命中、播放、本地文件处理不算新的供应商请求。

后台成本页面保留价格与内容更新规划输入，明确展示两池实际发送限额及分类，不将原软目标显示成唯一硬上限。
