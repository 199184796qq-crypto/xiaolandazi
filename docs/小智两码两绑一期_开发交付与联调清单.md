# 小智两码两绑一期：开发交付与联调清单

更新：2026-10-02。状态：本地代码及构建完成，尚未部署生产、尚未刷入实机，真实 MySQL 事务联测待完成。

## 1. 本次实现

- 库存单台入库登记 MAC，批量入库按 SN 行序配对 MAC；旧库存可通过“硬件登记”补录，已登记 MAC 不可随意改动。
- 合格且已售出的设备允许认领；库存测试设备需员工明确开启测试认领，填写原因并审计。未登记、不良、维修或报废设备不给有效码。
- 网关向管理服务查询设备登记和归属；服务端生成六位数字绑定码，10 分钟有效、认领后作废，有效期内重复查询保持不变。
- 绑定码使用密码学随机数，全局有效码哈希唯一；数据库保存 HMAC 和 AES-GCM 密文，不保存明文码。
- 客户账号输入绑定码与设备名称认领。默认“小蓝直播助手”，随后“02”“03”，客户内名称不能重复；名称可修改，释放后的序号不回退。
- PC 设备绑定页和手机 `/devices` 页都支持添加、改名、选择自己直播间、解绑直播间；替换已占用房间前有确认提示。
- 一台设备同一时间只绑定一个房间，一个房间只有一台主设备。运行中的设备、目标房间或原房间不可换绑，先停止任务。
- 解绑房间保留客户所有权。售后拥有独立“释放所有权”入口，需权限、原因和二次确认，清除归属、房间、心跳与旧码，并记录库存账及审计；不代表实物退回仓库。
- 网关每 5 秒同步归属和房间，未认领设备仅保持显示绑定码的受限连接，不启动房间音频；管理服务失败时不回退到旧绑定继续播放。
- 客户设备接口输出设备名称、业务编号和中文状态，不输出硬件 MAC；历史 SN 恰为 MAC 时替换为业务编号，包括直播运行会话。
- 状态展示含正常工作、离线、连续待机、已暂停、连接中、设备异常；页面离线依据 20 秒心跳超时判断，设备连续离线 60 秒作为 Agent 与计费硬停止信号；完整音频故障回执和恢复行为仍需联调补齐，不能据此宣称异常链路已验收。
- 固件隐藏表情、黄脸及开机表情层，接收 `device_status` 显示绑定码、名称、房间和状态。待机不再显示 MAC，断连时清除旧码，语音文字下发保持兼容。

## 2. 接口与数据

| 用途 | 接口 |
| --- | --- |
| 下一设备默认名称 | `GET /api/v1/live/devices/default-name` |
| 客户认领 | `POST /api/v1/live/devices/claim`，`binding_code`、`device_name` |
| 客户改名 | `PATCH /api/v1/live/devices/{id}`，`device_name` |
| 绑定房间 | 复用 `POST /api/v1/live/devices/{id}/bind` |
| 解绑房间 | `DELETE /api/v1/live/devices/{id}/bind` |
| 员工补录硬件/测试激活 | `PUT /api/v1/inventory/devices/{id}/hardware` |
| 售后释放所有权 | `POST /api/v1/inventory/devices/{id}/release-ownership`，`reason` |
| 网关查询登记/绑定码 | `POST /internal/v1/xiaozhi/provision` |
| 网关心跳 | `POST /internal/v1/xiaozhi/heartbeat` |

新增表：`device_hardware_profiles`、`device_claim_codes`、`device_name_sequences`、`device_provisioning_events`。由管理服务库存迁移流程创建，不批量迁移旧 MAC/房间配置。

内部接口通过 `X-Xiaozhi-Internal-Token` 鉴权；管理服务未设置密钥时关闭内部设备服务与客户认领。认领接口目前为单进程限流：账号每分钟 5 次，全局每分钟 100 次；多副本上线前需共享限流。

## 3. 部署顺序（本次未执行）

1. 先完成隔离 MySQL 事务测试，备份生产数据库和已有网关绑定文件，核对历史库存归属。
2. 在管理服务环境中设置 `XIAOZHI_INTERNAL_TOKEN`，网关使用完全相同的随机长密钥；不要把密钥放到浏览器或固件。
3. 发布管理服务，让新增表迁移完成，再发布 PC 和手机端。网关此时可暂留旧模式。
4. 在测试设备库存档案补录实际 STA MAC，核对销售客户。库存测试机由员工显式开启认领，不自动替全部库存放行。
5. 发布新网关并设置 `XIAOZHI_MANAGEMENT_BASE_URL` 为管理服务内部地址，例如 `http://127.0.0.1:8080`。保持已有 `XIAOZHI_DEVICE_SECRET`、公网 WSS、OTA 地址不变；内部接口不开放公网。
6. 开启管理模式后，以数据库归属为准，旧 JSON 绑定不再生效，旧网关绑定写接口拒绝修改；现有房间 25 和测试盒子应逐台认领验收，不静默迁移。
7. 最后刷入新的测试固件，完成“屏幕码 → 客户添加 → 房间绑定 → 音频与文字 → 换房/解绑”的实机验证，再向其他设备推广。

现有安装脚本不会自动把管理服务密钥同步到网关，也不会自动打开管理模式，部署时必须明确核对上述两个环境变量。回滚网关到旧模式可能恢复旧 JSON 路由，因此应停播并同时复核绑定，不直接热切换。

## 5. 固件与实机注意

源码目录：`C:\Users\19918\Documents\Codex\xz226`；构建目录：`phase1`。芯片 ESP32-S3，CAM 板型，16 MB Flash，DIO，80 MHz，屏幕等参数沿用本地原项目 sdkconfig。

本次交付的完整合并文件 `xiaolan-phase1-full.bin` 含引导、分区、应用和资源，可在 ESP32S3 FLASH DOWNLOAD TOOL 的单行中选择，地址填 `0x0`。应用单文件 `phase1\xiaozhi.bin` 只能写对应 `0x20000` 分区，不能当完整包写 `0x0`。

烧录前先完成服务器配置，核对实际板型和串口并备份当前配置。注意：完整合并包从 0 写入会用填充字节覆盖中间的 NVS 区域，原 Wi-Fi 配网等配置可能丢失，需要重新配网；不能声称“不擦除就能保留配置”。如需保留 NVS，使用分区文件分别按 `flasher_args.json` 的地址烧录，不要写合并包或执行全片擦除。烧录、屏幕效果、实际联网认领和房间音频仍未验收。
