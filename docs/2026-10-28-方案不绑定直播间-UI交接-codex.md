# 方案不再绑定直播间：界面交接（给 codex）

日期：2026-10-28。后端已上线，前端需要按本文件改。

## 1. 产品规则（本次生效）

- 一个账号可以建多个直播方案；
- 方案是**账号级资产**，不需要绑定任何直播间；
- 任意直播间开播前，从**本账号全部方案**里下拉选择；
- 「绑定方案」「解绑方案」入口全部去掉；
- 方案内的声音、事实、问题库、目的、读写规则随方案走；换方案即换一套配置。

## 2. 后端已改

| 变化 | 说明 |
|---|---|
| 方案列表 | `GET /api/v1/rooms/{roomID}/live-agent-plans` 返回账号下**全部**有已保存版本的方案，当前选中的排第一 |
| 选择方案 | 房间选择只写选择关系，不再要求绑定：`SelectLiveAgentPlanForRoom` 已去掉绑定校验 |
| 解析房间方案 | `GetLiveAgentPlanForRoom` 只看选择关系，不再联表绑定 |
| 已发布版本 | 去掉绑定联表，按房间选择取方案的最新版本 |

保存方案即生效，不再需要单独「发布/绑定」房间。

## 3. 前端要改的地方

### 3.1 方案切换

- 顶部/直播页的方案下拉：数据源改为上面的接口；
- 选中后调用现有选择接口（房间 → 方案），提示「已切换，重新开播生效」；
- 删除「绑定直播间」「解绑」按钮、以及相关确认弹窗、文案、状态标签。

### 3.2 开播前检查

- 没选方案 → 提示「请先选择一个方案」，并直接展开下拉；
- 选中的方案没有已保存版本 → 提示「该方案还没有保存，请先保存」。

### 3.3 声音

- 方案保存时校验声音可用：绑定的 voice binding 必须存在且 `status=ready`；
- 不可用时在保存处直接提示，并给出可选声音列表，不允许把失效声音存进方案；
- 声音选择只在方案内，不在房间上。

### 3.4 文案

- 「绑定方案」→「选择方案」；
- 「已绑定直播间」→「当前使用方案」；
- 「方案未绑定」不再作为错误。

## 4. 验收

| 编号 | 操作 | 期望 |
|---|---|---|
| P1 | 账号建 3 个方案 | 列表全部可见，无需绑定 |
| P2 | 房间 A 选方案 1 | 开播用方案 1 |
| P3 | 房间 A 改选方案 2 | 重新开播用方案 2 |
| P4 | 房间 B 同时选方案 1 | 两个房间可共用同一方案，互不影响场次数据 |
| P5 | 选一个没保存版本的方案 | 明确提示先保存，不进入开播 |
| P6 | 方案声音被停用后保存 | 保存被拦下并提示换声音 |
| P7 | 页面不再出现绑定/解绑入口 | 全站文案检查通过 |

## 5. 注意

- 不要删除数据库里的历史绑定记录，只是不再作为使用前提；
- 场次仍要记录本场使用的方案与版本，回放和账单需要；
- 同一方案被多个房间同时使用属于正常情况，不要加唯一性限制。
