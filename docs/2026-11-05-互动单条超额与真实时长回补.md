# 互动单条超额与真实时长回补

用户批准统一估时、计算临时额度恢复时间、过期保留欢迎机会；另批准单条超过分钟额度完整播放，按实际时长记账后延后后续互动，明确要求修改上线。没有批准缩短欢迎正文、修改提示词或增加模型调用，本轮不做这些变更。

## 行为

- 40/30/20秒仍是最近一分钟互动节奏额度，不再是单条音频硬上限。单条超过本档全部额度时，必须等该档额度全部恢复后才能借用一次；不允许在已有占用上连续借用。普通短段仍按所需时长等待。32.2秒在30秒或20秒档均可完整播放。
- 选中阶段与合成前统一由Core估算，每Unicode字符230毫秒、至少3秒；合成前采用包含后置称呼的完整文字和实际TTS语速，真实音频准备后按实际时长再预留。初始正文估算是未拼称呼、名义1倍速的暂估，不冒称实际声音长度。
- 已播额度按实际PCM累计毫秒记入，完整音频或部分失败均不取预估时长替代；旧无计数生产者保留原兼容处理。回执仍经过场次/任务/epoch所有权检查，重复/迟到回执不得重复记账。已起播不因排队期限到达而截断。
- 临时额度不足时，按最近一分钟历史重叠和当前档位计算最早可行毫秒，不再固定5秒重试。若恢复时间已赶不上原期限，记录audio_duration_budget_deadline并释放；不无限续期，不假装已合成或已播放。
- 未起播的欢迎不消费机会；旧正文/旧名单到期后，沿原调度器收集近期新观众再生成，不重放过时名单。
- Core终态保留任务类型、来源主题、标题、原截止和最后准备阻塞原因；预检日志保留估时、剩余额度、计算等待及原截止。模型回执契约、母版与客户方案保持不变。
