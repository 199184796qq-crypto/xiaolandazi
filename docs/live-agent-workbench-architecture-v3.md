## 方案定位与当前界面

方案是组合容器、版本快照与发布单位，不是一篇固定整场话术。保存版本与本场已加载版本不同；进行中的直播使用其启动快照，不因修改页面草稿而静默替换。

当前一级导航：**业务模式、商品与事实、互动规则、主播风格、声音、直播模式**。商品链接、活动福利、正式事实及来源仍按业务资产管理，不因界面合并而混为同一类数据。

- “初始化方案”主按钮执行增量准备；箭头菜单中的“全部重置”沿用明确重建流程，不把普通点击变成全部重做。
- “直播模式”位于“声音”右侧，进入原生成/预览能力；不恢复顶部“生成与预览”重复入口。
- 顶部保留绑定数量、方案编号和最新保存版本；已移除有待保存资料、本场加载/未开播及版本记录入口。移除标签不删除后台保存、历史读取或实际加载状态。
- 新建、声音语速等后续页面变更分别见[方案声音语速](2026-10-20-方案声音语速自动保存与回显.md)及[方案弹窗与语速发布记录](2026-10-21-方案弹窗与语速上线.md)；发布记录中的阻塞状态不能当作已上线。

## 资料、商品、活动与事实

原始资料只作为来源，整理不得覆盖原文。分析产生候选，用户采纳后形成正式业务资产；口播参考、主播风格和观众留言不能自动变成商品事实。

商品链接负责当前卖什么，编号、名称、规格、价格/数量、状态、来源和版本分别保存。活动福利负责临时优惠、赠品、有效期和适用条件，不把短期权益写成长期商品属性。过期/停用权益不得继续作为可说事实。

事实依据负责客观的产地、原料、规格、工艺、服务、履约及售后条件。正文、禁说、安全改写和来源关联必须完整传递，不能只取一行标签。公共事实与商品专属事实分开；每段只补本次结论直接相关的条件，不能因有公共事实就每段朗读全部限制。

话术参考提供组织、转场与表达方式，其中的价格、功效、人物关系和交易承诺不得升级为正式事实。用户纠正涉及事实或活动变更时仍须进入对应确认/版本流程，不能把一句对话直接改成所有场次的有效事实。

## 互动、风格与声音

互动规则负责事件处理与回答边界，不拥有主线配额或Core播放状态。当前轻量互动与目的解析见[内容策略契约](anchor-style/content-purpose-angle-strategy.md)；历史回灌、任务讲解和学习纠偏路径已在仓库下架，不能照旧文恢复。

主播风格只回答怎么说，可不绑定；未绑定时不得强制制造风格或评分资产。绑定时使用其有效版本与基准。个体昵称、主播自指、群体称呼和固定行动词分开，风格样本中的“表妹”等关系称呼不能直接套给未知观众。相关实播问题仍需验收，不能用风格分数替代事实与称呼核验。

声音与风格分离。方案保存供应商、模型/音色和语速；语速默认1，按租户+方案保存，新旧方案均兼容，刷新/切换读取真实设置。控制台调整后自动保存，旧方案版本提交不能覆盖独立声音设置。新语速影响后续TTS及声音指纹，不承诺已排队音频立刻变速。

## 正式生成与运行

方案准备得到商品、事实、任务/角度、互动规则、可选风格和声音；启动时冻结正式资产与配置。主线由程序逐段选择任务，以“必说、可说、不提、改写”四层提供本段事实边界；不是预先生成固定A/B/C/D/E整场稿再无限朗读。

首开现场生成新文字与TTS，后续普通段按[成品复用机制](话术库复用机制设计方案.md)朝七三目标运行。事实、风格与母版变更按指纹失效；语速/音色只换声音。缓存不能反过来调商品或绕过采纳检查。

审核开关决定是否有模型复核；SkipReview下程序采纳不是模型“通过”。完整步骤见[当前生成链路](话术生成链路架构.md)。TTS完成、排队、Core开始和PCM完成分别记录，不能把生成成功当作用户设备已出声。

## 版本、来源和审计边界

方案层负责引用正式资产、绑定房间、保存组合版本及加载快照，并记录相应操作与来源。原始资料、候选、采纳事实、风格、声音和运行快照有不同生命周期，不能把它们塞进一个无来源的全文覆盖操作。

Core消费编译后的运行任务与播放材料；Web通过管理API访问业务，保留租户/方案/房间授权。编辑、采纳、保存、加载和已播放是不同动作。版本回滚或初始化不能隐式覆盖其它客户、当前在途播放或未确认资料。

## 保留的设计底线与待闭环事项

1. 素材、参考话术、主播风格均不等于正式事实。
2. 活动有状态、条件和期限，缺失条件不能由模型补造。
3. 采纳与版本保存必须保留来源；修改草稿不自动改正在运行的快照。
4. 已下架回灌/任务讲解不得因旧文或旧界面建议恢复。
5. 统一自然语言变更提案、全模块一致的审计/回滚交互仍是设计目标，不能把旧路线图当作全部已完成。
