# 直播智能体组装工作台架构 V3

更新时间：2026-09-27

## 1. 核心定位

当前“直播策略”页面升级为 **直播智能体组装工作台**。

一个“直播间智能体方案”不再直接保存一篇话术，也不直接承载所有业务内容；它是一个 **组合容器 + 版本快照 + 发布单位**。

运行时生成链路：

规则层
→ 行业层
→ 当前直播间智能体方案
→ 商品链接
→ 当前有效活动福利
→ 已采纳事实依据
→ 已采纳话术参考
→ 已采纳互动策略
→ 主播风格
→ 声音
→ 直播期间动态纠正
→ 直播智能体生成
→ 主线 / 插播 / TTS / 分发

## 2. 顶部模块顺序

方案内部固定按以下顺序组织：

1. 直播素材
2. 商品链接
3. 活动福利
4. 事实依据
5. 话术参考
6. 互动策略
7. 主播风格
8. 声音
9. 直播智能体生成

其中只有“直播素材”是原始资料入口，其它模块都属于可管理的正式业务模块，必须具备候选、采纳、添加、修改、停用/删除、版本与审计能力。

## 3. 直播素材

直播素材是所有原始资料的统一入口，本身不等于正式业务数据。

允许的素材包括但不限于：

- 直接粘贴文本
- TXT / MD
- 图片 / 截图
- PDF
- Word
- Excel
- HTML
- 逐字稿
- 聊天记录
- 活动海报
- 商品资料
- 后续音频 / 视频转录结果

素材进入后由智能分析做“信息路由”：

- 商品与链接 → 商品链接候选
- 活动价 / 赠品 / 满减 / 限时条件 → 活动福利候选
- 产地 / 规格 / 快递 / 发货 / 售后 / 公司信息 → 事实依据候选
- 优秀口播内容 → 话术参考候选
- 欢迎 / 答疑 / 逼单 / 回主线等行为规则 → 互动策略候选
- 表达方式 → 主播风格候选

原始素材必须保留，分析和整理不得覆盖原始内容。

## 4. 商品链接

商品链接回答“这个直播间当前卖什么”。

每条正式商品链接至少包含：

- 链接编号
- 商品名称
- 规格
- 日常价格（如存在）
- 数量 / 组合
- 赠品关系（如属于长期固定权益）
- 适用场景
- 状态
- 来源
- 版本

临时活动价、限时赠品等不长期写死在商品链接里，应进入“活动福利”。

## 5. 活动福利

活动福利必须独立成模块，不并入普通事实依据。

原因：活动具有明显的时间性、条件性和失效性。

每条活动至少包含：

- 活动名称
- 关联商品链接
- 福利类型
- 福利内容
- 生效条件
- 开始时间
- 结束时间
- 数量限制（如有）
- 适用对象（如有）
- 运行时状态：草稿 / 待采纳 / 生效中 / 已过期 / 已停用
- 来源素材
- 版本

活动过期后，直播智能体生成器不得继续引用。

## 6. 事实依据

事实依据回答“什么是真的”。

适合保存：

- 产地
- 原料
- 规格
- 工艺
- 公司信息
- 默认快递
- 发货时间
- 售后条件
- 产品客观属性

分析阶段只产生候选，用户明确采纳后才进入正式事实。

## 7. 话术参考

原“直播节奏”改为“话术参考”。

这里保存用户希望智能体参考的优秀表达来源，例如：

- 自己过去的直播稿
- 别人的优秀逐字稿
- 经过人工确认的高质量生成稿
- 用户自己写的一段直播表达

话术参考的主要作用是提供 **组织方式、讲解路径、转场和表达案例**。

其中出现的商品事实不能自动升级为正式事实。

## 8. 互动策略

原“学习记忆”改为“互动策略”。

互动策略只保存直播过程中的行为与交互规则，例如：

- 新人如何欢迎
- 同类问题如何聚合回答
- 高热时减少答疑还是集中答疑
- 用户问价格时先回答什么
- 插播后如何回主线
- 什么时候逼单
- 哪类弹幕如何处理
- 老客如何称呼

直播中的用户纠正必须先经过“学习路由器”分类：

- “不要一直喊宝宝们” → 互动策略 / 主播风格
- “默认发顺丰” → 事实依据
- “今天活动价 69.9” → 活动福利
- “说话多短句、少书面语” → 主播风格

不能再把所有纠正都堆进一个模糊的“学习记忆”池。

## 9. 主播风格

主播风格只回答“怎么说”，不携带商品事实。

后续支持三种来源：

1. 系统主播风格库
2. 用户自己学习并保存的主播风格
3. 当前直播间在既有风格上继续微调的版本

主播风格必须支持采纳、添加、修改、复制、另存、停用、版本和审计。

## 10. 声音

声音回答“用什么声音说”。

至少包含：

- TTS 供应商
- 模型
- 官方音色 / 克隆音色
- 默认语速
- 情绪 / 语气偏好
- 其它支持的声音参数

主播风格与声音必须分离，不能绑定成一个不可拆开的对象。

## 11. 直播智能体生成

原“整场话术”升级为“直播智能体生成”。

只有前面的正式配置准备好后，才进入这一页。

输入：

- 规则层
- 行业层
- 商品链接
- 当前有效活动福利
- 正式事实依据
- 已采纳话术参考
- 已采纳互动策略
- 主播风格
- 声音
- 最新动态纠正

输出：

- A / B / C / D / E 多套完整主线变化稿
- 自动事实复核
- 链接一致性复核
- 活动有效性复核
- 相似度复核
- TTS 语气 / 语速建议
- 预览 / 试听
- 发布版本
- 回滚

## 12. 直播间智能体方案保存什么

直播间智能体方案只保存“组合关系”和“发布快照”，不把所有内容复制塞在一个大 JSON 里。

示例：

```text
菜籽油直播智能体方案01
├─ 商品链接版本 V5
├─ 活动福利版本 V3
├─ 事实依据版本 V8
├─ 话术参考集合 V4
├─ 互动策略版本 V6
├─ 主播风格：主播A风格 V2
├─ 声音：音色A V1
└─ 直播智能体发布版本
   ├─ V11
   └─ V12 ← 当前运行
```

方案层负责：

- 绑定直播间
- 选择各模块的正式版本
- 记录当前组合
- 生成发布快照
- 版本回滚
- 审计谁在什么时间修改 / 发布 / 删除 / 切换了什么

## 13. 前台操作方式

除“直播素材”外，其它模块的主要添加、修改、删除交互统一通过前面的系统智能体输入框完成。

典型流程：

用户自然语言输入
→ 智能体识别目标模块
→ 生成变更卡
→ 用户确认“采纳”
→ 写入对应模块的新版本
→ 记录审计
→ 当前直播方案引用新版本

后台模块页面主要负责：

- 查看
- 核对
- 采纳候选
- 查看来源
- 查看版本
- 回滚
- 停用 / 删除

## 14. 设计底线

1. 素材 ≠ 事实。
2. 参考话术 ≠ 事实。
3. 主播风格 ≠ 商品事实。
4. 活动福利必须有有效期和状态。
5. 分析阶段不自动进入正式业务数据。
6. 用户明确采纳以后才形成正式版本。
7. 直播运行时必须只消费当前方案引用的正式版本与当前有效活动。
8. Core 不负责业务配置解释，Core 只消费已经编译好的运行时结果。

## 15. 当前代码推进顺序

第一阶段：

1. 调整页面模块名称和顺序。
2. 新增“活动福利”页面位置。
3. 把“整场话术”升级为“直播智能体生成”。
4. 把方案头部明确为“组合容器 / 发布单位”。
5. 保留现有商品链接、正式事实、主播风格、声音与整场生成能力，不破坏当前数据。

第二阶段：

1. 为商品链接、活动福利、话术参考、互动策略、主播风格、声音补齐统一版本模型。
2. 前面的系统智能体输入框统一调用“模块变更提案”协议。
3. 采纳后写正式版本并记录审计。
4. 素材智能分析增加自动路由到各模块候选区。

第三阶段：

1. 直播智能体生成器只读取当前方案的正式组合快照。
2. 接入发布 / 回滚。
3. 最后迁移 Core 的运行时消费链路。
