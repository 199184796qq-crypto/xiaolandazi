# 滚动权重与防连续讲解修复

本轮按用户确认的方案修改调度器，主目录 `E:\直播伴播`，基线 `c26e28c`，实现提交 **`1d655c7`**。生产目前仍为 `565d63f`，本轮尚未部署。没有修改数据库、已保存方案、母版、正文生成、润色、最终审核或 TTS 服务，也没有开播或调用付费服务。

## 原因与修改

session315 使用 V10/id128。原程序先分配 24 个商品名额，再把整批顺序打乱。本场原版离线复现的前缀为 `1、1、1、1、2、2、2`；开场与收口沿用当时商品，又把三个连续 2 号商品名额扩大为五段连续 2 号内容。长期配额正确，不能保证短时间分布合适。

现在商品和卖点都只选择下一段，不预排整批：

1. 保留商品角色基准与手动频率的共同作用，归一化前限制最大/最小偏好比为 **1.2**；普通与主推、同手动频率的长期目标仍为约 **1:1.2**。历史 `role_weights` 中的旧比例不参与运算。
2. 商品讲解段按该商品“应讲次数减已采纳有效次数”的累计差额选择；加入有界随机扰动，差额大时优先补齐，差额接近时允许随机变化。首次按权重抽取，避免每场固定同一商品先出。
3. 选中商品后，再在它自己的卖点中按累计差额选择，卖点最大目标比保留 **1.3**。角度数量不会放大父卖点或商品的份额；角度冷却、角度权重及侧面选择沿用现有逻辑。
4. 公共/商品继续使用独立的五名额跨循环窗口，目标 **20%/80%**。公共段不消耗商品或商品卖点的名额；公共池大小不改变顶层份额。
5. 开场、商品讲解、收口均参与相邻商品检查。存在其它可用商品时，普通排程连续同商品最多 **2 段**；公共段打断相邻商品连续计数。四个相邻商品段不再允许全为同一商品，这是本轮用户接受的边界调整。
6. 开场/收口另用累计商品出场计数选择，不混入商品主体配额。两套计数随运行状态持久化，裁剪近期历史、跨小循环和 Redis 重载都不清零。

比例是长期段数目标，不是每个小循环固定配额，也不是音频时长比例。短样本受整数和连续限制影响，不能要求每个前缀都恰好等于 1.2 或 1.3。

## 边界与事实归属

- 当前选择在采纳前冻结；审核重试、失败稿、重复改写不消费名额，不重新抽商品。
- 已采纳且预生成待送播的内容也纳入连续性检查。若只等 Core 开始播放才计数，生产者可以提前排入一长串相同商品。
- 确定未送出的段落不算连续出场，并沿用原有商品/卖点/角度/公共配额返还；回执不明的段落保留，避免重发。返还在安全边界重算未来选择，不打断正在审核、修复或履行承诺的任务。
- 只有一个商品有可用素材时，允许连续供料，避免为了换品停播。已有的价格续讲承诺仍优先履行，属于普通连续上限的例外；履约后恢复正常选择。本轮没有修改承诺生成或审核流程。
- 收口如果换到另一个商品，只继承该商品的非公共事实范围；该商品此前没有采纳记录时，从其可用任务取范围，不能借公共任务的整包事实。
- 可选讲解返回主线时，若换了商品，同步重选它的角度任务，避免给旧商品角度重新贴上新商品标签。
- 已排队内容不追溯改写。旧运行状态保留当前范围，后续边界转入新选择；发布验收优先使用新场。
- 这是任务调度与材料归属修复。模型是否实际完成角度、是否偏离商品、是否重复公共口头语，仍需分别检查正文和播放回执，不能以任务标签替代内容验收。
