# 移除旧文字时间轴与报时程序校验

2026-11-04。本轮基线 `348225dbf7b608f661e2936610fcaf933cee71da`。仅本地实现与离线验证，未提交、推送或部署。原件、增量补丁、测试和完整路径清单保存在 `E:/直播伴播-local/remove-legacy-timeline-20261104/`。

## 报时调度范围

用户要求将随机偏移从 -30 至 +120 分钟改为 -60 至 +60 分钟。保留 2 小时基准，每轮独立随机：

```go
2*time.Hour + time.Duration(rand.Intn(121)-60)*time.Minute
```

默认间隔为 **60—180 分钟，包含两端，按整分钟随机**。房间另外配置的报时冷却仍在该间隔上累加。实际完成回执核销本次报时配额后，才计算下一轮；失败与超时重试沿用未完成配额，不重新抽取下一轮间隔。这里的调度偏移与文字有效期是两套规则。

## 永久退役旧文字播放控制

- Core 领取任务不再等待文字 Timeline、SafePoints 或由此计算的未来缓冲切点；运行、占用、真实音频余量等原有保护保留。
- 所有主线模式均从实际 PCM 扫描结果选择切点，内部音频客户端再次核验。`Sequential=false`、旧 `safe_points`、字幕切点标志、调用方偏移、抢答和旧跳句参数均不能绕过核验。
- 从插播切入的同一 PCM 位置恢复，不再基于文字跳过当前句、主题去重或生成文字衔接后跳段。
- 旧 CSV/SRT/环境变量文字时间轴加载、语义切点和语义恢复算法已删除。旧开发插播/时间轴接口、旧返回/衔接接口永久返回 410，无配置开关可以恢复。
- 真实时间戳字幕继续用于显示和基本数据校验，但清除 `SafeCut`、`PauseCut`，不作为播放控制依据。兼容协议中的旧字段被忽略。

共享工作区中另一个任务拥有的 `coreaudio/interaction_return.go` 与 `sentence_end_guard_test.go` 原字节保留；旧文字返回构造函数已无生产调用，最终 Linux 构建的符号表也不包含这些构造函数。没有覆盖其它任务的未提交实现。

## 报时输入与程序有效期

原 V2 实际生成路径漏掉了报时专用时钟，也绕过了既有程序有效期绑定。现与原报时路径共用程序时间和草稿管理：

1. 在现有报时模型请求发出前，程序固定本次北京时间和时段；V2 请求只为 `time_report` 增加“当前北京时间”“当前时段”两个字段，约增加 25—40 输入 token，不新增模型阶段。普通欢迎、问答等任务不会自动带这两个字段；方案原文、观众提问中自带的时间表达仍会正常发送。
2. 不向模型索要有效期。程序结合原始生成时间和口播中的时间表达计算期限。例如 10:35 生成的“十点三十五分”至 10:36 失效；“十点”至 11:00 失效；“上午”至中午失效。自相矛盾的时间表达改用程序现有时段兜底，不追加模型调用。
3. 合成前、提交播放和实际切入前继续检查程序期限。重试不能把旧话术重新标记成刚生成；过期仍保留报时配额，重新生成符合当时的报时。
4. 同一未完成报时配额按场次、方案、正式版本、事实、完整音色、约束与记忆隔离缓存。修正 V2 生成前后本地正文信封导致身份变化、等待切点重试重复合成的问题；保留原 V2 声音/风格/策略元数据。TTS 失败可复用有效文字，缺少声学切点可复用有效文字及已合成声音；方案等身份变化后不复用旧结果。
