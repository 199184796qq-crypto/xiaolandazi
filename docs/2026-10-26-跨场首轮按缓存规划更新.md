# 跨场首轮按有效缓存规划更新

用户于2026-10-26纠正了“每次开播首轮都不更新”的行为。第一次实施可能只完成首轮部分句子就下播；再次开播时，已存在有效缓存的句子必须立即参加整体规划，按预算和更新顺序选择复用旧版本或生成新版本，不能等待本场第二轮才开始更新。

## 根因与修复

跨场缓存本身已经逐句持久化，未完成整轮也能继承。问题在更新调度：每个新场次的本地轮次都从0开始，`prepareRecordingRefreshSchedule(first=true)`无条件跳过整个可选更新规划，把“本场第一轮”误当成“整库第一次冷启动”。

现在首轮先只读检查当前范围内的有效库存：

| 当前句子状态 | 新场首轮行为 | 费用性质 |
| --- | --- | --- |
| 整库均无有效声音 | 首轮只补原文基础声音，不等价格/账务查询，不安排可选改写 | 必要供料按真实请求记账 |
| 部分句子已有有效缓存 | 已缓存句立即进入整轮更新预算、版本数和新旧顺序规划；未选中则复用原话/旧声音 | 更新属于可选费用，复用不新发模型/TTS请求 |
| 其余句子没有有效缓存 | 补齐该句基础声音，不作为可选更新候选 | 必要供料 |
| 已有完整缓存 | 本场首轮即执行正常更新规划 | 受整轮报价与共享滚动小时费用准入约束 |
| 预算不足、更新关闭或价格/账务不可读 | 暂停可选更新，已有声音仍可复用，缺声继续走必要供料 | 不把重开直播当免费重新计费窗口 |

规划复用既有跨场更新余额和顺序，不新增“完成首轮”门槛，不恢复上一场播报游标。下一场仍按当前方案顺序播放；改写选中且成功的新声音会直接用于本轮。缓存必须继续满足当前租户、房间、方案、源句、上下文、事实、声音和P0身份；失效/缺失音轨或P0拒绝的旧内容不能当成可用库存。

整轮时长预估仍覆盖全部源句，已缓存部分采用有效声音时长、缺声部分采用文本时长预估。可选更新预算与实际收费仍通过共享房间滚动账本及逐请求准入；必要补声可超过软目标的原有业务语义保持，历史账务和后台预算参数不变。
