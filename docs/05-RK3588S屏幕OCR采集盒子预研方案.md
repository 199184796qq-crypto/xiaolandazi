# RK3588S 屏幕 OCR 采集盒子预研方案

更新时间：2026-10-04

状态：已记录，后期采用；当前不实施、不替换现有 Browser Collector。

## 1. 决策结论

直播伴播后期增加一条独立的 `screen_ocr` 采集路径，用于单路直播间弹幕读取。

正式硬件方向采用：

~~~text
直播手机
  ↓ Type-C 视频输出 + PD 供电
HDMI
  ↓
1080p UVC 采集卡
  ↓ USB 3.0
RK3588S 单路边缘盒子
  ↓ 本地裁剪、变化检测、OCR、去重
结构化弹幕文字
  ↓ WebSocket
Core Service / 现有 RoomEvent 链路
~~~

该方案只解决弹幕画面的读取和识别，不负责向抖音直播间自动发送弹幕。

## 2. 采用该方案的原因

- 原始直播画面在盒子本地处理，不上传服务器；
- 服务器不承担高频图片 OCR 算力和图片带宽；
- 不依赖抖音私有 WebSocket、Cookie、签名或 protobuf 协议；
- 单直播间配单盒子，资源边界清晰，故障隔离简单；
- RK3588S 内置 6 TOPS NPU，完成模型适配后适合低功耗长期运行；
- 后续可以做成标准硬件产品，并与设备绑定、心跳和远程升级体系结合。

## 3. 单路硬件基线

建议量产基线：

| 部件 | 基线要求 |
| --- | --- |
| SoC | RK3588S |
| 内存 | 4 GB；开发板阶段可使用 8 GB |
| 存储 | 32 GB eMMC，禁止仅依赖低质量 TF 卡长期运行 |
| 采集输入 | USB 3.0 UVC，输入 1080p30 即可 |
| 网络 | 千兆有线网络；Wi-Fi 只作为备用 |
| 散热 | 铝制散热器和小风扇，支持长期满载 |
| 供电 | 稳定 5 V / 4 A，具体以板卡要求为准 |
| 手机转接 | 支持 HDMI 输出和 PD 充电的 Type-C 扩展坞 |

不采用纯 720p 采集卡作为正式规格。手机竖屏画面进入横向 HDMI 后可能存在黑边，720p 会进一步压缩弹幕字体像素，降低中文 OCR 准确率。正式输入保持 1080p，盒子内再裁剪和缩放。

如果后期选用带稳定 HDMI IN 驱动的完整 RK3588 板卡，可以取消外置 UVC 采集卡；在完成真实板卡验证之前，默认仍采用通用 UVC 路径。

## 4. 盒子端软件链路

建议采用 Debian 12 或 Ubuntu 22.04，盒子端按以下顺序处理：

1. V4L2 获取 UVC 视频帧；
2. RGA 完成弹幕区域裁剪、缩放和颜色转换；
3. 以低成本图像差分判断弹幕区域是否变化；
4. 仅在变化时触发 OCR，每秒最多 2～3 次；
5. 使用 PP-OCR 轻量检测和中文识别模型；
6. 将 ONNX 模型转换为 RKNN，并由 RKNN Toolkit Lite2 调用 NPU；
7. 按文字、位置、时间窗口和相似度去除滚动重复弹幕；
8. 只发送结构化文字事件，不发送原始截图。

原型阶段可以先用 Python 验证采集区域、模型和准确率；稳定后将 V4L2、RGA、RKNN 和去重主链路收敛到 C++ 常驻进程。

直接安装普通 PaddleOCR 或 RapidOCR 时，默认可能只使用 ARM CPU，不会自动使用 RK3588S NPU。正式版本必须完成 RKNN 模型转换、量化、精度回归和设备端性能验证。

## 5. 建议事件契约

盒子向 Core Service 发送的最小事件：

~~~json
{
  "type": "comment",
  "source": "screen_ocr",
  "device_id": "device_xxx",
  "room_id": "room_xxx",
  "sequence": 1024,
  "occurred_at": 1791062400000,
  "nickname": "用户昵称",
  "content": "弹幕内容",
  "confidence": 0.94
}
~~~

约束：

- `sequence` 在单设备会话内单调递增，用于断线补偿和幂等；
- `occurred_at` 使用设备校时后的毫秒时间戳；
- 低于置信度阈值的结果可以丢弃，或进入可选的模型复核队列；
- 不从屏幕推断或生成抖音内部 UID、sec_uid 等字段；
- 进入 Core 后转换为现有 `RoomEvent`，继续复用 Redis、SSE 和 Agent 链路。

## 6. 性能目标

单路验收目标：

| 指标 | 目标 |
| --- | --- |
| 视频输入 | 1080p30 |
| 轻量变化检测 | 5～10 次/秒 |
| OCR 触发上限 | 2～3 次/秒 |
| 端到端文字延迟 | 正常场景不高于 1 秒 |
| 原始图片上传 | 0 |
| 原始图片落盘 | 0 |
| 网络断开 | 本地短队列缓存，恢复后按序补发 |
| 常驻运行 | 连续 72 小时无崩溃、无明显内存增长 |

快速滚动、花体昵称、徽章、礼物动画和 Emoji 允许存在少量漏识别；正式验收应重点统计弹幕正文召回率、重复率和错误率，而不是只统计单张图片 OCR 准确率。

## 7. 数据和合规边界

- 只服务主播本人或已明确授权的直播间；
- 只裁剪弹幕区域，不采集系统通知、完整主播画面和声音；
- 图片仅在内存中处理，OCR 完成后立即释放；
- 不建立观众画像，不出售或共享弹幕数据；
- 不尝试规避黑屏、投屏限制、验证码或其他安全措施；
- 如果正常 HDMI 输出或正常系统录屏无法取得画面，设备应明确报错并停止；
- 软件协议和隐私说明中明确采集目的、字段和保存时间；
- 实时事件继续遵循 `docs/04-实时数据生命周期与设备接入约束.md`：Redis 最多保留最近 500 条，直播结束或设备离线时主动清理。

屏幕 OCR 降低了直接连接私有接口和突破技术措施的风险，但不代表平台规则及个人信息处理风险自动消失。

## 8. 与现有系统的集成边界

后期实现时新增独立模块，建议目录名：

~~~text
edge-ocr-worker/
~~~

模块职责仅包括：

- 设备本地视频采集；
- OCR 和弹幕去重；
- 设备注册、鉴权、心跳；
- 结构化事件上传；
- 版本和运行状态上报。

Core Service 继续负责：

- 设备与客户、直播间绑定；
- `RoomEvent` 标准化；
- Redis 实时事件生命周期；
- SSE 和业务事件分发；
- Agent 决策与后续业务处理。

在 `screen_ocr` 完成真实验收以前：

- 保留现有 Browser Collector；
- 不删除现有 protobuf 解码链路；
- 通过按房间配置的采集源开关进行灰度；
- 同一直播间同一时刻只允许一个主采集源写入，避免重复事件。

## 9. 实施阶段

### 阶段 A：PC 侧算法验证

- 使用 Windows 窗口采集或普通 UVC 采集卡取得同类画面；
- 确定弹幕区域、预处理、OCR 模型和去重策略；
- 形成一套固定测试视频与准确率基线。

### 阶段 B：RK3588S 原型

- 验证目标板卡 USB 3.0、UVC、RGA、网络和持续散热；
- 将 PP-OCR 检测、识别模型转换为 RKNN；
- 在真实直播间完成单路延迟、准确率和 72 小时稳定性测试。

### 阶段 C：系统接入

- 实现设备身份认证、直播间绑定和 WebSocket 事件协议；
- 接入设备心跳、离线停止 Collector 和 Redis 清理闭环；
- 增加采集源灰度配置、指标和告警。

### 阶段 D：产品化

- 固定主板、eMMC、采集卡、电源和散热方案；
- 完成镜像固化、开机自启、看门狗和远程升级；
- 再评估定制 PCB、结构件、认证、包装、质保和批量采购成本。

## 10. 实施前必须验证的假设

1. 目标直播手机支持 Type-C DP Alt Mode 视频输出；
2. 手机可以通过带 PD 的扩展坞边充电边输出；
3. 正常 HDMI 输出能够显示直播间弹幕且不存在黑屏；
4. 目标 RK3588S 板卡的 USB 3.0 Host 和 UVC 驱动长期稳定；
5. 弹幕在 1080p 输入下具有足够的文字像素高度；
6. RKNN 量化后的中文、数字、符号识别精度满足业务要求；
7. 盒子时间同步、断线队列和幂等序列能够与 Core 对齐；
8. 客户使用场景具有主播本人或直播间授权依据。

任一假设未通过时，不进入批量硬件采购。

## 11. 初步成本口径

当前只记录预算区间，不作为采购报价：

- RK3588S 原型主板、存储、外壳、散热和电源：约 450～800 元；
- 1080p UVC 采集卡、Type-C HDMI/PD 扩展坞和线材：约 150～250 元；
- 单路原型整套：约 600～1050 元，不含手机、服务器、研发、认证、包装和售后；
- 批量成本必须在板卡和模型验证完成后重新询价。

## 12. 当前结论

当前版本继续使用现有采集实现，不立即购买硬件，也不立即改动生产链路。

后期正式采用方向确定为：

> 单路 RK3588S 边缘盒子 + 1080p UVC 采集 + 本地 RKNN OCR + 只上传结构化弹幕文字。

开始实施时，先执行阶段 A 的 PC 侧算法验证，再采购少量 RK3588S 原型设备；未经准确率、稳定性和合规边界验收，不进入批量生产。
