## 正在直播的方案禁止保存

用户补充要求：后台保存方案时，如果有直播间正在使用该方案，拒绝保存并弹窗说明。

- 点击顶部“保存方案”，在提示词、模式和版本保存前先请求保存预检；有占用则弹窗列出房间编号，页面编辑内容保留。
- 查询当前租户内所有选用该方案、场次尚未结束的 `running` / `paused` 房间，不局限于当前页面的房间。暂停状态仍占用方案。
- 全部相关直播间结束后，再次点击可正常保存。预检不能确认状态时拒绝本次保存，不把查询失败当空闲。
- 后台版本保存入口也预检，版本事务在锁定方案行后再次检查；启动直播也锁定同一方案行，协调“开播与保存同时发生”的版本落库竞争。直接调用版本接口不能绕过保护。
- 方案提示词保存、顶部保存链路涉及的内容模式更新也增加占用检查。此修改针对方案保存链路，不将所有独立资料/音色编辑接口宣称为完整的事务式方案编辑锁。

占用依据是数据库里的房间当前方案选择与活动场次。现有运行场次表没有不可变的 plan_id，本次没有改造热切换方案的存储协议；不能据此声称已核实 Core 内任意热切换失败后的实际方案身份。

主要代码：`internal/db/live_agent_plan_save_guard.go`、`live_agent_plan_versions.go`、`live_runtime.go`；HTTP 保存预检及相关保存入口；`web-console/src/views/LiveStrategyView.vue`、`src/api.ts`。

## 主线审查发现与修正

| 问题 | 修正后的行为 |
| --- | --- |
| 把进入待播或成功追加轨道当成实际播放，提前累计使用次数并启动改写 | 根据 Core 已接受 PCM 的起播/进度回执确认，按实际轨道编号幂等记数，再触发可选改写；重启恢复不会重复计数。服务端 PCM 证据不等于实机完整出声。 |
| 重启续供读取了其它模式的 checkpoint，或读最新保存版本而非正在播放的版本 | 读取长段供料 checkpoint，校验场次、版本、program；采用 Core 当前版本恢复，兼容首段启动回执丢失，不从头重播。 |
| 按文本哈希混淆不同组的同文话术，首轮非首项预热和跨组交换破坏组连续性 | 独立话术按组/条目稳定身份分池；首轮从预热短段所在组开始，组内保持连续，后续按最新设计处理固定组和随机组。单条轮选访问完组成员后才重复。 |
| 音色切换仅凭池元数据判定准备就绪，可能串音色或被一个坏缓存阻塞 | 校验实际音频文件、缓存键、当前合成参数、正文、模型、音色与时长；跳过坏候选。目标音色的各片段都有兼容缓存才切换，补播缓存限定当前音色。 |
| 原始音频和改写重复登记，淘汰后 Seq 重用，重启后轮选/音色块进度丢失 | 原始版本仅在原文供料路径登记；按模型/音色/音频身份去重，Seq 按历史最大值递增；checkpoint 保存已送轨道、轮选与音色块状态。 |
| 开场清理旧音色资产可能删除已经付费的可用声音 | 停用该路径的立即删除；旧池向稳定条目池合并时保留原文件和未使用资产，不以开播作为删除付费声音的依据。 |
| 预算检查与记账分离，原文漏记、改写/重新归档重复记，多个房间可同时越过检查 | 原文与改写都在实际新 TTS 提交前原子预留汉字预算；同任务恢复不重复预留。确认未提交才释放，供应商结果不确定时保守保留；最近一小时滚动计算，损坏预算状态拒绝新购买。 |
| 改写预算用尽分支可能重复解锁，且全局工作键造成不同方案相互影响 | 修复重复解锁；在途键包含租户/方案/片段/模型/音色；串行取得工作位后重新校验池、场次与所有权，停止后不再启动新任务。 |
| 新音频提交前退役旧版本，缓存命中也可能误删旧版本 | 新音频就绪后原子提交，重新检查容量和重复项；重复缓存不消耗版本名额、不触发退役。保留原文基线，只替换满足播放次数条件的改写版本。 |
| 字数预算使用所有字符，动态容量与全局可变配置混用 | 按汉字计算话术时长与新增 TTS 预算；容量从当前版本计算，尊重手工上限。条目很多时优先遵守总量分配，避免“至少3版”和总量80互相矛盾。 |
| P0修复把非P0项也当作硬删除；空模型结果仍可能继续加工 | 仅按 P0 命中处理；风险规则加载失败不继续送未检查的 TTS，空结果终止本次可选改写。按设计保留非空短回答和相同文本的允许行为，不新增模型审核调用。 |
| 正在播的旧版本改写读取后续编辑的新提示词/事实 | 新场保存已有提示词与事实的原样快照；依据事实指纹筛选改写缓存，同事实下改原文字句仍可复用。旧恢复场缺少快照时继续声音播放，但不再读取新事实启动可选改写。 |

上述冻结的是输入依据，不能证明模型每次输出都保持了全部事实。没有为此偷偷新增模型提示词或审核调用。
