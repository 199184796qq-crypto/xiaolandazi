# 保存方案同步等待首段声音

用户要求：缓存声音就绪后才返回保存成功；准备超时60秒则放弃本次保存。改好后直接上线。

话术优先、AI声音且支持整段合成时，在原权限、直播保存限制、话术规范和P0检查通过后，读取方案实际语速，以最终正文、完整音色、模型、语速及指令身份准备开场锚点的一条缓存。已有有效缓存直接复用；原恢复、坏缓存补合成、跨进程去重和费用记账保持。不会为了保存额外改写话术，也不生成全部片段或全部声音。

准备完成并校验媒体对象可读后才提交正式版本，最后发100%进度与成功回执。等待期间每5秒发送准备进度；生成、排队、缓存锁和对象校验共用60秒上限。失败、超时、断开请求均不新建或启用本次正式版本；前端原保存流程保留草稿和错误提示。其它录音/内容模式不新增TTS。

准备期间不持有数据库事务。最终提交仍在原事务中重新检查正在使用方案的直播间，并比较方案实际语速与已准备语速；中途开播或修改语速会拒绝此次正式保存。已经完成的付费缓存保留供正确身份重试使用，不删除旧声音。

已发给供应商的任务可能无法撤销。60秒结束只取消本次等待与保存，迟到的付费结果沿原供应商许可和段落锁保留，不启动新的后台保存，不显示成功，也不主动重购。用户重试时会在同一缓存锁下复用或恢复结果。60秒不是供应商保证免费取消的期限。

发布只更新Management，无迁移、前端或提示词变更，不手动保存客户方案、调用真实付费模型/TTS或开播验收；按共享锁、实际当前源码和全部直播/Core/采集空闲检查上线。测试包含真实等待顺序、两种供应商分支、超时脱离迟到结果、取消不生成、失败和异常、精确锚点与完整身份、提交语速变化和中途开播保护。
