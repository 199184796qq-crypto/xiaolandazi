## 1. 最终目标

把直播话术生成改造成可持续流式运行的分层系统：

1. 事实层决定“能说什么”。
2. 直播业务层决定“这一刻完成什么任务”。
3. 成交推进层决定“何时、用哪一种方式促单”。
4. 主播风格层只在最后决定“怎么说得像这个主播”。
5. 审核层在风格包装后重新核对事实、数字、链接、承诺和 L1/L2 禁止项。
6. 每个短段及时流出；任何主播风格失败都不能造成空白、跳段或直播中断。

最终不是“照着样本改写”，也不是用主播样本继承商品事实和销售策略，而是：

> 当前正式事实 + 当前直播业务任务 + 当前成交节奏 → 先生成正确正文 → 最后用主播风格包装。

## 2. 用户已经确认的硬边界

### 2.1 事实延展与主播风格必须彻底分开

- `fact_expansion` 只控制事实可延展范围。
- `anchor_style` 只控制称呼、自指、语气词、句式节奏、方言点缀和情绪表现。
- 数字比价、连续算账、稀缺催促、库存倒计时、社会证明等不是天然主播风格，而是业务策略或外挂能力。
- 商品、福利、价格、规格、库存、物流、功效、口碑、保障、承诺均不得从主播样本继承。
- 商品事实已经明确且用户开放了足够延展边界时，可做合规的合理表达；事实模糊项由审核模型提示用户复核，不应一律禁止生成。
- L1/L2 和明确的平台/法律禁区必须拦截或改写；用户明确输入的业务禁令必须服从，例如“不能讲快递时效”时不得扩展“上海明天一定到”。

### 2.2 主播风格是最后一层包装

- 不能让主播风格提示词改变正文选题、事实、商品、链接、价格、促单任务和业务顺序。
- 主播风格可以做：在事实前后增加稳定称呼或自指；在自然句尾调整语气词；加入短确认；调整长短句、停顿、情绪高低和少量方言点缀。
- 主播风格不能做：新造事实、删掉正文的直接促单、把强促单改成劝退、改变数字和链接、增加不存在的库存/销量/倒计时/观众反馈。
- 1000 字滑动窗口用于统计整体落实率，不要求每个 200～300 字短段覆盖所有特征。
- 窗口不足 1000 字时只看特征存在性和明显漂移，不对短样本词频做高置信强约束。
- 少量非主力口头词属于自然噪音；只有挤占主力词并形成稳定体系才算风格漂移。
- 目标是统计风格接近，不是逐句复制，也不是追求机械的 100% 原词复现。

### 2.3 流式生成优先

- 可以一次规划未来 8 个短段，但只能逐段生成、逐段审核、逐段流出。
- 8 段规划是滚动视野，不是一次写完 8 段后再输出。
- 第一段必须尽快出现，不能因风格分不足而连续修三次后跳过。
- 单段建议约 200～300 字，长度偏差只能小幅传递，失败短段不得把下一段膨胀到 600 字以上。
- 内容安全且事实正确时，即使风格包装失败，也必须立即放行基础正文。

## 3. 直播全过程状态机

参考文档：`C:\Users\19918\WorkBuddy\2026-10-06-16-26-12\直播全过程框架.md`。

### 3.1 主线循环

没有真实外部事件干扰时，循环结构为：

```text
开场/本轮重新进入
  → 主体推进（六种业务功能动态组合）
  → 本轮收口（总结 + 行动 + 过渡）
  → 下一轮重新进入
```

用户已经可以配置 `round_minutes`（前端目前 5～12 分钟、默认 7 分钟）。优先复用它作为“一轮循环时长”，不要重复增加含义相同的 `cycle_minutes` 字段。必要时只修改 UI 文案为“每轮循环时长”。

### 3.2 开场不是只出现一次

正常轮回会有轻量重新进入；真实新人事件可触发不同强度的重新介绍：

- 轻量钩子：约 1～2 分钟节奏。
- 中量重引入：约 3～5 分钟节奏。
- 完整重引入：约 10～15 分钟节奏。

预览或无真实事件时不得假装“刚进来很多新人”。直播运行态应由真实新人/在线变化/互动事件决定是否插入重新介绍。

### 3.3 主体六种业务功能

主体不是固定顺序模板，而是在一轮中动态选择：

| 业务功能 | 作用 | 事实来源示例 |
| --- | --- | --- |
| 塑品 | 讲清商品是什么、适合谁、怎么用 | 商品名称、规格、卖点、场景、个性属性 |
| 塑价 | 解释价格与选择价值 | 正式价格、规格组合、经授权的比价事实 |
| 塑信 | 建立来源与可信度 | 品牌、产地、资质、已确认口碑/销量 |
| 消虑 | 回答购买顾虑 | 保障、退换、试用、使用限制 |
| 逼单 | 给出清楚的下一步行动 | 链接、规格、福利、真实有效期/库存 |
| 承接 | 接到下一角度、商品或下一轮 | 商品关系、搭配、升级、不同需求 |

卖点轮盘、多商品调度和情绪波形用于避免机械重复，但不能成为固定六步骨架。

### 3.4 收口类型

- 话题收口：结束当前角度，接下一个角度。
- 商品收口：总结当前商品并承接相关商品。
- 本轮收口：总结本轮、给行动、引出下一轮。
- 全场收口：仅在真实下播/全场结束信号出现时使用。

### 3.5 互动是贯穿辅线

- 只有真实评论、提问、用户行为或直播事件才能触发互动。
- 互动插入后必须保存主线游标，回答结束后恢复原业务功能，不得把主线冲散。
- 无真实互动时，不得虚构“有人问”“老粉都在拍”“后台都看到了”等现场反馈。

## 4. 成交推进必须由程序保证

当前“逼单滑条高但 2000 字几乎没有直接促单”的根因：

1. 高强度通过重复 `action` 写进 `RoleSequence`，但传给规划模型时变成 map，重复权重丢失。
2. 段落生成器只收到泛化目标“自然提出下一步”，没有收到成交强度和直白程度。
3. 模型可以完全不选择行动段；即使选择，也容易写成“先看看、想好再回来”。

### 4.1 已开始实现的解决方式

- 将 0～100 成交强度转换成每批 8 段中最少的 `action` 段数量。
- 模型规划完成后由程序补足行动段，不能依赖模型自觉。
- 行动段只使用已授权商品、链接、规格、福利、保障等事实。
- 当前临时配额函数：
  - `<25`：0 段。
  - `25～49`：至少 1 段。
  - `50～74`：约四分之一。
  - `75～89`：约三分之一。
  - `>=90`：约二分之一。

### 4.2 下一步必须补 CTA 类型

成交强度决定频率与直接程度，事实决定能使用哪一种类型：

| CTA 类型 | 使用条件 |
| --- | --- |
| 直接选择/链接行动 | 有商品、链接或规格事实即可 |
| 确认型 | 有明确适用人群、规格、价格或福利条件 |
| 稀缺型 | 必须有真实库存/名额事实 |
| 时间型 | 必须有真实有效期/倒计时事实 |
| 顺序型 | 必须有真实发货顺序或排单规则 |
| 损失规避型 | 必须有真实权益到期/条件变化事实 |
| 社会证明型 | 必须有真实销量、评价、回购或现场行为事实 |

建议密度参考用户文档：约每 100～150 字出现一次轻重不同的成交动作，轻/中/重约 6:3:1，并呈波形分布。它是调度目标，不是要求每个句子催单。没有事实支持的类型应从候选集中移除，不得用高滑条换取虚构权限。

## 5. 正确的运行管线

```text
授权事实与禁令
  ↓
直播状态机：轮次阶段 + 主体业务功能 + 真实互动插入
  ↓
成交调度：CTA 类型 + 强度 + 事实支持检查
  ↓
基础正文生成（只保证内容、事实、任务、长度、衔接）
  ↓
主播风格最终包装（元提示词 + 最近1000字风格欠账）
  ↓
事实/数字/链接/L1/L2 二次审核
  ├─ 包装合格：流出包装稿
  └─ 包装越界或失败：立即流出基础正文
```

### 5.1 基础正文生成

- 不传主播风格元提示词，避免风格污染业务内容。
- 明确传入：阶段、业务功能、当前事实、CTA 类型与强度、上一段尾部、主线记忆、禁令、目标字数。
- 最多允许一次针对事实/结构/长度的修复。
- 基础正文若仍失败，优先使用授权事实模板；再失败也要给安全中性正文，不能跳段。

### 5.2 主播风格最终包装

主播样本分析时一次生成 `meta_prompt_md`，运行时复用，不要每段重复携带原始长样本。

包装器输入：

- 已通过事实审核的基础正文。
- 紧凑的 `meta_prompt_md`。
- 最近 1000 字的风格窗口与欠账。
- 本段必须保持不变的商品、链接、数字、福利条件、行动目的和业务角色。

包装器允许：

- 在位置槽补称呼、自指、承接词、短确认、句尾语气词。
- 调整句长、停顿和情绪力度。
- 少量替换为样本稳定表达。

包装器禁止：

- 新增/删改事实、数字、链接、利益条件和承诺。
- 改变 CTA 类型、强弱和购买动作。
- 把业务内容换成样本的商品、环节或逻辑。
- 为追词频机械堆词。

为了速度，先做确定性位置槽补丁；只有宏观节奏/情绪明显不足时才允许一次模型包装。模型包装失败、超时或复核失败，直接回退基础正文，不再反复修风格。

### 5.3 审核顺序

1. 基础正文先做事实硬审。
2. 包装后再次检查事实 ID、数字、链接、商品主体、福利条件和 CTA 目的。
3. 发现包装越界：丢弃包装稿，基础正文照常流出。
4. 风格评分只做质量观测和后续窗口欠账，不作为阻塞直播的放行闸门。

## 8. 已知性能故障与验收目标

一次真实 2000 字测试曾出现：

- `render_calls=23`
- `repair_calls=15`
- 第一段文本约 43.3 秒后才出现
- 总耗时约 1 分 59 秒
- 第 1、2、4、5 单元被跳过

这是旧架构“每段生成 + 风格硬审 + 多次修复 + 跳过”的直接后果。

重构验收目标：

- 8 段仍只做 1 次滚动规划。
- 每段基础生成 1 次，只有内容/事实失败时最多再修 1 次。
- 风格模型包装每段最多 1 次；能用确定性位置槽完成时不调用模型。
- 风格失败不增加重试，不跳段。
- 第一段不为空，所有计划单元均有输出。
- 首段耗时应显著低于旧的 43 秒，并在 metadata 中持续观测。
- 2000 字不再出现 23 次 render + 15 次 repair 这种调用量。

## 10. 手工验收场景

至少跑以下 5 组：

1. **2000 字、高主播风格、高成交强度**：第一段快速出现；8 段内有程序保证的直接行动节点；风格包装不删 CTA。
2. **无库存/倒计时事实**：可以直接引导点链接/按规格选择，但绝不能生成“最后几单、最后两分钟”。
3. **明确禁讲快递时效**：不得出现“明天到、两三天收到”，可以改成不承诺时效的发货说明。

5. **真实互动插入**：回答问题后恢复到原主体功能和原商品，不重置主线。
