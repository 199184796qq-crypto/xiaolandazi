## 界面与生效口径

| 类型 | 初始秒数 | 生效规则 |
| --- | --- | --- |
| 欢迎 | 0 | 原二维自适应间隔与设置下限取较大值，0 完全自适应。 |
| 点赞 | 30 | 保留最近 30 秒不同人的聚合、二维自适应；设置值为下限。 |
| 关注 | 20 | 同上，与点赞独立。 |
| 下单 | 5 | 普通新配额采用配置冷却；未完成配额保留原 10 秒重试、重新累计。 |
| 暖场 | 180 | 从最后一次真实互动结束计算，至少 180 秒。 |
| 弹幕问答 | 0 | 额外播报间隔，0 保留原节奏；不改变最近 60 秒最多 10 人、3 分钟不同人分档、50 秒入队 TTL 和原配额。 |
| 紧急投诉 | 不可调 | 独立开关；关闭后不降级当普通回答播出。 |
| 报时 | 0 | 在原报时计划上额外增加设置的秒数，0 保留原计划；实际完成才结算，不推迟已欠下的当次配额。 |
| 追问澄清 | 0 | 额外实际播报间隔；关闭后不创建追问或继续旧对话。 |

一般间隔从实际起播计算；暖场从上次互动结束计算，报时按原计划及实际完成。输入限 0–3600 秒整数，越界、小数、空值不会提交；低于默认值提示但不阻止，仍受自适应、配额和系统下限约束。0 不表示关闭。无效秒数不挡住关闭开关，错误值恢复为已保存值并明确提示。

总关或九项全关停止自动互动，主线照常。单关对应输入置灰，总关整组置灰。“扣 1”等主动参与归入弹幕问答同一开关。弹幕问答关、紧急投诉开时，共享意图分析仍可识别紧急投诉，但不播放普通回答；所有相关通道关闭后不产生这些自动任务。人工明确点播独立于自动调度开关。

旧房间未使用新控件时保持旧行为，首次显示从旧配置推导开关；第一次保存后改用明确的房间开关，避免被移除的旧滑轨或隐藏方案开关挡住显示为“开”的项目。旧数据/方案版本保留，不把房间控制另存为方案版本。

## 关闭与在途保护

Core 收到设置后同步撤销未播队列，取消采集/生成/准备中的任务；已取得本任务真实 PCM 起播证据的当前一句正常完成，不截断。Management 在模型/TTS 提交前检查，未播准备期间每 500ms 检查，关闭时取消等待；Core 在领取、插播、真实第一帧前再次检查，覆盖非 V2 报时。

持久化每类作废版本，即使快速关开、关闭推送迟到，也不会复活旧问答或旧报时。只允许紧急通道时采集的普通候选，不会在重新打开问答后转为旧普通回答。

释放待播成品和草稿引用，不删除共用已付费音频。供应商已接收的任务可能已计费，取消不表示退款。缓存清理只检查确有缓存的房间，整次数据库检查限制 500ms，故障不阻塞所有房间。

## 保存、审计与兼容

复用原房间偏好 GET/PUT 和开播下发，新增 `live_room_interaction_controls` 与 `live_room_interaction_control_history` 两表，保存租户/房间、总开关、九类开关、秒数、作废版本、版本号、修改人/时间和前后值。

前端字段：`interaction_active`、`interaction_switches`、`interaction_cooldowns`、`interaction_controls_revision`。先 GET 当前版本再 PUT，新控制修改需要匹配版本；冲突 409，非法秒数/类型 400。缺失类型开启，缺失冷却沿旧规则；旧客户端完全不带新字段时不重置已保存配置，空对象明确恢复默认映射。

房间归属、控制和审计在同一事务检查/保存，审计失败整笔回滚。Core 同一写锁内拒绝旧版本及相同版本不同内容，GET 克隆防止调用者改动内存。Core 重启从数据库恢复，开播前再次同步，同步失败不带未知开关启动。保存成功但热同步失败明确返回 502，界面重读保存值并可重试，不假报成功。

读写绑定房间与请求代次，迟到响应不串房；保存期间禁用重复修改。新增作废/版本字段仅程序内部传递，没有新增模型输入或提示词字段。
