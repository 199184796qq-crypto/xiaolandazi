# 六份方案母版与提示词维护

状态：本地实现与验证完成，尚未提交或部署。

“营销运维”新增“提示词维护”，可以分别修改主播人设、事实依据、红线禁止、直播话术要求、互动回答要求和话术规划。维护页正文与编辑框20px，方案页六个编辑框保持20px，桌面与390px布局可用。

方案页“拉取提示词”先确认替换六页，然后分别拉取对应母版，包括原来没有覆盖的红线和规划。拉取只更新草稿，顶部“保存方案”才保存方案原文并合成三份元提示词。取消、请求失败或返回缺项时整体保留草稿；顶部保存开始时清除旧拉取提示，正确显示本次保存结果。

事实依据保留现有业务：填入当前租户、当前方案的有效商品卡、福利与已确认事实，过滤停用/已删资料。母版删除商品/福利循环占位格式时仍补入当前资料；没有事实的方案不会带入其它方案数据。规划按原文保存与拉取，已有开场/开场方式占位符保留；样本节及模型输出协议继续由原程序拼接，没有改动运行时协议。

六份平台母版分别保存到现有mgmt_system_settings的plan_prompt_templates组；每份最多20000字且60000字节，原文空白、换行、Unicode及显式空值可回显，三份合成提示词仍受原20000字限制。未配置时只读项目已安装母版，不在读取或服务启动时写入默认行，无新迁移。保存由单个事务完成，并对六份原文整体做版本比较；多人并发不覆盖，版本冲突返回409并保留草稿。首次保存使用相同顺序的排他锁，真实MySQL测试覆盖并发首存与中途失败回滚。通用设置页隐藏这些记录并拒绝旁路更新。

维护接口为GET/PUT /api/v1/system/plan-prompt-templates，沿用system.settings.liveops.manage内部员工权限；普通方案页仍按原租户/方案授权读取自己的资料。平台母版更新不会自动修改已保存方案、正在运行的直播快照或客户声音缓存；只有用户随后明确拉取并保存方案才采用。

验证：前端类型与生产构建、Management完整测试、go vet及Linux构建通过；实际父页与维护页14组浏览器回归通过，无页面错误/外网请求。隔离本机MySQL测试验证逐字存取、显式空值、六行原子保存、过期版本拒绝、8个并发首次保存仅1个成功和失败回滚；测试schema已清理，测试端口已关闭。没有连接生产、调用真实模型/TTS或替用户保存方案。
