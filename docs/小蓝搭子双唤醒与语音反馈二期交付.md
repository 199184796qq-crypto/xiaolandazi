# 小蓝搭子双唤醒与语音反馈

日期：2026-10-02。本次代码范围：双词唤醒、设备私有语音反馈、回应称呼设置。服务器发布和固件构建完成后仍需用户烧录实机验收。

## 使用方式

- 完整说“小蓝，小蓝”；单独“小蓝”不作为本版唤醒词。两次连续、正常语速，不要隔很久。
- 只唤醒：回应“我在，有什么吩咐？”，提示音结束后进入一次新的录音。
- 一句说完：“小蓝小蓝，帮我音量调整到30%”。听完整句后回应“好的，稍等，马上就干。”，设备执行且服务器保存成功回执后才回应“已经调整好了。”；实际百分比显示在设备屏幕。
- 按键录音入口继续保留；双键恢复配置、单张环境照片保持一期功能。环境照片反馈“已经拍好并上传了。”只表示接收完成，不表示环境分析已经完成。
- 芊悦（Cherry）提示音在固件内缓存，所有称呼使用同一声线。录音期间不播提示，提示播放期间暂不接收新语音；不是全双工可打断对话。提示只在本机播放，不加入直播间音轨。
- 静音或音量为零时不会强制解除静音来播报；用屏幕或按键确认。

## 回应称呼

手机“我的设备”、电脑“设备绑定”中可选：自动、固定靓女、固定帅哥、固定小伙伴、中性回应。

自动模式在足够长的指令语音上估计声音特征，不确认个人身份，也不建立声纹库。仅唤醒词、录音太短、噪声、多人或置信度不足时一律中性回应。仅喊“小蓝小蓝”不足以可靠判断成人/儿童，因此自动模式纯唤醒固定中性；想每次唤醒都叫“靓女”等，请选择固定称呼。

固定模式对应“靓女／帅哥／小伙伴，有什么吩咐？”及“靓女／帅哥／小伙伴稍等，马上就干。”；操作失败只播失败反馈，不假报完成。设备转让后新所有者不继承旧客户的称呼偏好和语音事件。

## 服务端边界

- GET/PUT `/api/v1/live/devices/{deviceID}/addressing`：当前设备所属客户才能操作；PUT body 为 `{ "mode": "auto" }` 等五种允许值。
- 语音接口返回 `kind=command|wake_greeting` 及 `speaker_addressing=female|male|child|neutral`。纯唤醒持久为成功问候，但不下发设备动作。
- 启用 `DEVICE_ADDRESSING_MODEL=qwen3.8-omni-flash`，复用已有 DashScope 凭据；声学分析最多3秒，失败降级中性，不阻塞硬件控制。总语音处理预算29秒，留提交裕量，成功响应先发送再限时清理临时录音。
- 新固件 hello 声明 `device_feedback=true`。网关发 `control_feedback`（greeting/accepted/completed/failed），增强固件的反馈在终态状态消息之前发送，避免相邻消息间误接受新录音。
- 本地播放先隔离房间下行并排空旧音轨；播放完成及尾音排空后发送 feedback stop。问候结束后的录音生成新 request_id，不复用问候请求。
- 完成反馈必须同时满足硬件成功 ACK 和服务端匹配回执持久成功；重复请求不重复执行。失败、超时、断线不宣称成功。旧固件保留原状态消息兼容。
- 盒子不做小蓝豆扣减。设备语音、照片事件仍为 `billing_mode=disabled`、`charged_beans=0`。模型供应商调用可能产生正常 API 费用，不能等同于免费模型调用。
- 仍为有超时的文件 ASR，回应需要联网并等待服务器，不承诺瞬时唤醒回应。本期不新增身份声纹认证、连续视频流或照片分析器。

推荐烧五个分区文件，不先 ERASE，以保留现有 Wi-Fi 等配置。五行全部勾选：

| 文件 | 地址 |
| --- | --- |
| parts/bootloader.bin | 0x0 |
| parts/partition-table.bin | 0x8000 |
| parts/ota_data_initial.bin | 0xd000 |
| parts/xiaozhi.bin | 0x20000 |
