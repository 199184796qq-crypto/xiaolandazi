# 首次开场话术生成逻辑方案

> 适用：直播伴播系统「正式直播」（`Surface == "formal_live"`）首场开场白。
> 核对日期：2026-10-21；描述当前仓库的首次开场分支，线上是否包含后续提交需另查发布回执。

---

## 一、什么是「首次开场」

首次开场不是一条独立管线，而是**主线话术引擎里的一个特殊分支**，只在满足以下条件时触发：

```go
// mainline_reuse.go
func (s *State) FirstLiveOpening() bool {
    return s.Surface == "formal_live"      // 正式直播（非试听/预览）
        && s.Phase == "opening"             // 环节 = 开场
        && s.OpeningCount == 0              // 本场第 0 次开场（还没开过场）
}
```

三条同时成立 → 走「首次开场」特殊逻辑；否则走普通开场或主线中段。

**首次开场与普通段的根本区别**：
- **永远不命中话术复用**（`formalMainlineShouldReuse()` 里 `FirstLiveOpening()` 直接返回 false；`speech_library` 复用查询也被跳过）。
- **永远现场现生成**，不捞历史话术池、不抄旧稿。
- 与普通主线共用生成引擎、当前有效P0及本场分配的模型；有主播风格时注入腔调卡，无风格时允许正常生成，不强制绑定评分基准。首次开场文字和TTS均不得领取旧成品，且不计入滚动七三目标。

---

## 二、整体链路（两次调用）

正常成功路径包含**选材与写正文两次调用**，中间由程序把选材结果写入state。重复重生成、开启模型审核或上游失败重试会增加调用，不能把“两次”当作所有请求的固定上限：

```
advanceAnchorCycle（每段一个闭环的入口）
   │
   ├─ 判断 FirstLiveOpening()？否 → 普通主线流程
   │  是 ↓
   │
   ├─【第一次调用：选材】 completeOpeningSelection()
   │     · 程序按 RunID 哈希轮换 → 定「卖点」
   │     · 模型在该卖点候选角度里 → 挑「角度」  （temperature=0.8）
   │     · 程序按 RunID 哈希轮换 → 定「开场方式」（8 选 1）
   │     · 结果写回 state.OpeningSelection {卖点, 角度, 开场方式, LinkKey, Common}
   │
   ├─【第二次调用：写话术】 completeLiveCycleText() → generateDistinctFirstOpening()
   │     · 读首次开场历史（仅用于生成后去重，不喂原文）
   │     · renderCycleTextMessages() 把选材结果注入 prompt
   │     · 本场配置模型生成正文（不是程序写死某个供应商）
   │     · firstOpeningRepeated() 程序侧去重校验（重复则重生成，最多 2 次）
   │
   ├─ 有基准时程序评分/按配置补标点 → 当前本地检查
   │  SkipReview=false：执行所需模型复核并验证真实回执
   │  SkipReview=true：跳过模型复核，以程序实际采纳为准
   ├─ AddCandidate() 采纳 → 后续TTS/排队/Core回执另行核验
   │
   └─ rememberFirstLiveOpening() 把本次开场记入历史（供下一场去重）
```

## 三、第一次调用：选材（opening_selection）

### 3.1 候选池构建 `openingSelectionPool(state)`

从 `state.Queue`（本场卖点×角度队列）提取候选：

- 跳过无卖点的任务。
- 按「卖点 × 角度」去重。
- 每个角度候选带程序侧元信息：
  - `LinkKey`：商品链接（裸 id 拼 `ProductLinks()`，如 `"1"` / `"2"`）——**商品专属卖点才有**。
  - `Common`：是否公共卖点（门店地址/停车/环境等跨商品共享）。

返回 `卖点 → []角度候选`，用有序结构（先按卖点首现顺序、再 sort）保证轮换稳定。

### 3.2 卖点轮换（程序定，模型不选）

模型天然倾向选「角度最多的卖点」（如「6人餐内容详解」有 6 个角度），导致卖点维度锁死。所以：

```go
point := openingPointForRun(state.RunID, points)   // fnv32a 哈希取模
```

- **同一场直播 RunID 相同 → 卖点稳定**；**不同场 RunID 不同 → 卖点轮换**。
- 盐值 `runID + ":opening-point"`。

### 3.3 角度挑选（模型选）

程序只给模型看该卖点下的**角度候选**（角度 / 参考人群 / 观众顾虑，**不暴露 LinkKey/Common 等程序元数据**），让模型挑一个最能勾人的角度，输出纯 JSON：

```json
{"角度":"描述门店采用中式装修风格，营造典雅氛围"}
```

选材 prompt 也走**内容四层**（缩减版）：
- **必说**：开场卖点已由程序选定为「X」，从候选角度里挑一个。
- **可说**：角度候选列表。
- **不提**：统一未知项文案。
- **改写**：只做选择、不写正文、只输出 JSON。

关键参数：`temperature=0.8`（否则确定性输出永远选同一个「最优」角度）。

### 3.4 开场方式轮换（程序定，模型不选）

```go
sel.OpeningMode = openingModeForRun(state.RunID)   // fnv32a 哈希，盐 ":opening-mode"
```

8 类开场方式：欢迎型 / 利益钩子型 / 悬念型 / 痛点型 / 身份背书型 / 互动型 / 自嘲亲和型 / 直接开讲型。

### 3.5 选材结果反查归属

模型选了角度后，程序反查该角度对应的 `LinkKey` / `Common`，写回 `sel`——**这一步是卖点↔事实卡对齐的关键**，否则卖点/角度换了，写话术仍按队列原 task 筛事实，导致错配。

### 3.6 选材失败兜底

- 候选池为空 → 不选材，走原路径。
- JSON 解析失败 → 保留空选材，退回原开场钩子流程，**不阻塞**。

## 四、第二次调用：写话术（mainline_text）

### 4.1 选材结果注入 prompt

`renderCycleTextMessages` 开场段用 `state.OpeningSelection` 覆盖本次任务：

```go
task.SellingPoint = sel.SellingPoint
task.Angle        = sel.Angle
```

并注入两个程序轮换字段：

```go
packet["本次开场方式"] = sel.OpeningMode                  // 8 类钩子方向
packet["本次欢迎方式"] = openingWelcomeStyleForRun(runID)  // 8 套欢迎词，盐 ":opening-welcome"
```

### 4.2 事实卡分流（卖点↔事实对齐）

- **商品专属卖点**（`LinkKey` 非空）→ `alignFactsToLink(sideFacts, linkKey)` 按链接号二次过滤。
- **公共卖点**（`Common=true`）→ `appendBrandingFacts(sideFacts, BrandingCommonFacts())` 补进地址/停车/环境等 branding 事实（否则在商品段被 `ProductFacts` 挡掉，公共卖点名不副实）。

### 4.3 链接号规范化

`normalizeProductLinkLabel(id)` 幂等规范化：DB 里链接号有两种格式（裸 `"1"` vs `"1号链接"`），避免拼出「1号链接号链接」。

### 4.4 最终 prompt 形态（一条 user 消息，JSON）

结构 = **内容四层 + 表达四层**，不设 system：

**内容四层**：
| 字段 | 四层 | 来源 |
|---|---|---|
| 本次任务 | 必说 | 卖点×角度（选材结果覆盖） |
| 可说 | 可说 | 事实卡（按 LinkKey/Common 分流） |
| 不提 / 不提红线词 | 不提 | 未知项 + P0 红线词表 + pUser 表达限制 |
| 改写 | 改写 | P0 专属改说 + pUser 展开指导 + 事实卡补充约束 |

**表达四层**：
| 字段 | 含义 |
|---|---|
| 主播腔调 | 纯风格 + 量化基准 + 禁用表达（来自已绑定风格及基准；未绑定时不强行补造） |
| 本次开场方式 | 8 类钩子方向（程序轮换） |
| 本次欢迎方式 | 8 套欢迎词方向（程序轮换） |
| 环节指令 | cycle-opening.md 母版（四步结构） |

### 4.5 环节指令：开场四步结构（cycle-opening.md）

1. **欢迎 + 留人**：必须「欢迎欢迎」叠词起头放最前（防 TTS 吞字），留人跟在后面；措辞自己组织，按「本次欢迎方式」换说法。
2. **钩子**：按「本次开场方式」勾住观众，让他知道「值得听什么」。
3. **讲卖点×角度**：转入选定的卖点×角度，不跑题。
4. **轻轻招呼看链接**：自然招呼新粉，不重逼单。

## 五、复读源清理（本次重构的核心）

历史上首次开场高度复读、开场方式锁死，根因是三个「复读源」在喂模型。现已全部清理：

| 复读源 | 原问题 | 处理 |
|---|---|---|
| 历史开场完整原文 | `firstOpeningDirective` 把 180字×3段完整开头塞进 PendingFeedback → 模型照抄 | **停止注入**，只留「现场写新表达」纯指令 |
| cycle-opening.md 8 套欢迎/8 类开场完整示范句 | 模型逐字照抄固定留人话 | 全部改成「纯方向」（如「欢迎哥哥姐姐们式：称呼观众问好」） |
| 表达展开建议 12 条变体里的钩子指令 | 与「本次开场方式」打架 | 开场段**不再注入**（钩子全归「本次开场方式」） |

**「近期避重」开场段也整体砍掉**——卖点/角度/开场方式已由程序随机，模型无需避开历史。

**程序侧去重仍保留**（`firstOpeningRepeated`）：生成后比对历史（归一化 + 编辑距离阈值），重复则重生成，最多 2 次，仍重复则 `content_blocked`，不转 TTS、不降级用旧稿。

## 六、关键设计原则

1. **卖点、开场方式、欢迎方式 = 程序用 RunID 哈希确定性轮换**，模型只挑「角度」。这样：
   - 同场稳定（RunID 不变）；
   - 跨场轮换（RunID 变化）；
   - 模型不会锁死单一偏好。
2. **只有「角度」交给模型**，且 temperature=0.8 引入随机性。
3. **不喂任何历史原文给模型**——避重靠程序侧去重校验 + 程序轮换，不靠模型自觉。
4. **母版只给方向、不给示范句**——杜绝照抄。
5. **共用一套引擎**：与主线中段共用生成引擎、P0、模型、表达标尺，首次开场正常比普通正文多一次选材调用，并使用开场环节指令。


## 当前审核、缓存与排查入口

当前正式生成设置使用 `SkipReview=true`，不能再把程序采纳描述成模型审核“通过”。开启审核时仍须真实审核回执；生成P0约束和现有本地检查不因免模型审核而变成空规则。首开历史去重仍执行。详见[当前生成链路](话术生成链路架构.md)和[复用机制](话术库复用机制设计方案.md)。
