# TTS 前句级 P0 改写（2026-10-21）

## 1. 目标

互动 TTS 前的正文不做整段重生成，只处理命中 P0 的句子：

1. 按中文句末标点/换行切句。
2. 逐句扫 P0。
3. 只把命中的那一句回喂模型，用很短的四层结构要 2 个备选。
4. 程序选第一个仍不含 P0 的备选回填。
5. 两个都不行就丢掉这一句；其余句子原样组装。
6. 全部被丢掉时用安全边界句，不让 TTS 空播。

这样 token 只和命中句数相关，不会一句违规重写整段。

## 2. 实现

文件：

- `management-service/internal/decisionexecutor/tts_p0_sentence.go`
- `management-service/internal/decisionexecutor/tts_p0_sentence_test.go`
- 接入点：`management-service/internal/decisionexecutor/worker.go`，在生成正文之后、TTS 合成之前。

规则：

- `verbatim`（100% 原话/人工固定文字）跳过句级改写，保持原话。
- 提示词四层：必说/可说/不提/改写；不提层只放本句命中的 P0 词，不塞全量母版。
- 模型要求 JSON：`{"备选":["改写1","改写2"]}`。
- 程序用同一 P0 policy 再扫备选，选第一个零命中的；不是让模型自判。
- 候选保留原句句末标点；长度异常或仍命中则丢弃。
- 失败/超时：该句丢弃；全部丢弃则安全边界句。
- 日志只记录改写/丢弃计数，不打印正文或命中词。

## 4. 未验证 / 风险

- 未用真实模型跑 20 次改写；20 次是本地回归轮次。
- 未调用真实 TTS，未开播。
- 命中句越多，模型调用次数越多；每句 8 秒超时，极端情况下会增加延迟。
- 模型失败时该句会被丢弃，可能让回答变短；全部失败时走安全边界句。
- 只覆盖互动 TTS 链路；主线 TTS 的 P0 仍在候选采纳前处理。
