# 直播伴播商业系统设计

## 1. 文档定位

本目录用于沉淀“总部 + 代理 + 销售 + 客户 + 产品 + 设备 + 资金 + 合同 + 售后 + OEM”的完整系统设计。

系统不是单纯会员后台，而是一套多组织、多角色、多资金账户、多仓库、多结算规则的商业运营平台。

设计最高原则：

> 货动必有单，单动必有流水；钱动必有账，账动必有凭据；错误不删除，只能冲正或反向单据；任何结果都必须追到原始业务。

## 2. 四条主线

系统底层必须同时维护四条相互独立、可以交叉核对的主线：

1. 组织与权限线：总部、代理、部门、员工、角色、审批权限。
2. 客户与销售关系线：客户来源、归属组织、归属销售、历史转移。
3. 商品与设备线：SKU、批次、SN、所有权、所在仓、使用者、全生命周期。
4. 资金与结算线：支付、退款、返佣、提成、冻结、抵扣、提现、冲正、平账。

## 3. 核心领域

建议正式划分为 12 个核心中心：

1. 系统与组织中心
2. 产品与会员中心
3. 代理中心
4. 销售中心
5. 客户资源中心
6. 订单与支付中心
7. 财务与结算中心
8. 设备与仓储中心
9. 物流与售后中心
10. 合同中心
11. OEM 品牌中心
12. 审批、报表、审计与追溯中心

## 4. 不可破坏的底层规则

- 代理等级与代理上下级关系分离。
- 设备价格体系与消费会员体系分离。
- 消费会员由总部统一定义，代理只能销售，不能改会员权益和统一价格。
- 代理设备采购价由总部按代理等级/政策确定，代理可自行确定终端设备销售价。
- 客户支付资金统一进入总部收款体系，再按规则生成代理应结算资金。
- 财务余额、库存余额都是“结果”，真实依据是不可篡改的流水。
- 已签合同、已完成支付、已结算单、出入库单、退款单、提现单等关键单据不可物理删除。
- 历史规则必须保留版本与生效区间，历史订单按当时规则重建。
- 敏感操作必须保留经办人、审核人、复核人、时间、组织、岗位快照、原因、附件。
- 任何关键业务都拥有 business_trace_id，可一键穿透资金、产品、合同、审批和人员责任链。

## 5. 审核结果

本版设计已按以下六轮方式反向审核：

- 第一轮：正常业务闭环。
- 第二轮：退款、退货、拒收、少货、损坏、提现失败等异常流程。
- 第三轮：跨月结算、跨期退款、历史规则变更、代理升级降级。
- 第四轮：重复回调、并发锁库、重复提现、重复发货等幂等与并发问题。
- 第五轮：人员离职、代理退出、合同变更、售后跨组织等组织变化问题。
- 第六轮：从任意资金、设备、人员、订单反向重建历史与对账。

新增并明确了此前容易遗漏的能力：

- 结算周期锁账与跨期调整
- 代理风险准备金/延迟可提
- 负余额与跨期抵扣
- 重复支付/退款回调幂等
- 库存锁定与并发防超卖
- 异常签收与差异入库
- 资金和库存差异单
- 代理退出清算
- 合同/规则快照
- 业务事件可靠投递与补偿
- 一键全链路穿透查询
