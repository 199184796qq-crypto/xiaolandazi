# 02 设备与库存全生命周期

## 一、设备唯一身份

设备至少使用：

SKU + 批次号 + SN 序列号

SN 是设备生命周期主键之一，正式入库后不可随意修改。

## 二、设备三种关系必须分开

### 所有权 owner_org_id

设备经济所有权属于谁。

### 保管/仓储 custody_warehouse_id

设备物理上目前在哪个仓库或责任主体手中。

### 使用/绑定 user_customer_id

设备当前由哪个终端客户使用。

例如：

- 所有权：南充代理
- 当前仓库：总部售后仓
- 当前用户：客户张某
- 状态：维修中

完全合法。

## 三、设备生命周期

采购/生产
-> 待入库
-> 质检
-> 总部入库
-> 可用
-> 锁定
-> 拣货
-> 复核
-> 出库
-> 运输中
-> 代理待签收
-> 代理签收
-> 代理入库
-> 代理销售
-> 客户签收
-> 绑定
-> 激活
-> 正常使用

异常和逆向分支：

- 拒收
- 部分签收
- 短少
- 多收
- 运输损坏
- 退货
- 维修
- 返厂
- 换机
- 翻新
- 再销售
- 调拨
- 冻结
- 遗失
- 盘亏
- 报废

## 四、库存不是一个数字

每个仓库至少维护：

- on_hand：账面实存
- available：可用
- reserved：已锁定
- in_transit：运输中
- defective：不良
- after_sales：售后
- scrap_pending：待报废
- scrapped：已报废

库存余额可以缓存，但必须能够由 StockLedger 全量重算。

## 五、货动必有单

所有设备数量或状态变化必须有正式单据：

- 采购入库单
- 代理采购单
- 销售出库单
- 调拨单
- 客户退货入库单
- 售后入库单
- 换机出库单
- 盘盈单
- 盘亏单
- 报废单
- 调整单

已生效单据不可删除。

错误通过作废、反向单据或差异调整处理。

## 六、锁库防超卖

订单进入待发货阶段时：

available 减少，reserved 增加。

取消订单或超时：

reserved 释放，available 恢复。

真正出库：

on_hand 减少，reserved 减少，in_transit 增加。

必须通过数据库事务/原子更新避免两个订单同时抢同一 SN。

## 七、代理采购物流闭环

代理下采购单
-> 按代理等级/价格政策计算采购价
-> 支付
-> 总部仓生成拣货任务
-> 扫描 SN
-> 复核
-> 出库
-> 生成物流包裹
-> 运输
-> 代理签收
-> 代理确认入库

支持一个采购单拆成多个包裹、多次发货。

## 八、异常签收

代理不能只有“确认收货”。

必须支持：

- 正常签收
- 部分签收
- 拒收
- 数量差异
- 外包装破损
- 设备损坏
- SN 不符

异常签收自动生成差异记录和待处理售后/物流异常任务。

## 九、退换机

换机流程必须保留 old_sn -> new_sn 关系。

原机和新机各自保持完整生命周期。

原机可能：

维修 -> 翻新 -> 再销售

或：

检测 -> 报废

客户设备绑定变更也必须记录历史。

## 十、报废

报废流程：

发起
-> 技术/仓储检测
-> 上传证据
-> 审批
-> 库存从可用体系移出
-> 生成报废流水
-> 如有残值，生成财务处理关联
-> 完成

报废不能直接把 SN 删除。

## 十一、盘点

盘点采用冻结快照。

盘点结果：

账面数量 vs 实盘数量

差异不会自动直接改库存。

必须生成盘盈/盘亏差异单，调查、审批后生成调整流水。

## 十二、仓库全链路查询

按 SN、SKU、批次、出库单、物流单、员工均可查询：

- 入库时间
- 入库经办人
- 质检人
- 仓库/库位
- 锁库订单
- 拣货人
- 复核人
- 出库人
- 物流信息
- 签收人
- 售后经办人
- 报废审批人

所有人员保存当时姓名、组织、部门、岗位快照。
