# 11 后台菜单、页面层级与列表交互规范

## 一、页面层级统一原则

后台统一采用三级信息架构：

一级菜单 -> 二级模块总览 -> 三级具体功能

禁止把员工、角色、审批、流水、配置等多个独立业务功能长期堆在同一个二级页面。

### 一级菜单

一级菜单只负责业务域分类，例如：

- 系统
- 运营管理
- 商业管理
- 系统管理

### 二级模块总览

二级页面首先回答三个问题：

1. 这个模块现在整体是什么状态；
2. 这个模块有哪些功能；
3. 用户下一步可以去哪里操作。

二级总览必须包含：

- 面包屑/返回上级
- 模块标题与说明
- 顶部功能快捷卡片
- 关键数据概览卡片
- 功能分组
- 可用功能和规划中功能状态

二级总览不承载大量具体编辑表单。

### 三级具体功能

三级页面负责真正的业务操作。

所有三级页面必须统一提供：

- 返回二级模块总览
- 面包屑
- 当前功能名称
- 同级功能快捷切换

用户不能进入功能页后只能依赖浏览器后退。

## 三、二级总览视觉规范

顶部快捷菜单使用卡片，不使用纯文字链接堆叠。

每张功能卡片至少包含：

- 功能图标或识别符
- 功能名称
- 一句话说明
- 状态/类型角标
- 明确的进入提示

规划中功能可以展示，但必须以弱化样式标记“规划中”，不能让用户误以为已经可操作。

数据概览采用独立统计卡片，数字和状态为视觉重点，说明文字弱化。

功能分组采用业务语义分组，例如：

- 组织与人员
- 权限与风控
- 资金业务
- 账务与追溯
- 商品配置
- 奖励与结算

## 四、多数据页面统一规范

所有可能出现大量记录的页面默认必须考虑两种展示模式：

- 卡片模式
- 表格模式

典型页面包括：

- 客户
- 代理
- 销售
- 员工
- 会员方案
- 直播间
- 财务流水
- 资源流水
- 设备
- 库存
- 售后单据
- 审批任务

### 必备能力

大量数据页应统一提供：

- 关键词搜索
- 状态筛选
- 业务条件筛选
- 排序
- 每页数量
- 分页
- 卡片/表格切换
- 加载状态
- 空状态
- 无搜索结果状态

不能把全量数据一次性无限渲染到单页。

## 五、卡片模式适用场景

卡片模式适合：

- 需要快速识别人或组织
- 状态和多个关键指标并列
- 移动端/窄屏
- 需要更强视觉识别

卡片上只展示最重要信息，详细数据进入详情页。

## 六、表格模式适用场景

表格模式适合：

- 财务
- 库存
- 流水
- 对账
- 客户批量核查
- 大量记录横向比较

表格必须考虑：

- 横向滚动
- 固定关键字段（后续需要时）
- 排序
- 状态字段
- 操作列
- 分页

## 七、返回与导航规范

二级总览：

- 显示上级入口
- 显示当前模块名称

三级页面：

- 必须有“返回 XX 总览”
- 必须显示面包屑
- 必须显示当前功能
- 推荐显示同级功能切换

长页面的三级导航可采用吸顶方式，但移动端应退化为普通布局，避免遮挡内容。

## 八、权限注意

菜单可见不等于有业务权限。

前端导航必须和后端权限保持一致：

- 功能权限决定能否进入或执行
- 数据范围决定能看到哪些数据
- 高风险操作必须后端再次校验
- 不允许只依靠前端隐藏按钮实现权限

## 九、当前实现基线

当前 Web Console 已建立共享模块配置和共享三级导航组件。

后续新增二级/三级功能时，应优先扩展共享模块配置，不应在单个页面重新制作独立导航体系。

列表页面应复用统一的搜索/筛选/排序/视图切换/分页组件，以保持全系统交互一致。

## 十、统一链路导航组件

全系统二级、三级业务页面统一复用 `ModulePageNav.vue`，禁止在业务页面中重新手写面包屑、返回按钮或同级功能菜单。

导航配置集中维护在：

- `web-console/src/navigationUi.ts`
- `web-console/src/moduleUi.ts`

统一组件支持：

- 系统模块
- 客户工作台
- 代理工作台
- 销售工作台
- 内部员工工作台
- 个人中心

组件负责统一处理：

- 返回上级
- 面包屑
- 当前功能高亮
- 同级功能快捷切换
- 二级总览模式
- 三级功能模式
- 不同角色的上级工作台
- 不同权限员工可见功能

新增业务页面时必须优先扩展导航配置，再复用统一组件，不应在 Vue 页面内复制导航结构。

终端客户的直播、财务、邀请与推荐、账户与设置，以及代理和销售工作台，均与系统后台使用同一套链路导航视觉和交互。

## 十一、终端客户商城

终端客户工作台增加独立“商城”模块，不将商品购买入口混入财务管理。

客户工作台顺序：

- 直播运营
- 商城
- 财务管理
- 邀请与推荐

商城第一阶段展示时长卡商品，至少展示：

- 商品名称
- 可用时长
- 原价
- 当前折扣
- 折后价
- 立省金额
- 有效期/规则说明
- 购买按钮

当前阶段购买功能未开放：

- 按钮必须禁用
- 不创建订单
- 不扣减钱包
- 不产生资金流水
- 不产生资源入账

当前 Web Console 使用演示商品数据完成界面和价格展示联调。正式上线前，数据源应切换到后台 TimeCardPlan/TimeCardPlanVersion 配置，并按客户会员、渠道和生效规则计算可见价格。

商城负责“卖什么、多少钱”；财务管理负责“钱从哪里来、去了哪里、余额和流水是什么”，两者职责分离。
