# 直播智能体方案：业务归属、学习记忆与交付隔离

## 1. 核心业务实体

系统正式统一使用“直播智能体方案”。

关系：

- 一个用户可以拥有多台设备、多个直播间、多个直播智能体方案。
- 设备是播放/接收资源，可以更换，不承载长期业务知识。
- 一个设备在同一时刻只服务一个直播间。
- 一个直播间是独立运行单元，独立采集公屏、独立生成并输出一条权威声音。
- 一个直播间同一时刻只使用一套直播智能体方案。
- 一套直播智能体方案可以同时被多个直播间使用。

因此长期业务知识的主要归属不是设备，也不是单次直播会话，而是直播智能体方案。

## 2. 直播智能体方案承载什么

当前先落地：

- 方案名称与说明；
- 多直播间绑定；
- 专有名词/品牌/商品/人物/地域词术语库；
- 人工纠错记忆；
- 常见误识别变体；
- ASR/转写前可使用的热词集合；
- 转写后的确定性文本纠错；
- 与学习证据的来源关联。

后续可继续挂载：

- 商品/业务事实；
- 主线规划；
- 互动策略；
- 主播表达风格；
- 用户层规则；
- 学习版本与复盘结果。

## 3. 人工术语纠错策略

示例：

原始转写：丑都养鸭子
人工确认：绸都杨鸭子

保存为：

- canonical_text = 绸都杨鸭子
- observed variant = 丑都养鸭子
- source = manual_correction
- confirmation_count 累积
- scope = 当前直播智能体方案

同一方案以后在任意已绑定直播间中复用这条记忆。

纠错链路：

声音 -> 当前方案热词 -> ASR 原始文字 -> 当前方案纠错词典 -> 上下文/语义判断 -> 最终文字

第一版先提供“热词输出 + 已确认误识别的确定性替换”。以后接入真实 ASR 后把同一套术语资产注入 ASR 上下文。

## 4. 生命周期

- 停播：方案知识保留。
- 换设备：方案知识保留。
- 换直播间：方案知识保留。
- 多个直播间绑定同一方案：共享方案知识。
- 方案归档：不再参与新的运行，但历史学习和纠错数据保留用于审计与恢复。
- 单次 Session 结束不能删除方案知识。

## 5. 自学习与事实分离

学习系统必须区分：

- 表达/判断规则；
- 已验证业务事实；
- 术语和专有名词；
- 合规约束；
- 运行时故障。

“绸都杨鸭子”属于直播智能体方案的术语/业务知识，不属于通用规则层。

人工纠正优先级高于模型猜测。错误输出只作为负样本，不自动晋升为事实。

## 6. 研发测试、内部运维、客户交付三层隔离

### 研发测试工作台

允许显示：

- 场控 Agent / 评审 Agent / 学习 Agent 模型；
- Prompt 调试相关结果；
- 安全点、切入、回归、队列、评分；
- 术语命中与原始/纠正后文本；
- 延迟、内部状态、调试接口结果。

目标：最大可观测性，方便调教系统。

### 内部运维端

只给有权限的内部人员必要诊断和审核能力。规则层/行业层/用户层、学习候选、授权、发布记录按权限开放。

### 客户交付端

只暴露客户需要操作和理解的业务能力：

- 设备；
- 直播间；
- 直播智能体方案；
- 商品/主线/话术配置；
- 术语纠错；
- 业务化运行状态；
- 必要的学习建议和结果。

不向客户返回或打包核心内部机制：

- 内部 Prompt；
- 评分公式和阈值；
- 安全点算法；
- 问题队列和调度算法细节；
- Strategy Debt；
- 内部切入/回归决策链；
- Core/Audio 内部协议；
- Redis Key；
- 内部模型请求参数；
- 学习 Agent 提炼 Prompt。

## 7. 技术隔离原则

不能依赖前端 CSS、v-if 或隐藏按钮保护核心逻辑。

必须做到：

1. 研发专用路由只在 development 环境注册；
2. 生产环境访问研发路由返回 404；
3. 客户 API 使用独立业务 DTO，不返回内部调试字段；
4. 客户端正式构建不包含研发测试工作台组件；
5. 内部管理能力必须经过服务端权限校验；
6. 密钥、内部 Token、Prompt 内核永不下发客户浏览器。

原则：测试阶段“尽量透明”；交付阶段“能力可见，机制不可见”。
