# 直播智能体方案与交付隔离设计

更新时间：2026-09-25

## 1. 统一业务名称

对外统一使用：直播智能体方案。

不再使用“直播方案”“直播话术方案”作为正式业务实体名称。

## 2. 三个核心业务实体

### 2.1 设备
- 设备是声音输出资源，不承载直播业务知识。
- 设备可以更换、重新绑定。
- 同一时刻一台设备只服务一个直播间。
- 一个直播间运行时只对应一条权威声音输出。
- 网页、电脑、小智 AI 等都属于播放/接收层，Core 不依赖具体设备类型。

### 2.2 直播间
- 直播间是独立运行单元。
- 每个直播间独立采集公屏、维护上下文、问题队列和声音输出。
- 同一终端可以同时运行多个直播间。
- 每个直播间在一次运行中使用一个直播智能体方案。

### 2.3 直播智能体方案
直播智能体方案是可被多个直播间复用、可长期学习的业务知识资产。

一个方案未来可包含：
- 商品/业务事实；
- 主线规划；
- 互动话术策略；
- 主播表达风格；
- 专有名词和术语；
- 人工纠错记忆；
- 学习候选与已批准学习；
- 方案版本和历史。

关系：
- 一个直播智能体方案可以同时绑定多个直播间；
- 一个直播间一次运行使用一套直播智能体方案；
- 设备与方案没有直接知识依赖；
- 更换设备不会丢失方案学习结果；
- 更换直播间，只要继续使用同一方案，方案知识仍继续生效。

## 3. 人工术语纠错

示例：

原始转写：丑都养鸭子

人工纠正：绸都杨鸭子

这类纠错不是规则层，也不是设备记忆，而是直播智能体方案的术语知识。

第一版数据模型：
- 标准术语：绸都杨鸭子
- 常见误识别：丑都养鸭子
- 类型：专有名词/品牌/商品/人物/地域词等
- 来源：人工纠错
- 确认次数
- 所属直播智能体方案
- 状态

同一个正确词可以积累多个误识别变体。

## 4. 纠错生命周期

只要直播智能体方案仍有效：
- 停播不删除；
- 换设备不删除；
- 换直播间不删除；
- 多个直播间共用同一方案时共享；
- 方案升级版本时默认继承。

方案归档后：
- 停止参与新的运行；
- 历史纠错数据仍保留，用于审计和恢复；
- 不做物理删除。

## 5. 语音转文字纠错链路

目标链路：

声音 → 加载当前直播智能体方案术语 → ASR 热词/上下文词 → 原始转写 → 方案术语纠错层 → 上下文检查 → 最终文字

第一版先实现：
- 方案术语库；
- 人工错误变体记忆；
- 文本规范化预览；
- 多直播间共享。

后续 ASR 接入时直接消费同一套方案术语数据，不重新设计数据结构。

## 6. 学习边界

必须分开：
- 风格学习；
- 已验证商品/业务事实；
- 合规与真实性原则；
- 运行时规则；
- 方案术语纠错。

例如：
- “四川口语歧义要结合上下文判断”属于判断规则；
- “绸都杨鸭子是本方案正确专名”属于方案术语知识；
- “播放器没声音”属于运行时问题；
- 不能因为一次错误回答中出现某事实，就把它学习成真实商品事实。

## 7. 三层交付界面

### 7.1 研发测试工作台
目的：把系统调透。

允许显示：
- 场控 Agent / 评审 Agent 模型；
- 安全点；
- 切入与回归策略；
- 问题队列；
- 模型延迟；
- 评审分和评审原因；
- 原始 ASR 与纠错结果；
- 学习候选；
- 内部策略链；
- 诊断信息。

当前 5176 定位为研发测试工作台。

### 7.2 内部运维/管理端
目的：让有权限员工维护业务，不默认暴露全部底层实现。

可见：
- 必要的规则层/行业层/用户层配置；
- 直播智能体方案；
- 学习审核；
- 术语纠错；
- 客户授权范围；
- 业务级异常原因。

不默认显示：
- 完整系统 Prompt；
- 内部算法细节；
- Redis Key；
- Core/Audio 内部协议；
- 供应商密钥；
- 全量调度链。

### 7.3 客户交付端
原则：能力可见，机制不可见。

客户看到：
- 设备；
- 直播间；
- 直播智能体方案；
- 商品资料；
- 主线内容；
- 术语纠错；
- 运行状态；
- 待回答问题；
- 可操作的学习建议。

客户不接收：
- 场控 Agent 真实 Prompt；
- 评审 Agent Prompt；
- 安全点算法；
- 评分公式/阈值；
- Strategy Debt；
- 内部切入/回归决策链；
- 模型调用参数；
- 内部服务地址；
- Core/Audio 私有协议；
- Redis Key；
- 学习 Agent 的内部提炼 Prompt。

## 8. 安全实现原则

不能只靠前端隐藏。

正式环境必须做到：
1. 开发诊断接口只在 development 环境注册；
2. 客户 API 使用独立的业务 DTO，只返回客户需要的字段；
3. 研发诊断组件不进入正式客户前端构建；
4. 内部管理 API 与客户 API 权限域分离；
5. 密钥永远只存在服务端；
6. 核心决策 Prompt、调度算法和策略内部数据不发送到客户浏览器。

## 9. 当前第一版落地目标

- 建立直播智能体方案表；
- 建立方案与直播间绑定；
- 建立方案术语与误识别变体；
- 人工纠错长期保存；
- 同方案多直播间共享纠错；
- 研发测试页支持创建方案、绑定直播间、录入纠错、模拟转写纠错；
- Core/Management 的开发诊断路由仅在 development 环境注册；
- 场控 Agent 与评审 Agent 分开选择模型；
- 测试页可从当前模型账户动态读取模型列表。
