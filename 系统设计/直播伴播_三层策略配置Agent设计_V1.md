# 直播伴播三层策略配置 Agent 设计 V1

## 1. 产品目标

普通客户不需要理解 Prompt、YAML、DSL 或策略 ID。

前台只做三件事：

1. 选择行业。
2. 上传/粘贴自己的话术和资料。
3. 用自然语言和“策略配置 Agent”交流，告诉系统哪些地方要改。

系统负责把自然语言转换成机器可执行策略。

---

## 2. 三层策略

### L1 基础策略

用途：

- 国家/地区法律与监管要求；
- 平台规则；
- 系统公共合规边界；
- 绝对化、虚假事实、真正高风险问题等公共控制。

正式版权限：

- 只有平台有权限的管理人员可编辑。

约束：

- L1 是强制边界。
- L2/L3 不允许解除 L1。

### L2 行业默认策略

用途：

- 食品、生鲜、禽类、美妆、服装等行业共同经验；
- 常见问题怎么回答；
- 常见实时信息怎么处理；
- 行业常见风险和常识回答范围。

正式版权限：

- 只有有权限的行业运营/管理人员可编辑。

约束：

- L2 是默认能力，不是不可修改的最终答案。
- 客户可以在 L3 中覆盖不适合自己的 L2 业务规则。

### L3 用户特殊策略

用途：

- 客户自己的商品表达；
- 自己主播的习惯；
- 特殊禁语；
- 特殊回答流程；
- 对 L2 的补充、替换、关闭。

正式版权限：

- 客户可以通过自然语言配置。

约束：

- L3 与 L2 冲突时，L3 可以覆盖 L2。
- L3 永远不能突破 L1。

---

## 3. 生效关系

有效策略：

L1 强制边界
+
L2 行业默认
+
L3 客户覆盖

更准确地说：

Effective Policy = L1( L2 ⊕ L3 )

其中：

- L1：不可突破；
- L2：默认值；
- L3：客户覆盖值。

---

## 4. 前台交互

前台不展示机器语法。

页面采用聊天界面。

用户看到：

- 左侧：与策略 Agent 的聊天记录；
- 右侧：L1、L2、L3 当前策略文本；
- 顶部：当前对话准备修改哪一层；
- 底部：自然语言输入框。

测试阶段：

- L1/L2/L3 都可以切换和测试。

正式阶段：

- 普通用户只能直接配置 L3；
- L1/L2 的 Agent 配置入口受后台权限控制。

---

## 5. 策略 Agent 工作流程

用户自然语言
↓
Qwen3.8-Flash 理解
↓
识别当前目标层
↓
理解用户真实意图
↓
生成完整的新策略版本
↓
检测 L1 冲突
↓
向用户说明“我理解成什么”
↓
形成待应用 Proposal
↓
用户确认
↓
保存对应层
↓
重新编译 Effective Policy

---

## 6. 对话原则

用户不需要说：

- REPLACE
- EXTEND
- policy_id
- JSON
- DSL

用户只需要说：

“老人小孩的问题不要动不动找医生，正常就说做熟做软一点。”

Agent 应理解为：

- L3 特殊人群规则增强；
- 普通人群正常回答；
- 明确过敏/疾病/用药才提高谨慎；
- 不突破 L1。

然后给用户自然语言确认。

## 8. 当前 API

GET /api/strategy-chat/config

- 读取三层策略；
- 读取聊天历史；
- 返回 Effective Policy。

POST /api/strategy-chat/config

- 测试阶段手动保存 L1/L2/L3。

POST /api/strategy-chat/message

- 与策略配置 Agent 对话；
- 产生解释或策略修改 Proposal。

POST /api/strategy-chat/apply

- 应用当前待确认策略修改。

POST /api/strategy-chat/reset

- 重置测试策略与聊天记录。

## 10. 策略提交机制

默认不让模型一次修改后立即生效。

流程：

用户提出要求
↓
Agent 生成 Proposal
↓
用户看到理解结果
↓
用户点击“应用这次调整”或直接说“确认”
↓
对应策略层更新

这样避免一次模型误解直接污染正式策略。

---

## 11. 后续权限模型

测试阶段：

L1/L2/L3 全部开放。

正式阶段：

- 平台超级管理员：L1/L2/L3；
- 行业策略运营：允许维护授权行业的 L2；
- 企业管理员：只能维护本企业 L3；
- 普通直播间用户：按企业权限决定是否可维护 L3；
- 所有策略修改要有版本、经办人、发布时间、回滚能力。

## 12. 后续扩展

1. 用户上传历史主播话术后自动提炼 L3。
2. 自动识别推荐行业 L2。
3. L2 更新时检测哪些客户 L3 已覆盖对应规则。
4. 支持策略版本对比。
5. 支持灰度发布。

## 13. 核心产品原则

客户不是在“配置 Prompt”。

客户是在“交代一个新来的直播主管”。

系统负责把人话转换为策略，把策略转换为稳定可追溯的机器行为。

# 14. 话术表达双模式（2026-09-23）

同一条策略在运行时分两种表达模式。

## A. 固定原话

用户明确表达：

- “就按这句话说”
- “必须原话”
- “一字不改”
- “固定这样说”
- “100%原话”

系统行为：

1. 将该话术标记为“固定原话”。
2. 运行时直接读取固定文本，不交给大模型改写。
3. 不做同义替换，不做随机变化。
4. 如果固定原话与 L1 冲突，在配置/发布阶段直接提示冲突。
5. 不允许系统偷偷改写以后仍然标记为“原话”。

## B. 按意思灵活生成

用户表达：

- “按这个意思”
- “类似这样”
- “灵活一点”
- “换着说”
- “不要每次都一样”

或者没有明确要求逐字固定时，默认进入该模式。

系统行为：

1. 锁定核心意思、已确认事实、禁区和策略边界。
2. 大语言模型可以变化：
   - 开头；
   - 句式；
   - 语序；
   - 解释角度；
   - 口语词；
   - 承接方式。
3. 每次生成前读取同一意图最近已经播过的话术 recent_variants。
4. 主动避开重复句式和长片段。
5. 变化不能增加新的商品事实、功效、对比、价格、库存、优惠或绝对承诺。

原则：

“固定原话 = 锁文本。”

“按意思灵活生成 = 锁意思和边界，放开表达。”

这两种模式可以同时存在于同一客户策略中，不要求整套 L3 只能选择一种。
