## 十一、建议状态机

### Payment

CREATED
-> PROCESSING
-> SUCCESS
-> PARTIAL_REFUNDED
-> REFUNDED

失败路径：

PROCESSING -> FAILED

### Withdrawal

APPLIED
-> FROZEN
-> REVIEWING
-> APPROVED
-> PAYING
-> PAID

失败：

PAYING -> PAY_FAILED -> UNFROZEN

驳回：

REVIEWING -> REJECTED -> UNFROZEN

### SettlementPeriod

OPEN
-> CALCULATING
-> REVIEWING
-> CLOSED

禁止 CLOSED -> OPEN。

### OutboundOrder

CREATED
-> RESERVED
-> PICKING
-> PICKED
-> REVIEWED
-> SHIPPED
-> COMPLETED

取消仅允许在未 SHIPPED 前按规则回滚锁库。

### Device

INBOUND_PENDING
-> IN_STOCK
-> RESERVED
-> IN_TRANSIT
-> AGENT_STOCK
-> SOLD
-> CUSTOMER_BOUND
-> ACTIVE

售后分支：

ACTIVE
-> RMA_TRANSIT
-> AFTER_SALES
-> REPAIRING / REPLACED / SCRAP_PENDING
-> ACTIVE / SCRAPPED

### Contract

DRAFT
-> PENDING_SIGNATURE
-> SIGNED
-> ACTIVE
-> EXPIRED / TERMINATED / VOID

SIGNED 之后禁止物理删除。

## 十二、事件可靠性

为了避免“支付成功，但代理结算没生成”这种半成功状态，建议使用事务 Outbox：

同一数据库事务中：

- 写 Payment SUCCESS
- 写 OutboxEvent

异步消费者处理：

- 结算
- 业绩
- 通知
- 报表

消费者以 event_id 幂等。

失败可重试，不允许重复入账。

## 十三、不可变字段

下列数据进入正式状态后原则上不可直接修改：

- Payment 金额
- 渠道流水号
- LedgerEntry
- StockLedger
- 已签合同内容
- 已生效出入库单
- SN
- 已关闭结算期
- 已完成审批记录

纠错使用补偿、冲正、调整单。
