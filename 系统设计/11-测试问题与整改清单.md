# 11 - 2026-09-22 全流程测试问题与整改清单

> 来源：超级系统管理员创建普通“管理部员工”后，按真实使用流程逐页测试。原则：先记录、后集中整改。本清单作为本轮统一整改依据。

## P0/P1 权限安全

- 管理部普通员工只能“全局查看 + 协调 + 问题追踪”，不得因为拥有 `system.architecture.view` 获得写权限。
- 代理等级：普通管理部员工曾可真实新建等级（已产生测试记录 `auth-test-001`）。新增/编辑/等级调整必须使用独立写权限，前后端同时校验。
- 代理合同：普通管理部员工曾可真实创建合同草稿（已产生测试合同）。新建、编辑、提交签署、作废、续签、补充协议必须使用独立写权限，前后端同时校验。
- 代理退出清算：“完成退出并停用代理”属于高危动作，普通管理部员工不得看到或调用；后端必须独立强制鉴权，正式执行应经过确认/审批链。
- 资源调整：前端错误显示“调整”并可打开表单；后端已能拦截。前端需按 `resources.adjust` / `finance.resource.adjust` 隐藏写入口。
- 直播间：普通管理部员工曾看到“添加直播间/删除”；后端已按客户身份拦截。前端无权限时不显示写按钮。
- 所有无权限操作：按钮优先隐藏；后端继续兜底；错误反馈统一为系统 Toast/提示卡，不使用大红条或浏览器原生提示。

## 内部组织与角色

- 用户可见名称统一：组织架构 → 部门 → 员工 → 角色 → 权限 → 数据范围；不再出现“员工组/本组”等旧称。
- 系统内置部门：管理部、财务部、销售部、营销运维部、仓储售后部；系统自动建立并锁定，不可删除/改名/改编码。
- 新增“营销运维部”：负责客户直播设备与直播过程配置、联调、监控、异常处理、远程协助、运维工单；硬件问题可转售后 RMA。直播运维不碰资金、商业政策、库存账和财务审批。
- 直播运维内置角色：营销运维负责人、营销运维专员。
- 普通管理部员工：全局只读查看；管理部负责人：可按既有部门/角色新增、停用员工和分配已有角色，但不能修改底层权限定义、资金/商业规则。

## 员工编号与新增员工

- 员工编号改为全系统稳定编号：固定前缀 `EMP-` + 6 位数字，例如 `EMP-000032`；员工调部门编号不变。
- 页面只要求输入数字部分；自动补零并显示完整编号预览。
- 员工编号全系统唯一，输入时实时查重；重复红框提示并禁止提交；后端唯一约束继续兜底。
- 新增员工不默认勾选“部门负责人”；负责人必须主动选择。
- 角色选择卡片改为紧凑多列，选中整卡高亮，负责人角色提示高权限。
- 初始密码继续系统随机生成、首次登录强制改密；复制凭证为纯文本。

## 品牌与全局命名

- 内部管理端统一品牌：`小蓝搭子管理系统`。
- 内部管理端原“伴播搭子”全部统一替换；左上“伴”字图标后续替换为统一品牌图标。
- 用户可见“直播运营”统一改为“直播运维”（菜单、标题、面包屑、总览、说明、权限文案等）。代码内部稳定 API/字段可不强改。
- 英文内部状态/角色/编码不直接暴露普通用户：如 `active`、`IN_STOCK`、`REFUND_PENDING`、`management_staff` 等显示中文标签；必要时内部编码放高级信息。

## 全局 UI 规范

- 数据总览与功能入口必须视觉分层：统计数据放统一概览容器；可点击功能才做入口卡片。
- “功能菜单”和“功能分组”内容重复时只保留一套；入口多时直接在顶部入口区分组，不在下面再重复。
- 卡片视图必须是真正的中小型长方形卡片：宽屏从左到右 3~4 列，自动换行；达到页容量后分页。不能把全宽列表行叫卡片。
- 表格默认字号提高；字段多时使用横向滚动、列折叠/详情，不靠极小字体塞内容。
- 个人中心显示设置新增：表格文字大小（小/标准/大或滑杆）、表格密度（紧凑/标准/宽松）；全后台统一生效。
- 顶部二级功能导航按钮过小：统一增大高度、字号和留白；功能多时换行/横向滚动。
- 大数据流水页禁止全量平铺：统一“概览 + 搜索筛选 + 分页 + 聚合 + 详情钻取”。
- 原生 `window.confirm()` 危险确认改系统内居中确认弹窗；标题、风险说明、取消、红色确认按钮统一。
- 权限提示统一 Toast/提示卡，默认 3 秒自动消失，不遮挡主内容。
- 头像上传：统一 cover 裁切、拖动/缩放预览、确认裁切；上传后不再露出默认占位层。

## 路由/页面问题

- 组织架构“权限审计”入口曾跳到系统总览：修复为独立只读审计页面。
- 客户资源“管理审计”曾复用客户列表正文：根据入口显示真正审计内容；审计记录只能查看，不能删除/篡改。
- 客户资源“密码重置”：无权限角色不显示入口；有权限角色才进入明确“客户密码重置”页。
- 销售体系“管理销售部员工”按权限动态命名：有管理权叫“管理…”，只读叫“查看…”；统一跳组织架构，不另建人员体系。
- “重新统计”如果只是读刷新，文案改“刷新统计”。

## 代理体系

- 代理列表卡片可点击进入只读详情；表格提供明确“查看”。
- 代理/客户/员工/设备等对象数量可能很大时，不使用超长下拉框；改为“可搜索列表 + 当前选中高亮 + 详情联动 + 分页”。
- 退出清算采用代理列表选择，而非下拉框。
- 代理合同：系统合同编号自动生成、全系统唯一、永久不变；另留可选“纸质合同编号/外部合同编号”。
- 合同附件支持多张合同扫描/复印页：文件选择 + 拖拽上传 + 缩略图 + 排序 + 预览；签署/生效后原始附件锁定，后续走补充协议/追加附件。
- 合同签署后正文不可覆盖删除，续签/补充协议形成新记录并关联原合同。

## 设备、库存、物流、售后追溯

- SN 全链基础已可追：入库、锁库、出库、销售、客户绑定、激活、RMA/物流等。
- 换机必须显式显示“旧 SN ↔ 新 SN”，两边可互相点击穿透。
- 经办人不能只显示 `#1/#2`：显示“姓名 + 员工编号”，并可查看人员信息。
- 订单号、物流单、RMA、设备 SN 等关联单据全部可点击穿透。
- RMA 列表当前无法进入详情：补 RMA 详情钻取；至少覆盖申请 → 审核 → 寄回 → 仓库签收 → 质检 → 维修/换机/退货/报废 → 退款/财务流水。
- `REFUND_PENDING` 等售后状态统一中文。
- 物流轨迹补经办人、节点地点、签收人/签收方式/异常备注；真实环境保存真实节点时间。
- 全链记录只追加，不允许删除/覆盖。

## 资源中心

- “资源工作台”与“资源调整”当前内容重复：工作台只做总览/异常/待办；资源调整单独写操作；资源流水单独查来源去向和前后余额。
- 资源流水字段：资源类型、来源、去向、增减数量、前余额、后余额、原因、经办人、审核人、时间、关联业务单；不可改删。

## 个人中心与账号安全

- 所有密码输入框统一眼睛开关：登录、首次改密、当前密码、新密码、确认密码、重置密码等。
- “员工正式姓名”与“个人显示昵称”分离：正式姓名由组织管理权限维护，员工本人只改昵称。
- 账户安全补会话管理：当前设备、其他设备、登录时间、IP/大致地区、最近登录记录、退出其他设备。
- 修改密码后保留当前会话，其余会话失效。
- 密码输入提供强度提示。

## 已确认通过/基本通过

- 系统内置部门锁定；普通管理部员工部门/员工/角色基本只读。
- 初始密码随机生成、一次性展示、首次登录强制改密。
- 客户归属只读；销售团队/客户归属/业绩提成当前未发现资金写权限；“重新统计”实际只刷新。
- 会员方案、时长卡、设备商品、推荐奖励、结算规则对普通管理部员工当前为只读。
- 规则模拟器明确沙盒、不入账。
- 库存与仓储、物流与签收对普通管理部员工当前基本只读。
- 资源调整后端鉴权已能拒绝普通管理部员工。
